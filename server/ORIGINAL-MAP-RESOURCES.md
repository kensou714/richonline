# Original maps and BOSS startup inputs

The original native game library now reads the installed `Map/*.emp` directly. Python and generated map JSON are not runtime dependencies. JSON extracts under `protocol-analysis/board-startup/maps` are used only as an independent test oracle. `OriginalEmp` retains the complete uncompressed payload and header, including bytes without established business names.

`load_original_emp` supports version1/2/3 outer layouts, checks dimensions against the signed16 tile domain, decodes the additive-byte/LZO block and checks every core array boundary. Version2 has a decoded layout supported by the original disassembly but no bundled sample. `original_map_resources` validates its public input's layout, derives walkability and cardinal adjacency, applies the special-coordinate type7 override, and constructs referenced properties with owner=-1, original kind normalization and checked priceBase multiplication. Bounds/overflow checks are intentional native safety rules; the client did not perform all these checks.

`load_original_price_base` reads `[OTHER].priceBase` from the actual `Data/Option.kpd`. KPD decoding has an explicit caller limit (default4MiB, maximum64MiB). The native map loader uses the64MiB bound. It rejects truncated streams, incorrect sizes, invalid decompression and bytes following a declared compressed block.

The tail contains initial human cash/deposit/tickets/scale at+104/+108/+112/+116. After the counted array at+120, the parser reads card/weight pairs and both counted weighted-pool ID lists. A zero pair count skips both list headers, matching the client branch. The first pool is associated with a local shop-stock record generator; a universal reward interpretation is unproven. `pool_a_ids` and `pool_b_ids` intentionally do not select reward policy. Further tail fields remain intact in the raw payload; `parsed_tail_bytes` marks the understood prefix, not the end of the resource.

The bundled `CM_CS_2.emp` contains an actual initial scale0. The resource model preserves it; the4004 encoder and BOSS startup builder continue to reject nonpositive live scale. Loading a resource is not authorization to use every resource default for an active match. A future mode-specific strategy must supply a justified positive live value for this map rather than silently rewriting the source data.

`OriginalBossConfig` loads explicit per-stage local policy from the existing JSON schema; see `ORIGINAL-BOSS-CONFIG.md`. Its `implemented` status describes the migrated configuration's historical supported stages, not a claim that native gameplay is ready. `prepare_original_boss_board` joins validated resources, stage policy and a room-bound request into typed4000/4004 startup data. It verifies map name/signature, original single-player BOSS extension, human identity and both spawn directions. The human skill array uses the configured maximum; the BOSS record array remains explicit because original BOSS gameplay reads its separate BossWar table. Administrator balances deliberately override the EMP's default human funds.

Spawn coordinates, instance/context/date, unresolved game double, alignment bytes, suffixes and envelope metadata must be supplied explicitly by the caller. The constructor does not silently fill unresolved wire fields with zero. This input layer does not issue room handoffs, handle actions or create a running game. Production still requires the native BOSS strategy, game-to-lobby lifecycle, cards/landing/timeout/settlement flows and original-client playthrough. Static edges do not implement dynamic blockades, conveyor extensions or teleports.

Original IDA source and field limits: `protocol-analysis/ORIGINAL-MAP-RESOURCE-RECHECK-20261009.md`, `BOARD-STARTUP.md`, `ORIGINAL-NATIVE-STARTUP-RECHECK-20261009.md`. This module is for the original root client; the separate `Richonline/` client is not an evidence source.
