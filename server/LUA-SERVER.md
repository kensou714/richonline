# Lua 服务端架构

服务端正在迁移为两层。`RichOnline.Server.exe` 提供网络封包、加密、准入令牌、SQLite、回合状态和原子事务；`server/scripts` 承担已迁移业务。**并非全部 C++ 玩法都已搬完**：部分卡片、格子和商城仍调用原生兼容接口，脚本中的 `implementation` 字段区分当前实现。不能把拆出文件等同于完整迁移。

2026-10-11本地已安装A975E10F版本，并逐项核对151个Lua文件与构建副本一致；包含本页已记载的卡牌/商城迁移、随机奖励出售资格和装备回血。商城内NEW10切换角色允许未入房的频道用户，角色模型保存及NEW18同步仍由核心处理。此次只编译和离线安装，运行验收由用户进行；详见 `evidence/mall-character-selection.md`。

## 入口

- 股票成交底层在 `gameplay/stock.cpp` 和 `game/stock.lua`（`stock.trade`）：维护至多十槽的权威报价/剩余量与角色持仓成本，准备完整4204/4205，再与存款原子提交。**当前未挂接实际对局**；行情初始化、普通地图准入及六张股票卡仍未完成，不能据此认为股票已开放。边界见 `evidence/stock-trade-core.md`。
- 股票资源与开局准备在 `resources/stock.cpp`（`stock.open`）：解析Stock.kpd及EMP的股票配置编号表，按客户端地图类型门禁接收每槽30点的明确历史，准备4200/4201并从末两点建立相同报价。此为待接入的开局准备器，没有伪造历史生成器或自动启用BOSS股票，详见 `evidence/stock-opening.md`。
- 强抛卡1124新增 `card.stock_forced_sale` 准备事件：独立卡片Lua复核清仓金额边界和40E7，股票核心绑定原手牌、报价版本、在场槽及全体存款快照，原子提交扣卡与清仓。网络 `use` 入口仍拒绝，待普通股票对局工厂及路由接入；详见 `evidence/stock-forced-sale.md`。
- 大地产12的建造、升级、研究选择在 `tiles/tile_12.lua`，事件 `property.construct`、`property.upgrade`、`property.research`。核心提供真实产权/等级/场景上限/技能/许可证库存/研究空槽，逐项核对决策、续接类型和完整403D/403E/403F后才提交；BOSS自动建造升级也使用同一模块。落点分流、购地、神庙/花园及研究到期发卡仍在核心，详见 `evidence/lua-property-decisions.md`。
- 银行格9的开窗和存取款业务在 `tiles/tile_9.lua`，事件 `bank.open`、`bank.transaction`。核心先认证请求日历、道路和待决账户，Lua决定存取款／取消／超时并组织4018、402A；完整回包、金额和余额通过核心复核后才关闭等待，再经共享账本提交。路过续行与落点续接仍由核心状态机负责，详见 `evidence/lua-bank-tile.md`。
- 装备回合回血业务在 `mall/equipment_effects.lua`，事件 `mall.equipment_healing`；核心提供资源条件值并校验计划，通过共享资金顺序事务镜像客户端本地回血，各笔正收入分别累计、全部原子提交。
- `game/rewards.lua` 统一卡片格、福神、新闻和节日的随机卡池。新核心提供地图允许且具有局内出售价格的候选，Lua应用业务开关，返回值再经核心出售能力过滤；不因卡可使用就允许进入随机奖励。

- `main.lua` 是脚本版本入口，按事件分发到 `network`、`game`、`cards`、`tiles`、`maps`、`bosses`、`mall` 和 `events`。
- 大厅连接和对局连接各自拥有一个 Lua VM；连接关闭时 VM 一并释放，脚本局部状态不会泄漏到别的玩家。
- `scripts.reload` 重新读取脚本并校验全部模块。已建立的连接继续使用旧快照，新连接使用新快照。
- 控制管道 `status` 会返回 Lua API 版本、快照代数和模块数量。
- 商城会话创建独立 Lua VM，购买策略在其中执行；已创建的商城会话继续使用其脚本快照。

数据库接口在大厅登录/请求和对局动作事件可用。`require("core.database").batch(statements, callback)` 在原生批次完成后调用 `callback({ok,result,error})`，当前是**同步完成回调**，没有后台数据库线程。所有 SQL 都来自受信任脚本；不能把客户端 SQL 直接传入。可写 SQL 能修改整个业务数据库，策划只应调用封装的业务模块。每个语句可指定 `expect_changes=1`，不符则整个批次回滚。

脚本不能执行第二条 SQL、事务控制语句、PRAGMA、ATTACH 或超过额度的结果。数据库事务与内存对局事务不是跨存储原子事务；不能在同一个卡牌脚本中既提交 SQL 扣款又准备内存扣卡，商城/付费移动应继续使用原生幂等业务接口。

二进制报文使用 Lua 字符串保存，允许零字节。脚本只构造明文内部报文；外层加密、长度、发送完成确认和重放检查由 EXE 完成。卡牌事务先准备库存/资金，再构造完整回包，核心在发送前一次性提交，避免 Lua 报错造成扣卡或加钱不同步。

`route.prepare_move` 每次卡牌动作只允许调用一次，不能与地产、地面、状态、资金、关系或坐标修改计划混用。Lua 必须先返回一个卡牌确认包，再原样返回完整路线数组；漏包、换序或脚本失败均不扣卡、不启动移动。核心提交前复核角色、回合、日历、位置、方向、状态、地面和库存版本；真实路障、地雷、香蕉、银行和落点续接沿用已有路线状态机。`core/move_card.lua` 共享扣卡/路线编排，各卡模块指定步数与确认操作号。

Lua 准备事务成功返回前不改权威状态；原生兼容调用可能已经提交事务，因此其后脚本出错不能自动重试。网络发送失败沿用原有连接终止/结算恢复机制，不能宣称网络发送与内存提交组成一个事务。`network.sent` 只在原生启用发送确认时触发；收到普通客户端 ACK 不等于此通知。

洗牌1125由Lua对扣卡后的既有卡叠做Fisher–Yates排列并构造40E8，不生成替换卡。核心拒绝重复/缺失/空槽/越界顺序，按照回包顺序重建库存并执行资源合成；返回包必须与准备器生成的唯一40E8逐字节一致，且不能混入其他状态修改计划。旧安装版EXE缺少重排能力时，脚本在准备扣卡前直接走原有原生洗牌事务；候选EXE才使用新Lua路径。

## 业务拆分

- `cards/card_<编号>.lua`：每张卡一个文件，`cards/registry.lua` 建立编号与操作号索引。
- `tiles/tile_<类型>.lua`：每种棋盘格一个文件，已迁移模块使用准备接口，未迁移模块使用 `tile.native`。
- `maps/<资源名>.lua` 与 `bosses/<名称>.lua`：地图和 BOSS 的独立策略入口。
- `mall/service.lua`：商城协议入口；`mall/purchase.lua` 接管购买资格和有效期规划。目录、价格、日期编码、资源期限复核、扣款、库存和幂等收据仍由核心商城服务校验。
- `mall/equipment.lua`：NEW51/52穿戴与卸下资格。每连接首次装备请求创建独立策略VM；part槽位映射、等级和ROLE适用性由Lua检查，核心事务复核账号/有效期/旧键/角色快照。成功广播NEW83/84并更新频道缓存；准备和游戏中禁止变更装备。
- 激活事务仍由核心负责。事务内先投影账号库存与装备，原生准备全部在线缓存和通知，成功后发布；其他同账号连接用NEW21重建背包而不重复扣费，装备按NEW84/83顺序替换。商城余额使用NEW19资料更新，避免再次走频道进入及装备初始化。
- `events/feasts.lua`、`game/rewards.lua`：节日账本同步和随机卡池策略。

迁移新功能时，先在 Lua 文件中实现策略和参数校验，再为需要改变权威状态的动作增加一个窄的 C++ 核心能力。不要在 Lua 中复制库存、资金或房产状态，也不要通过脚本直接拼接 SQL。

## 本轮已迁移与未迁移

目前69张卡已使用Lua规则或业务编排（以脚本implementation字段为准，含后文续增的攻击、地雷、毒气和召神迁移）：冬眠506；财神1069、福神1070；陷害1054、送神1048；洗牌1125；立即移动卡1038/1080–1083；乐透504、四张视效1117/1118/1127/1131；移动状态卡1039/1040/1041/1042/1079/1084；20张地产卡1031/1032/1033/1036/1037/1059/1077/505/1062/1064–1068/509–514；资金卡1051/1052/508；街区卡1035/1058；放置卡1043/500/507、研究陷阱1181/1183、净空502；同盟1060、察看1072、飞吻1130、武器条约1115、开路1061；传送1116、换位503；清除1078。地产的特殊等级限制和增益生命周期仍由C++ `property.prepare` 内的现有计划器负责，不能把它们计为完整搬离C++。其余23张文件包括主动兼容入口、被动卡定义和本地入口定义。遥控骰子与二至五步卡使用独立的 `route.prepare_move`，不进入持续状态卡的 `motion.prepare`。

`property.prepare` 的操作：`convert`/`convert_classic`（property、kind）、`house`（position）、`swap`（property、buildings）、`grow`（levels、own_only）、`destroy`（current、property可选、levels）、`purchase`（返回price）、`seal`/`price_rise`（当前街区）。每次卡牌请求只允许一份地产/街区计划，提交前验证原始版本。购地现金必须严格大于地价，由购地脚本校验并准备扣费。

查税脚本分别计算现金/存款的十分之一，均贫和均富保留各自的向下取整、最小现金规则；核心阻止负余额或有符号DWORD溢出。卡牌脚本或回包转换失败时，只要没有调用原生副作用/数据库，就返回400B并保留全部计划前状态；`lua_card_committed` 日志记录真正成功提交的卡号、槽位与变化范围。
