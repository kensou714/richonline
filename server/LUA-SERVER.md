# Lua 服务端架构

服务端正在迁移为两层。`RichOnline.Server.exe` 提供网络封包、加密、准入令牌、SQLite、回合状态和原子事务；`server/scripts` 承担已迁移业务。**并非全部 C++ 玩法都已搬完**：大部分卡片、格子和商城仍调用原生兼容接口，脚本中的 `implementation` 字段区分当前实现。不能把拆出文件等同于完整迁移。

## 入口

- `main.lua` 是脚本版本入口，按事件分发到 `network`、`game`、`cards`、`tiles`、`maps`、`bosses`、`mall` 和 `events`。
- 大厅连接和对局连接各自拥有一个 Lua VM；连接关闭时 VM 一并释放，脚本局部状态不会泄漏到别的玩家。
- `scripts.reload` 重新读取脚本并校验全部模块。已建立的连接继续使用旧快照，新连接使用新快照。
- 控制管道 `status` 会返回 Lua API 版本、快照代数和模块数量。
- 商城会话创建独立 Lua VM，购买策略在其中执行；已创建的商城会话继续使用其脚本快照。

## 核心接口

`core.call(name, value)` 只能调用当前事件注册的能力，`core.capabilities()` 可列出当前可用接口。`core.array()` 表示空数组，普通 `{}` 表示对象，`core.null` 表示空值，数组从 1 开始、角色/库存槽位仍从 0 开始。

| 能力 | 输入 | 返回/作用 |
| --- | --- | --- |
| `lobby.native` | 无 | 原请求的原生大厅 Frame 数组，仅一次 |
| `network.native` | 无 | 原请求的原生对局 Frame 数组，仅一次 |
| `game.native` | 无 | 原请求的原生内部明文数组，仅一次，不能与脚本准备事务混用 |
| `tile.native` | 无 | 执行现有落点、保持复杂状态续接，必须恰好一次 |
| `game.snapshot` | 无 | 当前回合、角色位置/资金/资金版本、玩家 8 格库存；can_act 表示在场且未冻结/梦游/睡神控制 |
| `card.prepare` | `{card=504}` | 校验原请求日历/槽位/归属，准备扣一张；返回零基 slot、bank |
| `motion.prepare` | `{card=1039,target=0}` | 仅支持 104/105/106/107/136/141：复用 C++ 移动计划器，返回卡牌确认、4011 路径和受保护自目标的400B；准备状态时钟与路线但不提前提交 |
| `inventory.prepare_clear` | `{cards={1044,1045}}` | 在已准备扣卡的主库存中移除列出的卡种，随本次卡牌事务提交；每次动作至多一次 |
| `funds.prepare` | `{actor=0,cash=15000,tickets=0,deposit=0}` | 每个角色可准备一次增量，多角色与扣卡一起提交；未知存款不能写入 |
| `relations.break` | `{target=1}` | 准备解除当前角色与目标的既有正值同盟，提交时生效 |
| `relations.rules` / `relations.prepare` | 无 / `{target=1,days=6}` | 读取资源中的同盟天数；准备写入双方关系计数，与扣卡共同提交 |
| `relations.clear_actor` | `{target=1}` | 准备清除指定在场角色与所有人的双向同盟计数；只允许本动作一份关系计划 |
| `status.prepare_clear` | `{target=1,fields={"possession","frozen"}}` | 准备清除脚本指定的受支持状态；NPC 附身时钟随状态一起版本化提交 |
| `property.prepare` | `{operation="convert",property=12,kind=12}` | 准备一个版本化地产操作，与扣卡和资金共同提交 |
| `map.info` | 无 | 棋盘 width、height、cells；位置按 row*width+col 编号 |
| `route.preview_open_road` | 无 | 现有十步开路寻路的 directions 与 landings；不移动角色，仅生成一次预览 |
| `actor.relocation_snapshot` | 无 | 角色零基槽、当前位置、在场/冰冻状态及原始旅馆/医院/监狱/绑架可用性 |
| `actor.prepare_positions` | `{positions={{actor=0,position=123}}}` | 准备一至全部在场角色的道路坐标变更；拒绝重复角色和越界格，提交前校验原坐标 |
| `map.cell` | `{position=123}` | 真实地类、道路、地产引用、角色占用及放置范围；active_actor_occupied 仅在场角色，ground_occupied 为原始动态占用 |
| `research.traps` | `{kind="ice"}` 或 `{kind="fire"}` | 已启用陷阱的 freeze_timer、fire_radius、fire_rounds，来自服务器资源副本 |
| `ground.prepare` | `{position=123,npc=11,byte7=0,byte8=255}` | 准备放置动态物件；不覆盖已有物件，与扣卡共同提交 |
| `ground.prepare_batch` | `{objects=core.array()}` | 准备一批物件，条目与 ground.prepare 相同；拒绝重复/越界/覆盖，允许空批次 |
| `ground.snapshot` | 无 | 当前动作原始地面快照数组：position、npc、byte7、byte8 |
| `ground.prepare_remove` | `{positions={123,124}}` | 准备移除格号数组；拒绝不存在或重复的格号，允许空数组 |
| `random` | `{upper=100}` | 1..upper 均匀随机整数 |
| `db.roles` | 无 | 当前认证账号的角色列表，仅大厅 |
| `mall.calendar_expiry` | `{years=0,months=1,days=0}` | 仅商城购买策略事件可用，按本次服务端时间计算有效期与年份；全0返回永久期限0 |
| `db.batch` | `{statements={{sql="SELECT ... WHERE x=?",params={1}}}}` | 同一事务内结果数组：rows、changes、last_insert_id |
| `log` | 对象 | 结构化诊断日志 |

数据库接口在大厅登录/请求和对局动作事件可用。`require("core.database").batch(statements, callback)` 在原生批次完成后调用 `callback({ok,result,error})`，当前是**同步完成回调**，没有后台数据库线程。所有 SQL 都来自受信任脚本；不能把客户端 SQL 直接传入。可写 SQL 能修改整个业务数据库，策划只应调用封装的业务模块。每个语句可指定 `expect_changes=1`，不符则整个批次回滚。

脚本不能执行第二条 SQL、事务控制语句、PRAGMA、ATTACH 或超过额度的结果。数据库事务与内存对局事务不是跨存储原子事务；不能在同一个卡牌脚本中既提交 SQL 扣款又准备内存扣卡，商城/付费移动应继续使用原生幂等业务接口。

二进制报文使用 Lua 字符串保存，允许零字节。脚本只构造明文内部报文；外层加密、长度、发送完成确认和重放检查由 EXE 完成。卡牌事务先准备库存/资金，再构造完整回包，核心在发送前一次性提交，避免 Lua 报错造成扣卡或加钱不同步。

Lua 准备事务成功返回前不改权威状态；原生兼容调用可能已经提交事务，因此其后脚本出错不能自动重试。网络发送失败沿用原有连接终止/结算恢复机制，不能宣称网络发送与内存提交组成一个事务。`network.sent` 只在原生启用发送确认时触发；收到普通客户端 ACK 不等于此通知。

## 业务拆分

- `cards/card_<编号>.lua`：每张卡一个文件，`cards/registry.lua` 建立编号与操作号索引。
- `tiles/tile_<类型>.lua`：每种棋盘格一个文件，`tile.native` 负责共享落点事务。
- `maps/<资源名>.lua` 与 `bosses/<名称>.lua`：地图和 BOSS 的独立策略入口。
- `mall/service.lua`：商城协议入口；`mall/purchase.lua` 接管购买资格和有效期规划。目录、价格、日期编码、资源期限复核、扣款、库存和幂等收据仍由核心商城服务校验。
- `events/feasts.lua`、`game/rewards.lua`：节日账本同步和随机卡池策略。

迁移新功能时，先在 Lua 文件中实现策略和参数校验，再为需要改变权威状态的动作增加一个窄的 C++ 核心能力。不要在 Lua 中复制库存、资金或房产状态，也不要通过脚本直接拼接 SQL。

## 本轮已迁移与未迁移

目前50张卡已使用Lua规则或业务编排：乐透504、四张视效1117/1118/1127/1131；移动状态卡1039/1040/1041/1042/1079/1084；20张地产卡1031/1032/1033/1036/1037/1059/1077/505/1062/1064–1068/509–514；资金卡1051/1052/508；街区卡1035/1058；放置卡1043/500/507、研究陷阱1181/1183、净空502；同盟1060、察看1072、飞吻1130、武器条约1115、开路1061；传送1116、换位503；清除1078。地产的特殊等级限制和增益生命周期仍由C++ `property.prepare` 内的现有计划器负责，不能把它们计为完整搬离C++。其余42张文件包括主动兼容入口、9张被动卡定义和6张本地入口定义；二至五步卡仍属于主动原生兼容入口。

`property.prepare` 的操作：`convert`/`convert_classic`（property、kind）、`house`（position）、`swap`（property、buildings）、`grow`（levels、own_only）、`destroy`（current、property可选、levels）、`purchase`（返回price）、`seal`/`price_rise`（当前街区）。每次卡牌请求只允许一份地产/街区计划，提交前验证原始版本。购地现金必须严格大于地价，由购地脚本校验并准备扣费。

查税脚本分别计算现金/存款的十分之一，均贫和均富保留各自的向下取整、最小现金规则；核心阻止负余额或有符号DWORD溢出。卡牌脚本或回包转换失败时，只要没有调用原生副作用/数据库，就返回400B并保留全部计划前状态；`lua_card_committed` 日志记录真正成功提交的卡号、槽位与变化范围。

随机赠卡候选筛选、固定节日点券表、BOSS攻击类型选择和攻击许可同样由Lua驱动。卡片格、福神和节日共享资源/地图允许且业务开放的赠卡池。

地面接口在同一动作中共享一个原始快照；每次卡牌请求只允许一个放置或移除计划，准备后再读仍返回原始状态。范围、静态禁放格与在场角色筛选由脚本负责，核心负责合法坐标/道路、动态占用、版本和原子提交。火焰只验证中心范围，按资源半径裁剪方形区域；全部格被排除也扣卡成功。净空卡清除全部动态物件。冰冻的踩中效果、火焰伤害和持续时钟仍在原生落点层，本次仅迁移施放规则与通信。

同盟卡从服务端资源读取持续天数并写双方关系；察看、飞吻只有目标在场校验和本地动画回包；武器条约清除脚本列出的五种卡；开路卡调用原有寻路器预览真实路径，脚本按路径去重并删除动态物件，三字节方向按每步两位编码。开路只改目的格物件，不移动角色。关系衰减、真实地形寻路和库存版本仍在核心。

传送卡由Lua读取带符号目标格并准备施放者坐标，换位卡由Lua筛选在场、未冰冻且原始行动状态可用的角色，再按零基角色顺序轮换坐标；核心校验道路、当前坐标和扣卡事务。两卡沿用已有“只更新角色坐标并回成功包”的协议，不主动制造落点交互。毒气卡1182仍由原生战斗事务处理：它对每个命中格按更新后的临时资金重算战斗修正，可能触发破产终局；拆分前需要支持投影资金的战斗准备与统一终局接口，不能用普通 `funds.prepare` 提前逐格扣款。

清除卡1078由Lua列出要清除的八种状态及整行同盟关系；核心处理附身强度、计时炸弹归属、NPC时钟及版本校验。`status.prepare_clear` 仅接受 possession、timed_bomb、sleepwalking、turtle、stay、one_step、six_steps、frozen，不允许任意写入角色结构；免疫、攻击/伤害增益、资金、位置不受此卡影响。脚本回包成功转换后，再与库存和其他准备计划一起提交。

落点仍由原生状态机处理NPC/传送/碰撞和交互续接；格子 Lua 模块目前是兼容入口，未提供任意修改地图的接口。地图脚本可更改奖励筛选和关联 BOSS；新增地图资源装载仍需原生注册。商城原有日期兼容、套装、等级规则等限制仍在；本轮没有解除或完成这些未实现逻辑。所有核心 C++ 方法尚未逐个绑定；新增核心能力按事务边界继续迁移。

商城购买事件 `mall.purchase_policy` 收到已由目录确认的商品编号、币种、资源价格/积分/套装数/等级/期限与部署日期纪元；返回 `{allowed=false,reason=...}` 或 `{allowed=true,expires_at=...}`。Lua出错在数据库事务前拒绝，不能自动放行。当前客户端的2005纪元只能表示2005–2020，最新日志的2026限时商品购买确实因此失败；迁入Lua没有解除这个实际兼容限制。只有配套客户端日期兼容与离线数据库迁移后才能采用2021纪元，不能只修改Lua/服务端纪元强行卖货。购买回包仍先刷新权威余额再发77；激活仍先发213再刷新余额，防止客户端双扣。新增日志记录商品编号、键、币种、纪元。

构建：`cmake --build server/build --target RichOnline.Server -j 4` 会编译 EXE，并对全部 Lua 执行 `luac -p`（仅语法编译，不执行脚本）。源码脚本复制到 `build/scripts`。发布时 EXE 必须与同代 `scripts` 目录一起安装。目录按 EXE 路径定位，与 GUI 的当前目录无关。
