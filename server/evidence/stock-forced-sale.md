# 强抛卡1124原子清仓计划（待会话接入）

## 原始证据

只读核对 `docs/逆向资料/专题/40E0系列事件/01_事件处理与本地记录.txt`、`03_请求构造与等待记录.txt` 及 `证据/handlers.json` 中的 `677180`。股票卖出算法沿用股票专题 `7F9850` 的现价、float乘积取整及剩余量处理。

- C2S0097恰为8字节，+2请求日历、+4主手牌槽、+5库存组、+6局内股票槽。当前库存实现只支持组0，拒绝其他组而不伪造可用库存。日历必须由上层认证，不能复制为回复GmsvID。
- S2C40E7中+4卡槽、+5组、+6股票槽；+8+4*i为角色i最终存款。客户端按角色总槽数遍历，在场标志决定是否执行清仓。包必须覆盖所有原槽，不能把在场角色压缩排列；完整长度8+4*角色总槽数。
- 每个在场角色的正持仓全部卖出，按当前价执行7F9850并归还市场剩余量，随后覆写最终存款。没有持仓也执行6061扣卡和6006恢复。该处理直接卖出，不经过普通0201的跌停检查；本计划不套用普通交易涨跌停/限制门。动作是否允许仍由上层会话判定。

## 实现与提交边界

`RichonlineStockMarket::prepare_forced_sale` 使用同一股票市场、持仓和账本，接收已认证操作者、原槽活动掩码及其手牌实例。核验1124存在后准备全部角色资金快照，金额按现有float成交规则取整；任一活动角色金额溢出、存款溢出或市场剩余量溢出都拒绝整个计划。淘汰角色持仓不变，回包仍保留其存款槽。空持仓清仓也能准备成功并消耗一张卡。

独立 `cards/card_1124.lua` 的 `liquidate` 计算金额资格、最终存款及完整40E7。核心比较接受状态、原因与每一字节；Lua不能改变价格、持仓或直接扣卡。普通网络 `use` 保持原来的拒绝续接路径和 `reward_enabled=false`，未提前把卡加入随机池。

计划不可由调用者构造，绑定市场实例、市场版本、手牌实例、原库存、活动掩码及账本快照。`commit` 重新核对这些值；市场/手牌/活动掩码不符返回false，账本冲突沿用账本异常。成功回调只做不抛异常的库存和持仓写入，随后账本一次完成全部存款更新。同一计划再次提交因市场版本变化失败。任何准备失败都不改变库存或资产，不制造失败回包。清仓本金不计入现金收入成就，沿用资产交换规则。

上层必须保证会话串行化，验证日历、当前行动者、手牌归属和地图股票准入，并且只在提交成功后广播一次40E7。股票开局、路由、行情和发送续接尚未接入实际对局，不能把底层计划称为强抛卡实机可用。BOSS地图不因此开放股票。认购数量规则及红/黑/牛/熊的强制行情定价仍待证据，未猜测实现。
