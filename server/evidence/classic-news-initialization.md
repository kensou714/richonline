# 经典新闻累计项初值与图片索引绑定

## 当前客户端依据

- `64F2A0`在加载地图后以`G+C5C`为this调用`60D5C4 -> 7D9C70`。后者将子对象偏移1..32设为-1，并将DWORD偏移36写成5000，即`G+C80=5000`。该调用不依赖起始现金、存款或新闻策略。
- `693CE0`向同一偏移36累加完整报文金额，和上一轮单人支出消息的调用链一致。5000是客户端初值，不是从地图或概率推测出的服务端策略。
- 初始化函数还被`678E90`和`714D30`调用，涉及中奖后清理。这里只绑定新局初值；并未声称累计项终身只增不减。完整彩票和其它重置事件仍未接入经典会话，不因此放宽其支持范围。
- UI30构造器`6FB680`设置虚表`A25A60`；虚表+4经`6097B2`到`718DE0`，展示入口`7192F0`读取来源0的`this+72+4*picture`。
- `718DE0`仅初始化29个来源0图片槽：1、2、5、6、8、9、10、14、15、17、23、26、27、29、30、31、33、39、40、43、44、45、46、48、49、50、51、52、53。另一个来源1数组不混入该集合。0和3等索引即使小于100也不在初始化表中。
- 图片通过`60F3B5 -> 6DBA40(10,10,index,-1)`取`other_10_index`。`6D8130`的other.dat区段按连续OTHER组和组内连续O节创建12字节条目；只审阅该相关区段，不把大型加载器全部视为已审。
- 只读解码当前`Tex/other.dat`，核对OTHER_0..10、O_10_S_0..63连续存在。29个所需NP文件全部存在，逐项路径和SHA-256保存在JSON，不提交原始私有纹理。

13个函数窗口和虚表前5项均与当前磁盘PE逐字节一致，见`classic-news-initialization.json`。`inspect-classic-news-resources.py`可重新提取对应资源映射；这是静态资源检查，不执行服务端或玩法测试。

## 服务端调整

经典会话在构造时固定累计项为5000，删除可随意覆盖的initial_fines。新闻准备器直接采用NEW客户端已初始化图片集合，删除外部available_pictures配置；外部调用方不能再把未初始化槽声明成可用。格式、金额和图片校验仍在Lua调用及账本提交之前，原有原子资金/累计项/破产提交路径不变。

新闻策略仍需显式选择事件及金额。本轮不生成原版事件概率、不把BOSS新闻表用作经典新闻、不恢复完整彩票或多人新闻；经典生产mode0继续关闭。缺少NP文件或修改客户端初始化表的自定义客户端不在当前资源兼容范围内。

按用户要求仅静态审阅、Release编译、Lua语法检查，不新增/运行测试，不启动本机服务或客户端。BOSS双胜负和战后宝箱已有发布，本轮没有新实机日志，也不宣称解决飞弹基地连击回1血。
