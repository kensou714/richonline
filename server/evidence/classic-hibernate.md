# 经典冬眠卡506与冰冻回合续接

本轮仅修改server，接通经典共享会话的C2S164/S2C40F4并补齐冰冻回合。
生产经典准入仍关闭；多人实机行为未验收，不以单张卡接入代替完整经典模式。

## 客户端证据

`classic-hibernate-client.json`保存15个函数完整chunk、磁盘偏移、SHA256及反编译。
所有chunk逐字节匹配RnClient.exe；整文件SHA256为
`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。

- `651570/691F60`：请求164共6字节，+2日历WORD、+4主手牌槽、+5手牌组；
  至少两名在场且未住店/住院/入狱/绑架/冰冻的角色才可施放。
- `679530`消费40F4：扣一张506，排607D，施放者恢复操作。无目标列表网络字段，
  不另加607D网络包，不在用卡后直接结束施放者回合。
- `6812E0→7CF340`遍历其他活动角色，四个收容字段均须为-1且1500不大于0。
  先互清关系，再检查状态免疫、1071清醒保护，未抵挡才由`7F8320`写GValue30。
  所有目标抵挡仍消耗506。`7CD440`按目标的主手牌/第二套库存和当前地图查1071，
  不能借用施放者库存，也不能将未知第二套库存当作无卡。
- `7C0C50`每个新行动者先调用`7F8360`递减自己的1500。阶段4在收容/绑架分支
  之后、梦游/正常行动分支之前检查冰冻；仍冰冻时只排1800/1350提示并返回，无0011。
  因此计数2在自身首回合降为1并跳过，下一个自身回合降为0后恢复正常行动。

## 事务和Lua编排

经典规则新增显式`hibernate`资源项，沿用`RichonlineHibernateRules`的GValue30解析。
没有配置时返回400B且不扣卡，不从卡片文案推算持续次数。
会话使用真实2～4人主手牌和状态构造八槽快照，空槽明确不在场；收容字段未知拒绝。
调用已有共享冬眠计划器及`cards/card_506.lua`，没有复制BOSS单真人库存假设。

核心核对`card.prepare→hibernate.snapshot→hibernate.prepare`顺序、完整有序目标集合、
整数类型、资源计时和唯一准确40F4响应。没有免疫或主手牌保护且地图允许1071时，
必须由既有`secondary_sleep_protection_absent`证明第二套无可用清醒卡，否则整笔拒绝。

Lua和外部只读证明完成后再次比较回合、玩家卡牌对象身份及完整前置快照，
才逐槽无分配提交506、各目标1071和冻结状态。失败不保留部分库存/状态变化。
按当前回合及八个手牌槽保存成功164请求，相同字节重发不重复扣卡；
新回合重置，跨回合旧请求沿既有retired记录处理。原协议没有请求序号，
同回合同槽相同字节按重发处理，也意味着不会再次消耗该槽叠加的506。

经典结盟入口尚未开放，关系仍为构造时全零，与现有查税/均贫卡的前提一致。
本轮不声称已支持结盟；将来接入时必须将同一份关系权威纳入此快照、免租和共同提交。

## 冰冻续接

新增`frozen_wait`：在既有新回合递减、日历业务、研究扫描及收容分流之后进入，
广播420F，清本轮移动等待，不触发掷骰、当前位置落点或同格碰撞。
全部客户端的发送完成回调到齐后才起计，poll到期推进下一位活动玩家，
每次只推进一次；普通完整回合边界继续处理状态结束、日期及月限结算。
断线和新回合清等待，后续重复sent不会延长期限。

`frozen_turn_delay`默认1800ms，可显式配置1ms～5分钟，是服务端排队策略，
并非客户端播放完成ACK。发送完成也不证明UI已播放；不伪造移动结束报文。
计数降至0时不再进入冰冻等待，继续正常停走/梦游/掷骰流程。
