# 房间成员到游戏连接的公共绑定

原生产宿主只读取房主资料，创建一份 `RichonlineStartupPlan` 并把所有准入、发包确认、退出与结算回调闭包绑定到房主。此前经典启动和共享发送模块尚未通过这层宿主装配。

本轮新增 `bind_richonline_room_game_plans`，BOSS 生产入口已实际复用，不再在宿主内复制一套连接包装逻辑。BOSS 原来的初始化校验错误名保留，协议包格式、角色顺序、生产业务工厂和游戏规则不因此改变。

## 绑定不变量

- 全部真人连接和身份必须来自已准备房间，禁止重复连接、身份、房间槽或接收者，房主必须在成员中。按房间槽升序压紧后的局内槽不能误用账号ID或稀疏房间槽。
- 资源校验后的每份4000只允许local_slot不同，4004必须一致。业务工厂返回的4000、4004和信封必须逐字节对应原快照，不能改变身份、出生点、技能或资金；真人后面的合成槽必须为-1。
- 多人计划须提供完整发包确认、轮询和地图加载时限。后续移动上报取证后，经典宿主已改为接收一份整局回调并统一调用`make_richonline_shared_startups`，不再由业务工厂自行返回几份计划。详见`shared-movement-reports.md`。
- 所有成员和计划校验后才生成独立系统随机令牌。同一批的目标地址/端口一致，重复令牌拒绝。每条准入仍绑定实际channel、room和actor，注册表继续执行其原有认证与整局登记。
- 每个连接独立持有一次性启动计划，分别转发admitted、message、poll、sent、disconnected及结算/大厅确认回调。整批授权完成才返回，宿主尚未发出跳转时不会暴露部分成员。
- 校验失败、随机源异常或中途装配失败均释放尚未绑定的业务计划；已授权成员由原Startup释放。临时一次性所有者覆盖回调分配失败、计划尚未被Startup接管的空隙。清理不重跑业务事务，并避免同一计划重复通知。

## 经典宿主入口

`load_richonline_boss_host`增加可选`RichonlineClassicHostStrategy`。显式提供完整经典工厂时，mode0分别读取每名玩家当前装备及技能，使用已存在的经典资源验证和出生点策略生成启动快照，再给工厂传递全部玩家和真实信封，最后经公共绑定层返回每条连接计划。

没有把房主装备或背包复制到其他槽。未确认的trailing字节仍使用宿主原来明确配置的真人值，未赋予新语义。经典资源、等待/月数/押金选项依旧由既有启动构建器核验；本轮没有实现或扣除押金。

生产`richonline_boss_runtime`尚未提供该经典业务工厂，因此mode0明确返回`richonline_classic_host_session_not_enabled`，不向玩家发送半成品棋盘，也不把gameReady改为true。完整多人轮转、地产租金/建造、股票行情、结算和独立库存的整局装配仍未完成。这是宿主接入进展，不是经典多人可玩性声明。

## 验证范围

静态审阅覆盖成员错绑、快照被改写、部分装配失败、取消时清理所有权和原BOSS诊断兼容；Release编译及Lua语法检查。按用户要求不新增/运行测试，不启动本机服务或游戏。线上健康检查只证明发布与服务监听状态，不证明多人玩法或用户反馈的回1血问题已解决。
