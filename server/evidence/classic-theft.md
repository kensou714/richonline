# 经典抢夺卡与防盗卡的共享库存续接

本轮补上经典多人会话的116请求。此前经典roll只识别骰子、付费移动和两种股票卡，抢夺会落入out_of_phase；BOSS的合成对手没有手牌，仍不伪造库存或从玩家自己的库存借牌。经典生产准入仍未开放，本轮不是完整多人可玩性声明。

## 客户端依据

`classic-theft-client.json` 将10个函数完整chunk与原 `RnClient.exe` 的磁盘字节核对，客户端SHA256为 `feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。

- `6552A0` 经 `6927B0` 发送8字节116：WORD日历、BYTE源卡槽、BYTE源组、BYTE目标角色、BYTE目标主背包卡槽。服务器只支持源主背包组0，不能把组1当作主背包。
- `6706B0` 消费40C4，先通过 `7F86A0(target_slot,0)` 读目标卡号，再依序排动作、提示、条件解除同盟、扣抢夺卡、检查防盗。回包保持原四个BYTE目标字段，不额外广播库存插入以免客户端执行两次。
- `7CD890` 查1074；`7F85C0` 先从主手牌第0槽起查找，再查允许搜索的第二套库存。`800A50` 校验CARD类型及地图允许，不以Prop.enable代替自动卡资格。成功只扣一张防盗卡，抢夺卡仍消耗，目标所选卡不转移。
- 无防盗时给施放者添加所选卡一张，再从目标所选卡叠扣一张。共享 `RichonlineChanceResources::add` 重放客户端插入和合成，满包不添加，但不撤销目标扣除。选择防盗卡本身时也先走防盗阻挡。
- `64FF10` 选人排除当前角色、无效角色，以及旅馆1493、医院1494、监狱1495、绑架1497非-1的目标。冰冻不在这个目标过滤器中。视口与鼠标命中属于客户端输入，116不携带这些坐标，不假装服务端可还原本次鼠标位置。
- 40C4本地行动者最后排6006恢复操作，没有独立抢夺完成ACK；会话保持roll，不换人、不再次发送4010。

## 实现与一致性

独立 `theft_card.cpp` 只准备规范回复与双方库存投影。准备校验局号、地图、模式、角色所有权、0..7槽位、卡数量、抢夺卡资格和目标非空。两份手牌对象地址和原快照在提交时一起复核，之后只有noexcept库存赋值，避免只扣施放者或只扣目标。无效目标、空槽、没有抢夺卡或未知第二套防盗库存返回400B，不消耗任何卡。

`card_1053.lua::transfer` 与 `card_1074.lua::select` 分别承担抢夺和被动防盗编排；C++核对Lua的防盗槽、转移卡号及完整40C4，脚本不能指定任意新卡或改写另一位角色。双方库存变更由同一共享会话锁保护，并在既有广播通道发送一次。

经典规则新增 `secondary_theft_protection_absent`：当地图允许1074且目标主手牌没有防盗卡时，由准入层提供第二套无可用防盗卡的证明。未知或实际带第二套防盗卡时暂拒绝；未伪造装备消耗。主手牌有防盗卡或地图禁用1074时无需该证明。

当前经典会话尚无同盟关系写入入口，既有初始化关系为零，因此40C4的条件解除同盟不产生服务端状态差异；未来接同盟卡时必须同时把抢夺纳入双方关系事务。没有因本轮补单卡而开放生产经典模式、假造BOSS手牌或改变随机奖励池。
