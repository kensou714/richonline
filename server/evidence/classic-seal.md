# 经典查封卡：共享街区状态与日期递减

经典模式原先没有C2S100的处理入口，查封卡无法按原协议生效。本轮接入1035独立Lua模块及共享地产事务，并同步收租、升级和新建研发的查封判定。不是玩家实机复现记录；生产经典准入仍关闭，不能据此宣称经典多人已完整可玩。

## 客户端依据

`classic-seal-client.json`记录当前`RnClient.exe` SHA256 `feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`，38个函数完整chunks逐字节与磁盘PE相同。另保存三处关键汇编窗口，弥补反编译器隐藏ECX子对象偏移的问题。

- `653130`发送6字节C2S100：操作WORD、日历WORD、手牌槽BYTE、库BYTE，无目标WORD。只要求脚下能映射到地产，不以当前所有者或建筑等级过滤。
- `66C650`消费6字节40B4，从当前角色位置取地产，排6077同组查封、6061扣1035和6006恢复操作，无独立网络ACK。服务端成功后广播这一个原生回复，不额外发送查封动画或扣卡包。
- `7DF010`将所有地产D+4初始化为0。sprite11/12且初始kind不是8/9/10的记录进入Map+46C普通地产表；初始kind8/9/10进入Map+47C。`7E33F0`、`7E34D0`都以Map+46C为ECX调用`7ECFD0`遍历。**不是遍历整个68字节地产数组。**旧查封说明中“所有同组地产”应理解为该表的同组成员。完整伪代码隐去两个不同容器的接收对象，必须结合`7DFC76/7DFC8B`和`7E3437/7E34ED`汇编。
- `7E33A0`对表内D+6相同的地产D+4写5，不限owner或level；重复使用重设5。站在特殊地产也可使用，如果该组没有普通地产，原生仍扣卡但不产生地产变更。
- `7C0C50`仅轮首锚点且首次日历初始化之后推进日期；`7D8810`的首轮门不执行递减。未到月限且模式0（或模式2子模式0）时调用`7E34D0`；`7E3480`仅对正数减1。同日其他玩家行动不递减。
- 日期块还含scripted_event门：`7CF730`递减G+83830并在变0时退出该块。当前经典会话私有RawAuthority从-1初始化，没有420C宝箱写入路径；本轮按此已实现普通经典路径调用，未冒充接入经典剧情事件。BOSS的独立回合宿主不使用本轮日期计时。
- `7C6640`的自有地产升级/新建研发分支要求D+4为0；他有普通住宅/商店租金分支检查落脚地产D+4，查封时提示后进入stage4。末尾无主地产购买分支没有该检查，因此封闭无主地仍允许正常购买。
- `7E4140/7E42B0`的联排/商店报价不排除其他查封地产，本轮只在落点收租入口抑制，不改变计价集合。
- 已有研发任务`7E4C50`只按建筑kind、level和owner校验，没有查封门；任务继续计时，不能在查封时取消或暂停。

## 服务端提交和续接

`RichonlineClassicPropertyState::sealed_days`属于地块，换地/换屋不转移计时。构造时保存普通地产表成员，后续不按建筑当前kind重新计算资格。查封计划包含整个街区目标的前后快照；提交时与卡牌库存一起检查对象、当前状态及无未决交易，再以无分配写入提交。合法空集合可提交，库存仍按原生扣除；重复网络请求继续由共享会话的去重/阶段约束处理。

日历首次轮首跳过，之后每次`completed_rounds`连续推进一次统一递减；重复同轮不重复扣天数，倒退/跳号拒绝。月限结算在新轮前发生，不再执行递减。轮首锚点淘汰后，沿用会话通过4010同步的新锚点和日历计数。

落点收租、升级、新建研发均读取同一地产快照；Property/Research核心也验证真实sealed_days，不能只靠调用者传入的布尔值。无主地购买和已有研发计时保持原生行为。尚未实现的其他特殊建筑落点没有因本轮被宣称可用。

BOSS地产加载器当前只接收sprite12且空地或kind11～20，已经排除了初始kind8/9/10，故现有BOSS街区卡的目标集合在当前准入域内没有此次差异，不需要修改BOSS计时或攻击逻辑。
