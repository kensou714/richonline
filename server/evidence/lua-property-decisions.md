# 大地产建造、升级与研究选择 Lua 迁移

## 协议依据

复用 `owned-property-verification.md` 的客户端静态取证与历史通信记录：0037/0038/0039请求为六字节，403D/403E/403F回复为五字节；403D的有效建筑选择是11–20，默认请求-1必须解析为场景默认建筑，10表示取消。403E只增原建筑等级，不扣现金和许可证。研究所升级接受或拒绝后均继续0039研究等待。

只读交叉核对 `docs/逆向资料/专题/建筑选择界面与许可证门/02_选择提交与消息边界.txt`：0037的选择是+4低字节，+5是客户端未初始化尾字节，不引入新的零值约束。日历、等待类型和重复请求仍由现有回合状态机认证。

## 本轮实现

- `tiles/tile_12.lua` 独立实现三个选择事件。落点入口仍标记原生兼容，避免将购地、对手地产、神庙/花园与研究计时全部宣称已迁移。
- 建造输入包含产权、空地等级、默认建筑、场景上限、许可证表和真实八槽库存。Lua返回解析后建筑与零基许可证槽，以及完整403D。核心独立计算结果并逐字段比较，第一叠匹配许可证在库存副本中扣除；脚本或回包错误不提交建筑、库存或清除等待。
- 升级输入包含产权、种类、等级、场景和角色上限。Lua返回是否升级、新等级、research/temple/garden/complete续接类型与403E。核心复核后才处理附加效果并写等级；研究等待截止时间在升级提交前计算。BOSS自动建设/升级同样通过这两个事件，不制造人类选择等待。
- 研究返回最多三份新增任务和403F。使用64槽队列中最前面的空槽，满队列保持原结果、不覆盖任务；天数遵循原有有符号BYTE截断。核心核对槽号、地产、选择、卡号、天数及完整消息后一次替换队列，再关闭等待。拒绝/超时返回-1且不排任务。
- 事件绑定不提供数据库、库存写入或其他核心能力。使用该对局原有Lua快照；可选无脚本底层调用保持原生行为。

## 核验与范围

已静态核对默认/取消、缺许可证、禁用建筑、产权变化、角色/场景等级上限、升级后的研究等待、神庙/花园续接、BOSS自动分支、研究队列不足三个空槽与满队列。Release编译及159份Lua语法检查通过。按用户要求不新增或运行测试，不启动本机服务或游戏；本轮没有新的实机验证。

这是业务拆分与提交异常边界改进，不作为此前“升级建筑导致失败”或“飞弹基地后BOSS回1血”的新根因结论。普通模式小地产、开店卡和股票系统仍未补齐。
