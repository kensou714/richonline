# 经典会话股票买卖、等待余额及破产清仓

## 原协议依据

`classic-stock-client.json` 保存当前客户端七个函数/跳板的伪码、汇编和窗口哈希，导出时确认各窗口与磁盘字节一致。`67B350/67B560` 使用成交包内的角色槽更新买卖模型和最终存款；本地角色成交时还刷新已打开的银行 UI17。日常买卖不绑定当前走子角色，不用股票槽冒充日历。

`7BE160 -> 60A7ED -> 7F9950` 在股票模式下执行破产清仓。每个正持仓通过 `604C99 -> 7FDCA0` 加回该市场槽的剩余股数，再清数量与成本；没有股票卖出收入。这和普通 `4205` 卖出不同。

已有股票协议资料与 `richonline_stock_wire.cpp` 确认 C2S0200/0201 是六字节，+2 为股票槽，+4 为数量。`richonline_game_startup.cpp` 已在日历验证前独立解码；`richonline_shared_startup.cpp` 已按收包顺序持对局锁，并等待前一批消息全员完整发送后再执行下一操作。本轮复用这两个已有入口，不改变其去重或移动汇合行为。

## 本轮装配

`RichonlineClassicSessionRules::stocks` 由准入层显式提供资源、按地图槽排列的30点历史以及大盘值。会话用自身局号、EMP股票映射、同一账本及Lua实例调用 `prepare_richonline_stock_opening`，不能传入另一局已创建的市场。生成的4200/4201只在首次opening发送，随后4010。缺失股票策略则保持未开放；不随机伪造历史。

`RichonlineClassicWorld::stocks` 将同一市场交给局内业务。独立 `stock_action` 使用已认证连接槽，允许存活玩家在他人回合以及已打开的银行/地产/落点等待期间买卖。股票请求不进入日历比较、不被相同字节去重、不重开回合。成交广播4204/4205；余额/持仓不足等拒绝仅记原因，不伪造会推进落点的4206。已经淘汰或正在结算的迟到交易不改变资产。

银行等待保存的余额原先不可变化，直接接入股票会造成旧快照冲突。本轮仅对一笔已核实并提交的成交同步 `bank_funds` 和银行待决余额，保留原选择上下文及8秒期限，不再次发送4018。成交前必须与旧快照精确一致；未知来源的资金修改仍会报冲突。

嫁祸租金等待同样只更新该成交角色的资金快照；原租金金额、手牌、目标资格、地产与期限保持其原验证。选择/取消/超时按新的真实余额规划扣款。普通购地/升级原本在确认时读取最新账本，无需缓存旧余额。外部经典事件服务提交时必须读取当前账本，不能假定股票窗口会锁住局内存款；该约束写入服务接口。

## 破产事务

`RichonlineStockMarket::Retirement` 绑定市场对象及版本，准备阶段核验回收数量上限并调用 `stock.retire`。Lua返回每槽回收后的供给量，核心逐值及整数类型复核。行情、交易或市场限制变化均使旧计划失效，重复提交也失败。

经典普通租金及嫁祸导致破产时同时准备地产和股票回收。在原账本提交回调里先验证两份计划，再执行无分配清理和活动状态更新。持仓/成本归零、股数归市场、产权清除及局内资金扣付共用该提交边界。客户端按既有400E执行同一清理，不额外发4205，不把股票市值返还给已经破产的角色。
