# 经典局传送格接续

经典共享会话现在处理静态28、58、61。此前61末端在准备路线时直接报未实现，28/58没有完整的位置提交与回合续接。生产mode0仍未开放；本轮只补齐这个明确分支，不代表完整经典局可玩。

## 客户端依据

`classic-portal-client.json`记录23个函数/跳板的完整伪代码、反汇编、地址和窗口SHA256。窗口字节逐一与当前磁盘RnClient.exe一致，磁盘SHA256为`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`；不据此断言整个IDB一致。

- `7C54B0`首个模式门`604703→63E990→61260F→629E10`只判断mode4，不阻止经典mode0。其余前置门分别为脚本事件83830、静态类型、睡神1488==7、梦游1499及冰冻1500。
- 28/61通过`60BC56→7E6910`从Map+76/+78或+80/+82取另一端；入口4013排动画26、镜头、606C重定位、出口动画26，返回0。
- 58同样返回0，等待服务器4209。`67C080`读game WORD与destination signed WORD，不发新C2S，不排出口落点阶段。
- `694140`初始化动画续接值0；`637750`只在1/-1时触发其它续接。`6802A0→7F72A0/7F7990`重定位并保留原朝向。

传送后的出口静态奖励、地产、同格抢卡和岔路不会自行执行。不能调用普通complete来补发这些效果；既有出口地雷证据见`normal-cards/teleport-mine.md`。

## 服务端实现

道路拓扑从EMP尾部64/80读取28/61两组坐标，验证两点不同、均为对应类型的道路、且实际数量为2。61途中行为仍只由`portal_destination`负责；28不变成途中传送。新`landing_portal_pair`供落点使用，不从扫描顺序猜配对。

共享层仍先收齐所有玩家0011并验证不可变路线入口。会话再准备传送计划，复核Lua返回及最新计划后，提交同一份全员位置并保留方向，最后广播下一4010。没有新增待决ACK，不多走一次出口phase6或选方向；已结束的移动上报沿原共享层处理。28/61只发入口4013，58发4013与4209。

同格信息保持真实；经典入口必须带会话的phase6授权，不能把collision_resolved伪设为真。实际传送取消该次phase6，受控/脚本跳过传送则仍在原格进入普通后继；带地产的跳过分支交还phase2。当前经典会话尚未开放受控状态写入口。

随机传送沿用明确的`native-uniform-walkable-road-v1`服务端政策：从全图其它非孤立道路按位置排序，随机选择一次，可跨连通分量，不冒称原服务器概率。Lua只读取这一次索引，不能重抽或改变候选、目标和报文。原BOSS中的Lua报文准备/逐字节校验提取为共用函数，BOSS的计划再确认、已发4013去重、宠物复位、出口地雷与结算仍在原回合器中执行。
