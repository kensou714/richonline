# 经典红卡、黑卡、牛卡、熊卡与三次行情波动

## 已核对的客户端与资源

`classic-stock-trend-client.json`保存16个函数的完整chunk、磁盘偏移、SHA256和反编译。
所有chunk与当前RnClient.exe逐字节相符，客户端SHA256为
`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。

- `6580F0/658240`构造146/147请求，8字节，+4库存槽、+5分组、+6有符号股票槽。
  `658390/658450`构造148/149，6字节，没有目标股票。
- `692E80/692EB0`分别检查市场限制和股票数量。当前核心同样拒绝受限市场。
- `676300/676540/676780/676990`消费40E2..40E5，显示动作和文本、扣施放卡、恢复操作。
  它们没有修改股价或保存三次波动；成功确认不能代替真实行情更新。
- `80F170/80F2D0`接收服务端大盘及股价，更新前价、现价和涨跌幅。只修饰涨跌幅，
  不把收到的报价钳制为1..999.99，不能借本地模拟器的价格范围当网络契约。

本轮直接只读解包当前`Data/Prop.kpd`及`Data/Stock.kpd`，指纹和相关字段见
`classic-stock-trend-resources.json`。四张卡文案均为连续三次波动；**实际Stock资源
配置为rise=8.0、drop=-8.0**。此前提问中的“当前10%”已向用户更正，不能写入实现。

2026-10-12用户确认两项服务端规则：后用卡覆盖所选股票方向并重置为三次；
强制涨跌采用资源涨跌停幅度。这是用户确定的规则，不宣称恢复了原服叠加和定价算法。
每次价格为旧价乘`1+资源幅度/100`，高精度计算后写回float；当前为+8%/-8%。

## 实现与事务

四张独立Lua卡片复用`core/stock_trend_card.lua`，编排扣卡准备、读取真实趋势快照、
准备新趋势与确认。`stock_trend_card.cpp`核对操作号、长度、日历、主卡槽、真实行动者、
活动名单、市场限制和股票索引，并验证Lua调用顺序、整数域及唯一确认包。
趋势与库存经同一市场版本核验后无异常提交；失败不扣卡，重复提交旧计划失败。

红/黑仅改目标股票；牛/熊改本局全部股票。每股独立保存方向和剩余次数，后来的
单股卡只覆盖该股，不影响其他股票。普通买卖、认购、强抛不减少次数，也不清趋势。
扣卡前验证连续三次价格均能表示为有限正float，避免成功后才发现溢出或浮点停滞。

市场暴露`forced_trend_price`供行情策略取精确价格。`prepare_market`要求强制槽的新价
逐项匹配核心计算结果；所有股票、大盘、Lua报文通过校验后，提交行情和次数递减。
第三次成功后清方向。拒绝、旧版本计划、重复提交不耗次数。独立单股4203不当作整次
市场波动，不递减次数；它仍验证更新后剩余强制变化的数值可表示性。

经典会话在非初始日的日期推进处调用显式`stocks.fluctuate`一次，传入本局报价、
趋势、强制价格和大盘。策略可返回空表示本日不波动；有结果时广播4202。
日期策略的整次4202是本实现计次单位，不冒充原服行情频率。旧`turn_start`不得重复
处理已由该入口完成的行情。股票策略回调必须只读；市场版本、全员状态/位置和回合
在返回后再次核验。

未装配行情策略的经典会话拒绝这四张卡并返回400B，不出现扣卡后永久等待行情。
BOSS模式沿用原生拒绝；随机奖励开关尚保持关闭，不能把经典接入当作所有地图已支持。
