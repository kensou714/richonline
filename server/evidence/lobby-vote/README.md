## 服务端行为与明确策略

- 每个频道的每间房有独立投票；连接编号是会话generation。投票成员、提议者、目标、房主与房间绑定，重复票、外人票、其他房间/频道票不能影响此轮。
- 提议自动计一票同意。所有成员表态即结束；10秒到期时未表态计弃权，截止时刻到达的票不再计入。房主也可以被投票移除，房主离开后取剩余连接顺序首人，保持既有房间转移策略。
- 成功加入、离开、断线、准备/取消准备、直接修改地图、直接踢人、换队或更换角色会作废本轮。失败请求不作废；角色持久化失败保留原轮。投票期间不得直接进入game_pending。
- 80没有取消原因字段。成员/状态变化时将整轮票作废，发送`0/0/原成员数`，避免客户端显示通过却未执行动作。这是本地兼容策略，并非已恢复的历史服务端计票算法。
- 39畸形或业务拒绝返回该请求的通用失败`-1`并保留连接。40过期、重复、格式错误只记录拒绝且不修改状态；NEW踢人投票发送40但登记27失败回调，不伪造额外ACK。
- 换图提议仅允许更新扩展，保留既有规范化房间元数据限制；没有在投票阶段承诺地图资源可玩。开局仍经过原资源、签名、人数及runtime门禁。投票通过不能开放未支持地图或多人游戏。
- 该协议没有投票nonce。连续两轮同一提议者、同一类型之间，字节完全相同的旧40无法与新票区分；没有发明客户端不支持的请求ID。本轮连接generation、已结束轮、跨房间和成员变动得到隔离，但不声称解决该协议固有限制。
