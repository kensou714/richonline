# 经典地产租金接入共享会话

本轮将种类0/1的他有地产接入`classic_session.cpp::land -> rent -> property_effects -> complete`。支持正常资金转移、地主状态免收、付款者状态0免租/状态1加倍，以及局内八槽手牌1050免费卡。生产模式0仍未开放；本记录不代表经典多人玩法验收。

## 客户端证据

`classic-rent-client.json`记录当前客户端SHA、38个函数的磁盘/IDA窗口一致性、相关伪代码与地主状态门汇编。主函数只截取租金段；函数哈希覆盖各自完整窗口，不宣称整个IDB一致。

- `7C6640`的地主状态门使用所有者槽读取P+1488/1493/1494/1495/1497/1499/1500，付款者的1472/1480则按所有者索引。不能把地主住院免收误写成付款者住院免交。
- `7E4140`只合计sprite11、kind0、相同所有者和区域的地产。系数为500/1000/2500/5000/8000/12500；每块乘积保留低32位，解释为signed32后向零除1000，再累加。Lua与C++都保持这个顺序，不用64位正常乘积替换原行为。
- `7E42B0 -> 7E6B40`按全地图相同所有者的sprite11/kind1数量计费，每块为当前系数乘4000，不使用区域或等级系数。
- `7CCE60`先判断金额至少5000及1050适用性；命中时消耗第一张匹配卡，跳过1056和常规扣款。`7CD090`在金额至少10000且1056可用时进入608C等待。
- `7F85C0`先查1520开始的局内八槽，再查282开始的第二套八槽。当前会话仅持有前者。达到自动卡门槛且手牌未免付时，必须由`secondary_rent_cards_absent(actor)`同步只读地证明第二套没有可用1050/1056；回调缺席或返回false均在扣款/扣卡前拒绝。不能仅凭没在手牌找到就收费。
- `7C6640`生成收款者6060（收入、存款）和付款者6060（支出、现金）。消费者`67FA90 -> 7FA0A0/7F83F0`分别增加存款、先扣现金后扣存款。`693220`要求扣款前总额严格大于实付金额，相等也不能进入普通落点继续。

计价系数依据只读资料“计价系数字段来源与更新”和“计价周期计数来源”：本会话从新局4004启动，当前系数与地图基准相同；首次先手仅通过种子门，此后每完整轮推进一次日历。正基准每30次日历推进加1，零基准不增长。没有外部4004改系数或动态类型19的写入口。这里只计算租金使用的当前系数，不声称利息、节日等日历业务已实现。

## 提交与续接

地产对象保留资源区域，并从当前产权/等级状态报价；不使用开局所有者或旧价格缓存。Lua的`property.classic_rent_quote`与`property.classic_rent_payment`产生报价和支付分支，C++复核完整结果及整数类型。

付款和收款通过一次`ledger.commit_batch`提交，同时检查两人的余额版本。免费卡的剩余手牌在该事务的无分配回调内提交；任何余额/库存校验失败不留半笔租金。收租存款收入继续使用账本既有正净收入计数。付款顺序为现金、存款，地主现金不变。

正常、免租或免费卡抵扣都先发送4013并进入地产附加效果，之后才由会话处理一次同格phase6、岔路和换人。4013已经启动客户端本地6060/6061，因此不额外发送资金或扣卡包。既有移动全员汇合和阶段约束阻止重复落点再次扣租。

## 保留边界

- 1056选择、取消和超时后续已接入，见`classic-rent-transfer.md`。淘汰后仍至少两人活动的租金破产已接入，见`classic-bankruptcy-continuation.md`；最后存活者可由显式全员结算器接管，见`classic-settlement-continuation.md`；未配置该结算器及月限边界仍在资金提交前明确拒绝。
- 地产封闭/加倍、关系卡、第二套自动卡的使用与消费尚未开放。会话内关系与地产计时字段目前只有已验证的新局初始化，不能让新增客户端状态写入口绕过此处权威模型。免费卡支持范围是第一套八槽手牌。
- 非0/1地产、负租金、付款人cash+deposit超过signed32以及地主存款入账溢出均拒绝，不能静默归零或夹成假成功。
- 普通模式的完整服务工厂、库存装备同步、其它经济事件和持久结算仍需继续；本轮不改BOSS和死亡宝箱，不宣称修复飞弹基地后回1血。

按用户要求，只做静态取证/审阅、Release编译及构建中的Lua语法检查，不新增或运行测试，不启动本机服务/游戏。部署的监听检查不代表玩法已实测。
