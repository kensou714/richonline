# NEW1182 毒卡会话接入

## 本轮证据修正

`poison-new-decompile.json`保存当前NEW客户端输入SHA256及函数反编译。此前历史合同对计数复位未闭合，本轮以下证据取代“整局累计”的假设。

- 677CC0消费40EC，在game身份校验前对game+60加1；绝不能重放成功包作为去重响应。
- 7C0C50函数入口无条件清零game+60，位于分阶段switch之前。4010处理65D520及本地续接681C40通过60B1BB调用它。当前支持的卡片恢复行动不经过此入口；回合协调层在begin_turn清零，行动阶段连续使用保留计数。未来若增加不换角色的回合阶段重入，也必须同步此复位。
- 639170通过60E05A→7E14A0检查坐标边界，通过7E1580和63E340/370/390/3C0计算±width/±1；不是道路邻接寻路。射线可跨非道路，6395D0再过滤命中的格子是否道路。
- GValue25=3；中心和第一步layer0，第二步layer1，第三步layer2。方向0向下、1左、2上、3右，先层后方向。实际矩形地图的射线不合并；纯规划接口仍保持重复位置语义。
- 6395D0排除施术者、未激活角色及1494/1495/1497非-1状态；没有冻结、旅馆1493或队伍豁免。60D83A→63F010读取actor1472关系字节，命中关系>0时经63EFE0清除双方关系。
- 每次命中调用7CE420取得伤害D及百分比P，再按`(D-P*5*layer)*(1+0.5*((count-1)/3))`截断；Prop1182.hurt当前2500。同一行动前三次倍率1，第四至第六次1.5。每次命中重新解析资金相关装备，不能把第一击结果缓存到后续命中。
- 7F83F0按现金、存款顺序扣除，负伤害保留原有增加现金语义，现金+存款归零为破产。成功包负责客户端本地效果，服务端不再追加现金增减包。

## 服务端实现

模式3本地玩家使用156，8字节calendar/slot/bank/activation1/opaque7；成功40EC原样携带尾字段。要求真实地图CARD/EMP允许1182、战斗桥接、共享背包、原始状态资格及终局依赖。

纯战斗计划按格子/角色顺序计算，提交前持有原共享快照。桥接通过账本批量CAS检查双方资金、卡片、角色状态、地面和地产，再在同一串行房间操作中提交卡片、所有伤害、关系与计数。未命中仍扣卡并递增；失败不发送40EC、不提高计数。相同请求在还有库存时是下一次使用，协议没有可用于区分重复包与真实重复操作的请求ID；旧calendar或错误阶段拒绝。

生产双角色模式一方破产即进入既有终局协调器；40EC必须先于终局消息。纯计划支持最多8个角色并做全量准备，但未因此开放多人生产模式。

## 验证

- 战斗计划：两个受害者、精确总余额、冻结不豁免、自己不受伤、原始状态排除、未知字段拒绝、重复命中时重新计算现金装备修正。
- 战斗桥接：过期状态不改计数/背包/资金/关系、前三次基础与第四次增伤、双向关系清除、无卡拒绝不提高计数。
- 研究卡回合夹具：156/40EC精确字节、400B拒绝、同回合累积、下回合清零、旧calendar拒绝、40EC→终局顺序、坐标射线跨过非道路。
- 真实加密GameService TCP：连续4次使用→普通移动→Boss回合→下一玩家回合再用；精确验证共享资金86250及余卡3，无额外效果或ACK。
- 当前BS_1_1/BS_1_2/BS_1_4对三张研究卡的资源成员资格已验证。全套日志见`build/protocol-poison-final-build.log`、`build/protocol-poison-final-tests.log`。没有实机UI验收，旧native-server和旧运行服务未修改。
