# 飞弹基地周期和逐发选点的 Lua 接入

当前本机最新日志仍是 native-51556，缺少新版逐发余额记录。现有代码在每发伤害计划后检查淘汰，资金耗尽即停止后续齐射并进入原结算入口。本轮没有新的实机复现，不宣称找到“连续攻击后回到1血”的唯一原因。

## 生产调用链

- `boss_session.cpp` 将局内 Lua 实例交给 `configure_construction`。`property.cpp::prepare_missile_round` 现在调用 `building.missile_clock`，由独立 `scripts/buildings/missile_base.lua` 编排周期。
- `combat_world.cpp` 构造生产世界时，和既有 `boss.attack` 一起绑定 `building.missile_target`。`combat_session.cpp` 每发弹重新计算道路、地雷、敌人或 NPC 候选，再调用该选点入口。
- 未配置 Lua 的底层调用保留原生行为。正式服仍由启动时的 Lua 快照提供脚本，新模块通过 `main.lua` 注册并纳入既有发布语法检查。

## 状态及协议边界

新基地时钟0只装载周期；1递减至0才齐射并重装。升级保留现有倒计时，重装时读取当前等级的 PAO 资源。核心先计算合法结果，再检查脚本返回的字段、整数/布尔类型和值，只有完全一致的计划可进入共享提交；脚本不直接修改地产。

每发只调用一次既有随机源，Lua只能读取这个已生成的零基索引一次，绑定当前候选数量，最终位置必须对应同一索引。保留原候选顺序及重复位置权重，不增加随机调用、不缓存上一弹的目标集合。道路合法性、BOSS受控限制、空池停止、攻击伤害、头盔、地雷连锁和死亡停射仍由C++控制。

Lua异常或计划不匹配发生在战斗事务提交前；已有原子提交继续负责时钟、资金、手牌、地产、地面和活动状态。外部随机源已经消耗的抽样不回滚，失败不自动重试该事务。出站仍是每发40BF，整轮末尾4016；不新增现金包或改变客户端伤害动画顺序。
