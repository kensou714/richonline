# BOSS 月份到期结算（2026-10-10）

## 客户端通信依据

本轮通过 IDA-MCP 的 RnClient.exe 实例 `5c7b48b1123e` 核对：

- `64F2A0` 将房间月份乘 30 后写入 `G+83788` 的单字节字段；按无符号字节截断，零表示不设期限。
- `65B450` 的 4000 初始化经 `60FD06` 调用 `7D87B0`，将已过天数和动作计数分别清零。
- `65BEF0` 的 4004 经 `600455` / `693710` 更新的是第二个 DWORD（动作计数），不能将 snapshot.calendar_counter 当成已过天数。
- `7C0C50` 的 phase0 每次递增动作计数，但仅当前角色等于轮次锚点时推进日历。`7D8810` 将首次锚点的天数置 1，并跳过日期前进；后续通过 `7D8840` 增加天数和日期。
- `7D6CE0` 的到期条件为非零期限且 `elapsed_days > unsigned(BYTE(G+83788))`，不是大于等于。
- 到期后调用 `7CF780` 显示文本 269，跳过普通操作阶段；该路径未发现新网络请求，服务端不能继续等待掷骰。
- `65D520` 的 4010 使用 actor+4、anchor+5、replay+6 调用 phase0。

## 服务端实现与政策边界

当前双角色会话先由 BOSS 槽位 1 开始，玩家槽位 0 结束时计一整轮。新 BOSS 回合以 `complete_rounds+1` 对照客户端期限，在状态计时、附身资金效果和攻击之前发送 4010 并进入终局。

期限沿用地图资源中的月份，按客户端规则转换为 uint8；不增加 GUI 必填字段。最后一轮已完成的 NPC 轮末刷新保留既有顺序，之后发送到期 4010。

**未完成 BOSS 挑战而到期时记玩家失败，是显式模拟器政策 `native-unfinished-boss-month-limit-loss-v1`，不是已还原的原版服务端胜负算法。**

期限终局不扣现金、不把存活角色标成破产、不伪造 400E 淘汰；沿用已有的持久化结算和发包确认，发送 401B、400F。原破产终局路径保持独立，重复结算仍由原协调器及存储处理。
