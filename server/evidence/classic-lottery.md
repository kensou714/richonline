# 经典彩票购买、奖池与开奖（2026-10-12）

本轮接通静态type4彩票格的UI18购买、0029/402B应答、当月15日轮首402C开奖、
中奖资金与号码重置、破产号码释放，并保持节日→开奖→剩余日历→研究扫描的先后关系。
完整经典生产准入及其它日历更新仍未完成，本轮不开放生产经典模式。

## 客户端证据

`classic-lottery-client.json`包含31个完整函数及UI18虚表必要跨度，全部函数块和虚表
逐字节匹配磁盘RnClient.exe，SHA256为
`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。
仅静态读取，没有修改客户端/IDB，没有运行游戏或玩法测试。

- 阶段1的7C584A分支对应type4：7D9D10发现1..32仍有空号，且当前现金严格>1000，
  才排608B并返回0；号码售罄或现金<=1000直接继续。幽灵、梦游、冻结和脚本事件的
  公共前置会跳过该选择，不从存款借钱来打开UI。
- 681CC0打开UI18并设置pending18。6E6080/6E7720/6FB2C0定位UI18虚表A250A0；
  714730登记号码控件，7147C0经7282A0只启用未售1..32，714920点击后通过
  603BD7→7BBF70发送6字节0029：WORD日历+2、signed BYTE号码+4、未命名BYTE+5。
  控件33发送-1取消。自动动作的-2先在客户端从32向1找空号，无空号才原样发送-2。
- 6604F0消费402B：WORD游戏+2、signed BYTE号码+4。-1不扣款；有效号码先
  7F83F0扣1000，再693FF0写号码拥有者，693CE0将1000加入G+C80。随后清pending，
  排6080 stage2并暂停1000ms。响应必须去重，客户端自身不会防重复扣款。
- 7D9C70初始化1..32拥有者=-1、奖池=5000。奖池正是新闻累计项G+C80，
  当前会话变量news_fines。不能另开与新闻罚款无关的5000奖池。
- 7C0C50 selector3在727A90返回日期15、当前槽等于轮首、7D9D60有号码时停止继续，
  等待402C；此门没有节日的scripted_event==-1限制，不能复制节日准入门。
- 660670消费402C的号码BYTE+4、中奖角色BYTE+5（-1无人中奖）、奖金DWORD+8，
  +6/+7当前链未读取。它打开UI19、排6400ms暂停及608A selector2，没有开奖C2S确认。
- 714D30阶段2才在客户端给赢家加现金。无人中奖不清号码、不重置奖池；有人中奖才调用
  7D9C70清全部号码并复位5000。中奖者取得的是整份报文奖池，不是额外固定5000。
- 7BE160/7BE450经7D9CC0释放退出角色自己的号码，其它角色号码及奖池保留。

## 服务端实现

`RichonlineClassicLottery`独占号码表和购买等待；`tiles/tile_4.lua`负责购买、开奖意图。
购买绑定认证角色、日期WORD、位置和单调回合序号。服务端超时采用合法取消，不伪造
原客户端自动选择概率；-2只有全部号码已售时才按取消处理，不把负数写到数组前部。
正号码已售或资金变化导致现金<=1000时回取消。+5接受原始未命名字节，不强求零。
所有Lua结果、报文、资金范围在扣费前校验，再在同一账本事务扣1000现金、登记号码、
增加同一news_fines奖池。取消不扣款、不增奖池。重复/迟到0029不会再次提交或重发402B。
换人后的旧选号在行动槽校验之前去重；当前角色正在选号时仍优先受理新请求，不按历史
字节永久吞掉同日再次购买。彩票分支显式保留脚本事件跳过门；当前会话更早的碰撞准入
仍拒绝脚本事件，因此这不代表整局脚本事件已支持，后续开放时仍须补齐公共阶段。

开奖仅由轮首日期15触发，没有号码不发送402C。宿主随机源在全部32个号码上选择，
允许无人中奖；均匀随机是本项目显式策略，不声称恢复了原服抽奖分布。
有赢家时通过账本事务同时加现金、清号码、重置奖池；无人中奖只记录本次扫描去重，
不调用账本禁止的空批次，也不触碰余额或奖池。加钱和奖池累加保护signed DWORD上限。
破产产权/股票提交同一回调释放号码，不退原票款。

会话先执行已接入的13槽节日，再开奖。402C向全部连接发送完毕后才起计，默认等待
6400ms，再恢复剩余日历回调及研究扫描，不重复4010或提前420F。发送完成和服务器时钟
都不是客户端UI播放确认，卡帧/关闭窗口等实机行为仍待验证。
等待阶段早到的合法0010保留意图；断线关闭原共享会话并清理等待。
开启lottery必须同时配套feasts并提供完整剩余日历turn_start，不允许用固定complete
冒充尚未核实的其它日历业务。402C的两个未命名字节由准入显式配置，不能猜测业务含义。

彩票格购买完成继续地产业务及同格phase6。当前静态type4与地产混合的自定义地图明确
拒绝，未宣称原版资源之外的组合已支持；地图资源、月限资产估值和完整普通建筑效果仍待接入。
