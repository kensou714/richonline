# BOSS 行为与奖励阶段调整

依据用户本会话确认：第2章指阿占卜；各 BOSS 从自己的第一关重算；负面神明仅成功附身时抽一次，不按附身持续回合重复。

## 已实现的服务端规则

- 黑贝贝：每次可行动的 BOSS 回合独立判定地雷/飞弹/核弹，基础20%/15%/10%，每关增加2个百分点。阿占卜为20%/20%/10%，每关增加3个百分点。地雷选择真人四邻的合法空道路，飞弹/核弹瞄准存活且不在医院/监狱的真人。一次攻击造成死亡后立即停止剩余攻击，进入既有终局流程。
- 疯狂地雷：负面附身成功后按30%+5%×(本 BOSS 关数−1)抽一次，概率封顶100%。显式梦游、睡神受控梦游、冰冻、已死亡或宝箱阶段不触发。一次均匀抽取5～7枚，再从全图合法空路无放回选位；排除角色、逻辑宠物、已有动态物及不支持落点的格。没有空格时不放雷，但仍发送一次台词。
- 覆盖地面附身、庙宇召神、Lua召神卡和原生召神卡成功入口；免疫挡下的附身和单纯延长附身不抽取。NPC1/2/6为当前生产支持的负面来源；NPC18预留于Lua负面集合，但当前NPC宿主尚未支持该附身，不能宣称幽灵附身已实现。NPC7按梦游排除。
- 台词由原BossWar资源选择实际非空的第5组；不存在则选择其他实际存在的组。BS_3_4使用5/2，其余现有12张地图为5/1。直接600A指定BOSS槽位，不挪用宠物或幽灵提示。
- 除黑贝贝外，可行动的 BOSS 回合另独立20%判定火焰。本次对“全图放置”按覆盖所有合法空道路实现；保留现有物件、角色、逻辑宠物和禁止地形。401C/type26按原GValue半径逐区域同步，避免客户端单格/区域语义不一致。火焰的资源装载与玩家火焰卡的赠卡准入分离。
- BOSS回合记录turn_sequence，恢复行动不重复抽武器或火焰。宝箱改为死亡原格、当前单真人仅一次移动，结算回房显示策略详见boss-chest-phase.md。

## 静态依据与验证边界

- boss-behavior-client.json记录22个客户端函数的完整chunk字节与磁盘匹配及SHA256。401C明确携带owner，避免玩家召神时把雷归为玩家。600A的actor+12用于取BOSS子索引及显示角色；网络队列可分派注册的600A。
- boss-behavior-resources.json为只读解包摘要：13张地图各42～57条道路；地雷/火焰索引容量与道路数相同，每格只登记一次。全图火焰同步包数不超过道路数，低于客户端255条有效队列容量（并非已完成完整队列压力验证）。记录原资源hash、台词索引与狂暴字段，不公开资源正文。
- Release候选编译通过；不新增/运行测试，不启动本机服务或客户端。最终固定提交构建和线上发布另记实际回执。
- 附身事务先提交，技能随后独立准备并经共享战斗事务提交；不存在网络请求内自动重试。规划错误会关闭本局，不能把部分已提交状态当作未消费请求重试。空地不足属于正常成功路径。
