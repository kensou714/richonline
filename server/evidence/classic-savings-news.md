# 经典新闻：并列最高存款奖励

经典共享会话的静态1新闻入口新增406F。原来只处理单个行动者的金额消息，406F若沿用该接口会漏发其他储蓄第一名的奖励。现在核心按所有活动角色的存款选出并列第一，每人增加报文指定的完整现金奖励，再继续当前行动者的phase6及岔路处理。

## 协议依据

`classic-savings-news-client.json`保存当前NEW客户端6657D0、7C0540、63E7D0的完整伪代码、反汇编及函数字节SHA256。三个函数窗口逐字节与磁盘PE一致；IDA导入文件哈希单列，未冒充当前磁盘文件身份。

- 6657D0读取game WORD+2、图片signed WORD+4、奖励signed WORD+6；报文共8字节，没有收款人列表或mask。
- 60733B跳至7C0540，其最高值初始为0，只比较活动槽的存款。63E7D0实际读取game+3632+slot活动字节，IDA中的MFC名字不是业务含义。
- 所有并列最高存款的活动槽各获得完整金额，不是平分；全部零存款时全部活动槽中奖。非活动槽不参与排名，即使保留的存款较大也不影响结果。
- 客户端逐人排新闻提示、6060现金收入和动作，最后仅排一次6080阶段2。服务端不额外发送现金奖励包，也不按赢家数量重复406F。

## 实现和提交边界

新增纯准备函数接收2–4个资金快照及活动名单。金额按非负signed WORD校验，图片沿用已核实的29项UI30白名单，拒绝未知存款和有符号余额溢出。奖励只增现金；存款、点券、预备金和新闻罚款累计项不变。

Lua的tile_1模块按同一规则准备全部资金结果、零基获奖槽和4013/406F两帧；C++逐值及逐字节核对，并检查资金和名单值的整数类型。准备回调只允许一次，错误结果不会提交账本。

会话在调用只读选择策略前取得所有角色快照。批量提交也包含未获奖者的原值：其存款或版本若在准备后改变，整个事件拒绝，不能给过时的第一名发奖。提交回调同时核对活动名单、行动者状态/位置和罚款累计项。任何一名获奖者余额溢出时都在提交前拒绝，不保留部分奖励。正收入成就沿共享账本原有规则累计。

本轮静态审阅覆盖单一第一、多人并列、全零、已退场角色、资金版本改变、任一获奖者溢出及Lua错误结果路径。按用户要求不新增或运行测试、不启动本机服务或客户端；构建和发布结果以本轮版本回执为准，静态审阅不等于实机验收。

选择策略仍须由地图业务显式提供。未推定原服务器新闻概率或奖励金额，尚未开放生产经典模式；新闻住院、全卡变卖、完整股票新闻和其他特殊格仍需接入。BOSS飞弹基地回到1血仍缺少新版逐发现场日志，本次改动不作为该故障的修复结论。
