# 经典共享会话商店等待

此前经典会话没有内置商店等待：静态10未接入，通用event只接受单一pending opcode，不能完整承接0030买入/退出、0031出售及0035刷新。本轮接入独立shop阶段，复用现有商店资金、库存、货架及期限核心。生产mode0仍未开放，账号金豆扣费由明确的准入回调提供，不能把服务端接口完成当成完整玩法验收。

## 客户端证据

`classic-shop-client.json`保存18个函数的完整伪代码及函数字节窗口哈希。本轮与磁盘RnClient.exe逐字节相等，EXE SHA256为`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。静态落点公共入口同时沿用`classic-local-rewards-client.json`和`classic-portal-client.json`。

- `6609B0`的4030先复制全局货架。刷新标志0打开本地当前角色的UI20，所有客户端等待10000ms；标志1只刷新，并由本地行动者执行650110扣金豆，不重设等待。
- `609320→63F760`比较当前槽G+3624与本地槽G+8。服务器必须认证当前行动角色，不能把商店永久绑在槽0或某一连接上。
- `7BC050/7D6020`提交6字节0030，+2为日历低WORD，+4为商品槽或-1；+5不是服务端可要求为零的字段。0031同为6字节，0035为4字节。
- `660B00`的4031非-1按当前货架取卡及数量、扣一次价格、清该货架槽；不结束等待。`660CB0`的4032清指定手牌槽全部数量，增加一次半价点券，不按堆叠数量乘价，也不结束等待。
- 4031(-1)清pending并排6080(stage2)，随后才进入地产和phase6。不能在买卖成功时提前抢卡/换人，不能把成功回复当作幂等回包反复发送。
- `710D60/711C80`保留商店中的Shift弃卡路径0032；4033只丢卡，不加点券。它不能被当作0031出售。
- `7D6F90`检查G+83809>0停业，`7BAE60`将它初始化为0。当前经典宿主尚无动态NPC16及其停业写入口；未来接入时必须镜像该状态并在开店前判断，不可仅凭本轮商店接口宣称已支持停业事件。

## 实现与边界

`RichonlineBossShop`新增按已加载目录装配的构造入口，复用同一地图的价格/可售目录；经典会话每人绑定自己的手牌实例和共享账本槽。`RichonlineClassicShopPolicy`显式配置商品兼容字节和同代GoldCharge；`services.shop_refresh`由准入层绑定账号及共享支付协调器。没有回调或有效价格时沿用既有安全关闭逻辑，不免费刷新、不伪扣金豆。抽货架使用房间的既有随机源；不猜原服务器抽取概率。

开店先准备货架、库存和余额版本，然后调用现有`tiles.tile_10`。核心验证Lua回包数量和完整字节，再核状态、位置、脚本事件及phase6授权，最后提交开启和期限。无脚本路径使用同一准备/提交器。受控角色只发4013；混合地产引用拒绝，不能跳过未接通的小型商店地产逻辑。

shop阶段只由当前真人的0030/0031/0035驱动买卖/刷新，连续正常交易继续等待。关店或服务端期限到达后进入同一次落点的complete，由宿主执行phase6及岔路，不重复4013。已关闭的商店保存角色与日历，在后续阶段忽略格式正确的迟到商店请求；当前正在进行的商店始终优先处理，不能按请求字节去重并吞掉合法连续刷新或买卖。

商店内0032复用已有弃卡事务，保持商店阶段。股票的独立入口维持原共享账本；商店买卖每次重新取资金版本。碰撞授权只对mode0生效，原mode3碰撞校验不放宽。日志记录开店货架、库存、角色、位置，以及请求槽位、点券前后值和决策原因。

本轮只静态核对、审阅、Release编译及Lua语法编译；按用户要求不新增或运行测试、不启动本机服务或客户端。经典生产准入、动态NPC/停业、地图完整业务及付费绑定仍需要继续，实机购物验收不在本轮编译结果的证明范围内。
