# 经典坐牢新闻、免罪卡和出狱

本轮接入4080/4082/4083/4084/4085/4086/4088/4089/408A九条坐牢新闻。复用已实现的医院保险事务与退出协调，不混淆医院1494和监狱1495。生产经典mode0仍未开放；地图新闻选择和完整第二套库存事务仍须装配。

## 原协议依据

`classic-jail-client.json`记录17个完整函数；`classic-jail-validation.json`确认2106条指令及函数哈希与磁盘RnClient.exe一致。轮首阶段4、卡槽扫描和资源资格另复用classic-hospital-client.json及jail-continuation证据。本轮无客户端执行或游戏测试。

- 九条消息都先核对WORD+2游戏编号。4088在+4读取新闻图signed WORD、+6读取天数signed BYTE，其余只在+4读取天数，不能塞入不存在的图片字段。固定文字中的天数不是服务端报文天数。
- 667CF0、668120、668370、6685C0、668810、668A60、668E90、6690F0、669340均在提示/角色动作后调用7CD1C0。1057查找由7F85C0先扫描局内八槽，再扫描可用第二套槽；800A50验证CARD类型和地图许可，不检查Prop.enable。
- 免罪成功排提示262、声音315、角色动作56、6061扣一张1057，最后排6080(stage2)。不运行动画11，不入狱、不清stay、不转移角色、不调用保险。
- 免罪失败排动画11。631950/631B40/631A50负责入场、状态应用及结束补写；7F8160移动至监狱入口、隐藏并重置宠物，写1495=days、1493=-1、1496=0，方向和其他状态保留。

## 实现

共享处罚准备器逐项验证新闻opcode、图片、正signed BYTE天数、收容状态、资金和库存。先选择第一张可用1057；成功后保留保险卡、现金、原位置和角色状态，统一提交扣卡，再从原新闻格继续phase6碰撞与岔路。未免罪才选择1049、清stay、提交1495及监狱入口，并进入收容等待。

Lua的card_1057独立负责免罪分流；未免罪时复用card_1049的赔付准备，tile_1只组装相应消息。C++复核完整Lua结果、整数类型、库存和消息字节，资金/库存/状态同笔提交。第二套免罪缺少权威证明时在提交前拒绝，不能当作没有卡；只有需要保险时才要求第二套保险证明。免罪成功无需监狱坐标，也不读取保险库存证明。

医院和监狱共用confinement_wait/confinement_exit，但各自选择状态、位置和策略。只在自己的轮首递减天数，正数跳过行动，零数退出。普通角色等待本人0015；受控角色使用显式延迟，早到合法0010只缓存一次意图，归位后生成路线。重复/迟到0015沿用已完成请求去重，断线清空等待。

entry_delay=10000ms、turn_delay=3150ms、controlled_exit_delay=1800ms和普通退出exit_timeout=30000ms均为服务端显式排队策略，不声称是原服概率/动画时长或测得的网络ACK。超时未收到普通角色0015会明确报错。
