# BOSS 胜负通知修正（2026-10-11）

## 已确认根因

用户反馈黑贝贝死亡后先提示黑贝贝胜利、再提示失败。原服务端将 `400D` 命名为 bankruptcy_notice，并对每个淘汰槽先发 `400D` 再发 `400E`。

当前 NEW 客户端静态反编译确认：

- `400D -> 65CC00`：读取包 +4 角色槽，排角色动作5和文本13「獲勝!」。
- `400E -> 65CF40`：读取包 +4 角色槽，调用 `7BE160` 清活动状态与资金，排败退动画。
- `401B -> 65E460`：独立写结算资料；`400F -> 65D390` 显示结果界面。

因此 `400D` 不是破产预告。新序列为每个败者一次 `400E`，真正获胜的玩家一次 `400D`，随后 `401B`、`400F`、大厅58。部分淘汰也只发 `400E`。

## 持久发送游标

原存储固定按 `败者数*2+3` 计数。新记录的 delivery.message_version=2，计数改为 `败者数+3+玩家获胜时1`。写入、待读取和结算资料刷新校验采用同一计数。

历史 JSON 缺少版本时解释为1，保持原有数量和游标，已完成的资料刷新仍可读取。禁止把版本1的未完成结算按新版包序列重放，明确返回 legacy_outbox_requires_reconciliation，不改写历史玩家结果。对局标识验证仍先于恢复。

## 验证与边界

已静态核对客户端分支、结算组包、数据库入队/游标/刷新边界；`RichOnline.Server` 增量编译通过。遵照用户要求未新增或运行测试，未启动本机服务和客户端。固定提交的发布构建另行执行。

此修正不宣称解决飞弹基地后血量回到1，也未开放战后宝箱。宝箱协议目前确认 `420C -> 67C5E0` 调用 `7CF6A0` 清地面动态物、通过 `7F91F0` 清攻击卡和若干状态，并把 game+83830 设为2，再放 NPC32；末尾发送两字节 C2S0002。`7CF730` 只在值大于0时递减并返回是否到0。拾取、奖励抽选与持久发放仍需闭合后接入。
