# 多连接开局与顺序发送

本轮继续经典地图的真实接入前置工作，补齐跨连接共享的调度适配器，并修正生产通用入口的股票包结构判定。普通地图会话工厂、共享回合规则、每人手牌、经典地产、行情策略及结算仍未完成；没有据此开放普通房间或BOSS股票。

## 无日历的股票请求

既有`stock-trade-core.md`所依据的客户端消息生产器已证明0200/0201为六字节，+2是股票槽、+4是数量。此前`richonline_game_startup.cpp`把除0002以外的动作全部按+2日历认证，因此合法股票槽会被误判为过期日历；它们不会进入交易内核。

本轮将唯一的股票请求解码器移至codec层的`richonline_stock_wire.cpp`，保留原来的长度、消息号、股票槽0..9及数量1..32767校验。启动计划新增可选`stock_action`，通用入口在完成地图加载后先识别0200/0201，完整解码后分派该回调。没有回调时明确拒绝股票能力，不将包交给普通卡牌分派，也不发带落点副作用的4206。此分支不读写日历、不执行已结束动作去重，不吞掉两次相同买卖。

启用交易回调的计划还必须提供实际整帧发送观察器；行情开局完成和在场资格由具体会话继续校验，只有观察器存在不等于行情已发完。BOSS计划未设置股票回调，能力仍关闭。

## 共享调度适配器

`make_richonline_shared_startups`接受同局各真人的4000和共用4004，返回各连接可交给现有`make_richonline_game_callbacks`的计划。它检查局号、完整角色顺序、快照槽数、local_slot唯一性和所有真人的端点覆盖。除local_slot外的4000必须逐字节相同，合成角色不能拥有真人连接。

所有业务回调在同一局互斥锁内串行执行，不得反调本适配器。各连接依旧使用原来的单连接准入、加密及计数逻辑；共享层只负责已经认证的局内槽，不从请求正文读取施放者身份。

每位真人收到4000并回0000后，原连接适配器发送其4004。共享层等所有人的4000、0000及4004整帧发送确认到齐，才调用一次opening。不能用“已生成初始化包”代替发送完成。业务消息可广播或指定真人收件人；4010和后续4004资金同步只能广播，避免不同连接日历计数分叉，并校验角色槽／完整快照长度。共享层禁止重复4000和由外层专门处理的4006。

每批响应按同一顺序进入各收件人的待发队列，通过各自poll/action返回给运输层，转为待确认队列。只有和队首逐字节一致的sent才移除，不因一次poll就确认发送，也不在下一次poll重复返回同一消息。所有收件人发完整批后才处理下一条入站操作；等待期间的操作按到达顺序排队。普通动作保留原始信封和明文，股票保留解码后的请求；不按内容相等去重。空响应的业务可以继续处理下一条，计时poll只在队列空闲时调用，时钟推进仍归业务所有。

出站明文采用现有编码器的509字节上限，每连接最多256条待发／待确认消息、总字节上限1MiB，入站最多64条。每次广播先验证全部收件人和局号，准备全部新队列后统一替换。业务调用后发生分配或编码故障时整局标记失败，不自动重跑事务；这不是持久消息队列或断线重连保证。

断开回调每位真人最多一次，并清该连接队列；开局前断开使共享层失败。现有注册表在非结算阶段仍取消整个房间，本轮没有改变其离线政策。已持久结算的terminal_pending与大厅58观察器不受游戏失败门遮挡；game_finished还要求该连接快照已确认且队列已清空，具体持久结算与显示延迟由业务回调负责。

## 检查边界

静态审阅覆盖两名玩家先后加载、单边未确认、开局广播、发送期间收包、连续相同股票请求、错序确认、私有消息和断开清理的控制流；没有执行这些场景。按用户要求只进行Release编译和构建内Lua语法检查，不新增／运行测试、不启动本机服务或游戏。

共享适配器目前编入库供经典会话使用，生产BOSS仍使用现有单连接回调。下一步必须把经典地图准备结果与实际业务状态、资金及手牌接成会话，并提供真实行情和结算后再改provider准入；不能把本文件当作多人玩法上线证明。
