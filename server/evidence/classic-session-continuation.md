# 经典多人整局回合接续

本轮把已有经典启动、共享移动汇合、公共手牌、共享账本、经典地产和岔路模块装配到一份具体会话。入口是 `make_richonline_classic_session(startup, rules)`，返回经典宿主所需的一份 `RichonlineSharedCallbacks`。生产 runtime 尚未提供完整经典服务，因此模式 0 仍未开放。这不是多人玩法验收记录。

## 权威状态和协议接续

会话核对每名玩家的连接、身份、出生点、4000 和 4004；只允许各份 4000 的 local_slot 不同。位置数组、状态数组、账本、产权和回合序号只创建一次，每人持有独立手牌及骰数偏好。初始附身状态明确设为客户端初始化的有符号 -1，不使用表示未知的 optional 空值。

起始行动槽、每人可用骰数、起手卡和随机奖励候选均由显式规则传入，不套用 BOSS 先手或 BOSS 起手卡配置。起手牌沿用 4019 的前四槽同步，奖励候选经过同一商店实际可售检查。每个非重播 4010 只递增一次日历 WORD，严格递增的回合序号另存；每绕回起始槽一次才增加完整轮数。状态计时分别调用前一角色结束和当前角色开始钩子。

- `0010(parameter=0)`：只有真实当前行动连接能够掷骰。先准备并校验整条权威路线及 4011，再记录移动序号和待决终点。
- `0014`：只更新发送者的个人骰数偏好。现有客户端 `70A7E0` 界面刷新和 BOSS 已有路径允许它在非行动阶段出现，因此不把它当作当前行动者的掷骰授权。
- 指定骰点卡 `103`：使用当前行动者独立库存，先完成路线准备，再扣卡并广播 40B7/4011；无卡时只恢复操作，不扣他人卡。弃牌 `50` 使用同一角色的真实槽位。
- 普通 `0011`：必须经过上一轮实现的共享层收齐全体一致上报，只提交一次当前行动者的位置和方向，再进入落点。独立移动序号不能用回绕的日历替代。不得把这份 action 绕开共享层直接挂到各条连接。
- 地产：普通种类 0/1 的未归属购买、种类 0 普通升级使用已有 `RichonlineClassicProperty`。绑定行动槽、日历、回合序号、落点地产和该玩家 equipment[2] 的 LAND 字段。取消、资金不足和超时也必须进入 `property_effects`，不能直接换人。购地/升级结果的 Lua 决策及原子资金/产权提交仍由已有模块执行。
- 空道路和已支持卡片格使用现有消息编码/公共手牌模块。多人同格后续已由会话在静态/地产完成后的phase6统一处理，再进入岔路；详见 `classic-phase6-continuation.md`。
- 落点真正完成后，度数大于 2 的末端先等待 `0034`；提交 `4035` 和朝向后才发送下一 4010。岔路沿用六秒取消策略，地产采用显式服务端决策时限。

业务事件必须返回明确的 complete 或 await_event，并且等待时必须给出下一 opcode。保留给移动、地产和岔路的 opcode 不能借业务事件绕过阶段校验。所有客户端共享相同的广播队列和发送屏障，业务回调在该对局锁下串行执行。

已接受的有限历史请求保存发送者和完整字节，只用于已结束操作的迟到请求。当前阶段的合法操作优先处理，连续相同交易不能通过全局去重吞掉。原协议没有操作序号，不能宣称可区分日历回绕后字节完全相同的任意历史重放。任何必需成员退出会关闭整局，不缩减人数或伪造移动确认；工厂装配失败及未交付回调析构也释放业务成员，显式退出不会重复通知。

## 服务装配边界

`services` 工厂收到同一份账本、地产和每人手牌引用；回调上下文包含全体位置、状态及权威行动槽，span 只在同步调用期间有效。`landing` 返回空值表示没有处理也没有提交副作用，才进入基础分支；返回结果时业务负责完整停止/后继消息。`property_effects` 负责地产选择之后的附加效果。`event`/`poll` 负责业务等待，不能用空成功跳过未知玩法。同格phase6由会话统一处理，业务回调不得提前或重复转移同格手牌。

银行后续已接入同一会话，详见 `classic-bank-continuation.md`：0028全员确认检查点、0027行动者选择、402A恢复原路线或末端续接。普通地产租金、免租和局内手牌免费卡后续已接入，见 `classic-rent-continuation.md`；第二套自动卡须有权威库存证明。仍需补齐：嫁祸选择和破产、特殊建筑选择、封闭和附身效果、传送末端、动态地面物、状态受控移动、新闻及其他特殊格、回合日历经济事件、库存与装备效果、股票行情和持久结算。月限按客户端 months*30 的 BYTE 边界检查，未接结算前明确停止而不是无限续局。普通掷骰尚依赖客户端请求，没有伪造一个原服务器自动掷骰时限。

上述未完分支仍显式拒绝；生产模式门保持关闭。BOSS 回合器和黑贝贝死亡宝箱不改动。本轮不会解决或声称解决飞弹基地攻击后回到 1 血的问题。

## 取证与验证

沿用 `shared-movement-reports.md` 的逐窗口客户端核对、`classic-property-choice.md` 的地产协议证据，以及只读的 `docs/逆向资料/专题/回合继续与落点调度/阶段2_01_入口与分支树.txt`、`阶段2_02_建筑选择与本地事件.txt`、`阶段2_03_租金与未决边界.txt`。本轮没有新增客户端逆向一致性断言。

按用户要求仅静态审阅、Release 编译和构建内 Lua 语法检查；不新增/运行测试，不启动本机服务或游戏。发布健康检查只证明实际交付及监听，不证明普通多人或各类落点已实机可玩。
