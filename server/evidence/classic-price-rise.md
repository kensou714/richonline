# 经典涨价卡：五天街区标记与住宅租金

经典共享会话原先未处理C2S119，且住宅租金模型没有D+5涨价字段。本轮将1058独立Lua模块接入经典地产卡事务，并同步原生的按日递减和逐块住宅计价。属于实现缺口审计，未冒充玩家实机复现；生产经典准入仍关闭。

## 原生证据

`classic-price-rise-client.json`记录当前客户端SHA256 `feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`，20个函数全部chunks逐字节与磁盘PE一致，另保存四个关键汇编窗口。日期初始门、月限和剧情状态边界沿用`classic-seal-client.json`的完整证据。

- `655840 -> 692810`生成6字节119：操作WORD、日历WORD、槽BYTE、库BYTE。脚下须关联地产，且当前建筑kind8/9/10不可用；不要求所有者是自己，也不要求有建筑。**119对应卡1058，不适用前面96～102的opcode+935卡号规律。**
- `672020`消费40C7，以当前角色位置取地产和街区，排6078、6061扣1058及6006恢复操作。包内没有目标地产、街区或租金字段；服务端不能从客户端伪造的额外字段取目标。
- `681030 -> 7E3560 -> 7E3510`遍历Map+46C普通地产表，将D+6等于目标街区的D+5写5。表成员由`7DF010`加载时确定：sprite11/12，排除初始kind8/9/10；D+5初始为0。重复使用重设5，不叠加倍率或天数。
- `7E3630 -> 7E35E0`遍历同一表，只递减正D+5。`7C0C50`中它紧随查封计时，共用经典模式和日历门：首轮初始化不递减，每次锚点推进一天时减1，同日其余玩家不减。
- `7E4140`逐块选择同owner/同街区的sprite11、kind0住宅。先将地价×计价系数×等级系数保留低32位，按signed32除1000并向零取整；该块D+5>0才以SHL1翻倍，最后累加。不是先将全部乘积相加再整除，也不是把最终报价无条件翻倍。
- `7E42B0 -> 7E6B40`的商店报价只数同owner的sprite11/kind1，每块4000×计价系数，**不读取涨价标记**。商店可以收到标记，但不因此增加收费。
- `7C6640`先检查落点查封/地主控制和收容等免租门；通过后才调用住宅或商店报价。付款者原生附身状态1的翻倍、免费卡/转嫁卡阈值在报价之后处理。本轮保留这一顺序，涨价与附身可叠加，查封仍优先免租。

## 实现与原子性

`RichonlineClassicPropertyState`增加`price_rise_days`，与`sealed_days`独立。两者都属于地产本身，产权、建筑交换及拆除沿用快照保留它们，不转移到别的地块。查封和涨价统一为`prepare_card_street(StreetEffect)`，保留查封允许站在特殊地产使用的区别，只有涨价拒绝来源kind8/9/10。

共享会话先验证合法用卡阶段、日历、玩家位置、主手牌槽及1058库存，再准备整条街区的状态与扣卡计划。提交前复核全部参与对象/状态；无效请求返回400B，不扣卡，成功只广播一次6字节40C7。仍用既有共享会话阶段和重放约束，无额外动画ACK或资金包。

`advance_street_effects`替代只处理查封的入口，同一次日期推进独立减少两种正计时；重复同轮不扣，跳号/倒退拒绝。查封时涨价继续倒计时，解除查封后只使用仍未到期的涨价标记。

住宅C++报价与`buildings.classic_property` Lua同时加入逐块涨价计算；Lua收到每块真实计时，结果须与核心完全相等。商店不翻倍；付款、免费/转嫁、破产及结算继续消费这个实际报价。购地费用和总资产地价字段不因租金标记改变。
