# 经典饭店落点、住店与离店

本轮补kind4饭店的0026/4028转盘、费用、免费卡、财神免付、穷神加倍、type2嫁祸、
住店计时和离店恢复。只面向已有经典共享会话；生产经典准入、电脑公司/房产公司等
其余缺口仍未完成，不将编译通过解释为完整玩法验收。

- 7C0C50 stage4：计数归零，或7F7F60发现原道路对应建筑等级为0/不再是kind4，即离店。

  原生随后6084(4,0,0)只执行地产附加效果，再恢复同一行动者界面，不重新收租或做phase6。

## 事务与会话

`classic_hotel.cpp`提供严格请求解析、报价/4028、GValue住店规则及位置计算。
`buildings/classic_hotel.lua`独立镜像报价与几何，C++核对完整结果和整数类型。
饭店复用转盘等待和资金/手牌支付事务，保留自己的0026去重历史。
超时明确返回4028(-1)，属于服务端恢复策略，不冒称原服托管分布。

原始状态模块新增PreparedHotelEntry：先验证四类收容状态，再由无分配提交写入住店和
移动回报标志。直接付款时与双方余额、免费卡同时提交；type2嫁祸时与代付余额、1056
消费及可能退场同时提交。未通过资格/几何/账本校验时不先扣费再入店失败。
入住保存原道路、饭店引用、内部格和入店方向，计时不依赖客户端没有上报的动画位置。

收费成功后不执行落点phase6，也不额外发6060/6061/6066。入店与剩余天数回合采用
显式服务端排队延迟；出店普通角色须0015，超时关闭而不伪造成功。
受控角色使用独立延迟，保留早到的自动掷骰请求，归位及附加效果完成后再执行。
等待/离店期限从全员完成对应消息投递后开始，网络发送时间不算客户端动画时间；
投递确认仅表示服务端已发送，不能当成客户端动画完成或实机验收。
离店附加效果若产生等待，沿用event/poll续行，并保留“完成后回行动界面”的状态，
不走普通落点的碰撞/岔路/换人。
