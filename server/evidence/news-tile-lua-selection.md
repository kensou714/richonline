# 新闻格 68／69／70：Lua 加权选事件

`BwNews` 的蓝、红、黄三列仍由 C++ 读取，分别限制 68、69、70 格能出现的事件。核心先为每个可闭合事件准备资金、手牌或状态计划，并排除破产续接、无可出售奖励卡、客户端优先级未核实等不能安全完成的分支。枚举候选时已有的随机参数与卡牌抽样顺序不变。

只有候选全部准备完毕后，核心从原随机源抽一次权重游标。`tiles.tile_68/69/70.select_news` 调用共享 `tiles.news_select`，按候选相对权重返回序号。核心复核序号必须与游标落入的区间相同；Lua 不能增添事件、改变权重或写账本。

## 落点编排与提交边界

后续审阅发现 `rules.script=std::move(script)` 之后，旧新闻回调捕获了空的局部 `script`。因此前一版虽然已编译部署，线上实际仍走 C++ 抽样。现改为捕获 `rules.script`，使用当前对局的不可变脚本快照。

三个新闻格的 `land` 现调用共享 `tiles.news_landing`：先通过 `tile.news.prepare` 准备事件（其内调用 Lua 加权选择），再返回 `4013/4096` 两帧。嵌套 Lua 调用复用既有递归锁、调用栈恢复及指令预算；准备器没有账本、库存或状态副作用，仅沿原次序消耗随机数。

回合层核对完整回包字节、角色及状态快照，准备 NPC 状态时钟，然后由账本 `commit_batch` 在校验资金版本后同时提交手牌和状态时钟；成功后才进入原有路口选择或下一回合。Lua 抛错、回包修改、库存或状态版本冲突均在提交前拒绝。已提交状态不再以 `status_change` 交给 `resolve`，避免重复修改时钟。原有已发 `4013` 去重、梦游 BOSS 新闻规则及可出售奖励池保持不变；旧核心或不适用的落点在准备前回退。

这是已闭合新闻类别的选事件和落点编排迁移，不代表所有新闻类别已复刻。原服务器的颜色列概率与未闭合事件仍无证据，当前等权策略保持不变。未运行游戏或自动测试；已编译服务端并通过全部 Lua 模块的语法检查，实际新闻格行为待玩家实测。可用 `lua_tile_news_committed` 日志确认该分支完成。
