# 经典换位卡503：坐标与扣卡共同提交

## 客户端规则

`classic-swap-positions-client.json`保存11个函数的完整chunk、文件偏移、SHA256和
反编译内容，逐字节匹配当前RnClient.exe（SHA256
`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`）。

- `651290`检查至少两名可参与角色，`691ED0`构造操作161，请求6字节：日期、手牌槽、卡包。
- `678C80`消费40F1，显示503、声音301、动画39、扣一张卡，再恢复操作界面。
- `7CF170`先快照全部合格角色坐标，再按角色槽顺序给每人下一位合格角色的旧位置；
  最后一位取第一位的位置。不是随机洗牌，也不是交换朝向。
- 筛选要求活动、旅馆/医院/监狱/绑架均为-1且未冰冻；梦游和狂暴不属于目标排除项。
  `63EF50/63EF80/63F4A0/63EFB0/63F4D0`及相应thunk确认字段。
- `7F72A0`更新人物道路坐标及画面坐标，不写朝向；`7F7990`重置宠物跟随格。
  此动画不触发新格地产、地面物或同格碰撞事件，不另发移动到站包。

## 服务端实现

独立`classic_relocation.cpp`准备全员位置快照和503扣卡计划，既有独立`card_503.lua`
通过`card.prepare → actor.relocation_snapshot → actor.prepare_positions`生成意图。
核心严格核对调用顺序、整数类型、每个目标位置及唯一40F1回包。

共享经典会话以真实行动者的主手牌处理161；仅行动阶段、无未完成移动、无脚本事件时
可用。活动角色收容字段未知、坐标不合法或不足两人均拒绝，不扣卡、不换位。
提交前再次核对回合、行动者、卡对象、库存、全部角色状态、原坐标及朝向；所有检查
成功后在无异常提交段共同更新扣卡和位置，其他字段保持。回包后仍处于行动阶段，
之后掷骰从新位置开始。旧日期重发沿会话已有历史请求逻辑处理。
