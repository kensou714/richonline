# 经典多人局租金破产退场

普通租金和1056嫁祸支付现在可以淘汰一名玩家并继续多人局，前提是淘汰后至少还有两名活动玩家。最后存活者的持久结算仍未装配，生产经典模式仍关闭；此记录不是完整玩法验收。

## 客户端依据

`classic-bankruptcy-client.json`保存当前客户端SHA和20个函数/跳板的磁盘与IDA窗口一致性。`7F5D90`仅导出末尾110行，其余业务函数导出完整伪代码；函数哈希覆盖各自完整窗口，不声称整个IDB一致，也不把客户端行为当作原服务器实现。

- `65CF40`消费400E，先清理该角色，再排败退动画和提示；它不是400D胜利消息，不能反复发送来补状态。
- `7BE160`先验证在局及活动标记，清现金、存款，调用地产回收和角色状态清理，最终减少活动人数并清活动标记。原槽及在局记录保留，破产不等于断线。
- `7E6200`的普通模式路径通过`63EC70`清所有者，再清该角色的占有记录。`63EC70`仅把地产记录+3写为-1，保留建筑种类、等级及价格。
- `7F9560`清1496/1498/1499/1500/1501/1502及关系、效果；不直接清手牌和票券。当前会话仅映射已实现的移动状态，未开放股票、关系卡及建筑增益的写入口，不声称那些系统已经接入。
- 普通模式`7F9950`清持仓和成本、将正持仓回收市场，不是卖出入账；本轮不创建虚构的股票清算。`7D9CC0`清持有位置记录。
- `7F5D90`末端0011上报门检查移动角色，没有本机活动资格门。共享层继续等待包括破产者在内的已连接成员，并仅把合并后的行动者请求交给会话；不能缩减汇合人数。

## 提交与续接

地产对象先准备全图产权快照，提交前复核快照及无未决购地，然后只清败者的owner。会话同时预检活动人数、月限和后续轮序。所有分配及Lua业务调用都在账本事务前完成；事务回调先完成校验，再通过无分配操作提交地产、活动名单和必要的手牌变化，不重新进入账本锁。

普通租金用现金、存款总额夹取实付，收入进入地主存款；同一`commit_batch`提交资金与退场。消息顺序为4013、400E，然后向下一活动玩家发送4010。当前行动者已破产时不再处理地产附加效果、同格phase6或岔路。

嫁祸用既有`commit_sequence`保留先收款后扣款的顺序，同时提交剩余手牌及退场，消息为40C6、400E。取消导致原行动者破产时直接换人；其他代付者破产时原行动者继续地产附加效果及phase6。地主自己代付仍按入账后的实际余额判定，不因为原余额小于租金就误淘汰。

活动名单保留原槽号，落点占格、碰撞、嫁祸候选及轮序均排除非活动槽。业务上下文同步提供只读active视图。已破产客户端仍可发送自身0014骰数偏好；其他业务请求仅吸收已记录的迟到操作，不能重新行动。

先手淘汰时，服务器选择其后的首个活动槽作为新轮首，通过4010+5同步，日历和租金周期按实际新轮首推进。这是明确的服务端策略，不宣称恢复原服务器算法。最后两人边界、将越过未实现月结的退场都在扣钱扣卡前拒绝。

## 验证与边界

完成静态协议及事务路径审阅，增量Release编译和构建内Lua语法检查通过；发布另从固定提交独立编译。按用户要求不新增或运行测试，不启动本机服务或客户端。线上健康检查仅确认交付、进程和监听，不代表多人破产已实机验收。

本轮不改BOSS胜负及死亡宝箱。飞弹基地连续攻击后回到1血仍缺少新的实测日志，不能宣称已修复。完整经典服务工厂、最后存活者和月限持久结算仍需继续。
