# 经典贸易中心落点与支付

本轮接入 kind3 贸易中心的他有地产落点、UI15 的0025/4027、支付和嫁祸续行。
自有地产仍进入既有升级流程。生产经典模式尚未开放；饭店、电脑公司、房产公司及
完整准入仍需继续，不能据此声称经典多人玩法已可上线游玩。

## 当前客户端证据

`classic-trade-client.json`保存当前RnClient的SHA256、23个函数全部chunk的磁盘/IDA
字节一致性和伪代码。7C6640只保存相关摘录，哈希覆盖该函数全部chunk。
客户端SHA256为`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。

- 7C6640在他人kind3地产排6087；6929B0读取D+1==3，7D7500写6087。
  地主睡神、梦游、冰冻、收容及地块查封在入口抑制收费；不能换成付款人的控制状态。
  同盟/关系仍没有经典写入口，不把本轮边界解释为已实现同盟。
- 681A50打开UI15并设pending11。7BBCE0/7D5F60生成四字节0025，+2是日历WORD，
  无点数选择参数。只有行动者本人连接可确认。
- 712F20初始化转盘位置6；7131E0将位置逐次减1，低于1回到6，只有当前位置等于
  4027给定结果才停止。因此正常结果只能1..6，0及其它结果会导致转盘不正常停止。
  未找到原服务器分布，`trade_result`必须显式提供只读选择策略，没有默认均匀概率。
- 65FDC0读取4027的+2局号和+4 signed结果。-1关闭UI15并排6084(4,0,1)，不收费。
  其它结果按7E4360计算`M+100 * signed D+2 * 600 * result`，D+5>0再翻倍。
  核心和独立Lua模块均保留32位乘法回绕，再按signed32解释，负报价在提交前拒绝。
- 正常4027更新UI15，暂停队列3600ms，排6042(owner,amount)。67E970先处理财神免付、
  穷神加倍，再调用7CCE60免费卡和7CD090(type1)嫁祸；没有保护卡则先入地主存款，
  再从付款人现金优先扣款，余额耗尽走破产，不继续普通附加效果。
- 6712B0的成功与取消switch均将type0和type1合并到同一分支。成功才扣原付款人1056，
  新付款者不递归检查免费/嫁祸卡。成功或正常取消后排6080(2,5)，只执行附加效果。
  普通6042及-1取消则排6084(4,0,1)，681890执行相同地产附加效果后转phase6。

## 实现与提交边界

`classic_trade.cpp`处理严格四字节请求、合法结果、原生报价及4027编码；
`buildings/classic_trade.lua`独立计算报价和回包，核心核对完整结果及整数类型。
共享会话保存地产、行动者/地主状态、位置、日历和回合序号，确认时复核。
等待期间股票可正常成交，最终按确认时账本读取资金；只读结果策略调用前后核对
各人余额和手牌，禁止选择策略顺便修改资金或扣卡。

支付复用已有普通租金的保护卡与共同账本事务，不用住宅报价替代贸易费用。
免费卡优先；第二套库存仍须权威缺席证明。嫁祸缓存type1并沿用同一资金、目标资格、
手牌事务；额外保留4027的3600ms动画时间，再加既有决策超时。
地主作为代付者仍按先收存款、后扣现金顺序执行，不净额抵消。

0025重复及超时后的迟到请求按行动者/日历有限历史吸收，当前等待优先。
超时使用明确的服务端策略4027(-1)，不伪造原服概率，也不扣卡/扣款。
4027已经让客户端本地执行6060/6061，因此服务端只镜像账本与库存，不重复发钱或扣卡。
后继包排在4027后，客户端暂停及本地队列维护消费顺序；没有伪造动画完成ACK。
普通收费、免付、免费卡、嫁祸结束均进入一次地产附加效果与同格phase6。
破产沿用部分退场或最终结算器，缺少最终结算能力时在资金提交前拒绝。
