## 普通移动确认不是宠物完成确认

`64FE70` 对每个角色先调用主人 `7F5D90`，再调用宠物 `640DA0`。两者分别使用 actor+0x350 与 pet+0x54 的计时器，`81BD10` 按 GetTickCount 判定并更新各自时间。0011/0012/0028 的生产点不读取宠物进度，也不等待宠物到达；不能通过确认或固定服务端延时推断 pet+68。

## 可用同步入口 402E 及其明确副作用

表初始化 `7EE330` 将 A9E198 设为 60E816，对应 0x402E。调用链为 `60E816 -> 7EFC70 -> 602BB0 -> 6607A0`。

消费者只读取：+0 WORD opcode、+2 WORD game id、+4 signed BYTE heading。`607A2F -> 64F710` 验证 game id 等于 game+83844。作用对象是 game+0xE28 的当前角色索引，在 game+0xE00 的角色数组中取对象；包不携带独立角色槽位。

`6607A0` 顺序：

1. `608BC8 -> 7F7940` 写 actor+1460 的方向，再经 `798350` 写 actor+876 的显示方向。传入原方向时两值保持不变；无骰子、卡牌、钱、状态计时或位置写入。
2. `601A3A -> 7F7990` 根据主人当前 position 和 `(heading+2)%4` 求后方；先检查边界，再检查后方道路。不成立时使用主人当前格。
3. `603D12 -> 641250` 写 pet+68 当前格、pet+64=0、本格像素坐标；`7F7990` 同时把该格写入 actor+536 跟随目标。主人保持停止时 `640DA0` 看到 current==target 直接返回，不依赖动画赶上。
4. UI channel 4 调用 `6E3B40` 设置 1350ms 提示，`6E4640` 写 RichStr 310 文本。只读 LZO/CP950 解码得到：**幽靈作怪，被迫轉向!**。本入口无 609D34 本地事务排队、无扣卡、无重掷、无新增 C2S ACK。UI 操作有面板显示/失焦等正常副作用，不能称为无提示同步。

## FIFO 与插入位置

`64F870` 立即分派的特例只有 4041/4042/4043/4053..4057；402E 与4010都走默认 `5FF1B3 -> 698050`，以尾游标写入288字节记录。`7BB290` 每轮 `60F356 -> 7D8010` 从头游标取一条再进行表分派。因此402E不会越过已经入队的4010，不会直接在网络线程提前作用于旧角色。

服务端应仅在带PET人类合法移动确认后，先验证并提交真实position/direction，然后把同方向402E放在对应响应的4013、下一角色4010、恢复移动包之前；同步记录安全后方宠物格。该策略需要服务端保证此时当前角色仍为该人类。BOSS无PET时不发送。

停止依据：0011的正常末端和障碍分支先 `600BD5 -> 7F5C90 -> 7F5D50(0)`；0012炸弹分支同样先停止；0028银行分支先 `6057B1 -> 7F5D10`，将主人state设2且像素进度清零。主人当前position与heading已经由跨格逻辑写好。停止后的402E复位得到稳定宠物格，银行后续恢复移动则再次进入跟随。

4035方向选择不会复位宠物：如果402E已经在之前执行，之后只改主人heading时，服务器应保留先前宠物格。不能仅因heading变更便自行重新计算宠物。

真实传送、换位、入院/入狱/旅馆重定位已走7F7990，不需要伪造额外同步消息。61传送格在7F5D90排606C出口重定位；6802A0先7F72A0写主人出口，再7F7990复位。服务器须按出口与当时heading同步安全后方格，不能保留入口旧格。
