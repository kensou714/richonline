# 经典房产公司落点加盖与拆除

仅接入经典模式大型建筑kind6的既有客户端自动效果。它没有新增C2S选择消息：
服务端通过地产共享状态镜像客户端已处理的变化，不另发改级包。生产经典准入仍关闭，
此项不代表其余地图事件或整体对局已完成。

## 同代客户端依据

`classic-estate-client.json`保存客户端SHA256、24个函数的完整代码chunk哈希、
逐块与磁盘PE原始字节相等核验及有界调用点反汇编。

- 7DF010装图时按记录号从0递增，sprite11/12且kind不属于8/9/10的地块依次进入
  Map+46C普通候选表；记录号在当前资源解析器中是地图格索引。既有服务端资源解析器
  也按这个顺序生成地产，计划显式以记录号升序遍历普通候选。初始特殊地块不因后续
  状态改变而被加入候选表。
- 7C6640的自有kind6路径先执行效果，再到LABEL_217打开升级询问。效果使用升级前
  的公司等级；65ECA0消费4021后经693D70排6084(4,0)，681890只执行地产附加效果，
  不再执行公司加盖。受控状态和当前地块查封会拦截
  自有效果。自有目标先查住宅kind0，再查其他大型建筑；目标等级必须严格小于公司等级，
  各类别取最低等级，同级保留表内第一项。大型目标kind不在2..6时先改为kind3，
  然后按公司等级加盖，经典模式上限5级。当前公司本身从大型目标排除。
- 他有kind6路径按地主暂停收效及地块查封条件拦截。目标属于来访者，优先级为住宅
  kind0、商店kind1、其他大型建筑；需正等级且不超过公司等级。各类别取最低等级，
  同级选表内最后一项。按公司等级拆除，因此当前已验证0..5级域中目标归零；住宅、
  商店保留kind0，大型建筑变kind-1，产权和地块自身计时不转移。
- 目标不存在时客户端直接续行，服务端也提交无效果计划。既有地产附加效果和同格
  phase6由会话续接；不能因为房产公司效果结束就直接换人。

## 核心与Lua

`classic_estate.cpp`从原普通地块集合准备完整候选快照与目标变化；
`buildings/classic_estate.lua`独立选择同一目标和最终kind/level。核心逐字段核对Lua
整数结果，再通过地产模块已有的完整快照匹配与无分配提交应用。客户端与服务端均
不对没有网络ACK的本地动画增加虚构确认。自有效果在首次落点、升级等待之前提交，
升级接受、拒绝、超时与4025续行都不重复执行，也不会误用升级后的公司等级。
