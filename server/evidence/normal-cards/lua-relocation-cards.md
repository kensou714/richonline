# Lua 传送和换位卡迁移（2026-10-11）

行为对照为迁移前 `boss_turns.cpp::auxiliary_card` 143、161 分支；本轮不是新的客户端逆向结论。按用户要求只改代码和编译，不运行游戏或协议测试。

- 传送卡1116：C2S143/S2C40DF均8字节，+6为小端有符号WORD目标格；只接受有效道路。现有分支仅把施放者坐标改为目标，回包原样携带槽位/银行标记/格号；没有补发落点或引爆消息。
- 换位卡503：C2S161/S2C40F1均6字节；按角色槽位升序筛选在场、原始旅馆/医院/监狱/绑架状态均为-1且未冰冻的角色，至少两名；将每个资格角色移到下一个资格角色原位置。当前双角色房间即互换。
- `actor.relocation_snapshot` 只读取原始资格和坐标；`actor.prepare_positions` 拒绝非道路、重复角色和不在场角色，记录每人原坐标，回包完整转换后核验并同库存扣除一起提交。它不负责落点；如要新增传送到地雷的结算，须另行验证客户端续接语义，不能伪造额外回包。

毒气卡1182继续保留原生战斗事务。现有 `prepare_richonline_combat_poison` 按 footprint 单元逐次命中、每次针对投影资金重算 damage terms，最后统一写资金/库存/状态并处理破产；普通Lua `funds.prepare` 每角色只允许一次，直接替换会改变算法和终局时序。后续迁移应先提供支持临时资金投影的战斗计划接口，再把范围/衰减策略交Lua。

本轮 `cmake --build server/build --target RichOnline.Server -j 4` 包含 C++ 目标和全部 Lua 语法编译；编译通过不等于实际游戏验证。
