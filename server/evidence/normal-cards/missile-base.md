# 飞弹基地：周期齐射与回合续接（2026-10-10）

## 当前问题

`data/logs/native-54416.jsonl` 的 Kid Ken 3-4 房间中，155号地产为kind12，01:35:29时未购买、01:49:42时属于玩家，随后升至5级。原 `RichonlineBossProperty` 只有研究队列，无飞弹基地周期队列；战斗桥只有BOSS攻击和手牌攻击入口，服务端也从未发送客户端基地计时所需的4016。本轮补齐这些入口。

## 本轮确认

只读 IDA 输出保存于 `missile-base-client.json`，目标为当前 `RnClient.exe`。

- `7E5E00`（thunk `600158`）在四字节队列的空槽登记地产编号，倒计时初始化为0。登记调用来自购地、建造/改造等地产处理路径，不能只处理开局预建基地。
- `7E5F10`（thunk `609C8F`）递减正倒计时；到0时，无主地产移出队列，否则按当前等级装入下次周期。它没有发送请求，也没有排队飞弹效果。
- `7C0C50` 的 phase8 分支仅在 `7D6D70` 成立时调用该计时器。`7D6D70` 比较 `game+3628` 与 `game+3624`，是轮首角色与当前角色相等的判断，因此计时单位为完整轮，不能对两个角色各计一次。BOSS模式还要求 `game+83830 == -1`。
- `7AF4A0` 将PAO四列读入 `this[4*level+20..23]`；`7ECC10` 返回 `this[4*level+20]`，故BOSS基地计时使用首列，等级从1开始。
- `7E6090`（thunk `60506D`）仅检查指定玩家是否拥有倒计时为1的基地。其调用者 `705C70` 更新UI状态；此前把UI参数44称为已确认的地图发射命令没有充分依据，不能据此推定存在C2S44发射请求。
- `66E830` 接收10字节 `40BF`：WORD opcode、WORD game、BYTE slot、BYTE bank、WORD target、BYTE attacker、BYTE flag。`flag != 0` 时仍排队目标镜头及飞弹动画18，但跳过用卡提示、扣卡、恢复人物视角和普通用卡续接。本实现使用flag1满足已确认的非零分支，不声称恢复历史服务端具体取值。
- `7EE330` 分派表的A9E120位置映射4010/65D520，A9E138位置相差6项，映射4016/65DF30。后者仅读取game WORD并排队本地608A/phase8，再设置500ms延迟。响应为 `16 40 <game WORD>`，无需客户端ACK，也不自带飞弹效果。新增原始证据见 `missile-base-continuation.json`。

## 服务端实现与策略

- 轮首发送4010，处理当轮地雷到期，再发送到期基地的40BF齐射及4016，最后继续原回合。每个完整轮号只提交一次；不是每个角色回合都扣周期。
- 与7E5F10对齐：新基地倒计时0；首次4016装入当前等级周期，之后每轮递减，1降至0时齐射并装入当前等级的新周期。升级保留正在运行的倒计时；改造成基地或从零建造时重新初始化，销毁或失去所有权时清零。所有权改变但地产仍为有效基地时保留该地产周期，后续齐射使用现任所有者。
- 按资源指定类别，在每发弹之前重新读取计划内的目标集合，以均匀随机选择道路、现存地雷、现存NPC或敌人位置；目标为空时跳过余下弹数并正常重装周期。均匀概率、空目标跳过和按地产编号处理多基地是明确的本项目策略，未宣称恢复历史服务端随机算法或调度顺序。
- 目标限制在实际道路格，不沿用普通BOSS攻击的角色可视范围。按用户已有要求，BOSS处于一/六步卡、乌龟、停留、梦游、冰冻、医院或监狱等受控状态时也不触发基地攻击，当轮周期仍正常推进。
- 每发弹复用共享飞弹伤害规划器，更新头盔、现金/存款、地雷连锁和动态NPC；一旦实际破产就停止余下齐射并走原结算流程，不额外扣手牌。基地周期与伤害、地产、地面物和角色状态在同一个账本提交回调里生效，失败时不会先提交周期。
- 新增 `richonline_missile_base_clock` 和 `richonline_missile_base_fired` 日志，包含轮号、地产编号、剩余周期、所有者、等级、目标类别、请求/实际弹数、控制状态和目标格。
