# 点券格5/6/7的Lua事务迁移

## 协议依据

2026-10-11读取当前IDA实例 `7a8a6607e358` 的 `7C54B0`：case5/6/7先检查模式3的合成角色标志，普通角色分别取80/50/30，排本地6001和6062，type5追加6002。公共入口的睡神、梦游、冻结检查会跳过这些奖励。该结果与 `docs/逆向资料/专题/回合继续与落点调度/阶段1_落点分支与本地事件.txt` 的0x7C5924分支记录一致。

当前NEW协议4013继续落点后，客户端自行计算点券与播放动画；服务端只镜像账本，不能另发一次奖励。这里的5/6/7是EMP静态格类型，不是卡号或道路位置。

## 实现

- 各格Lua模块指定80、50、30，共享 `ticket_reward.lua` 按合成角色/控制状态改为0，调用 `tile.tickets.prepare`，返回唯一六字节4013。
- 核心 `prepare_richonline_ticket_landing` 复核模式、角色与合成标志、道路和碰撞资格、无地产引用、静态类型、奖励金额及有符号点券上限。它只生成账本前后快照和响应，不提前修改资金。
- 原生 `RichonlineBossLandingState` 的点券格预检查和落点也使用同一准备器，避免维护两份奖励校验。
- Lua准备至多一次，禁止混用原生落点、赠卡及随机准备。完整返回值转换和逐字节核对完成后才通过版本化账本提交；脚本异常、篡改金额、漏包/多包/错误位置或账本冲突均不提交本次点券。
- NPC前缀已发4013时沿用外层去重；碰撞、方向选择、回合续接和宝箱阶段跳过静态格的规则不变。旧EXE、无账本和有地产引用的入口在准备前回退原生。
- `lua_tile_tickets_committed` 记录角色、类型、位置和点券前后值，便于后续实机核对商城消费所用账本。

按用户约束只进行静态协议核对、代码审阅、C++编译和Lua语法编译；不新增或运行测试，不启动本机服务或客户端。普通角色获点、受控跳过、NPC后续和购卡余额表现仍需要实机反馈。此迁移不代表其他新闻/商店/传送格已迁入Lua。
