# 均贫卡1052的实际通信效果（2026-10-10）

## 证据与原缺口

源码审计发现C2S115原先直接进入统一400B拒绝分支，尚未应用实际效果。不是新实机日志复现。

live IDA实例 `5c7b48b1123e` 重新反编译 `655030`、`670330`，并对照既有40C2系列证据：

- 请求为8字节：115、动作计数WORD、库存槽BYTE、库存组BYTE、目标角色BYTE；末尾字节未作为业务字段使用。
- `670330`（40C3）以游戏号校验后读取双方现金，执行32位加法再算术右移一位。对当前允许的非负且不溢出输入，等于向下取整平均。
- 两次606A只设置现金，不修改存款、点券。总和为奇数时丢弃余数，没有向某方补1；与均富卡不同，没有至少1元的钳制。
- 条件606B解除双方同盟，再扣发起卡；本地玩家通过6006恢复操作，没有新的请求或结束回合ACK。

## 服务端处理

115接入现有正常卡牌事务，要求玩家当前可操作、计数匹配、主卡包持有1052、目标为另一存活角色。准备双方账本快照及剩余卡包，8字节回复40C3的目标仍使用BYTE+6，未使用的尾部写0。

双方现金总和超过INT32_MAX时明确400B恢复、不扣卡，避免客户端32位加法回绕成负数。可支持的非负范围内按客户端公式设置双方现金，包括0；不因为本卡现金变为0而伪造破产结算。扣卡、清同盟和双方现金更新共用现有账本提交检查，存款/点券保留。

没有修改商店掉落、Prop模式开关或地图成员表来强行发卡；仅补齐收到合法且实际持有的卡牌请求时的效果。Prop的均贫卡cm/pk/hb为true/false/false，不据此伪称它已成为默认BOSS奖励。

16项剩余拒绝分支的日志改为 `card_effect_unimplemented`，避免把服务端未实现误写成客户端模式禁止。92项注册入口的当前统计为61项处理、16项暂未实现、9项被动、6项本地返回。
