# 福神随机两张卡：四个来源统一（2026-10-10）

## 原因与证据

用户此前要求福神附身随机赠送两张卡。本轮先核对最新日志仍为 `native-54416.jsonl`，未取得新的实机奖励记录；源码检查发现NPC会话的地面福神、神庙召唤、福神卡1070及请神卡召来福神四条路径，仍直接传入 `policy_.fortune_cards`，生产配置来自地图固定数组。节日随机发卡不经过这些入口，不能代表福神已经随机化。

通过live IDA再次确认当前客户端 `65F0C0` 的4023处理器依次取+4、+6两个WORD卡号，各以数量1调用 `6110BB -> 7F8780`。同一个卡号可以出现两次；接收端没有要求两张不同。`7F8780` 使用首个空位并执行合成，满手牌不会插入但继续流程。反编译保存在 `fortune-random-client.json`。

## 实现

- 生产 `boss_session` 安装统一的 `fortune_selection` 回调；四条人类奖励路径每次各调用一次，连续抽取两张卡。不为无权威背包的合成BOSS抽卡或操作玩家背包。
- 抽取使用现有地图可用且已接入的卡池与均匀随机策略，两次允许重复。该概率是明确的本项目策略，不声称恢复原服务器概率。
- `prepare_random_reward(source)` 支持针对尚未提交的背包抽取。第二次抽取使用第一次插入/合成后的背包；福神卡使用自身扣除后的背包，请神卡使用1047消费后的背包。所有抽取均只准备，不中途写入权威背包。
- 仍由原 `plan_richonline_fortune` 编码4023并按相同顺序插入两张卡，保留地面phase1、神庙phase6、用卡恢复操作及附身时钟。满手牌沿用资源插入器的正常不插入行为。
- 生产日志 `richonline_fortune_reward_selected` 记录房间、两个卡号和策略名；这是选卡日志，不是提前宣称事务已提交。独立调用方没有选择回调时仍可显式使用固定奖励配置，生产入口总是绑定随机选择器。
