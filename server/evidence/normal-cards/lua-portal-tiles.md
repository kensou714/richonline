# 28／58／61 传送格的 Lua 落点编排

## 原有证据及行为

依据 `evidence/random-teleport58.md` 和 `evidence/normal-cards/teleport-mine.md` 的 NEW 客户端取证：28／61 的入口 `4013` 已驱动客户端完成配对传送；58 需要 `4013` 后跟 `4209` 指定目的地。两类路径都不应等待额外落点确认，出口地雷仍由服务端显式发送 `4017` 并提交战斗，不能再发出口 `4013` 递归触发静态事件。

## 迁移

此前三份格子 Lua 文件只是原生包装，实际传送分支在调用 `tile.land` 之前就已更新位置。现在在该分支增加纯准备接口，三份独立模块调用 `tiles.portal_landing`，编排目的地及报文。受控／脚本事件的跳过分支在无地产引用时也走同一接口；需要地产处理的组合保留既有原生续接。

核心继续根据真实地图配对、道路邻接、角色及控制状态产生计划。随机传送仍沿用全地图非孤立道路等概率政策，可以跨连通分量，和战后宝箱的连通候选不同；原服务器随机算法尚无证据，不冒称原版概率。核心只抽一次，Lua 的随机回调只能读取一次与候选数量绑定的索引，不能重抽或扩大候选。

Lua 必须返回确切目的地、报文数量和逐字节相符的内容。随机传送两帧，配对或跳过一帧；脚本抛错、错误目标、重复准备、额外资金／重定位包均在位置、宠物及出口战斗更新前拒绝。随机源可能已消耗，不能据此宣称失败回滚随机序列。

通过回包校验后重新调用纯计划器读取脚本事件状态，对照续接类型、配对出口、确认包、随机候选及当前角色状态。已有 NPC 阶段发送过的入口 `4013` 先参与完整校验，再在发送前去掉。位置、保留朝向、宠物复位、出口地雷、破产／宝箱和正常下一回合继续使用 `complete_portal_landing`，不另造一套战斗状态。

旧 Lua 模块的 `tile.native` 在此接口中只选择兼容结果，脚本返回后才执行续接，不在回调内移动角色。无脚本的底层路径保留同一组报文及候选。中途经过61格的路线、传送卡与换位卡不在本轮范围内。
