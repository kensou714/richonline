# 57 类兑换格：Lua 编排与延后提交

客户端语义沿用 `evidence/merchant57-session.md` 中的 NEW7C54B0 取证：玩家有至少 25 点券时扣 25 点券并加 2000 现金；合成 BOSS 不扣点券而加 2000 现金。脚本事件、睡神、梦游、冰冻跳过兑换，玩家点券不足也不改变余额。只发送 `4013`，客户端本地执行兑换动画和金额变化，不追加资金增量报文。

## 本轮迁移

`tiles.tile_57.land` 不再把完整业务交给 `tile.native`。核心的 `tile.merchant.prepare` 使用本局兑换会话验证真实地图、道路度数、角色、资金、控制状态及 `game+83830`，准备不修改账本的计划，并向 Lua 提供点券余额和脚本事件标志。Lua 独立编排兑换／跳过条件，返回现金增量、点券成本和唯一的落点确认。

回合层只允许一种落点计划，禁止准备兑换后再调用原生、卡牌、新闻或点券计划，也禁止重复准备。Lua 完整返回后，核心验证结果形状、金额整数、金额与原协议规划相符、整份报文字节一致，然后复核当前角色状态并提交。脚本异常、篡改金额、错误包长、额外资金包等在提交前拒绝。

`RichonlineMerchantSession::land` 与脚本入口共用新的 `prepare/commit` 接口。提交前再次读取 `game+83830`；资金快照版本及状态仍由原特殊落点事务校验，重复提交被拒绝。响应和结构化日志在余额写入前分配；提交后使用已有不抛出日志接收器，保留 `richonline_merchant_landed` 的前后现金、点券和 outcome。已经发过的 `4013` 继续由原落点链去重，路口选择及回合续接不由 Lua 伪造。

没有细粒度能力的旧核心或未配置兑换会话的底层调用者在准备事务前回退到原生。生产规则持有同一兑换会话，避免另造账本或在移动后的空脚本变量上调用。

## 验证范围

仅静态核对及 C++ Release／全部 Lua 模块语法编译，不新增或执行测试，不启动本机服务或游戏。实机兑换及连同 NPC 的落点续接尚待用户验证。固定提交、发布包哈希及线上健康状态保存于本机发布回执；不将编译和部署健康检查视为玩法验收。
