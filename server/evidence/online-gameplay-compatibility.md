# 线上商城日期与地图选择配套修复

2026-10-11核对发现，线上进程确实运行`c4676565779b`，但持久化bootstrap沿用了早期配置。安装器只切换资源目录，保留了`original_2005`及空的客户端兼容标识，也没有本机的`unlock_all_boss_maps_for_testing`。因此EXE版本相同不能证明运行能力与本机一致。

## 现场依据

- 线上启动日志明确记录`inventory_date_version=2005`和`date_mode=original_2005`。原日期编码不能表示2026年的限期商城物品；配套的本机客户端已使用2021纪元。
- 线上`stage_progress=[1,1,2,0]`且缺少解锁标志，本机已有该标志。同步的是用户测试用地图选择范围，地图自己的运行能力门禁不变，不声称全部章节完整。
- 线上11:41:08.309 UTC收到NEW10模型切换，11:41:08.319成功发送NEW18；11:41:09.575执行部署stop。该时间窗口的掉线与维护停服吻合，不能将其记为模型切换再次抛错，也不能由一次响应证明所有商城路径均已验收。
- 线上备份的迁移预检ready=true、unresolved=0、重编码映射0；4个账号、4个角色、4件库存、4条装备记录可保持。真实数据和详细日志只放在被忽略的本地工作目录，不提交仓库。

## 配套工具

`tools/deployment/Set-ServerGameplayCompatibility.ps1`只作用已核实的现有发布，先检查实际进程、任务、EXE/迁移器/客户端哈希，再备份配置、任务和在线数据库。预检通过后通过ExpectedInstance正常停服，从停止后的线上库重新生成迁移副本，以File.Replace保存原文件，再切换匹配的配置。

日期改为`compat_2021_v1`，兼容标识为`richonline-inventory-date-2021-v1`。可显式同步测试用BOSS地图解锁。开服前失败恢复原文件；开服后不自动用旧备份覆盖玩家新数据。启动后检查全部监听就绪、实际EXE路径和日志中的2021纪元，保存独立配套回执。原release的sourceCommit不改写为仅工具改动的提交。

本次不改客户端、不覆盖本机或线上账号数据为测试库、不新增或运行游戏测试。PowerShell语法检查和真实备份迁移预检已通过；上线结果以远端`deploy/current-gameplay-compatibility.json`及后续启动日志为准。商城实际购买、连续购买、装备与地图开局仍需用户实机确认。
