# 经典武器条约：全员主手牌清理

本轮仅修改server。经典共享会话接入武器条约1115，请求142，确认40DE；复用独立Lua模块`cards/card_1115.lua`，由C++准备并提交全员库存。经典生产准入仍关闭，不能以本卡接入推断经典模式完整可玩。

## 客户端依据

客户端SHA256：`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。`classic-weapon-treaty-client.json`保存11个函数完整chunk与磁盘PE逐字节一致的哈希及反编译结果。

- `657DA0 -> 60E6FE -> 692DC0`生成6字节请求：WORD142、WORD日历、BYTE槽号、BYTE手牌组。
- `675970`消费40DE，核对game_id，排显示和音效312，然后经`610346 -> 6949D0`排2字节606D；之后排6061扣施放者指定槽/手牌组的一张卡，本机行动者由6006恢复操作，不需要新增ACK。
- `680310`遍历`G+E20`角色数，调用`60B49F -> 63E7D0`检查`G+3632+slot`活动标志。汇编`680360`明确从`G+E00+slot*4`取当前遍历角色对象，再调用`610BED -> 7F8FF0`，不是只清施放者。
- `7F8FF0`遍历角色`P+1520`处的8个主手牌槽，每槽6字节。卡号为1044地雷、1045定时炸弹、1046飞弹、1063核弹或1075安全核弹时，将卡号设为-1、数量设为0，清整叠。其余卡槽不变，无压缩、合成、地面道具移除或第二套手牌清理。
- 606D的活动门不排除住院、监禁、冰冻、梦游等状态。已经退出活动名单的角色不清。1115不在五类武器中，客户端先清武器再扣卡，与服务端准备库存时先扣1115再清武器结果一致。

## 服务端事务与边界

`RichonlineClassicWeaponTreatyPlan`核对6字节请求、日历、主手牌组0和0～7槽号；施放者须持有1115。全部2～4名角色的手牌对象须有正确角色槽、相同game_id/地图、经典mode0。准备时保存对象引用、全部库存与活动名单，只修改计划副本。

Lua绑定仅有`card.prepare`和`inventory.prepare_clear`，必须依次各调用一次，卡号和清除表必须精确匹配且为整数；返回值须为单个规范6字节40DE。Lua失败或返回不符时不扣卡、不清库存。原BOSS单真人宿主仍使用原绑定；本轮没有改变其执行逻辑。

经典会话只允许已认证当前行动者在掷骰前操作，检查收容、控制状态及脚本事件门。准备后再次核对行动者、日历、回合序号、位置、方向及施放者状态。提交前统一核对所有库存、对象身份与活动名单，然后在会话串行执行范围内通过noexcept固定数组赋值提交，任一预检失败都不留下部分清理。广播一个40DE，客户端自行显示、清卡、扣卡并恢复操作；不追加清卡消息、不结束回合。

本次不开放洗牌1125。客户端证实它会清空所有活动真人的主手牌，但全员随机分配算法仍待用户确认，不能复用单真人BOSS的自洗牌实现到经典多人。
