# 经典同盟卡1060与全局日期关系时钟

## 客户端证据

`classic-alliance-client.json`含18个函数完整chunk、磁盘偏移、SHA256及反编译，
全部逐字节匹配RnClient.exe，SHA256
`feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。

- `655A60`使用`64FF10(a5=0,a6=0)`选择其他在场真人，排除四种收容状态，
  冰冻/梦游不在目标排除条件。`692870`构造121，请求8字节，目标在+6。
- `672600`消费40C9，排606B建立同盟、扣1060、恢复操作。`6801E0`双向调用
  `694E10`写P+1472目标槽。写入值是A870AC，即GValue11低字节；`7B9AD0`
  按indx将GValue记录填入A87080的DWORD数组。当前服务端支持1..127天。
- `63F010`以有符号byte>0判断同盟。`7C6640`在7C9577/7C95FB处读取付款者
  按地主索引的同盟，跳过付款；P+1480队伍关系是另一组字段，不能混用。
- **计时更正**：`7C0C50`先检查`7D6D70`当前槽等于日期锚点，初始日由
  `7D8810`跳过日期推进；之后日期块调用`7C01C0`，遍历所有活动角色调用
  `7F94A0`，逐人递减八个正值同盟槽。并非各自在自己的回合减一。
  旧`card-dispatch-92.md`和辅助卡迁移说明的“自身回合到期”应以此证据更正。
- `66DA60`梦游卡先排双向破盟，再检查免疫和1071保护；被抵挡仍破盟。
  `7CF340`冬眠对合格目标先互清关系再检查防护。`7F9560`清状态时遍历正值
  同盟并双向解除；破产链`7BE160`也清关系。

## 实现

新增独立`classic_alliance.cpp`，复用`card_1060.lua`：严格核验
`game.snapshot → card.prepare → relations.rules → relations.prepare`、整数参数及唯一
40C9。共享经典会话保存开局全零的八乘八关系矩阵；同盟卡在真实行动者、日期、
全员状态和位置及库存仍匹配时共同提交双向关系与扣卡。同盟天数由准入显式传入
同代GValue11，缺失时拒绝用卡，不猜默认值。

租金、电脑公司、贸易中心/饭店的免收入口和他有建筑附加效果读取这份关系。
查税/均贫、梦游在各自原子提交段解除双方关系；清除和破产解除目标的所有正值
双向关系；冬眠快照、提交都携带真实关系。均富不解除同盟。资金/清除独立计划器
的关系调用由共享会话协调，关系快照先核对，成功提交后只执行无异常数组赋值。

日期推进时，全体活动角色同步递减同盟计数；不在初始日、重复请求或普通恢复操作
时递减。BOSS原有按行动者递减一行的实现同步改正，避免双方同盟到期时点不一致。
客户端日期块还受脚本事件和月限分支控制；当前经典脚本事件保持-1，BOSS月限
在时钟前终止。未来接入脚本事件时须重新核对日期准入，不能无条件复用该递减条件。

## 边界

仅支持当前已经接入的经典卡牌/破产链；未来陷害、武器、毒气等经典入口必须接入
这份同盟权威，不能创建第二份关系状态。1480队伍关系、NPC独立附身时钟、动态
地面及完整生产准入仍未完成。BOSS宝箱阶段沿用无同盟奖励流程。
