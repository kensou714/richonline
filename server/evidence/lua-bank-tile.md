# 银行格9的Lua业务与核心校验

## 依据

只读参考 `docs/逆向资料/专题/银行与资金/00_银行等待与回复闭环.txt` 及现有银行、道路、资金账本实现。4018必须完整8字节，+6区分路过与落点；402A完整12字节，动作0存款、1取款、2退出，金额在+8。客户端不做完整余额或重复回复检查，因此服务端必须维持一次性待决与资金守恒。银行选择等待8000毫秒。原服务端已实现这些规则，本轮是业务迁移，不声称发现了新的实机银行故障。

## 实现

- `tiles/tile_9.lua`独立处理`bank.open`与`bank.transaction`。开窗保留目标格、路过标志和已核实保留字节；交易先处理BOSS不交易、超时，再处理取消、非正金额、余额不足、目标余额signed32溢出及合法存取款。
- 核心从原始0027解析动作、signed32金额并验证日历，输入真实待决余额和服务器超时结果。C++保留独立资金边界校验，逐值检查Lua的有效动作、实际金额、两个余额、结果类型和完整402A二进制。多字段、缺字段、错包或决策不符均在关闭银行等待之前拒绝。
- 开窗4018校验成功后才启动八秒计时。BOSS的4018与退出402A全部准备好再返回，不提前建立待决；脚本异常不会遗留一个BOSS银行等待。正常提交、主动取消与服务端轮询超时共用同一交易入口。
- 对局使用已经保存在`rules.script`的VM，避免捕获已被移动的局部script。未配置Lua的底层调用者保留原有规则与回包。
- 路过0028仍由核心检查不可变4011路线与银行检查点；402A后恢复原路线。银行落点保留4013去重及原落点阶段续接。受控角色和宝箱阶段的银行跳过策略不变。重复0027继续由既有已完成决策记录抑制，脚本不发第二次回包。
- `bank_result`在验证后的共享账本提交成功后记录`richonline_bank_completed`，含角色、格号、结果枚举、两个余额、路过标志与Lua启用状态。结果枚举沿用头文件：1转账、2退出、3超时、4BOSS退出、5非正金额、6不足、7溢出。

这里的银行是对局内现金／存款转换，不操作大厅银行或持久账号充值；资金仍由共享对局账本拥有。Lua无资金写入能力。账本的乐观版本校验及角色/路线校验仍由原状态机承担，不把脚本校验扩称为全部游戏状态的回滚事务。

## 验证范围

静态核对存款、取款、取消、到期边界、零／负金额、余额不足、signed32上限、BOSS经过与停步、路过与落点续接；编译Release与全部Lua语法。按用户要求不新增或运行测试，不启动本机服务或游戏。实际银行窗口、交易数值及关闭后的动画仍需玩家验证。
