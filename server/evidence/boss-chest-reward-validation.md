# BOSS 宝箱抽奖提交前校验

本轮继续核查死亡、宝箱和结算链路。当前实现已经纠正400D胜利／400E失败通知，并在420C生成宝箱后，等待拾取或三个完成回合才释放结算。最新本机日志仍为此前的native-51556，本轮没有新的实机复现，不能把本次加固作为胜负双提示的根因。

静态审查发现，`claim_boss_chest` 的Lua奖品选择入口此前只检查返回索引是否在奖池内。它没有要求随机回调恰好调用一次，也没有验证返回奖品是否对应本次随机权重区间；错误脚本可以返回另一个合法索引并进入持久化事务。

核心现在先校验正权重和总和上限，固定一次均匀抽样，按原始奖池顺序计算应命中的区间。Lua仍负责奖品选择，但只能读取这一次抽样；核心要求回调参数完整匹配、恰好读取一次且返回索引与权重区间一致。所有校验均在缓存奖品、调用库存事务和释放结算之前完成。合法脚本的抽奖权重、奖池顺序与随机调用次数不变，第三回合拾取优先于超时结算的行为不变。

原有固定`:chest`操作键继续保证同一次领奖的幂等写入，奖品确认后沿用缓存，不在数据库重试时重新抽奖。满背包丢弃、Active／NotAct、期限和技能前置等级沿用原有实现。

验证范围为静态审阅、Release编译和Lua语法检查；按用户要求不新增或运行测试，不启动本机服务或游戏。实机宝箱显示、拾取提示、三回合结束及返回大厅后的物品展示仍待玩家验证。
