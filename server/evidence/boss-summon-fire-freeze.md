# BOSS 请神断线、单格火焰与冰冻建设修复

## 本轮用户规则

- 非黑贝贝 BOSS 火焰技能仍为每可行动回合 20%，但每次只在全图合法空路随机放 5～7 处，每处一格；无放回选择，空位不足时少放。排除已有物件、角色、逻辑宠物和静态类型 28/58/61。
- 冰冻 BOSS 不建设、不升级自己的地产。尤其要覆盖移动落点刚踩中冰陷阱的情况，不能仅在轮首跳过行动。
- 仅修改服务端；不新增/运行测试、不启动本机服务或客户端。

## 线上请神断线根因

线上源码 d9b7cabaec1d、实例 3464-110534403540900 的日志显示：2026-10-11T17:40:17.275Z，请神卡 1047 将 npc6 附到 BOSS 后成功触发疯狂地雷，requested=5、placed=5；17:40:17.285Z 因 `lua_script_error:richonline_game_response_instance_mismatch` 关闭连接。

卡片与放雷计划已提交，外层 `Startup::output` 却把台词 600A 的 +2 台词组误作 game id。此前 Lua 卡片内部的特殊处理未覆盖外层发送门；黑贝贝 1-4 首次狂暴台词也经过同一门。

现在仅对精确的 600A（16 字节、组 1～7、索引 1～16、类别 1、有效合成 BOSS 槽、零填充）和 601A（8 字节、有效非负位置、单格火/清除形状）采用独立结构校验。其他消息继续校验 game id，所有帧仍使用本会话的 299 envelope。完整运行日志只保留于忽略构建目录，不随源码公开。

## 单格协议依据

`boss-fire-cells-client.json` 记录 29 个函数的完整 chunks 与磁盘字节核验；客户端 SHA256 为 `feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。

- 401C -> 65E590 -> 604C71/7CEF30 的 npc26 分支按 GValue26 半径扩散，因此不能将它当成单格火。
- 600379/694720 构造 601A。原火焰卡 677EE0 为每个合法格分别排入 8 字节 601A：+2 有符号位置、+4 npc、+5 owner、+6 timer，+7 未使用（服务器填零）。
- 7EECED 注册表项 AA6148，表基址 A8E0E0，索引正是 601A；60D362/7F15D0/600C8E 指向 67E370。网络默认队列 64F870 经 7BB290 使用同一分派表。
- 67E370 -> 604D66/7E2380 只写地图 +60 下的单格四字节记录前三字节，并通过 604C80/63E8C0 将第四字节置 1。它只为 npc12/27 注册地雷、为 npc28 注册雷神；npc26 不登记火焰计时表。
- 原火焰卡 677EE0 与区域放火 7CEF30 另外调用 6074D0/7E2D40 注册计时表。7E2F00 按存活 owner 回合递减，失效 owner 在锚点回合递减；到零调用 7E28B0 删除。
- 因此 BOSS 单格火新增对象元数据 `server_timed_fire`，在服务端轮首计算后用 601A 更新 timer 或用 npc/owner/timer 均为 255 清格。普通区域火焰不带该标志，保留客户端原生时钟，避免双重计时。
- 7C3220 从地图格 npc26 读取火焰伤害，不依赖火焰计时索引。7E28B0 删除火时查不到索引会直接跳过索引删除，仍清格；爆炸、清障后不会遗留服务端标志。战斗桥复制存活动态物件的完整对象；删除即移除标志，普通火焰在同格重新生成默认不带标志。
- 所有包、候选地面和消息容量先准备，再提交地面事务。单格倒计时包在 4010 后、基地攻击和掷骰之前发送；进入宝箱阶段仍由 420C 清图。
