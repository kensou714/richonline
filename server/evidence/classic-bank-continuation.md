# 经典多人银行暂停与原路线续接

本轮在上一轮经典整局会话内实际装配已有银行核心与 Lua 业务，并将共享上报汇合限定扩展到已核实的 `0028`。生产模式 0 仍未开放；这不是银行实机验证结论。

## 客户端只读证据

`shared-bank-report-client.json` 保存 25 个函数/跳板的完整伪代码、起止地址、窗口长度及 SHA256。每个窗口逐字节与当前磁盘 PE 对照一致，磁盘 SHA256 为 `feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。它不代表整个 IDB 与磁盘一致。未修改客户端、数据库或 IDA。

- `7F5D90` 中间步的银行分支：静态类型 9、`6059C8 -> 63E4D0` 的 P+1488 != 7、`60F5A4 -> 63E500` 的 P+1499 == 0、`605BEE -> 7D6F90` 的 G+83809 <= 0、`607098 -> 7D5E10` 的 G+83830 == -1。这里没有当前槽等于本机槽的门，也没有普通末端的 P+552 条件。
- 停步 `6057B1 -> 7F5D10` 将移动状态设 2、清像素进度。`604E51 -> 693CB0` 保存中途标志；`6098AC -> 6938F0` 写 WORD opcode 40，即 0028；+2 日历 WORD、+4 当前位置 WORD，发送 6 字节，经 `610977 -> 6BF380` 的公共通道。
- `6BF380` 检查主状态和连接资格，不检查当前槽等于本机槽。结合上一轮 `shared-movement-report-client.json` 同一磁盘版本的 4011/6010 公共动画生产链，普通、未受控的各真人客户端均会产生途中银行报告。
- `4018 -> 65E1B0` 只给 `609320 -> 63F760` 判定的本机行动者开 UI17；所有客户端均登记等待 16。完整包至少 8 字节，+6 为中途标志。
- `7BBE60` 构造 12 字节银行选择，在 `609320` 为真时才发送。0027 是行动连接的选择，不属于全员上报汇合。
- `402A -> 660320` 按当前行动角色修改现金/存款，清等待。中途恢复缓存的移动并自增路线游标；末端则续接本地 stage2。客户端不按请求号去重，服务器不得重复发送交易回复。

只读补充文档：`docs/逆向资料/专题/银行与资金/00_银行等待与回复闭环.txt`。本轮保留其静态证据边界，没有把旧文档的磁盘哈希混同为当前文件版本。

## 整局装配

`RichonlineSharedMovementWait` 末尾增加 opcode，默认 0011，保持既有四字段调用的行为。允许值只有 0011 和 0028。匹配指纹包含操作码、日历和位置；全体连接一致后仅将控制连接的实际请求交给业务一次。0012/002A 仍不自动汇合。等待期限仍从当前批消息全员完整发送后开始；缺少成员时失败，不补造确认。

经典会话通过显式 `bank_wire` 策略创建一份 `RichonlineGameBank`，复用 `bank.open`、`bank.transaction` Lua 及原有八秒选择期限。未提供该策略时银行仍拒绝，未命名 padding 不自行猜值。

4011 整条路线只生成一次。会话从尚未经过的游标开始找第一个中间银行格，公布 0028 等待；没有中间银行才公布终点 0011。收齐报告后只提交该检查点的位置/方向，清当前移动等待，广播一次 4018。期间仅当前行动连接能选择存取款；其他玩家的骰数偏好仍独立保存，不影响此次交易。

银行记录行动槽、日历、当前位置以及共享账本的余额和版本。结果必须与该待决完全一致。存取款、取消、金额非法/不足/溢出和超时共用已有银行核心验证及 Lua 回包复核，再通过账本版本提交。现金与存款转换不涉及大厅账号银行，也不写入持久账号余额。

中途 402A 后只把游标移到该检查点后一格，建立更大的移动段序号，等待下一银行或最后终点。保留同一日历和回合，不重新广播4011，不重掷骰、不重扣指定骰点卡。可连续经过不同银行，且不能提前用0011越过尚未确认的银行。

最终停在银行仍由0011汇合，先4013再4018，交易后执行落点收尾/岔路/换人。带地产引用的银行格仍明确拒绝。同格收尾在后续版本已接入，详见 `classic-phase6-continuation.md`，交易完成后才执行同格phase6。完整经典租金、状态、特殊格和结算继续补齐后才能开放生产。

已关闭银行登记行动者与日历，包含服务端超时，因此没有实际接收0027时也能识别迟到选择。新银行当前待决优先处理，不能全局去重吞掉合法的同额交易。原协议无交易/移动序号：同日历、同位置的重复经过以及同日历再次开窗时字节完全相同的历史交易，不能在网络层绝对区分；没有虚称解决这种不可辨识重放。
