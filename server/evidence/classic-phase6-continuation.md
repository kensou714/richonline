# 经典多人同格phase6与Lua决策

此前经典会话在落点遇到其他玩家时直接拒绝，无法走完普通多人同格路线。本轮把现有碰撞核心接入落点最后阶段，允许同格空道路、卡片格、已支持的地产选择和银行末端正常续接。生产经典模式仍未开放；新闻、租金、完整状态和结算等仍需继续补齐。

## 静态依据

`classic-phase6-client.json` 保存 `7CB050` 及十个相关跳板/实现的完整伪代码。各窗口逐字节与当前磁盘 PE 一致，记录起止地址、长度和窗口 SHA256；客户端整体磁盘 SHA256 为 `feeeac1bf9605690e8a774452456320125d7d3dbaa2dc73d529f8230c0677bc7`。不据此断言整个 IDB 一致，未修改客户端或运行游戏。

`7CB050` 是本地 stage6，在静态格和地产阶段后运行。它先处理同格手牌效果，最后才按路口及控制状态决定是否生成岔路选择。`608B14 -> 727B70` 检查 P+1488 == 6；只有非合成当前角色触发。按角色槽递增遍历，目标须激活、非合成、非本人、同格且 `60274B -> 63EFB0` 的 P+1497 == -1。

`5FF15E -> 7F8E10` 从八格手牌中选择第一个非空槽；`6091AE -> 7F86A0` 读取该卡号。构造的两条本地6061分别消耗来源一张、向当前角色增加一张。这些是客户端本地事件，不应再另发网络转移包。既有碰撞核心及 `RichonlineChanceResources::add` 已保存来源扣卡、满手插入失败和合成顺序，本轮复用，不改为现实游戏直觉中的“满手不扣来源”。

## 会话接续与状态

经典会话创建一份 `RichonlineRawAuthority`，沿用已有客户端初始化镜像，分别记录各角色的原始1497字段及全局83830字段。当前角色开始时只执行该角色的原始状态时钟，4011提交时记录移动开始，退出时失效原始权威；没有把每次消息当作全体角色计时。

落点进入时先核实原始状态已知、全局脚本事件未抑制此阶段、每名角色附身值在有效范围内。回合模块的 optional 空值表示未知，不能当作无附身；只有明确的有符号 -1 才转为碰撞核心约定的无附身值。

为保持真实占格，`occupied_by_other_actor` 不清零，`collision_resolved` 不伪设为真。新增 `phase6_collision_authorized` 表示经典会话已验证原始状态并承诺在收尾执行phase6，不表示效果已经执行。公共卡片格在模式0下接受这个明确授权，BOSS既有占格门保持原行为。

进入落点挂起一次phase6。购地/升级选择、特殊业务等待和银行末端交易期间保留它；途经银行不执行phase6。只有业务明确 complete 后，才从最新的全体库存和位置准备同格变化，在同一对局锁下复核并统一提交。完成后清除待决，再等待岔路选择或换人。重复完成会拒绝，不会因岔路轮询或重复0011再次转移手牌。

## Lua与核心分工

`scripts/game/collision.lua` 独立选择同格转移意图，通过 `collision.plan` 注册：按真人槽顺序，每个符合条件的目标取首个非空卡槽。它返回来源、目标、来源卡槽、卡号，以及是否允许继续判断岔路，不发包、不写账本或库存。

C++核心用已认证快照独立核对完整结果、整数身份/卡号和次序，再按已有资源插入/合成规则准备最终库存。所有角色的库存计划及Lua结果通过后才提交；脚本错误或返回差异不会提交这一轮同格变化。原静态格或地产阶段已提交的业务不因此变成可回滚事务。

当前经典会话尚未接入附身获取及完整状态迁移，因此不能把本轮称为线上状态6/神明玩法已开放；本轮补的是普通同格放行、既有同格核心的整局接入及其Lua业务边界。

## 验证

静态审阅覆盖普通无转移同格、状态6多目标顺序、来源空手、首槽多张、目标满手与合成、地产/银行等待后收尾、岔路后不重复执行、原始字段未知时拒绝，以及Lua验证先于库存提交。Release编译和全部Lua语法检查通过；按用户要求不新增/运行测试，不启动本机服务或游戏。后续部署只核验版本和监听，不将其当作玩法实机验证。
