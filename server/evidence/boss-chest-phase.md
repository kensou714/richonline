# BOSS 胜利宝箱（服务端实现）

## 原始协议与资源依据

- NEW RnClient `67C5E0` 消费 `420C +game:u16 +position:i16`，通过 `7CF6A0` 清动态物并设 `game+83830=2`，生成 NPC32，发 C2S0002。没有额外字段读取。
- `7F91F0` 清12种攻击卡；`7F9560` 清1496/1498/1499/1500/1501/1502及关系；清附身、定时炸弹、建筑攻防绑定和效果倒计时，保留医院/监狱及装备免疫。
- `7C3220 case32` 返回0等待服务器，不在客户端发奖。`7F5D90`的NPC30分支是香蕉皮，不是途中拾取宝箱。服务端在经4011验证的0011最终落点处理拾取。
- `7E2B80 ->7E28B0 ->7ECAF0`保留NPC32；同步修正净空卡的C++和Lua实现。
- `67C740`消费420D的技能索引、级别和丢弃标志；`67D1C0`消费4211的物品ID、未激活及丢弃标志。两者只提示，物品必须独立入库。
- BossWar的dropBox独立于firstProp/againProp。Active、NotAct是物品；Yan/Pao/Chang/Zhong/Kong/Mi/Ba/Shan/Zhao/Shou是技能0..9。第三字段为相对权重；BS_1_1十项权重总和111，不能视为百分比。

## 状态和持久性

1. BOSS死亡时先按原有结算事务锁定胜利。新增bonus阶段只放行outbox前缀400E，其余400D/401B/400F/大厅58等待。
2. 随机选一个非玩家所在的连通道路格，清动态物和已核实状态，发420C。只接受第一次0002开启奖励回合。
3. 保留原anchor1、只轮到真人0。客户端`7C0C50`仅current==anchor时递减本地2次计数；服务端独立数满3次完成回合，避免客户端第二次递减到0停止掷骰。这是服务端兼容策略，不宣称恢复了原服务器算法。
4. 奖励阶段跳过基地、BOSS行动、普通静态落点/地产/碰撞、节日和NPC刷新。仍使用验证路线、银行途经跳过、成对传送路径和末端方向。开放普通/付费骰子、遥控骰、固定步数、洗牌及净空卡，其余战斗/地产卡恢复控件并拒绝。
5. 拾取时按原始权重抽一次；第三次移动落到宝箱仍优先得奖。没拾取则第三次回合完成后释放结算。重复0002和已记录0011不重开回合或重发奖励。
6. `game_boss_chests`绑定已提交的win及角色/关卡；固定`:chest`操作键，一次事务写奖励、库存和审计。满仓记录丢弃，重放不重新抽奖/补发/延期。断线保留已提交胜利；尚未拾取的宝箱不自动发奖。
7. 大厅58后的资料刷新同时给当前连接发送新增物品77；连接进入频道时记录领取游标，登录/进频道已有背包不会重复添加。凭inventory_id查仍存在的实际实例。

## 期限及技能兼容政策

- 免费奖励使用Prop的yearP/monthP/dayP，保留Active/NotAct。使用数据库当前日期版本；旧2005纪元无法表达当前日期时，键不塞伪日期，数据库保存真实UTC到期时间。库存展示、装备及开局均按expires_at验证；旧客户端日期显示不完整，不视为永久奖励。
- 技能按角色、索引、级别持久保存；下一局只提升连续已获得的等级。现有全7级默认设置不改，已有等级不下降；越级奖励保存待前置等级齐备。
- 常规firstProp/againProp仍是独立的既有结算奖励，不借用该入口发宝箱。

## 验证边界

按用户要求仅静态取证、代码审阅和编译，不新增或执行测试，不启动本机服务/客户端。需要用户真机确认420C后3次掷骰、落点领奖、满背包提示及返回大厅背包显示。伤害不同步导致BOSS回1血尚未确认根因；新增逐次飞弹命中现金/存款/攻防/淘汰日志用于后续定位，不宣称此问题已修复。
