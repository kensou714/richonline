# 嫁祸卡1056的经典租金接续

本轮实现7CD090的type0租金等待：4013触发客户端608C/UI27，原付款人提交0076，服务端广播40C6，再进入地产附加效果及同格phase6。支持选择其他玩家、选择地主、取消和服务端超时取消。只覆盖局内八槽手牌，不把type1/2的其它支付或type3陷害入狱混进来。生产经典模式仍关闭。

## 协议与证据

`classic-rent-transfer-client.json`保留当前RnClient的SHA以及15个相关函数的磁盘/IDA窗口一致性。只读既有40C2专题明确未审type0，本轮补查6712B0的两张switch表及60A298调用前的ECX来源，不从type3推导租金。

- `7D6050 / 7BC100`生成六字节0076：+2日历WORD、+4 signed目标BYTE，+5未赋业务语义。-2只是客户端内部“查首个合格对象”的参数，在线请求是实际槽或-1。服务端拒绝-2和越界槽，不回显padding。
- `7174B0`的UI27只允许激活的前四槽，排除原付款者和hotel1493/hospital1494/jail1495/kidnapped1497非-1的对象。地主可选，冻结和梦游没有额外排除。服务器按同一权威状态生成资格列表，未知原始值不当作正常。
- `681D30`按缓存的原付款人是否本机开UI27；此type0的付款人正好是当前行动者。只有该认证连接可以确认，不能让选中的代付者确认。
- `6712B0`校验GmsvID、清等待并关闭UI27，只读取回复目标+4。服务端发送完整已知五字节40C6，不伪造响应+5的语义或声称捕获过原服务器包长。
- 取消分支type0：不扣1056，对原付款人的现金+存款夹取缓存金额，再给地主存款、扣原付款人现金/存款；余额严格大于金额才排6080(2,5)。
- 成功分支type0：先扣原付款人的1056，对新付款人余额夹取缓存金额，再给地主存款、扣新付款人；不会重入7CCE60/7CD090，不递归检查新付款人的免费卡或嫁祸卡。
- `6080 -> 681380 -> 7C6640(a4=5)`仅调用地产附加效果；不能再发4013或重新走租金入口。之后才允许phase6与换人。

`7BB530`的客户端托管按随机值选择-1或-2，UI取消717650则明确提交-1。本轮服务端超时采用显式decision_timeout后取消，不声称复制了客户端托管概率或原服务器超时策略。

## 状态与原子提交

会话保存原付款者、地主、地产状态、落点、日历、递增回合序号、未夹取租金、全部余额版本、候选资格和原手牌。打开UI只发送4013，不扣卡、不扣钱。收到选择或超时时重新验证快照，保留此前确定的租金，不重新报价。

`plan_richonline_rent_transfer`只准备资金步骤、剩余库存和40C6，不提交。`cards/card_1056.lua`的`rent`提供独立业务决策，C++核对完整结果和整数类型。随后会话通过一次`ledger.commit_sequence`提交全部资金步骤，并在同一事务的无分配回调中提交剩余手牌。取消保留卡片，成功只扣一张。

地主作为代付者时，收款和付款指向同一个人。第二步使用已入账的存款和更新后的版本，遵守先收存款再扣现金的顺序，也保留账本的逐笔正收入计数；不能简化成一笔净零转账。例：地主现金12000、存款5000，租金10000，最终现金2000、存款15000，总资产17000不变。

40C6已触发客户端6060/6061，不追加任何扣款或扣卡包。已结束等待按原付款人和日历保留有限历史，超时后没有实际请求也能吸收合法迟到0076；当前等待始终优先。原协议没有序列号，不能保证区分日历回绕后字节相同的历史重放。断线清理待决并关闭整局，不伪造取消或扣卡。

## 尚未完成

资金耗尽后的部分退场已接入，见`classic-bankruptcy-continuation.md`：淘汰后仍至少两人活动时提交40C6和400E，按原行动者是否存活决定继续落点或换人。最后存活者可由显式全员结算器接管，见`classic-settlement-continuation.md`；未配置该结算器及月限边界仍在资金和手牌提交前拒绝。第二套自动卡依然要求库存业务提供权威证明，关系卡和其它type暂不开放。原协议成功嫁祸可能清除同盟关系，但本经典会话尚无同盟写入口，不能把这一边界当作完整同盟系统。
