# Original game admission and startup

The `richnet_original_game` C++20 library implements the original client's game connection boundary. It is separate from the other client's redirect and does not turn on the manager's `gameReady` flag. It is not a complete game strategy or a production BOSS listener configuration.

## Calling contract

1. Construct `OriginalGamePlan` with explicit initialization, snapshot, envelope policy and both strategy callbacks. Unknown game double/header/record-tail/envelope-tail values must be supplied explicitly; the encoder does not silently invent zero defaults. Calendar, player count/local slot, directions, tile signs, snapshot count/instance agreement, scale and encoder limits are checked.
2. `OriginalGameRegistry::prepare` validates the plan and exact human wire ID, creates unpredictable redirect values, and stores a bounded, expiring reservation keyed by its owning lobby generation. The owner must be nonzero and unique per live reservation. A replacement invalidates the old descriptor. Lobby configuration, leave, cancel-ready and disconnect must call `cancel(owner)` when integrated. Room-ID reuse must not reuse a stale generation.
3. The returned S2C22 contains IPv4 bytes, little-endian host port, A/B/C. The exact expected32-byte GameServer C2S0 is room/game/user/B/C/A/0/0. A is limited to nonnegative signed32 as required by7961A0. The registry consumes the whole descriptor once, including the version-specific final constants; incorrect fields do not consume another player's reservation.
4. Pass a provider backed by `registry.consume` to `make_original_game_callbacks` for each connection, and use `GameService` with `ClientVersion::legacy`. The callbacks are connection-local. An accepted plan emits4000. C2S1 is a repeatable two-byte initialized/heartbeat signal. The first two-byte C2S0 emits4004, then invokes `map_ready` once. Repeated0/1 do not reset context or replay opening rewards.
5. `action` receives decoded client bytes only after map-ready. Context-bearing operations must match the current low16 action counter. C2S2 is a separate event callback without a context word; it is not used as a heartbeat or automatic turn acknowledgement. C2S10 requests connection closure after map-ready. The strategy must validate opcode-specific lengths, decisions, turn ownership, board rules and pending events; this boundary does not fabricate responses for unimplemented actions.
6. Returned strategy plaintext is encoded through the original299 envelope with independent BCrypt filler. Downlink instance IDs must match, snapshot scale must be positive, and turn slots must index the supplied player list. A4004 resets the tracked action context; normal4010 increments it with low16 wrap. IDA confirms this increment on the active game path; strategies must send terminal settlement rather than4010 after alive_count<2 without the client's special continuation state. Delayed/nonzero4010 branches are not counted as an immediate increment.

`OriginalGamePlan::disconnected` is cleanup for a consumed game plan, including startup validation or strategy failures. It executes at most once. Pending cancellation/expiry/replacement destroys unexecuted strategy closures and their RAII captures; it does not simulate an active player's departure. A future provider must not allocate an externally registered match during prepare without a separately owned cancellation lifetime. Registry operations are mutex protected; session callbacks run on the game service thread. Lobby state mutation from that thread will require queued generation-checked events, not direct room-directory access.

## Evidence and remaining integration

Protocol sources: `protocol-analysis/ORIGINAL-NATIVE-STARTUP-RECHECK-20261009.md`, `GAME-LOBBY-ENTRY.md`, `GAME-STATE-MACHINE.md`, `GAME-CALENDAR.md`, and original handler instructions. Every opaque byte is preserved in tests with nonzero fixtures; preserved fields are not claimed to have recovered meanings.

The reservation and typed startup components are intended for the native BOSS strategy. Production integration still requires map-backed spawn/configuration, rewards and objects, BOSS-first turns, all card/landing/timeouts and terminal/lobby-return events. Native callbacks with a synthetic strategy prove transport and ordering, not an actual playable board. The original4000 double and any remaining fields must be resolved or backed by explicit reviewed original policy before enabling real-client startup.
