// 4052：共享日期三字段写入与后继显示
// ============================================================================
// 7EFF90转发662DC0；校验GmsvID后以ECX=G+0xC44调用694320。
// 读取下界8字节；没有消息长度、年/月/日合法性或范围检查。
//   +4 signed WORD -> WORD[C+8]  = WORD[G+0xC4C]。
//   +6 signed BYTE -> BYTE[C+10] = BYTE[G+0xC4E]。
//   +7 signed BYTE -> BYTE[C+11] = BYTE[G+0xC4F]。
// 694320只进行三次窄写入；不清C+4的行动/同步值，也不修改其余字段。
// 本处理器没有队列、睡眠、回合续接、pending清除、动画或确认消息发送。
//
// 字段命名依据
//   7D90E0读C+8 signed WORD；727A70读C+10 signed BYTE；727A90读C+11 signed BYTE。
//   7D8E60用这三个getter将年份、月、日传给7D8DE0。
//   7D8DE0索引(year-2004)*26，每年13条两字节月/日记录，命中返回0..12，
//   否则返回-1。7D8E60将结果转成“存在日期记录”的布尔值。
//   这条索引规律与UI双位显示共同支持“年/月/日”命名。
//   表究竟是节假日、活动日或其它特殊日期，需要读取表的初始化及资源才能确定。
//   年份范围未在此钳制，date table单例6288B0只见分配0x340；不能据此推定所有年合法。
//
// UI消费者7080D0
//   先取G，再经63E590取得C；7D8E60命中时图集基号由5换为65。
//   月、日分别用sprintf("%02d")格式化，各只读取字符串前两个字符。
//   减'0'后加图集基号，从资源组10获取相应图像，写入控件81/82与83/84。
//   同函数另将DWORD[G+83804]转为两位文字，写控件85/86；本批未命名该数值。
//   这证明日期有后续显示消费者，不能证明每次4052到达时立即刷新UI。
//   负值或超过两位的值会偏离正常数字显示预期，处理器本身未拒绝这些输入。
//   本批没有为Buffer采用伪码132字节容量结论，未单独核RTC描述。
//
// 搜索边界
//   field_scan.json仅是0x620000..0x900000已声明函数中汇编文本含
//   0C4C/0C4E/0C4F的候选扫描；命中6C0E50属于另一对象，不能归入G日期字段。
//   实际消费者经C+8/+10/+11的getter访问，纯G绝对偏移搜索会漏掉它们。
//   未声明范围7E29DC也使用63E590，未作为已分析函数计数。
//   其余C getter调用者与后续游戏日期事件仍需单独分析，本篇未宣称全程序写入源穷尽。
