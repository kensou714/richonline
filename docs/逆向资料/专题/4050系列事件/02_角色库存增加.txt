// 4051：向角色group0增加一个ID，flag非零先清槽0
// ============================================================================
// 7EFF70以ECX=G转发662D00；原伪码的stdcall及全局调用省略了实际this来源。
// 读取下界8字节；校验packet+2后才执行下列步骤。
//   +4 signed WORD：新ID。
//   +6 signed BYTE：角色槽号，取P=DWORD[G+0xE00+4*slot]。
//   +7 BYTE：非零时先清group0第0槽；零值不清。
// handler没有本地角色过滤，也不检查+6范围或P空指针。
//
// +7非零的顺序：662D48..662D7C
//   7F8710(P,0,0)读取signed WORD[P+1522]即group0槽0数量。
//   7F8920(P,0,旧数量)执行WORD数量减法；结果signed<=0时数量置0、ID置-1。
//   这里只选择槽0，没有按新ID搜索原槽，也没有清空整个八槽表。
//   数量减去自己得到0，所以正常顺序确实释放了第0槽。
//   7F8920按P+1404指向对象的+8与DWORD[P+1408]比较，符合才通知UI12更新。
//
// 增加：662D81..662D9C
//   7F8780(P,signed ID,1)扫描8槽，找到第一个ID=-1的位置，写ID和数量1。
//   不合并同ID数量，也不保证写槽0；flag为0且八槽已满时无插入。
//   插入后可能刷新本地UI12，再调用800FD0自动合成，必要时再次刷新并显示合成文字。
//   UI通知经6E4640调用槽对象vtbl+0x10，文字通知经6E46D0调用vtbl+0x1C。
//   表管理器、UI槽和P+1404的精确生命周期另见已有专题。
//
// 自动合成的可见边界
//   800FD0处理60字节配方记录，输入库存是P+1520的8个6字节记录。
//   材料匹配计数按“匹配ID的槽数”累加，非直接累计槽内数量。
//   被选材料槽写ID=-1/数量0；倒序清槽留下的最低选中槽写产物ID/数量1。
//   配方/产物有效性检查及资源装载不是4051载荷的一部分；详见商店与购买流程。
//
// 返回与通信
//   7F8780通常返回插入成功标志，但P+1416非零时末尾可直接返回1。
//   所以返回1不是单独的“已入库证明”；662D00也没有处理失败、回滚或重试。
//   本handler及已查库存/合成链没有直接调用6BF380发送消息。
//   未见600x回合续接、pending写入、玩家选择等待或动画队列申请。
//   间接UI消费者未穷尽，故不外推成“整个游戏永远不会因库存更新发包”。
