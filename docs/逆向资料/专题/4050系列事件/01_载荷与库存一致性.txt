// 4050：库存ID一致性检查，不是库存快照覆盖
// ============================================================================
// 7EFF50以ECX=G将packet转交662BF0；662C1F调用64F710检查packet+2 WORD。
// 64F710比较WORD[G+0x14784]，不符弹出MessageBoxA("Error GmsvID")并返回0。
// 三个handler均使用这一门槛；弹框后的返回不能当成消息已成功执行。
//
// 载荷读取
//   +0 WORD      操作码归属由分派表确认，本handler不重复读取。
//   +2 WORD      GmsvID校验值。
//   +4+16*i+2*j  signed WORD：角色i的group0第j槽ID，j=0..7。
//   i=0..signed DWORD[G+0xE20]-1；人数<=0时不进入比较。
//   读取下界为4+16*N，N为正人数；这里不验证消息长度或N上限。
//   角色指针取DWORD[G+0xE00+4*i]；未在此检查槽号、空指针或人数<=8。
//
// 比较位置
//   662C6C..662C7F：push group=0、push j、ECX=P[i]，调用7F86A0。
//   7F86A0返回signed WORD[P+1520+6*j]，与signed WORD载荷比较。
//   它也支持group1=P+282、group2=P+330；4050固定选择group0。
//   每个6字节记录还有数量及未命名字段，4050只比较ID，不比较数量。
//   全部相同不修改角色库存、UI、pending或行动状态，也不发确认消息。
//
// 不一致分支：662C9C..662CDB
//   6942F0把局部两字节对象首WORD写为0003；6BF380接收地址及长度2。
//   因而错误载荷只有操作码0003，没有本处填写的角色、槽号或GmsvID。
//   6BF380还检查主状态<12及A76724单例对象首字节非零，才包装并交付事件9。
//   该首字节的完整语义未闭环；调用不证明已上网。
//   随后Sleep(1000)，再调用_assert("0",源路径,10046)。
//   这条分支不申请玩家选择，不排入动画队列，也没有“等待服务器纠正”状态写入。
//   它同步调用睡眠和断言；不能把卡住现象一概归为缺少4050确认回复。
//   若断言返回，控制流继续下一个j，每个不一致项可能再次报告/睡眠/断言。
//   断言弹窗、终止或调试器行为取决于CRT/运行现场，本批没有实机验证。
//
// 开发用途
//   服务端若发送此消息，应该按角色顺序提供每人8个group0槽ID，空槽为-1。
//   该消息不能补齐缺失库存；修正数据需使用真正的库存写入消息。
//   应同时记录人数、消息实际字节数及本地ID表，诊断0003前后的差异。
