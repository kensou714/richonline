// 4043通知队列：补齐构造、容量、出队和销毁
// 本篇是26函数首轮之后的追加分析；独立审阅范围须单独辨认。
//
// 对象布局与初始化
//   7BAE60在G+0x18调用7D5C50，组成8字节计时器和20字节二元队列。
//   T=G+0x18：DWORD阈值、DWORD起始tick。
//   Q=G+0x20：DWORD基址/模数/数量/读索引/写索引，共20字节。
//   7D5C50先经81BC80→81BCB0设阈值30并取GetTickCount，
//   再以ECX=T+8调用7D7F50，仅把Q基址清0；此时并未分配记录区。
//   游戏初始化64F2A0在64F5C4..64F5DC把T阈值重设3000，
//   同时以参数8调用697E10初始化Q，分配8*8=64字节并清计数与读写索引。
//   这是8个物理位置，满判据预留1格，所以最多同时保存7条。
//   不能把构造时30误写为游戏运行时的通知消费间隔。
//
// 入队与丢弃边界
//   4043→662A70→697EA0写入signed(packet+4)、signed(packet+5)两个DWORD。
//   判满时返回0，不覆盖最旧记录；本处理器没有重试或延迟入队分支。
//   本地入队失败是否会被更外层处理，尚未见协议补偿证据。
//
// 消费路径
//   游戏更新64F780最后在64F856调用64FBD0，ECX为G。
//   先用6952D0比较Q的read==write；为空立即返回，不更新计时器。
//   非空再用81BD10检查T；需要now>last且unsigned(now-last)>=threshold。
//   到期时再次取GetTickCount写回last。每次调用只弹出1条，不追赶遗漏的多个周期。
//   GetTickCount回绕后的now<=last会挡住本次消费，不能只用无符号差值解释它。
//   697F30保存旧read，推进read，减count，将旧槽两个DWORD复制到调用者8字节局部。
//   pop自身不判空；这里的安全前提由64FBD0的外层空检查提供。
//
// UI通知转换
//   64FBD0将出队二元记录转为24字节UI通知：DWORD[0]=8、[1]=第一值、[3]=第二值。
//   [2]/[4]/[5]未业务赋值；不能把第二值错放为[2]。
//   接着调用6E4640通知UI槽0的vtbl+0x10，与4041的通知值2共用桥接。
//   出队发生在槽0非空检查之前；槽0不存在时桥接不调用UI，已经出队的项不重新放回。
//   槽0实际业务、通知2/8的具体含义仍须继续追消费者，不在本篇凭名称猜测。
//
// 销毁与初始化边界
//   7D5CA0以T+8调用7D7F80→7D80B0；若Q基址非空，delete[]后置空。
//   7D80B0被自动误命名为COleDispParams析构，实际应按调用点和指令描述。
//   697E10本身未释放旧基址；重复初始化是否总由外层销毁隔开，尚未闭环。
//   malloc/new失败语义、跨线程并发生产消费、G生命周期其它分支未在本组分析完成。
