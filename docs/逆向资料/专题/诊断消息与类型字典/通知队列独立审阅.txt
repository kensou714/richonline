// 独立打开IDA租约，重新解析当前RnClient.exe的PE节表映射。
// 当前磁盘SHA-256：
// a23410e79637e312c932f861176d8d81cd1fd5d222a286f279feccdece6263c2
// 三份原证的15个函数及跳板共103段，原证/当前磁盘/当前IDA字节全部一致。
// 另独立检查64FC63的RTC头及64FC6B的两项描述，磁盘与IDA一致。
// 复用首轮已核验的697EA0、6985D0、698610、6279C0、6E4640依赖原证。

// 构造、初始化与容量
// 7BAE8F执行add ecx,18h；7BAE92才调用经6075F2跳板到达的7D5C50。
// 7D5C50向81BC80传30，再经81BCB0写阈值与GetTickCount起始值。
// 队列构造传this+8给7D7F50；后者仅清首DWORD，不代表队列已可用。
// 64F5C4..64F5DC重新设置计时阈值3000，并向G+20队列传初始化参数8。
// 697E10设置模数、清数量及读写索引，申请8乘模数的记录区。
// 6985D0按read==(write+1)%modulus判满，697EA0在满时返回0且不写槽。
// 因此物理槽8、有效容量7成立；不会覆盖最旧项，也未见该处理器重试。

// 非空检查与时间门槛
// 64FBD0先以G+20调用6952D0；read==write时直接走退出路径。
// 空队列不会调用计时检查，也不会在此更新last。
// 非空时以G+18调用81BD10；81BD43的jbe拒绝unsigned now<=last。
// 81BD53的jb拒绝unsigned(now-last)<threshold，等于阈值允许继续。
// 到期后第二次调用GetTickCount并覆盖last；不是last+=threshold。
// 因此每次调用最多消费一项，不累计补发错过的周期。
// now回绕后若不大于last，本次会被拒绝；正文没有误当成纯差值计时。

// 出队与通知布局
// 697F30保存旧read，再以698610推进read、递减count，拷贝旧槽两个DWORD。
// pop内未检查空队列；64FBD0的外层检查是此路径的前提。
// RTC两项分别是栈偏移-16/大小8和栈偏移-48/大小24。
// 反编译数组长度包含保护间隔，不能据此把局部对象写成16/32字节。
// 64FC1E、64FC28、64FC2E依次业务赋值通知DWORD[0]=8、[1]=x、[3]=y。
// 通知[2]/[4]/[5]没有业务赋值；调试栈填充0xCCCCCCCC不构成协议字段。
// 64FC19出队早于64FC3E进入6E4640；桥接传入槽索引0与通知地址。
// 6E4640在锁内检查槽对象，并同步调用vtbl+0x10；槽对象为空则跳过调用。
// 本路径没有重新入队动作，故空槽会丢弃已取出的项；通知8业务含义仍未知。

// 销毁和证据边界
// 7D5CA0把this+8交给7D7F80，再原样传给7D80B0。
// 7D80B0仅在基址非空时delete[]并置空，没有重置模数、数量和读写索引。
// 697E10没有先释放旧基址，正文保留重复初始化生命周期未闭环是正确的。
// 64F2A0、64F780、7BAE60只核验相关调用点，清单没有提升为整函数完成。
// 并发、分配失败、UI消费者业务、实际服务器包序列及实机效果均未由本次证明。
