// 响应头与正文
// ----------------------------------------------------------------------------
// 8BA950在阶段1读取两个DWORD：type和L，当前header存于连接+0x18。
// type通过无符号比较要求<3；L分别以A3023C最小表和A30248最大表检验。
// type 0：44 <= L <= 3644；正文=DWORD标量+36字节固定记录+DWORD count
//         + count*36字节数组。标量、固定记录和数组分别写不同缓存实例。
// type 1：4 <= L <= 4404；正文=DWORD count+count*44字节数组。
// type 2：L == 4；正文DWORD保存为ACBD68。
// 两DWORD响应头不含在上述正文长度中；不能把响应上限直接套作请求包长度。
// header门通过后分配16字节reader对象及L字节正文存储，保存到连接+0x28。
// 接收正文完成后才消费数据。正文构造失败的外部异常路径尚未闭合。
//
// 接收结果与游标边界
// ----------------------------------------------------------------------------
// reader阶段中recv返回0，或返回-1且WSAGetLastError==10035，都会返回1。
// 本地返回1代表泵继续保留连接；不能把recv==0翻译为本函数立即报错。
// 其他-1返回0，交给8BB2E0失败路径；一次响应结束后写连接阶段3。
// 阶段3不同于四类型队列通道的回到阶段1，不在此推导持续多响应契约。
// 8BAF70只是返回reader+4当前指针；8BA830只推进游标，未比较剩余长度。
// 8CC740取当前DWORD后推进4字节，亦无剩余门；原证复用整数键树专题。
// type0和type1数组循环均重新读目标count并用无符号j<count条件继续。
// 固定复制分别rep movsd 9次和11次，再推进正文游标36或44字节。
// 当前已审路径没有独立count<=100或数组总字节不大于剩余正文的比较。
//
// 值区与共同约束
// ----------------------------------------------------------------------------
// ACBD94的既有树契约：mapped是100*36字节记录+DWORD count，共3604字节。
// 节点分配3624字节，mapped=N+16；N+3620 color，N+3621 isNil。
// type0 j==100从mapped+3600开始复制36字节，首先覆写count和树标记，
// 第9个复制字节开始越过节点分配边界；后继循环条件又读被覆写的count。
// 此为机器码可达的畸形正文路径，未启动游戏复现，未确认可利用性。
// ACBD70是另一个树实例；reader写其mapped+4400 count和44字节记录，
// 不能用ACBD94的节点尺寸、红黑标记位置和构造函数替代该实例的证据。
//
// 合法发送端须同时满足容量和长度，不能只满足header长度上限：
// type0：0<=count<=100，L=44+36*count。
// type1：0<=count<=100，L=4+44*count；100容量由8BD060构造参数补证。
// type2：L=4。
// 这组式子是兼容发送建议；当前客户端没有实现对应联合校验。
// count=0跳过数组复制；旧缓存其余记录不因此统一清零。
// 对未知记录字段应保留原宽度和顺序，不凭步长给文本、名次或业务命名。
