// ============================================================================
// 三类型结果请求与容器 / 请求头、缓存门与单连接替换
// ============================================================================
// 原证：bounded_raw.json六入口及dependency_raw.json十三依赖。
// formal_functions.json仅对前者作字段适配；源SHA和JSON Pointer可逐字段复核。
// 本篇只描述该独立TCP通道，不能将0/1/2类型当游戏主队列消息号。
//
// 三种请求包
// ----------------------------------------------------------------------------
// 起始是两个BYTE：+0=0D，+1=0A；+2为小端DWORD type，+6为DWORD key。
// 8BB970构造type0，8BBC60构造type1，8BBF10构造type2；初始key均FFFFFFFF。
// type0与type2另有+10起32字节区，构造时memset为0；type1只有10字节头。
// 8BB700 / type0 / 42字节 / key+32字节Source / ACBD94缓存命中则跳过发送。
// 8BBA00 / type1 / 10字节 / key / ACBD70缓存命中则返回1，跳过连接替换。
// 8BBCD0 / type2 / 42字节 / key+32字节Source / 无对应缓存命中门。
// type0与type2的Source用strncpy(...,32)，满32字节时不保证NUL终止。
// 不能因构造时预置0就保证最终文本终止：strncpy可能覆盖整个32字节区。
// Source的编码、业务用途和允许字符尚未恢复，不命名为角色名或排行榜字段。
//
// 新连接建立顺序
// ----------------------------------------------------------------------------
// 8BBA00与8BBCD0先构造栈上请求并写key；存在ACBD64时flags=1删除旧对象。
// 此时没有先将全局置0。随后new 44并调8BA510，再将返回对象写ACBD64。
// new 16并调8CC5D0(10或42)，该reader放入新连接+0x0C，再append整个请求。
// 8BBCD0在append之后才ACBD68=0，保留append返回EAX；不是发送前清结果。
// 8BBA00的缓存命中返回1；其他路径返回append结果，不能统一解释为发送成功。
// 零new路径会写0，但后继仍解引用连接；当前正文没有完整空指针恢复门。
// 两入口异常尾块仅释放相应临时new内存；不在此声称全局对象状态自动恢复。
// 该通道同时只有一个ACBD64槽，第二请求会替换前一连接，不具请求队列语义。
//
// 44字节连接对象
// ----------------------------------------------------------------------------
// +00 DWORD socket / +04 DWORD event：事件泵写入，8BA510未见初始化写。
// +08 BYTE 建立流程标志，初值0；+09..+0B填充未恢复。
// +0C DWORD 发送reader指针，初值0。
// +10 DWORD 接收阶段，初值1；+14 DWORD 当前响应类型，初值FFFFFFFF。
// +18..+27 内嵌16字节header reader，构造容量8。
// +28 DWORD 正文reader指针，初值0；对象总长由请求入口new 44核对。
// 这里的阶段初值、嵌入位置来自构造正文；socket/event不能推为已可靠置零。
//
// 从原请求取type与key
// ----------------------------------------------------------------------------
// 8BA7B0取ACBD64->+0C，8BA880令cur=base，8BA830跳过2，再8CC740读DWORD。
// 8BA8D0相同，但跳过6，读取原请求key；最终游标分别到+6和+10。
// 两函数没有全局/发送reader空门，也没有独立容量检查；它们不是close函数。
// 接收type0/1用8BA8D0取得缓存键；失败通知用8BA7B0取得请求类型。
// reader读取会改变共享发送游标，不能描述为无副作用查看器。
//
// 局部UI使用关系
// ----------------------------------------------------------------------------
// 754110的754162/754171/754183窗口以this+48相同key依次请求type1、取指针、取count。
// 这里只证明三调用及相同键；整段UI生命周期、指针有效期和索引边界未恢复。
// owner755290局部块：75580E push A842D0作为type2 Source；key取
// A85A10+[this+50]*84首DWORD；前驱将UI读值strncpy64到A842D0，首BYTE非0才进块。
// 64字节复制上游与42字节请求的32字节Source是两层截取，均不额外推文本身份。
// 真实文本身份与操作名称未知，禁止把UI105或文本1054直接命名成榜单。
