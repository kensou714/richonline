//
// [与已知通信专题连接]
// 辅助连接 ACBD64 经 8BA950 收取结果；类型 0 包长常量范围 44..3644。
// 格式为 DWORD 标量、36 字节固定记录、DWORD count、count * 36 字节数组。
// 本专题不重复其整个收包状态机，只审 type 0 写入 ACBD94 的边界。
// 8BB700 的查重请求接口只导出保留，未新增请求协议的完整语义结论。
//
// [真实机器码写入]
// 8BAC71 ECX=ACBD94；8BAC76 调 61195D -> 8BC3A0，
// 8BAC7B 将 reader 取得的 DWORD 写 mapped+0xE10（3600）。
// 8BAC97 / 8BAC9C 再取同一 mapped，8BACA4 比较 j 与该内存 count，
// 8BACAA 用无符号 jnb 结束，没有与 100 比较。
// 8BACBF / 8BACC4 再取 mapped，8BACCC j*0x24，8BACD8 rep movsd 复制9个DWORD。
// 8BACE4 推进 reader 36 字节；8BACE9 回到 ++j。
//
// [reader 契约]
// 8CC740 经 8BAF70 直接取 reader 当前指针并解引用 DWORD，随后 8BA830 游标+4。
// 8BAF70 只是返回 reader+4 字段；8BA830 只加游标，没有剩余长度或边界比较。
// 本轮闭合上述读取原语；更外层包长状态机另见网络专题。
// 包长上下界本身不能证明 count 与正文剩余字节或目标容量相符。
//
// [目标越界的精确位置]
// 正常 j=0..99 的 36 字节写入都位于 mapped[0..3599]。
// j=100 时目的地址为 mapped+3600=N+3616：
//   前4字节覆写 count；随后覆写 N+3620 color / N+3621 isNil / 两字节尾部；
//   从第9个复制字节起越过 N+3624 分配边界，总复制仍为36字节。
// 由于下一轮重新读已覆写的 count，后续循环次数还可能被这次越界改变。
// 这里只确认机器码存在危险路径，不宣称已实机复现崩溃或可利用性。
//
// [服务端实现约束]
// type 0 必须限制 count<=100，并要求正文实际长度与 count 完全一致。
// 以当前已知格式计算：body_bytes=44+36*count；100条时3644字节。
// 对接入端须在发送前检查整数乘加和资源容量，不能靠客户端 reader 拒绝畸形载荷。
// count=0 合法目标行为是存零、跳过数组复制；旧 mapped 的其他槽位不会统一清空。
// 这些是兼容性及边界建议，尚未修改服务端协议实现或 rnclient.exe 补丁。
//
// [不要扩大结论]
// 本值区与角色数组无关；36 字节记录内部文本/数值字段尚未命名。
// type 1 的 mapped=4404 与其100*44记录是另一树实例，本轮不混入该布局。
// 静态越界结论可以指导后续修补，但补丁需另验完整寄存器、栈和错误返回流程。
