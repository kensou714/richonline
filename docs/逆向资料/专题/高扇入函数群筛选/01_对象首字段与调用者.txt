// 入口和ABI
// ----------------------------------------------------------------------------
// 0x60C87C：E9 rel32跳板，落0x85BB10；55处call经此入口。
// 0x85BB10：保留ECX并经0x60B7F6 E9跳板调用0x85C710；返回EAX原值。
// 0x85C710：ECX=this；0x85C733 mov eax,[ebp+var_8]；
//           0x85C736 mov eax,[eax]；无空指针检查，取this+0的DWORD。
// 0x85BB10中的0xCC填充、__RTC_CheckEsp是运行时调试构建辅助，
// 不对ECX指向对象附加语义。Hex-Rays将85BB10显示为无参数函数，
// 但汇编明确在0x85BB1C保存ECX并在0x85BB33恢复，不能丢失this。
//
// 局部调用者 / 完整函数字节已导出，但只审以下路径
// ----------------------------------------------------------------------------
// 0x85EA60：1053字节；对多个12字节局部记录做重复比较、移动和交换；
//            16处经0x60C87C取首字段，0x603899承担字符串比较。
//            伪码具有区间划分/双侧推进形态，具体排序算法及稳定性未证明。
// 0x85FEA0：209字节；六处取首字段，三轮比较及条件移动。
// 0x860000：350字节；六处取首字段，索引按2*i+2推进，读写记录首DWORD；
//            与二叉堆下滤形态相符，容器归属和边界保证未追到调用上游。
// 0x85F190：319字节；四处取首字段，遍历区间并在比较后移动记录。
// 0x860370：236字节；四处取首字段，索引按(i-1)/2回退并写记录首DWORD；
//            与二叉堆上滤形态相符，不能仅据形态等同标准库具体模板实例。
// 调用热点里还有0x860530等未导出完整函数，不归入上述审阅。
//
// 可证字段与边界
// ----------------------------------------------------------------------------
// 此接口只给出“从ECX指向位置取首DWORD”。调用者把返回指针与
// 0x603899字符串比较所需参数连接，因此多个调用点的首字段可解释为
// 字符串指针候选；并不证明所有调用点共享同一种对象布局。
// 12字节局部记录来自0x85EA60伪码和堆调整调用现场；未证明其源码类型名。
// 0x603899、0x6042B2、0x605469等被调用函数的完整契约尚未在本题闭合。
