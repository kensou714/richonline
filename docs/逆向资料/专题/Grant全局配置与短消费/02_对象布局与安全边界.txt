// Grant / 对象布局与安全边界
// ============================================================================
// 此处字段名为分析别名，源码类型名未知；所有偏移相对于Grant对象this。
// new尺寸、构造写入、读取器写入与短访问器消费共同形成布局证据。
// 原证：grant_core_raw.json/5..9、grant_supplement_raw.json/0。
//
// 字段布局 / 以宽度为准
// ----------------------------------------------------------------------------
// +000000 / 4字节   relive_blood；默认0；RELIVE/blood -> atoi。
// +000004 / 4字节   relive_bount；默认-1；RELIVE/bount -> atoi。
// +000008 / 100000  prop_values[5][5000]；DWORD单元，默认全部-1。
// +0186A8 / 4字节   ic_code；默认0；VERSION/ICCode -> atoi。
// +0186AC / 100     gate_enable[100]；BYTE单元，默认全部0。
// +018710 / 1字节   only_english_nick；默认0；精确true -> 1，否则0。
// +018711 / 3字节   对齐空隙；当前构造未直接初始化。
// +018714 / 4字节   ip_exp_factor；float默认1.0；IPBONUS/exp -> atof。
// +018718 / 4字节   ip_gold_factor；float默认1.0；IPBONUS/gold -> atof。
// +01871C          分配末端，不可据此扩展到邻接对象。
// 0x186A8=100008；0x186AC=100012；0x18710=100112；末端100124。
// 默认-1是位模式与取值事实；“无限次”只对已核消费分支成立。
//
// prop表 / 写入和读取约束不对称
// ----------------------------------------------------------------------------
// 装载器写入：行由五种rule字符串映射约束；prop_id=atoi，没有上下界。
// 7D98E0读取：signed arg0<0或arg0>=5时返回EAX=-1；其他情况直接
// 读取DWORD[this+8+20000*arg0+4*arg1]，arg1不作范围验证，retn 8。
// 伪码以unsigned <=4表达接受集合，集合一致；本文按实际signed分支记录。
// 值本身没有归一化、最小值限制或溢出检查，允许任意32位表单元。
// 可复算的相邻字段关系：rule=4、prop=5000得到+0x186A8，正是ic_code。
// rule=0、prop=-1得到+4，rule=0、prop=-2得到+0；说明负索引可落入前字段。
// 这些是地址算式的静态别名风险，不宣称当前缺失配置已经触发越界。
// rule行本身的范围检查不能保护第二维，开发导入器必须验证0..4999。
//
// gate表 / 读写均无范围门
// ----------------------------------------------------------------------------
// 7D99D0直接AL=BYTE[this+0x186AC+arg0]，retn 4；不转换为规范0/1。
// 装载仅置1，构造置0，所以正常配置产生0/1，但访问器接受原始任意字节。
// gate id=-4的算式落+0x186A8；id=100落+0x18710昵称标志。
// id=104落+0x18714第一个float的低字节；无界id还可能离开分配对象。
// gate_0/1/2的序号是发现顺序，键值才是最终写入id；不能混为同一索引。
// 例如缺gate_1，即使存在gate_2也不会访问后者；本文仅示范控制流，
// 未创建这样的Grant资源，也未声明其为真实样本内容。
//
// 行读取 / 128不是复制前安全上限
// ----------------------------------------------------------------------------
// 8198E0从parser+0x90取读指针，读至LF；逗号作为普通内容，不结束该读。
// 高位字节>=0x80按双字节推进；反引号后接n写入LF；末尾写NUL。
// 循环写入没有复制前容量阻断，最后才断言写入计数+1 <= 传入容量。
// Grant传128，因此超过容量的输入可能先改写栈，再进入断言现场。
// 这是写后断言，不能称为截断、拒绝超长行或保证128字节以内。
// 双字节与反引号行为也不等于完整Unicode或已验证的GBK解码器。
// 行读取不推进对象游标；返回值并未作为Grant读取成功bool消费。
// 复用出处：大厅URL读取与缓冲契约/证据/functions_raw.json中的8198E0。
//
// 配置制作端 / 可直接应用的验证条件
// ----------------------------------------------------------------------------
// 在将来补齐合法Grant样本时，先验证prop_id属于0..4999、gate id属于0..99，
// rule仅用当前五个精确符号，gate_n从0开始连续；每个PROP同时具备prop、
// rule、num三键。保持每个解码后行含NUL在内不超过128字节。
// 输入必须由真实解析器格式决定，不能把本文的字段表当作已经确认的
// 文件书写样例；当前资源缺失，段行语法应沿用文本段键解析专题。
// int字段提前执行完整数字语法/范围验证；float提前拒绝非有限数。
