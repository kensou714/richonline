// Grant / 生命周期与配置读取
// ============================================================================
// 核心结论：这是一个约100KB的进程单例配置对象，聚合复活参数、五规则
// 道具数值表、gate字节表、昵称标志和两个浮点倍率。文件名本身不能证明
// “赠礼”业务；本文采用Grant仅为当前资源与函数群的导航名。
// 原证：grant_core_raw.json、grant_supplement_raw.json、grant_navigation_raw.json。
//
// 6280E0 / 懒建入口
// ----------------------------------------------------------------------------
// A76720非零时直接返回该槽；零时operator new(0x1871C)，尺寸100124字节。
// 分配返回非零后以ECX=this调用7D9100；分配返回零则将零写回全局槽。
// EH尾块保留分配后构造异常时的operator delete路径，不能据此声称异常
// 被吞掉或返回零。该入口未见锁与原子操作，多线程调用安全性未闭合。
// 正常返回EAX=全局槽值；不能把“取得单例”直接解释为已加载配置。
//
// 7D9100 / 初值构造
// ----------------------------------------------------------------------------
// 先调用7D9C30：DWORD[this+0]=0，DWORD[this+4]=-1，返回this。
// 双循环5行，每行5000个DWORD，表起点+8，行步长20000，全部写-1。
// +0x186A8写DWORD 0；+0x186AC起100字节memset 0。
// +0x18710写BYTE 0；+0x18714/+0x18718分别写位模式0x3F800000。
// 后续atof后fstp dword的读取现场印证这两个DWORD位模式为float 1.0。
// +0x18711..+0x18713未见直接初始化，不能将整个对象称为清零。
// 构造返回this；不打开Grant.kpd，不验证游戏规则或服务端状态。
//
// 启动与关闭 / 有限现场
// ----------------------------------------------------------------------------
// 启动623E52压入Data\Grant.kpd路径，623E57取单例，623E5E调用7D91D0。
// 623E63直接继续下一调用，当前窗口未判读取器AL/EAX，也未判单例为空。
// 邻近其他资源有自己的失败判定，不能将相邻判定挪到Grant调用之上。
// 关闭62437D判断A76720非零，624392调用operator delete，62439A将槽清零。
// 此有限窗在delete前未见对象析构调用；不推导整个退出函数的释放顺序。
//
// 7D91D0 / 文件门与解析准备
// ----------------------------------------------------------------------------
// 局部资源loader对象24字节，parser对象168字节。实际行读取传容量128；
// 伪码将String标为136字节属于栈布局恢复，不能当作容量安全证据。
// 81B4C0装载返回零：只清理loader，AL=0，未写Grant业务字段。
// 返回非零：81B7F0、8191D0，读取loader数据627140及长度627120，
// 然后819250(mode=2,src,len,0)。初始化返回值没有成为失败分支。
// 正常进入读取流程后，即使段或键缺失，末尾也AL=1。
// 这是“经过装载门并走到末尾”的返回域，不是全字段完整有效保证。
//
// 段与字段 / 依原控制流次序
// ----------------------------------------------------------------------------
// VERSION / ICCode：段与键均命中才读行、atoi，写DWORD +0x186A8。
// NICKNAME / OnlyEnglishNick：段与键均命中才读行；strcmp精确等于true
// 时写BYTE +0x18710=1，否则写0。没有大小写转换、空白归一化或布尔atoi。
// RELIVE / blood：atoi后写DWORD +0；RELIVE / bount：atoi后写DWORD +4。
// 两键分别判断命中，bount拼写由C字串原证确认，不纠正成其他英文单词。
// GATEENABLE：从gate_0开始，随后gate_1、gate_2连续查键，首次缺键结束。
// 键值atoi得到id，直接BYTE[this+0x186AC+id]=1；键序号不是gate目标id。
// 没有清除已启用项，也没有对id执行0..99范围判定。
// PROP：以819470前向寻找重复PROP段；prop、rule、num键命中返回均未判定。
// prop读行后atoi为列；rule用精确strcmp映射CM=0、PK=1、TC=2、BS=3、KO=4。
// 其他rule文本维持-1并跳过表写入；有效行才读num，atoi后写
// DWORD[this+8+20000*rule_index+4*prop_id]，没有prop_id范围判定。
// 重复段可覆盖同一单元；前向段游标使循环不会每次重读首个PROP段。
// num键地址A2D500经人工四字节原证确认6e756d00，实际push的是地址本身。
// IPBONUS / exp、gold：分别命中后读行、atof，再fstp dword到+0x18714/
// +0x18718。未见正数、有限数、最小值或最大值判定。
// 各主要块之间均调用81A090(0,0)，只是复位解析游标，不重置Grant对象。
//
// 文本段键契约 / 已审来源的必要部分
// ----------------------------------------------------------------------------
// 819470用+0x8C段游标向前扫描；819660在当前段中找键，不推进段扫描位置。
// 81A090(0,0)以parser+4的base同步+0x94、+0x90、+0x8C三个游标。
// 819250模式2按给定长度复制，没有额外添加NUL；底层解析风险遵守原专题。
// Grant调用的是8198E0行读取助手，不是819A20逗号字段读取助手。
// 首个NICKNAME读前没有再次memset String；行助手通常写末尾NUL。
// PROP未判键查找失败后仍调用行读取，不能将缺键行为写成安全默认0，
// 因为行读取时的当前指针由解析器此前状态决定。
//
// 失败与再次读取
// ----------------------------------------------------------------------------
// 构造默认值只在懒建时设置。7D91D0自身不调用7D9100或7D9C30。
// 有明确段/键命中门的字段若缺失则不写，保留旧值；首次读取时保留构造
// 默认。PROP已命中段后缺键仍继续读写，必须保留前述解析器状态未知边界。
// 再读GATEENABLE只置1，旧gate启用项不会被清掉；PROP未提及单元也不清。
// 文件门失败：业务写入尚未开始，对象沿用进入函数前的状态。
// 装载门通过后逐字段原地写入，没有临时完整对象和原子提交/回滚流程。
// 静态证据不保证中途异常后状态、不保证解析器初始化失败后的运行行为。
// 当前Grant.kpd缺失，未验证客户端启动失败表现，不将缺文件推为卡住根因。
