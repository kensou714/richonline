// 6AD9F0 / 一个输入对象指针、ECX根、retn4
// ----------------------------------------------------------------------------
// 输入Q的+4是signed WORD，先movsx扩展到32位，再作为64F0C0的索引实参。
// 本体没有Q非空、长度、索引或字串返回非空的门；依赖调用前提必须另证。
// 先push78h，6279C0普通retn不消耗该参数，返回根供6E4520(120)调用。
// 6E4520只把AL作为谓词返回；6AD9F0 movzx AL后非零直接结束，零才进入查找。
// 短契约原证：reused_raw#/records/2与#/records/3，不能由GetSize自动名理解为数组长度。
// 未找到P：把signed WORD值存栈局部L，6E3B40(root,102,0,0)后，
// 再6E4640(root,102,&L)，最后629E90(1)；L是栈局部地址，不是拥有型堆对象。
// 6279C0没有栈参数，故两组push在getter前并不意味着它接收这些业务参数。
// 6E3B40的retn0Ch及6E4640的retn8分别消耗对应参数；局部调用顺序已静态核实。
// 找到P：signed WORD值与A23ACF地址传6A8970，ECX保持M；没有在本体读P字段。
// A23ACF未被导出器接纳为严格C串，不能凭byte标签称空字符串或某提示文本。
// 编号120与102的业务名称、629E90与6A8970的完整副作用未闭合。
// 本体不同退出路径保留不同外部调用EAX，不声明统一BOOL成功或失败返回。

// 73D560 / 界面对象U和三DWORD输入Q
// ----------------------------------------------------------------------------
// 先经628270取根M；调用U+4对象上的8E31B0(Q+0,0)与8E3340(Q+4,0)。
// 随后把DWORD[Q+8]写DWORD[U+48h]，取64F0C0(M,U+48h)给出字串S。
// Q的三个字段都直接读取，不是本体证明的网络包布局；输入长度与NULL门未见。
// 编号2/3/6以8E2C10(U+4,id,0)查询控件；该查询可返回NULL，本体随后直接解引用。
// 三站点均把控件地址送ECX，从首DWORD取vtable，经+C4h调用，caller检查ESP一致。
// +C4h为196字节，即零基第49个DWORD槽；不把该槽自动称启用/禁用API。
// 编号2站点73D5F2压完整DWORD 1。
// 编号3站点73D631的低BYTE表示6A85C0(M,S)返回AL是否为0。
// 编号6站点73D679的低BYTE表示6B20A0(M,64F0C0(...))返回指针是否为NULL。
// 最后vcall的返回EAX经RTC检查后退出；实际签名和返回类型未证，不能称BOOL。
//
// 不可省略的DWORD高位 / 73D61D至73D626
// ----------------------------------------------------------------------------
// movzx EDX,AL；neg EDX；sbb DL,DL；inc DL，只最后两步写低BYTE。
// AL==0时压00000001；AL非0时压FFFFFF00，而非00000000。
// 在已知只读低BYTE的被调契约之前，不能把实推DWORD简化为普通int bool。
// 73D668至73D66C：neg EAX；sbb AL,AL；inc AL；NULL时压00000001。
// 非NULL P时压((-P)&FFFFFF00)，低BYTE为0，高24位保留-pointer的计算结果。
// 最后的inc AL不会向高24位进位；EAX非NULL且低位恰为0等边界仍按完整neg标志处理。
// 本体足以证明低BYTE未命中标记；控件+C4是否只取BYTE仍须核实际vtable目标。
