// ============================================================================
// 角色退场 / 7BE160 的直接写入与地图关联
// ============================================================================
// 原证：endgame_cleanup、endgame_role_retirement、endgame_exit_and_land、
//       endgame_retirement_setters、endgame_disconnect 各 JSON。
//
// 进入条件
//   64EFA0(G,slot) 读 BYTE[G+3640+slot]。
//   63E7D0(G,slot) 读 BYTE[G+3632+slot]，IDA误名 IsAutoHideMode。
//   两者都非0才执行7BE160正文；getter本身不检查slot范围。
//   这两组标志不同：前者在普通破产后保留，后者在普通破产末尾清零。
//   本文称前者“在局记录标志”、后者“活动标志”，仅是已证用途的工作名称。
//
// 正常破产分支的次序
//   63F680(P,0)、63F6B0(P,0)：直接置 DWORD[P+1504/P+1508]=0。
//   7E6200(M,slot)：回收此槽相关地产、设施和地图占有记录。
//   某地图模式再调用7F9950(P)，本批只作依赖导航。
//   7D9CC0(G+3164,slot)：遍历相对+1..+32 BYTE，匹配slot则写-1。
//   对前 DWORD[G+3616] 个有效角色，把 BYTE[P_i+1472+slot] 清零。
//   随后按角色各状态谓词调用清除函数，再执行7F9560(P)。
//
// 7F9560 的公共角色清理
//   清 BYTE[P+1496]、+1498、+1499、+1500、+1501、+1502。
//   遍历8个关系槽，条件成立时清本角色和对方角色的对应 P+1472 关系位。
//   最后调用两个状态setter(0)，其完整产品名称待其它角色状态专题补全。
//
// 末尾分流
//   7C0C00(G,slot) 真：向特殊模式管理器提交(G,-1)，不走以下计数/活动位写入。
//   否则另一个特殊模式条件成立时提交(G,-2)，随后继续普通收尾。
//   DWORD[G+3620] 减1；6935F0 将 BYTE[G+3632+slot] 置0。
//   在局记录标志 G+3640+slot 没有在该普通破产尾部清零。
//   第二次7BE160通常被活动位挡住；但400E外层的动画/文案并无同样幂等保护。
//
// 地产归属核心
//   地图格记录地址 = DWORD[M+56] + 68*位置。
//   63EC70(M,位置) 只把该记录 BYTE+3 所有者写为0xFF，未改等级BYTE。
//   7E3E60(M,slot,位置) 在三条件满足时先调用关联列表移除，再清所有者，
//   重取显示资源写 DWORD[格+24]；末尾对另一格类条件调用附加清理。
//   不能把“回收地产”笼统写成重置全部68字节或把等级归零。
//
// 7E6200 多模式扫描（静态局部审阅）
//   模式分支扫描6字节记录、64条12字节内嵌记录、三组4字节位置记录；
//   匹配此所有者时，位置WORD置-1；设施关联会同时清多个角色的对应状态。
//   某分支通过回调遍历另一类集合，其回调业务尚未展开。
//   多处调用63EC70提前清所有者；最后公共扫描仍用所有者谓词过滤。
//   所以不能假定每个已清所有者的格子最后都会再进入7E3E60。
//   设施数量、容器初始化及其它枚举约束未由此函数单独证实。
//
// 与离线清理7BE450对照
//   7BE450先要求在局记录标志，保存旧活动位；只有旧活动位非0才清地产/状态并减数。
//   它不执行7BE160开头的现金和存款清零。
//   不论旧活动位，尾部清 G+3632+slot 与 G+3640+slot，
//   并把旧活动位保存到 BYTE[G+3656+slot]。
//   破产和离线不能共用一个“删除角色”布尔字段模型。
