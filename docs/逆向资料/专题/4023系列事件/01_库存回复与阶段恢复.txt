/*
 * 库存回复与阶段恢复
 * ============================================================================
 * G为游戏对象，current=DWORD[G+3624]，local=DWORD[G+8]。
 * P=current角色指针，即DWORD[G+3584+4*current]。
 * 三个入口先取G+1600队列head，再核验packet+2 WORD GmsvID。
 * 字段读取下界不是完整网络帧长度；处理器本身没有独立长度检查。
 */

// [4023 -> 65F0C0] 下界8字节；+4/+6是两个signed WORD物品ID。
// 分别调用7F8780(P,id,1)。都以同一个当前角色为对象，按空槽插入数量1。
// 不是先检查两个空槽再原子插入：第一次可能成功、第二次可能失败。
// v30被两次返回值覆盖；卡栏已满提示只取第二次结果，不合并第一次结果。
// 7F8780末尾经6019BD -> 7FD7A0读取BYTE[P+1416]，非0时强制返回1。
// 该字节为0才返回入槽标志v7；此字节用途待查，不能解释成库存全满判断。
// 因而返回1也不能直接当作本次入槽成功；原证调用点7F88C0及其后分支。
// 合成与容量策略详见商店专题；本处理器不验证两ID的资源合法域。
// 两次入槽无条件发生；G+3672+current非零只跳过随后提示/6002，不跳过库存修改。

// G+3672+current==0时：
//   6003：UI4、显示=1、暂停=1、窗口1800、暂停1350、文本A787E0、长度128。
//   文本两行分别为“獲得 物品名”；第二返回假时追加154“卡片欄已滿，丟棄”。
//   6002：编号19、演员current、暂停=1、时长1350。
// 物品名693370按属性表base+1128*id+660取指针；没有本地范围检查。
// 文案sprintf写全局缓冲，6003复制指针而非复制文本；重叠回复可改写排队文本。

// [4024 -> 65F410] 下界8字节；+4..+7是四个signed BYTE库存槽号。
// 首槽+4==-1时，整个提示/扣除/6002区域跳过，即使后面三个槽不是-1也不消费。
// 否则先读取每个非-1槽的group0物品ID，组装“失去 物品名”逐行提示到A78880。
// 随后按数组原顺序对每个非-1槽调用7F8920(P,slot,1)，各扣数量1。
// 不是按物品ID扣除，也不去重；重复槽会重复扣。同槽已清空后的行为仍由原函数决定。
// 没有先做槽范围检查；signed BYTE<-1也会进入getter/扣除路径。
// 最后6002编号10、演员current、暂停=1、1350；不同于4023的编号19。

// [共同后继] 4023和4024使用相同优先分支，依据回复到来时的G状态。
// A：BYTE[G+83834]非零：清83834；排6004(type1,duration=DWORD[G+83784],actor=current)。
//    current==local时，紧接着排6006(mode1)；非本地不排6006。
//    此分支不清83835；两标志同时非零时只执行A，另一个保留。
// B：83834为0而BYTE[G+83835]非零：清83835；排6080(stage6,+3=-1)。
// C：两个标志均0：排6080(stage1,+3=-1)。
// 所有记录使用64FA50返回的新cursor继续插入，保持该处理器内部顺序。
// 错误身份时不做这些业务写入；不应另外伪造一个统一“继续回合”回复。

// 6004 -> 67DB40 -> 7BB430：仅读记录+2 WORD/+4 DWORD，更新pending类型/时长/start。
// 写在记录+8的actor在此消费者不读取，不是网络身份认证字段。
// 6006 -> 67DBE0：参数非0且当前角色+1493/+1494/+1495均-1才传操作启用1。
// 所以A分支排入6006也不保证玩家立即能操作；等待状态和操作开关必须分别观察。
// 6080 -> 681380：stage1完成才自动追加stage2；stage2完成才追加stage6。
// stage6不再由该handler追加其他阶段；其具体落点/岔路选择见既有阶段专题。
// 83834/83835还有其他写入者，本篇只确认本次消费规则，不为二者命名官方状态。

// [4029 -> 660160] 下界6字节；+4 signed WORD物品ID。
// 先排6001编号14、+6=0（播放不暂停）；然后向当前P插入数量1。
// 生成UI4提示到A78920，窗口1800、暂停1350、128字节；入槽返回假则追加154。
// 最后排6080(stage2,+3=-1)，直接从地产阶段恢复；不是重跑stage0或stage1。
// 不使用83834/83835共同分支，也不直接排6004/6006。

// [共用消费者] 本地编号并非网络opcode。
// 6001 -> 67D7F0：编号是声音ID；按+4/+5传播放选项；+6非零才设置暂停。
// 6002 -> 67D880：编号映射到角色头像帧，再按演员+4选P；有效role时显示UI9。
// 编号19映射5、编号10映射3（7FB200懒初始化表）；声音ID由role与编号组合。
// 6002可通知本地UI0刷新大头像；+6非零时按给定时长暂停，0时长默认1800。
// 6003 -> 67DA40：按+4显示UI，或+5关闭UI；+6非零时设置队列暂停。
// 窗口持续值与暂停值独立；本系列1800窗口/1350暂停并不意味着同一结束点。
// 64FB10写G+12时长、G+16=tick；这是基础队列消费门，不是7BB430的pending计时器。
// 64FA50固定288字节槽复制与cursor规则沿用基础队列专题，未处理队列满返回-1。
