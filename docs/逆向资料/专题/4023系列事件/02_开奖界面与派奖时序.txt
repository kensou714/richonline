// [入口660670] 身份核验成功后，下界12字节：
// packet+4 signed BYTE中奖号码；+5 signed BYTE中奖角色槽，-1表示没人中奖。
// packet+8 DWORD奖金；+6/+7在本handler未读取，不能替它们编造语义。
// 694020(L,bonus)写L+36，即G+3200；它不是MFC按钮style。
// 打开UI19持续值0，再以两DWORD {number,winner}同步通知其虚表+16。
// 接着64FB10(G,6400)，最后在原队列游标排608A参数2（4字节记录）。
// 未验证number在1..32、winner有效、bonus合法；处理器自身不检查UI创建是否成功。

// [对象] 6E77B0分配92字节、6FB300写虚表A25170。
// 6E6080的工厂登记指令6E6255写入+148，指向60DFD3 -> 6E77B0。
// 虚表+4=714BC0初始化；+16=714C70接收结果；+20=714D30帧更新。
// +120仍是基础控件点击入口，本篇不声称UI19需要点击才能开奖。
// 714BC0为控件300注册事件19回调；通用事件分派内部未在本篇展开。

// 714C70：
// W+72 DWORD号码；W+76 DWORD中奖槽；W+80 DWORD阶段=0；W+84 DWORD起始tick。
// control300.data[0]=L+36奖金，供提示显示。
// 声音15以选项(1,1)提交并保存句柄；底层循环次数为0，实际约定见音频专题。
// 实际播放仍受音频开关影响，不能从这两个BYTE直接保证实机循环表现。
// W+88 BYTE在到达阶段2时置1；该位的完整退出消费者未在本篇恢复。

// [阶段0] 每帧随机移动控件1..32，约1000ms后阶段变1并重置tick。
// 715140依据控件100容器尺寸，让号码控件沿四方向随机移5..13像素并限边。
// 随机的是表现位置。中奖number/winner早由服务器报文写入W，客户端不抽奖。

// [阶段1] 再过1800ms：
// 取中奖号码同ID控件的+188图像ID，放到控件200并隐藏原号码控件。
// 文本400显示177“本期中獎號碼：”加number。
// 阶段变2，重置tick，停止音频对象保存的声音句柄，W+88=1。

// [阶段2] 再过1800ms：
// winner==-1：声音22，文本179“本期沒人中獎，獎金將累積到下期”。
// 不执行现金增加，不重置号码占有数组，也不把奖金置回5000。
// winner!=-1：声音23，取P[winner]名字，显示178“本期中獎者：\n名字”。
// 7FA050(P,L+36,1)：DWORD[P+1504]现金增加奖金，并调用金额通知。
// 随后P+388头像帧写5；本地winner另通知UI0掩码1刷新大头像。
// 7D9C70(L)：L+1..32的BYTE号码拥有者全部写-1；L+36奖金设5000。
// 两条路径末尾阶段变3并重置tick，保证持续帧更新不会重复派同一笔奖金。

// [阶段3] 只读取tick；714D30没有主动关闭窗口、发网络回执或清pending。
// 理想帧推进在约1000+1800+1800=4600ms执行阶段2，与队列暂停6400ms独立。
// 帧调度停顿、UI未创建、窗口被提前关闭会影响派奖是否到达，不能按墙钟保证。
// 余额增加发生于UI帧更新，不在660670收包入口；定位余额不一致时应同时记录W阶段。
// 不从此推定服务器的现金账本也等客户端动画，服务端结算必须另核。

// [608A参数2] 681C40把signed BYTE+2交7C0C50，scratch=0。
// 7C0C50清G+60后由case2跳LABEL126，绕过default的换行动者主干。
// 63ECA0成立时进7E4C50；否则mode3且G+83830==-1，或mode4时进7E51A0。
// 两辅助沿地图挂起奖励记录扫描，构造后续提示/6079并清到期记录；本篇仅审阅主干。
// 接着7F7CF0(P)：P+1488==-1直接返回-1，否则递减P+1490。
// 递减后的signed BYTE >0返回-1，<=0返回P+1488；负值也进入返回状态分支。
// 返回!=-1时排6088(actor=current)和608A参数1。
// 返回-1时进入LABEL134的角色附加效果及持续动态物件清理链；大函数仍为局部分析。
// 因而开奖后的参数2不是6080的stage2，也不直接等同“下一玩家回合”。

// [资源与扩展] 本期号码控件只有1..32；以packet号码查控件未做本地范围验证。
// 新增号码须同步UI控件、随机表现循环、L+1..32和7D9C70重置边界。
// 奖金字段是32位运算，7FA050直接相加无溢出保护；扩经济数值须另审合法域。
// UI与Intf严格gb18030往返；文案严格CP950往返；客户端实际仍用其ACP接口。
// 证据资源脚本只读解码，不提供游戏配置重打包或实机派奖证明。
