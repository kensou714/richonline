// 版本归属
// 本批数据库沿用CB35F69F...历史输入；取证时磁盘SHA-256为：
// a23410e79637e312c932f861176d8d81cd1fd5d222a286f279feccdece6263c2。
// 各证据JSON保存完整函数字节和disk_bytes_equal；本批均为true。
// 该对照仅覆盖函数入口至end_ea，不能证明所有外部数据和运行依赖都相同。
// 全局版本核验参见../../全量分析/版本核验_第二批.json。

// 结构：以游戏业务对象G为基址，队列Q = G + 0x640
// Q+0x00 / DWORD / 记录存储基址；每条固定0x120，即288字节。
// Q+0x04 / DWORD / 物理槽数N；不是可容纳记录数。
// Q+0x08 / DWORD / 当前记录数，插入成功递增、取出递减。
// Q+0x0C / DWORD / 头下标head。
// Q+0x10 / DWORD / 尾下标tail，指向下一次尾插位置。
// 未由这些函数证明Q的完整sizeof；不能将后续字段直接并入此结构。

// 初始化与容量
// 0x64F2A0开头对G+0x640传入0x100，经0x60176A调用0x697FC0。
// 0x697FC0写N、清count/head/tail，再申请N*288字节并存入Q+0。
// 该路径为256*288=73728字节；0x698640以head==(tail+1)%N判满。
// 所以保持合法下标时最多255条，不是256条。初始化未在本函数检查重复分配。
// 分配符号被识别成CMFCRibbonQuickAccessToolBarDefaultState::AddCommand，
// 本文只依据栈参数和返回指针描述分配行为，不继承该不可靠类名。

// 基本操作与ABI
// 0x698680：next(i)=(i+1)%N；0x6986B0：i-1<0时返回N-1，否则i-1。
// 0x698050：thiscall，栈上按值传入288字节记录，末尾retn 0x120。
// 满时返回0；否则完整复制到tail，tail=next(tail)，count++，返回1。
// 0x7D8010：thiscall，调用者提供288字节输出区，末尾retn 4。
// 先保存head、推进head并count--，再复制旧head槽到输出区；自身不判断空。
// 0x7D7F20：仅用head==tail判空；调用者必须先判空再取出。
// 以上运算没有锁；是否跨线程并发使用需由调用上下文另证。

// 指定位置插入：0x6980F0
// 正确ABI为thiscall(Q, record[288]按值, physicalIndex, returnMode)。
// EBP+8起是记录；EBP+0x128为physicalIndex，EBP+0x12C为returnMode。
// retn 0x128正好清理288+4+4字节。不是Hex-Rays打印的64个整数参数。
// 满时返回-1；不满时计算从head到physicalIndex的环形距离d。
// 若d<=count-d：从head沿next遍历到插入点之前，逐条复制到prev(原槽)，
// 新记录写在prev(physicalIndex)，head=prev(head)。
// 若d>count-d：从prev(tail)沿prev遍历至插入点（含），逐条复制到next(原槽)，
// 新记录写在physicalIndex，tail=next(tail)；插入点等于tail时直接写空尾槽。
// 两条分支都实现“在指定记录之前插入”；physicalIndex==tail表示追加，count++。
// returnMode=1返回新记录后一槽；=2返回前一槽；其他值返回新记录自身槽。
// 算法选择较短搬移侧。physicalIndex是物理下标，不是逻辑序号。
// 本函数不验证下标属于有效区间；循环终止依赖调用者满足前提。

// 本地记录包装：0x64FA50
// 签名可按G、Src、Size、physicalIndex理解；其thiscall末尾retn 12。
// 将Size字节复制到栈上记录区，再按值复制完整288字节给0x6980F0。
// this实际改为G+0x640；returnMode固定1，因此适合串接多条插入记录。
// 小记录的尾部来自入口rep stosd写入的0xCC，而非清零或真实报文长度。
// 函数自身没有Size<=288检查；实际可达性须追踪各调用者长度来源。
// 例0x63ACC0两次插入分别传4和10字节，并用前次返回位置接续插入。
// 该例仅证明局部记录操作，不能把此包装命名为TCP发送函数。

// 接收入口分流：0x64F870
// 读取Src首WORD为消息号，没有先在此函数检查Size>=2。
// 0x400C/0x400F先执行两组前置调用链：0x6062D8取对象后调用0x606EBD(0)，
// 0x60837B取对象后调用自动误命名的operator[](1)，随后仍进入后续分流。
// 0x4041/0x4042/0x4043及0x4053..0x4057直接调用对应处理入口。
// 其余消息执行Size字节栈复制，再完整按值传288字节到0x698050。
// 队列满返回0；该包装未将此返回值转成明确的重试/失败通知。
// 包装未做Size上界检查；这不是已证明可由服务器触发的越界结论。
// 直接处理入口的字段长度与完整语义留给网络/游戏分派专题继续恢复。

// 消费入口：0x7BB290，每次调用至多取一条
// 门一：0x691BD0读G+83831，即G+0x14777的单字节标志；非零不消费。
// 该标志暂名“消费抑制位”，不能仅凭一个getter命名为动画忙或暂停。
// 门二：0x7D7F20检查Q为空；为空不消费。
// 门三：0x64FB70检查G+0x0C的等待时长；仍在等待则不消费。
// 三门均通过，0x7D8010取出记录并完整复制到全局0xA87B88。
// 首WORD按有符号short扩展；汇编显式比较0x4000..0x7FFF。
// 用消息号直接索引DWORD表基址0xA8E0E0，非零项才调用。
// 处理器cdecl参数为(G, &全局记录)，调用者add esp,8清栈。
// 处理器拿到的是共享全局缓冲地址；若处理器内重入本消费入口且门控允许再次出队，
// 下一条会覆盖当前记录。尚未证明存在这种重入路径，也未证明所有处理器不保留指针。
// 本群没有据此证明可重入或跨线程安全；加钩子时不能自行假定该指针可长期持有。
// 不在区间或表项为空的记录已经出队，不会自动留在队头重试。
// 函数各路径均返回1；不能用该返回值判定“本次一定完成了一条事件”。

// 等待时长与时间戳
// 0x64FB10写DWORD[G+0x0C]=时长，DWORD[G+0x10]=GetTickCount()。
// 0x64FB50只清G+0x0C，取消等待。
// 0x64FB70在时长非零且无符号elapsed>=时长时将时长清零。
// 返回值是“仍有等待时长”，不是“队列有消息”。elapsed使用32位差值。
// 长时间卡住须分别核对抑制位、队列空、等待时长和处理器内部流程。
// 服务端已发送不等于客户端已消费；调试记录应区分收到、入队、取出与完成。

// 注册表与后续逐群分析入口
// 0x7EE330被自动误命名为_cfltcvt_init，实际写入310个分派表项。
// 第二批_分派映射.json逐项保留code、写入指令VA、槽地址、跳板字节和目标。
// 0x4000对应表地址0xA9E0E0，不要误把0xA8E0E0当第一个业务槽。
// 注册映射只是已识别，310个处理器的业务语义不能据此标成全部已分析。
