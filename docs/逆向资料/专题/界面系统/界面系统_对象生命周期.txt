// 一、总链路与边界
// ----------------------------------------------------------------------------
// 启动入口 0x623CB0 -> 跳板 0x61223B -> 0x6E2CD0(this, hWnd, Interface根路径)。
// 0x6E2CD0 的 this 是 UI 管理器；0x6E3B40 显示其临界区位于+0x6A8。
// 本文不据此宣称恢复了sizeof；它把根路径复制到 +0，
// 分配 0x5164 字节的引擎上下文（0x6046CC -> 0x8E0080），设置窗口尺寸、HWND，
// 通过 0x60336C 注册一组 UI 回调，再经 0x60838F 绑定成员函数表，最后调用 0x6E2F70。
// 成功加载 Intf.kpd 后写 this+0x40=1，并用 0x5FFB04(127,0,0) 进入初始界面。
// 0x6E2F70 读取 Interface根/Intf.kpd；失败直接返回0，调用者随之停止初始化。
//
// 单个 .ui 的实际调用路径在 0x8E4AD0：
//   0x60DEE8 -> 0x8E4AD0 -> 0x9105D0（a3=1时解码）
//   -> 0x60C822/0x90FEC0 读取 Head 字段
//   -> 0x60B2C9/0x90FFB0 读取 left/width/top/height
//   -> 0x60881C/0x8E06F0 将 Type 转为 0..12
//   -> 0x60B21A/0x8E22C0 创建控件对象
//   -> 控件虚表+124 继续解析其字段
//   -> 0x6079A3/0x8E4DC0 递归查找 Parent 并创建子控件。
// 0x8E06F0 配合 0x8E24D0 映射控件类型：0 plane、1 label、2 title、3 button、
// 4 edit、5 radiobutton、6 checkbox、7 groupbox、8 scrollbar、9 progress、
// 10 listbox、11 slider、12 tree。0x8E06F0 另支持 top/left/mid/right/
// bottom、true/false 等布局/枚举值，并可由引擎回调扩展。
// 0x8E4AD0 的 a3=0 分支调用 0x9100A0，以 rt 原样读取；a3=1 分支才在 0x9105D0
// 每个字节减去 RichNet[i mod 7]。因此只凭“文本可打开”不能判断该文件是明文。
//
// 二、Intf.kpd 的对象表与初始化/销毁
// ----------------------------------------------------------------------------
// 0x6E2F70 分配 160 项，每项 0x84(132) 字节；首 DWORD 是 indx，+4 是运行时控件指针，
// +8 是 file（容量64），+0x48 draw，+0x49 dynPop，+0x4A center，+0x4B nadjust，
// +0x4C free，+0x50 offsetX，+0x54 offsetY，+0x58 prev动态数组，+0x68 dvs动态数组，
// +0x78 活跃容器插入返回的索引，+0x7C 自动关闭时长，+0x80 上次显示时间戳。
// 这说明“160”是固定槽数量，不是 Interface 文件数；indx 未见范围检查，编辑器必须拒绝
// 越界或重复编号；未证明 indx 必须连续，prev_N/dvs_N 则在首个缺号处停止读取。
// 当前 117 个 *.ui 通过只读父子关系检查，但不等于全部运行时可用。
// 每个槽由 0x6E2910 构造：构造 +0x58/+0x68 两个动态整数容器，并清零
// +4、+0x48..+0x4B、+0x4C、+0x50、+0x54；未见它初始化 indx、file 或
// +0x78/+0x7C/+0x80，不能假定整个槽均有默认值。释放包装器为 0x6E29C0。
// 管理器销毁 0x6E2B40 先经专用回调释放槽127和21的下游对象，再释放槽数组和引擎上下文。
// 0x703A80/0x605C3E 设置容器容量；容器元素按 4 字节保存整数，0x6B8A60 在扩容时按增量复制。
//
// 三、创建、显示、关闭和 free 策略
// ----------------------------------------------------------------------------
// 本文对象偏移和虚表偏移均以字节为单位；表中函数指针宽4字节。
// 0x6E3B40(this,index,a3,a4) 是显示入口：若槽对象为空，读取 this+0x48+4*index
// 处的工厂指针；非空时调用，空时分配0x48字节默认对象（0x605DA6 -> 0x6E1D90）。
// 创建工厂表起点是 this+0x48；然后把根路径与 file
// 拼接，调用对象虚表+0 加载资源；加载成功再调用虚表+4、+8，记录 a3 于+0x7C、当前tick
// 于+0x80，并将 this+0x568+index 的 pending 字节清零。虚表+0x50 若已可见即提前返回；
// 否则调用虚表+0x3C 并遍历 prev/dvs 对象。
// 0x6E4020(this,index) 是关闭入口：仅当对象存在且虚表+0x50 报告“已显示/可关闭”时调用
// 虚表+0x40，再按 prev/dvs 回调恢复相关对象，写 pending=1，调用 0x6116D8(槽+0x78)。
// 0x6E42C0(this,index) 是资源释放入口：free非0且对象存在时才调用虚表+0x0C；free==1，或free==2且
// 0x609087(->0x625ED0) 报告可用虚拟内存不足时，再调用 this+0x2C8+4*index
// 处的释放工厂指针。无论上述条件是否成立，该入口末尾都会清除对应 pending 字节。
// free 字符串由 0x6E3610 映射：false=0、true=1、auto=2；未知值返回-1。
// 0x625ED0 比较阈值 < dwAvailVirtual；静态阈值0xA67250=0x1000000（16MiB），
// 因此auto在可用虚拟地址空间<=阈值时销毁；这不是物理内存或显存检查。
// free=false在本释放入口跳过虚表+0C和释放工厂，但总管理器析构仍会清理对象。
//
// 四、prev/dvs 的已证消费者
// ----------------------------------------------------------------------------
// 0x6E3B40 显示对象后，枚举 prev（槽+0x58），对每个关联槽调用其对象虚表+0x44，参数0；
// 再枚举 dvs（槽+0x68），只对关联对象可见且管理器恢复标志=0的项调用虚表+0x48参数0，
// 并把管理器对应标志（+0x608+slot）置1。0x6E4020 关闭时反向调用 prev 的+0x44参数1；
// 对 dvs 仅当恢复标志=1且对象当前不可见时调用+0x48参数1，并清标志。由此可确认：
// prev 是显示/关闭成对传播的启用状态；dvs 是带恢复记忆的隐藏/显示状态，
// 不是普通的资源依赖列表。关联项缺对象时会跳过，顺序依赖配置数组的连续性。
// 基类包装器0x6FA100/0x6FA160将上述+0x44/+0x48转发到根控件虚表+196/+200。
// plane虚表0xA31430解析到0x8E3A70（写控件+384启用位）、0x8E3EB0（写+385可见位）；
// 读取端0x6FA210/0x6FA270直接读这两个字节。停用/隐藏同时会清理相关焦点、悬停等上下文，
// 因此不能只修改显示像素或手工改一个布尔字节来替代完整调用链。
// 0x6E3750/0x6E3AB0/0x6E43E0 扫描160槽，排除127、21、137等保留项并批量销毁、
// 关闭或处理 pending；这些排除值是实现事实，尚未恢复其产品语义。
//
// 五、虚表与回调边界
// ----------------------------------------------------------------------------
// 管理器成员表由 0x6E6080 写入：创建工厂写入范围 this+0x48..+0x27C，
// 释放工厂写入范围 this+0x2C8..+0x4FC；每项4字节，两组按槽号对应，范围内有未写入项。
// 完整表各有160槽；该函数未覆盖每槽，不能假定任意槽都有回调。
// 0x8E22C0 先询问引擎上下文+20的自定义创建回调，
// 失败才退回 0x8E24D0；创建根对象挂入引擎上下文+20696，并将前一对象写入新对象+408。
// 子控件0x8E23F0写新对象+400为父对象、父对象+404为首子项、子对象+408为旧首子项。
// 0x8E12F0 管理引擎上下文+20760(0x5118)的RichNet解码密钥；它不是资源根路径。
// 0x8E0080 初始宽高800x600、
// 字体/界面参数和链表指针。0x6E2E60 把15个渲染/窗口回调注册到全局运行时。
// 基类默认对象构造 0x6E1D90 设置 CRecentFileList vtable；该名称是编译器/库残留，
// 不能当作产品语义。它的析构在 0x6E1DD0，资源初始化在 0x6E1E40。
//
// 六、资源工具与补丁边界
// ----------------------------------------------------------------------------
// 当前 Interface 目录有117个 .ui（另有 Intf.kpd）；只读脚本按 RichNet 密钥变换统计节、
// 控件和 Parent 引用，结果位于 ui_resource_inventory.json。该结果只能证明文件结构一致，
// 不能证明所有 Type、图片名、文本编号或回调均已注册。
// 新增 UI 的安全流程：备份原文件 -> 保持 Head/Parent引用存在、节名唯一、控件ID无冲突 -> 按本版本密钥编码 ->
// 检查 Intf.kpd 槽号与 file 字段 -> 检查图片/文本依赖 -> 静态清单 -> 隔离客户端验收。
// 未恢复的项目：控件虚表每个槽位的完整语义、0x6E6080 两组回调对应的产品名称、
// 活跃容器具体排序、引擎扩展回调+20，以及完整失败回滚路径。
// 待调查风险：0x6E3B40将新对象指针写入槽后才调用加载；加载失败分支仅解锁返回，
// 未在此处清空已写入的指针。下一次调用会跳过创建/加载分支；需要结合上层失败处理
// 判断是否会留下半初始化对象，不能据静态局部分支宣布已复现崩溃。
// prev恢复不使用计数器，dvs恢复记忆为每槽单字节；重叠弹窗关联同一对象时的恢复顺序
// 值得建立实机回归，不可假设已具备嵌套模态引用计数。
// 因而本专题只支持静态编辑器约束与研究导航，不宣称已具备通用 UI 编辑器或 EXE 补丁。
