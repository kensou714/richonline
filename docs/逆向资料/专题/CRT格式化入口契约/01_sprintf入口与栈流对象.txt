// sprintf入口与栈流对象
// ============================================================================
// 静态事实：9206D0是cdecl可变参数入口，结束用普通retn，调用方清理实参。
// EBP+8为Buffer，+12为Format，+16是首个可变参数槽；返回EAX来自格式化器。
// 9206DC用LEA取得EBP+16并保存在EBP-4；它没有复制任何可变参数内容。
// 伪码va_copy((va_list)v7,va)误表达了这个地址赋值，不能据此构造第二份参数表。
// 原证：证据/sprintf_raw.json，9206D0..9207BE，238字节与当前磁盘完全一致。
//
// 栈上的临时FILE形对象
// ----------------------------------------------------------------------------
// 9206D6把EBP-2Ch地址存到EBP-Ch；最低可确认使用跨度为16字节。
// 对象+0：当前写指针_ptr，92074D设为Buffer，写NUL后加1。
// 对象+4：计数_cnt，92072D写7FFFFFFFh；不是调用者传入的容量。
// 对象+8：基址_base，920744设为Buffer。
// 对象+12：标志_flag，920737写42h，即十进制66。
// 本体没有初始化其余FILE成员；栈上预留空间不能直接等同完整类声明。
// 将42h解释为可写字符串流的位组合，需要结合932CD0的实际测试位；见后续分支资料。
//
// 调用与收尾
// ----------------------------------------------------------------------------
// 92074F..92075B依次压入首可变参数地址、Format、临时FILE地址。
// 602ED5是五字节E9桥，落到932FC0；call后调用方清理12字节。
// 返回值先存在EBP-8；Buffer非NULL才进入末尾NUL路径。
// 92076F..920782先把_cnt减1，再按signed检查是否小于0。
// 非负时920789直接写一个NUL到_ptr，随后_ptr加1。
// 负数时调用60BD64→932CD0，参数Ch=0和同一FILE；其返回值不替代函数返回值。
// 9207B7仍返回格式化器原先的EAX，NUL未被入口自行计入返回值。
// 返回值是否按已写字符统计、遇错如何取值，必须查格式化器而不能只凭函数名。
//
// 断言不是拒绝返回
// ----------------------------------------------------------------------------
// Format为NULL时先报告sprintf.c第93行，文字format != NULL；Buffer为NULL报告94行。
// 两次均通过60D817→928CB0，5个32位实参，调用方清理20字节。
// 报告返回1才执行INT3，其他值直接继续；INT3后顺序流也接续后续代码。
// 本体没有由NULL断言直接返回错误的路径，不能把它写成安全参数校验。
// 报告器的对话框、调试器中断与恢复行为，以及NULL最终结果，尚未实机验证。
// 928CB0内部没有在本专题审阅；不得依据CRT函数名推断终止进程。
//
// 对内容扩展的意义
// ----------------------------------------------------------------------------
// 该ABI只有Buffer、Format、可变参数，没有目标容量；7FFFFFFFh是内部流计数。
// 目标数组实际容量、格式串来源与输入最大长度须在业务调用处独立证明。
// 断言、RTC栈检查、后续UI记录中的标称长度，都不会变成此入口的写入上限。
// 本专题为只读静态分析，不调用原CRT、不构造畸形输入、不运行游戏。
