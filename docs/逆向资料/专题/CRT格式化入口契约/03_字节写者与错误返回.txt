// 字节写者、计数模式与错误返回
// ============================================================================
// 934100是cdecl单字节写者：BYTE值、FILE指针、累计计数指针三个参数。
// flag&40h且_base==NULL时，934118..934123只把累计计数加1，不访问目标内存。
// 其余路径先_cnt--；signed结果非负便写低BYTE并_ptr++，负数调用932CD0。
// 写入返回-1时把累计计数置-1，否则累计+1；写低BYTE之后不会自动追加NUL。
// 因此入口Buffer==NULL虽触发断言，报告后继续时存在仅计算长度的路径。
// 该路径仍解析Format、扫描%s源、消费可变参数，并可能执行%n写者，不能视为无副作用校验。
// NULL Format没有相应免读取逻辑；两种NULL情形不能混写成一个结论。
//
// 重复字符和固定长度文本
// ----------------------------------------------------------------------------
// 9341D0重复字符写者逐次调用934100；循环采用原计数signed>0，遇累计-1立即停止。
// 非正padding不会输出，即width-正文长度-前缀长度为负时不补空格。
// 934220固定长度写者在flag&40h且_base==NULL时直接累计+=长度，不扫描源。
// 其余分支按signed正长度逐BYTE读取源并934100输出，遇累计-1停止；不依NUL终止。
// 正文可含NUL；返回计数统计成功输出BYTE数，末尾入口追加的NUL不计入。
// 没有读目标剩余空间或接收目标容量参数；_cnt源于sprintf的7FFFFFFFh。
// 数学容量证明应使用实际编码后的总字节数加1，不能只按字符数或返回值猜容量。
//
// 参数游标访问器
// ----------------------------------------------------------------------------
// 9342B0输入是游标变量的指针，先把游标加4，再从新游标-4取DWORD到EAX。
// 9342D0先加8，低DWORD到EAX、高DWORD到EDX；它没有检查可变参数个数。
// 934300先加4，再从新游标-4取WORD到AX；短整数仍占用4字节可变参数槽。
// 上游声明、格式宽度和实际压栈类型须一致；无法从这些访问器自动发现格式/实参错配。
//
// 932CD0：对本题字符串流的精确结论
// ----------------------------------------------------------------------------
// 本体File参数为NULL时报告flsbuf.c第102行，返回1才INT3，随后仍继续。
// 932D03先读取对象+16为文件句柄；该值尚未成为文件写入实参便经过标志筛选。
// 932D0F检查flag&82h；为0，或者flag&40h非0，均走932D22设20h错误位并返回-1。
// sprintf设42h，所以_cnt耗尽时必经这条字符串流拒绝分支，不刷新磁盘、不扩容Buffer。
// 932CD0自身完整汇编已读，但文件分支依赖isatty/getbuf/write/lseek的内部均未审阅。
// 这些后段涉及读写切换、缓冲重置、FILE+24容量与写入结果比较；本专题仅保留导航。
// 本体读取+16不意味着sprintf已把该成员初始化，更不等于实际调用了文件系统API。
//
// 返回和收尾极限
// ----------------------------------------------------------------------------
// __output见累计-1后在下一轮终止；sprintf仍按Buffer非NULL尝试追加NUL。
// 收尾的flsbuf返回值被丢弃，所以入口返回值不包含“终止NUL写入成功”的单独承诺。
// 7FFFFFFFh计数不是现实分配空间；即使返回正数，也不能推出写入符合调用者数组界限。
// Buffer=NULL的计数路径按32位加法累计，超大长度回绕没有全局拒绝；未做实机验证。
// 正常有限输入、有效且足量目标、合法格式和匹配实参仍是业务调用者需要证明的条件。
