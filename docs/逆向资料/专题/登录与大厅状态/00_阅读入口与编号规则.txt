// 四种编号必须分列
//
// wire_type：TCP大厅帧type字段，32位有符号整数；本文十进制。
// scheduler_key：错误调度器匹配请求的32位键，常与C2S type相同但不能假定。
// callback_category：本地ACB864/ACB868回调类别；不直接在线上传输。
// ui_id：界面注册编号；不是回调类别，更不是服务端消息type。
//
// 例：扩展登录wire_type=600，scheduler_key=600，错误callback_category=58，
// 最后使用UI66、73、64。四层不同编号是正常映射，不能当协议不一致。

// 反编译陷阱：600不是88
//
// 0x87E640伪代码把部分参数误推为char，后续调用显示88。
// 完整汇编三处都push 258h：登记、待决容器记录、连接失败派发，均为600。
// 0x88D340包头汇编同样push258h；不是88号登录协议。
// 0x834BC0按DWORD取键并有符号比较，0x86BB60按DWORD复制键值对。
// 最终结论：此处没有已证明的600/88错配，不作为BUG登记。
// 原始错误伪码照原样保存，用ABI和汇编说明纠正而不修改IDA类型掩盖证据。

// 反编译陷阱：不是C++异常门槛

// IDA把该函数误命名为__uncaught_exception；不能据名字解释成异常处理。
