// ErrorScheduler本身未提供通用超时证明
//
// 目前恢复的调度器入口：登记key、配置默认/专用错误处理器、按错误分派、取消。
// 所有者链表节点只保存key，结构见05；没有逐节点deadline或retry_count。
// 87E170的静态直接调用点（经60564E）为：
//   87DFE0与87E640：登录连接失败，本地产生-143。
//   87FD30：收到大厅wire-1后按包内key/error分派。
//   8A1720：前置对象条件不成立，本地对key10产生-132。
// 尚未找到“遍历所有请求并在超时后87E170”的调用链。
// 这不排除UI、系统消息、底层连接或未恢复的间接调用有自己的时间控制。

// 确证的15秒在哪里
//
// 87EE40建立登录连接，在初始接收前调用8DBDC0(15,0)构造时间值。
// 该类型+0为WORD子秒字段，+4为DWORD秒字段；不能按普通timeval布局读取。
// 88DD50把值保存在接收包装对象+0x30，并在+0x38构造88DE20适配器。
// 88E1B0每次入口把保存时间复制到适配器+0x10，再经其虚表+4调用88DEE0。
// 虚表A2FE2C+4→6052E8→88DEE0，已保存原始表字节和跳板。
// 88DEE0以适配器+0x14为tv_sec，WORD +0x10为tv_usec，调用select。
// 初始值因此是15秒、0微秒；select返回0时写errno=11并返回-1。
// select非0的分支继续87C1E0底层读取，包括select返回错误的情形，
// 不能把“走非0分支”写成select已经确定成功。
// 时间更新辅助函数和异常时间值未在本批逐项证明；不宣称整个登录绝对15秒结束。

// 连接初始读取失败后的处理
//
// 87EE40检查88E1B0返回值<=0时，析构已有+112与+116对象并将它们清零，
// 退出该连接路径并返回0。上层常规/扩展登录入口再产生本地-143。
// 类别58的UI收尾仍依02所述双门槛、6AFB60与6A1190路径执行。
// 这段是登录连接阶段初始读取的失败路径，不能复制为房间type3/7/8的通用超时。

// 容易误读的87ED10不是已经证明的重连
//
// 87ED10先调用this+112传输对象虚表+8，再取保存的地址字符串和WORD端口。
// 之后调用898C30；898C30构造“地址:端口”键，交8996E0查询范围并移除。
// 8996E0→89A950确定键范围，89A7D0执行范围清理；当前链不调用87EE40。
// 这里是连接管理登记清理证据，不应仅因读取了地址端口就命名为自动重连。
// 87ED10还作为大厅基类虚表条目存在；已发现的直接业务调用来自855E10。
// 不排除上层在清理返回后另行发起连接；那需要独立追调用者。

// 登录派生对象的断开通知与自释放
//
// 虚表A2F704的+16→855F50：发本地成功通道类别108，置this+212为1，
// 随后87ECA0调用this+112传输对象虚表+8。
// 虚表+20→855E10：若+212非零，调用虚表+16；否则发本地类别35。
// 接着87ED10清理连接登记，最后调用自身虚表+0，参数1，释放自身。
// 登录析构855600会先清理+0xC8请求键链表，再进入大厅基类87DD40资源释放。
// 类别35/108和+212的游戏界面文案、所有动态触发源尚未完整闭环。
// 不把“成功回调通道”中的类别名称等同于登录成功；这里也承载状态通知。

// 重试结论的界限
//
// 已审连接函数没有重试循环；87EE40的静态直接调用者仅常规和扩展登录入口。
// 重新调用这些请求会重复登记相同key，替换旧ErrorBundle并向所有者链表追加键。
// 上层按钮、定时器和外部调用仍可能重新进入入口；本批没有全局排除这些来源。
// 因此排查时分别记录：首次连接、初始读取超时、收到错误、UI收尾、对象销毁、
// 再次调用请求。不能只依据同type重复日志判断是客户端自动超时重试。
