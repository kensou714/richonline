// 创建房间
//
// 84F470挂默认错误回调84F700→category3，再调用871600。
// 871600登记scheduler_key3，构造871720→874700，C2S wire3。
// 创建载荷固定128字节加扩展，扩展与E88字段参见既有房间协议资料。
// 服务端错误统一wire-1并携带key3，87E170匹配后回调、释放、erase。
// category3→6AFEF0：错误-144/-142/-124/-119/-105各有文本分支，
// 其余走541，操作UI74与UI64并提交本地结果记录。
// 不把提交本地记录直接命名为TCP回复，也不把UI API污染名称当真实语义。

// 进入房间
//
// 84E3E0挂默认回调84EFB0→category7；870C80登记key7，
// 870DA0→874540构造C2S wire7，载荷4字节目标键。
// wire-1/key7错误→category7→6B0220，操作UI64、73并调用6A1190重置状态。
// 错误-147/-133→文本537，-132→710，-124→733，-104→536，其余538。
//
// S2C wire10：读取两个前缀DWORD并解析房间记录，构造887290事件。
// 事件执行地址887310未声明IDA函数，本批保存完整只读汇编范围。
// 887670比较房间对象关联ID与本地身份；命中时设置当前房间指针，
// 修改本地身份/容量相关字段后调用房间管理器虚表+16。
// 不命中则依初始化标志更新已有房间或加入房间表。
// 因而相同wire10既可能完成本地进入，也可能只是更新旁观列表。

// 离开房间
//
// 84F060挂默认回调84F2E0→category8；870F60登记key8，
// 871070→874620构造C2S wire8，载荷DWORD0。
// category8不在6BE8D0的显式switch分支中：错误回调到UI层后走默认返回。
// 外层87E170仍会释放bundle并erase，所以仅能称“缺少此分发器的提示分支”。
// 尚未证明该请求的UI等待由哪里收尾；不能把默认返回直接称必现卡等。

// 主要S2C事件与存储
//
// wire5：解析房间，保存前缀键到大厅对象+132，构造886F40。
// 执行地址886FB0读取事件+8，经871E60加入房间关联容器。
// wire10：887290/887310，区分本地房间与列表更新，见上。
// wire16：8870E0/887150，经房间管理对象虚表+8通知。
// wire30：完成数值整合后经房间管理对象虚表+4通知，属于初始化依赖链。
// 以上成功事件未统一调用87E170(error)，不能虚构一个全协议通用ACK清等待。

// 房间转游戏：S2C wire22
//
// 87FD30对应原汇编case22（伪代码case24是switch归一化后的值），
// 读取IPv4 DWORD、端口WORD、额外DWORD、8字节令牌。
// 经管理器虚表+4创建独立游戏对象，然后87A110建立TCP并发送游戏type0。
// 此处不是登录派生对象的虚表+12；两处构造入口属于不同对象，不能混用。
// 游戏入场消息携带管理器键、房间键、自身ID、令牌和额外DWORD。
// 不要把内层0x4000初始化当成额外大厅“开始游戏”请求。

// 重要返回值陷阱
//
// 87A110只有内部连接函数成功才构造并发送type0，
// 但无论内部连接是否成功，最终都return1。
// 87FD30据这个返回值把新游戏对象挂到管理器+44；
// 因而“对象已保存”或“87A110返回成功”并不能证明游戏TCP连通。
// 排查此处等待要看真实connect结果、游戏type0是否发出、type1/299是否回来。

// 本地成功通知不是网络帧
//
// ACB864成功回调类别0x12经6BE2E0→6AC070处理对象离开/移除关联。
// 满足当前对象与游戏状态条件时会进入本地消息0x6021路径。
// 这属于本地队列状态通知，不能将其直接发给服务器作为线上ACK。
// 0x6021及消费抑制状态由并行队列/解析专题继续闭环；本批不重复命名其业务。
