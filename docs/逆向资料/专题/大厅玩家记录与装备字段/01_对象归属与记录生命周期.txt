// ============================================================================
// 对象归属与记录生命周期
// ============================================================================
// 记号：DWORD 为 4 字节；所有 +偏移均为十进制字节数。
// L = 大厅侧控制对象；U(id) = 底层玩家对象；R(id) = 对外记录视图。
//
// 对象链
//   610DB9 -> 628270：取得单例；首次分配 0xABC 字节并保存到 A76728。
//   6BE2E0 的相关通知分支取得该单例，再调用本专题的记录与装备处理函数。
//   82B090 case 0：按 signed WORD 玩家 ID 找到 U，再调用 856C30。
//   856C30 刷新 U 内部的记录区，并返回 U+128；因此 R(id)=U(id)+128。
//   L 的指针表条目只借用该视图，不能独立 delete R(id)。
//
// L 的已确认字段
//   +1228  DWORD  配置容量；6B7900 返回此值。
//   +1236  指针   R 指针表；R(id)=DWORD[DWORD[L+1236]+4*id]。
//   +1240  DWORD  本次分配的表容量；6A2480 从 +1228 复制而来。
//   +1248/+1252/+1256/+1260  四个同容量旁表；用途本专题不命名。
//   +1264  DWORD  自身玩家 ID；629E30 直接返回。
//   +1292  DWORD  6A2E30 从 R(self)+76 复制；自然含义尚未确认。
//
// R 的稳定入口
//   +52   DWORD    6B7A90 返回；缺记录时返回 0；自然含义未确认。
//   +112  字符地址 玩家名字，64F0C0 返回该地址；缺记录时返回 NULL。
//   +144  DWORD[32] 装备槽原始编码；对应 U+272，共 128 字节。
//   R 的名字对应 U+240；856C30 将底层名字复制到此处。
//   本文只声明已访问区，不据此声称完整 R/U 结构大小已经恢复。
//
// 分配与释放
//   6A2480：分配 4*capacity 字节的 R 指针表并清零；另分配四个旁表。
//   旁表在该函数中没有同样的 memset；不可写成“五张表均已清零”。
//   6A2350：分别 delete[] 五个数组并置 NULL，不遍历释放 R(id)。
//   此函数没有重置容量或自身 ID；外层生命周期条件仍须单独保证。
//   6A2E30：selector case 3 写自身 ID，case 43/45 各复制 28/32 字节。
//   伪码中的 CWnd::GetClientRect 实际是 60F1E4 -> 82B090 数据选择器。
//
// 通知对应关系：以下是 6BE2E0 的本地通知码，不是网络 opcode。
//   2    -> 6AAEF0：从 p+4 取 signed WORD id，重新取得 R(id) 并保存。
//   5    -> 6AB0D0：复制名字、将 R 表条目清零，再通知相关界面刷新。
//   8    -> 6AB340：重新绑定 R(id)，刷新玩家详情及列表的相关界面。
//   20   -> 6AC1D0：重新绑定 R(id)，按房间/自身条件刷新相关界面。
//   6ADEC0 也会重取 R(id)；其输入与界面分支只作字段更新旁证。
//
// 离开路径的尺寸细节
//   6AB0D0 的名字局部变量 RTC 名为 rName，容量 33 字节。
//   strncpy 的 Count 为 32；反编译器显示 Destination[40] 不是实际声明。
//   此处不释放底层 U，也不把复制长度当成通知包长度。
//
// 查找与边界
//   6A25E0 / 6A2D90：在 [0,capacity) 中逐个检查条目，strcmp 名字。
//   返回首个匹配 ID；未找到返回 -1；没有大小写或编码归一化过程。
//   64F120 只检查 table[id] 是否非 NULL，不检查 id 或表指针的有效性。
//   64F090 直接取 table[self]，没有 NULL 或范围检查。
//   名字/装备 getter 的缺记录返回值不等于完整边界保护。
//   新工具须先校验表已建立、0<=id<capacity、记录存在，再访问字段。
//
// 原证：record_access、record_lifecycle、record_sources、capacity、
//       equipment_actions、notification_dispatch 及 data_ranges.json。
