// ============================================================================
// 换装请求与成功通知
// ============================================================================
// 以下闭合的是静态客户端路径；成功通知与网络响应的完整映射仍待抓包确认。
//
// 三层编号必须分开记录
//   行为     828F60 本地命令类别    序列化业务操作    6BE2E0 本地成功通知
//   穿戴     52                   51               63 / 0x3F
//   卸下     53                   52               64 / 0x40
//   同一个数值出现在不同分派器中，不代表同一个通信协议字段。
//
// 穿戴入口：605E3C -> 6A32A0(L,slot,newRaw)
//   读取 6B7970(self,slot) 得到 oldRaw。
//   oldRaw<=0：构造 {self,slot,newRaw}，以类别 52 调 828F60。
//   oldRaw>0 ：L+1272=1，L+1276=slot，L+1280=newRaw；随后提交卸下。
//   两条路径最后均写 L+1288=slot，并关闭界面 100。
//   RTC 确认局部 xData 是 12 字节；不是伪码的五元素数组。
//
// 卸下入口：5FFCF8 -> 6A3390(L,slot,oldRaw)
//   写 L+1288=slot；构造 {self,slot,oldRaw}，以类别 53 调 828F60。
//   RTC 同样确认 xData 为 12 字节。
//   828F60 case53 只传 slot 给下层，未消费 xData[2] 中的 oldRaw。
//   下层 8ACC20 按 slot 查当前装备对象；不存在则不构造卸下请求。
//
// 提交链
//   case52 -> 84B550 -> 8AC920 -> 8ACA40，参数沿调用栈最终写入 1,slot,newRaw。
//   case53 -> 84B950 -> 8ACC20 -> 8ACD70，写入 1,slot,当前装备对象的 +8 值。
//   8403B0 返回该对象 +8；不能用先前 UI 缓存 oldRaw 替代这次查询。
//   84B550/84B950 注册完成回调并建立任务；任务框架与发送器仅作外部边界。
//   84B8A0/84BC20 将全局 A6779C、A677A0 复位为 -1，并回调业务码 51/52。
//   本专题不把“注册回调”本身当成网络已经收到成功响应。
//
// 反编译类型修正
//   868530 在栈参数地址复制 4 字节，返回 this，ret 4；伪码 char 不可信。
//   8ACA40/8ACD70 使用完整 DWORD 压栈，不能把物品编号截断到 8 位。
//   8ACF50/8AD030 请求基础容量为传入长度+12，本组传入 12。
//   两函数首先写完整常量 0x10A1D85F，再写业务码 51/52。
//   伪码把完整常量显示为 95，是 char 类型传播造成的截断。
//   随后还有长度相关写入；未审发送器封装，不把构造序列当作最终线上包。
//
// 穿戴成功：6BE2E0 case63 -> 6AE370
//   p+2 的 WORD 低 12 位在 520..600 时刷新界面 74、75。
//   p+4 作为 signed WORD 玩家 ID；自身时刷新背包分类及相关界面。
//   自身显示 RichStr 622“裝備飾品成功!”；外人走相关房间界面刷新分支。
//   本函数没有主动发送下一次穿戴请求。
//
// 卸下成功：6BE2E0 case64 -> 6AE5A0
//   同样读取 p+2、p+4，按自身/他人选择界面刷新路径。
//   自身路径在刷新后依次检查三个标志，优先级不可交换：
//     L+1272：清零，再调用 6A32A0(L+1276,L+1280)，完成先卸后穿。
//     L+1271：清零，显示 RichStr 725 的角色改变、特殊装备自动卸下提示。
//     L+1273：清零，以 L+1284 查名字显示过期提示，再调用 6A3500。
//   三者均未命中，显示 RichStr 623“卸下飾品成功!”。
//   6B14F0 展示 RichStr 621“卸下飾品失敗!”并清 L+1272；其外层来源未全追。
//
// 对通信排障的直接意义
//   卸下之后不再穿戴：先检查成功通知是否走到 6AE5A0、自身 ID 是否匹配、
//   L+1272 是否仍置位，再核对底层装备数据是否已在通知前更新。
//   6AE5A0 本身不直接清 R 的槽；重入 6A32A0 时仍会读取该视图。
//   若模型尚未更新，会再次看到旧装备；静态路径不足以证明实际发生该故障。
//   重复或乱序通知的动态行为尚未验证；不可无条件补发某个“完成包”。
//
// 原证：equipment_actions、equipment_flow、equipment_requests、packet_fields、
//       equipment_success、notification_dispatch、data_ranges、rtc_ranges.json。
