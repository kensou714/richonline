// ============================================================================
// 装备槽与编码契约
// ============================================================================
// 输入域：大厅记录视图 R；不能替换为棋盘角色的八槽道具库存。
// 槽号：0..31；三个遍历函数使用 32，856C30 将对应区清零 0x80 字节。
//
// 两种读取接口
//   604C44 -> 6B7970(id,slot)：返回 R(id)+144+4*slot 的完整 DWORD。
//   60EF41 -> 6B7A20(id,slot)：读取同一 DWORD 后执行 &0xFFF。
//   二者缺记录时返回 0；二者都没有校验 slot 或 id 的上下界。
//   低 12 位表示物品编号；原值中的其余位必须保留，不可统一清除。
//
// 现有位语义
//   bits 0..11：物品编号，范围由掩码限定为 0..4095。
//   bit 16：本专题确认其参与过期装备筛选与自动卸下处理。
//   bits 12..15、17..31：本专题不命名，不能假设保留位永远为零。
//
// 过期证据链
//   6A3500 遍历 32 槽，只处理 raw!=0 且 (raw&0x10000)!=0 的首项。
//   先调用 6A3390(slot,raw)，再置 L+1273，并保存 raw&0xFFF 到 L+1284。
//   卸下成功通知 6AE5A0 消费该标志，显示 RichStr 753 后再次调用 6A3500。
//   原文：“您的裝備[%s]已過期，`n自動卸下!”。
//   这支持“过期处理标志”的名称；并未证明时间戳格式、时区或过期计算端。
//   自动卸下按通知逐件推进，不是一次遍历立即提交所有槽位。
//
// 比较语义并不相同
//   6A3490(raw)：将参数与自身 32 槽的完整 DWORD 比较，找到即返回 1。
//   它不屏蔽状态位；不同高位但相同编号可能不相等。
//   输入 0 也会匹配空槽，因此不能把该函数无条件命名为“拥有物品”。
//
// 6A7900(itemID, requireEquipped) 的双重条件
//   L+1596 指向 O，DWORD[O] 是数量，DWORD[O+4] 是 8 字节记录数组。
//   先找 (row.raw&0xFFF)==itemID 且 bit16==0 的背包条目。
//   requireEquipped==0：有上述条目便返回 1。
//   requireEquipped!=0：还须自身 32 槽中有低 12 位等于 itemID 的装备。
//   未找到返回 0；该函数不是仅扫描装备，也不按完整 raw 比较。
//   6A71C0 从 selector case19 重取 O 并建立若干分类视图；只审此来源。
//   本专题不赋予每条 8 字节记录第二个 DWORD 的自然名称。
//
// 原始正负判断
//   6A32A0 用 signed raw<=0 判断可直接提交穿戴，否则先卸下。
//   这是有符号比较，不能在重写时悄悄简化成 raw==0。
//   raw 高位有效域尚未完整恢复，不据此制造带 bit31 的“合法物品”。
//
// 扩充约束
//   只加配置无法突破低 12 位编号限制或 32 槽循环上限。
//   装备管理工具应分别显示 raw、编号、slot、已知状态，保留未知位。
//   保存操作前应校验 0<=slot<32；调用原 getter 不会自动提供该保护。
//
// 原证：record_access、record_lifecycle、record_sources、equipment_actions、
//       equipment_flow、bag_refresh、resource_samples.json。
