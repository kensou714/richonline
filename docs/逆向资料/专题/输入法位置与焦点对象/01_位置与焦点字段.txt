// U = dword_ACC3C8 指向的 UI 对象；C = DWORD[U+20716(0x50EC)]。
// 629F80：ECX=U，返回 C；没有 U 空指针检查。
// 625C27 取全局 U，625C2D 经 60D4C5 调 629F80，然后才检查 C 是否为零。
// 因而“无焦点则不调位置 API”已确认；“无 UI 对象也安全返回”没有依据。
//
// 控件字段与坐标
//   +344(0x158) 相对 X；+348(0x15C) 相对 Y。
//   +356(0x164) 高度；629EF0 直接返回这个 DWORD。
//   +360(0x168) 绝对 X；629F20 直接返回这个 DWORD。
//   +364(0x16C) 绝对 Y；629F50 直接返回这个 DWORD。
//   +400(0x190) 父对象指针；这里的含义由 8E30D0 的局部坐标更新复核。
// 8E30D0：有父对象时，绝对位置 = 相对位置 + 父绝对位置；没有父对象
// 时二者相等。随后回写相对位置并清零 +28/+32/+36/+40 四个 DWORD。
// 本篇不为这四个缓存字段赋业务名，也不证明全部移动入口均调用更新器。
//
// 625C10 使用 POINT = { C.absoluteX, C.absoluteY + C.height + 4 }。
// 这是控件下沿再加 4 的位置，不是编辑文本插入光标的字位坐标。
// 函数内没有 ClientToScreen/ScreenToClient，也没有 DPI、缩放或负值钳制。
// “绝对”指本控件树累计坐标，不能据此称为桌面屏幕坐标。
// 更改渲染缩放时需另外核实 HWND 客户区与 UI 坐标系统的一致性。
//
// 组合窗参数
//   625C6D ImmGetCompositionWindow(HIMC, &CompForm)，不检查 BOOL。
//   625C72 设置 CompForm.dwStyle=0x20，即 CFS_FORCE_POSITION。
//   625C7C/82 写入 POINT，再 625C8F 调 ImmSetCompositionWindow。
//   rcArea 没有主动覆盖。样式的操作含义以 Windows SDK 为准。
//
// 候选窗参数
//   625CA0 ImmGetCandidateWindow(HIMC, 0, &Candidate)，查询第 0 个列表。
//   625CA8/AE 只写 Candidate.ptCurrentPos，625CBB 调 SetCandidateWindow。
//   dwIndex、dwStyle、rcArea 均依赖 Get 留下的内容；没有主动设置样式。
//   因而不能声称客户端总是强制候选窗口按某一种样式贴在控件下方。
//
// 失败与返回值边界
// 625C20/25 先用 0xCCCCCCCC 填充 0x60 字节栈局部区域。
// 两个 Get 的返回值均未测试；若失败且未填全输出，未覆盖字段可能仍为
// CC 或部分输出。传给 Set 的结果与实际 API 实现有关，这是静态风险。
// 四次读句柄均经 61276D -> 629FB0，没有 HIMC 空值检查。
// 两个 Set 的 BOOL 也没有控制流判断，没有回退、重试或错误日志。
// C=0 时返回 0；成功进入主体后返回最后一个 Set 的 EAX 残留值。
// 这不是 CMFCRibbonButton* 返回接口；已见 WndProc 调用方忽略此返回值。
// 尚未做任何实机失败注入，不能把上述风险写成已复现的用户故障。
//
// 原证：ime_seeds.json 的 625C10/629EF0/629F20/629F50/629F80；
//       ime_dependencies.json 的 8E30D0。焦点设置/销毁详见输入与快捷键
