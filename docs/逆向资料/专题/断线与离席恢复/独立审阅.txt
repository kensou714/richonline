// 二、4009补发条件与字段
// 65C340先验证包内+2 WORD，再读取+4有符号BYTE槽和+5 BYTE子类型。
// 仅当槽等于G+8记录的本机槽时进入补发分支；远端槽只显示等待提示。
// 每个子类型分支再次检查P(slot)+384是否为1；为1时不重建请求。
// 子类型2、14、17、26分别构造WORD 0x0011、0x0012、0x0028、0x002A，
// 调用者随后写入两个WORD并以长度6提交。+2来自G+0xC48低16位，+4来自P(slot)+1464低16位。
// 因此这四个WORD不是收到包的+2或+4原样转发，也不是GmsvID原值。
// 发送还经过610977至6BF380；6BF380要求主状态小于12且连接谓词成立。
// 未命中子类型、非本机槽、P+384等于1或发送门槛失败时，均不能推断有ACK或pending清理。

// 三、4009局部缓冲大小更正
// 65C340伪代码把局部对象显示为char Buffer[132]，这是反编译器依据栈布局的合并显示。
// 当前PE的RTC表位于0x65C671，首项记录offset=-144、size=128、名称szTmp，
// 0x65C671起20字节：05 00 00 00 79 C6 65 00 70 FF FF FF 80 00 00 00 CD C6 65 00。
// 前8字节为count=5与数组指针0x65C679；首项12字节为offset/size/name三个DWORD。
// 0x65C6CD字符串原字节：73 7A 54 6D 70 00，即szTmp加终止零。
// 其余四项为每个6字节xPack。按RTC边界，sprintf目标实际为128字节szTmp；
// 132字节是包含相邻调试填充或栈布局的表观范围，正文不应写成有效缓冲容量132。
// sprintf仍无独立容量参数，姓名和资源字符串的长度约束仍是未决风险。

// 四、400A本机与远端离席
// 入口读取+2 WORD、+4有符号BYTE槽、+6有符号WORD、+8 DWORD、+12 BYTE；+5未使用。
// 本机槽命中时调用65C0D0(0)，该函数跳过包ID读取，修改连接对象首字节并切换主状态7。
// 这条本机分支没有证据表明会关闭socket、释放对象、改远端槽字段或直接写pending。
// 远端槽先要求存在位有效，再清活动位、关系和玩家槽字段；不会删除P(slot)。
// 清理返回后65C700写入160字节槽记录内的+128h DWORD（包+6 WORD符号扩展）、+12Ch DWORD、+135h=0、+136h=1，
// 并按+12是否为零显示“玩家已离线”或“玩家退出游戏”。
// 只有pending WORD为20、G+83813等于该槽且G+83812为3时，才构造6004。
// 6004消费者67DB40只读取+2和+4并调用7BB430，将pending改为1、更新时长和Tick；不读取+8。
// current等于本机槽时另发6006；这与6004的pending链是两条不同操作。

// 五、400B、6006与6021边界
// 400B先验证+2 WORD；current槽位置取P(current)+1464，地图中心计算使用宽度和高度索引。
// current等于本机槽时构造4字节6006，+2写入收到包的+4操作字节，+3未赋值。
// 400B的空包入口可跳过ID验证，但current等于本机槽时65CAD5仍读取包指针+4；
// 空指针在该静态分支会形成地址4读取风险，外层是否能以空包调用到达此处未证。
// 65C0D0(0)则在空参分支后不再读取包数据，两者不能使用同一空包安全结论。
// 6006消费者67DBE0只有操作字节非零且P(current)+1493/+1494/+1495均为-1时传入1，
// 否则传入0；该分支最终调用712610做操作、鼠标和UI掩码处理。
// 400B、400A和6006均没有写G+83831抑制位，也不构造6021。
// 6021链单独由7EED01至67E410触发，设置G+83831=1并记录G+152 Tick；
// 650460在UI36开启后以无符号elapsed达到2000切换主状态4。它既不等同于本机离席的状态7，
// 也不等同于400A清理后发送6004的pending=20至1过程。
