// ============================================================================
// 4009 -> 65C340：提示等待目标玩家，按子类型重建请求
// ============================================================================
// 直接读取跨度6字节：+2 WORD GmsvID，+4 signed BYTE slot，+5 BYTE子类型。
// 本handler没有独立长度参数或slot范围校验；直接字段跨度不能写成完整网络帧长度。

// 先提示，再决定本机是否补发
// GmsvID通过后，取P(slot)+112名称指针；时间单例62A0A0经81BC30更新本地时间。
// 按“<%02d:%02d:%02d> %s%s %s”拼出时间、RichStr[16]、RichStr[12]和玩家名。
// 当前资源16=“等待”、12=“玩家”；因此该提示为“等待玩家”，不是“重连成功”。
// 649A30用颜色0xFF00D0D0加入文字显示链；625D30另复制至全局MultiByteStr并更新Tick。
// 文字拼接是本地显示，不是由本函数把提示字符串发给服务器。
// RTC栈变量表65C671有5项；首项65C679记录offset=-144、size=128、name=65C6CD(szTmp)。
// 实际声明缓冲为128字节；Hex-Rays的Buffer[132]合并了邻接哨兵，原伪代码保留作原证。
// sprintf没有独立长度参数；名字和资源合法性须在来源处另查，不能据声明大小保证拼接安全。

// 补发门槛
// 65C43B经63E560检查packet.slot == DWORD[G+8]；远端槽不执行以下四个请求分支。
// 每个分支再用packet.slot取得P，693860检查DWORD[P+384]是否等于1。
// P+384==1则不重建请求；字段的完整业务名称尚未确认，不能擅自写成“正在断线”。
// 未匹配四个子类型时只保留提示，不执行默认补发、pending清零或状态切换。

// 子类型与六字节请求
// packet+5   构造实现   请求WORD   发送调用点
// 2          693890     0x0011     65C4EC
// 14         6938C0     0x0012     65C55D
// 17         6938F0     0x0028     65C5CE
// 26         693920     0x002A     65C63C
// 四个构造实现都只写WORD操作码；随后调用者填满+2/+4两个WORD，提交长度6。
// +2 = low16(DWORD[G+0xC48])：63E590返回G+0xC44，63E440读取子对象+4。
// +4 = low16(DWORD[P(packet.slot)+1464])：63E410取该槽当前位置。
// +2不是直接读取G+83844的GmsvID；也不是照抄收到的packet+2。
// 这里根据当前位置重新组包，没有读取旧发送包缓冲；“重发”不表示原封不动重传字节。

// 调入口与实际发送分开
// 四条路径调用610977 -> 6BF380，而6BF380先要求主状态<12，再检查连接谓词。
// 只有通过门槛才封包并进入6042DA的通道9提交路径；handler返回值不能当网络ACK。
// 本函数没有写pending类型/时长，没有直接插6006，也没有清6021抑制位。
// 若服务端期待补发而无日志，应同时核对slot==local、P+384、子类型、主状态和连接门槛。
// 四种子类型的服务端语义及原始请求触发点尚需对应协议专题继续确认。
