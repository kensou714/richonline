// 7FAAD0初始化
// ----------------------------------------------------------------------------
// 从外部Src复制固定18字节位置；清count并将9个标志逐一清0。
// 遍历全部9槽，对位置!=-1的项累计count；不移动位置项、不压紧空洞。
// 因而数据应把有效位置连续放在前count槽。若前部有-1、后部仍有有效位置，
// 下述只遍历前count的函数会漏掉尾部位置。这是结构契约，不是已确认地图故障。
//
// 7FAB70 / 7FAC40：按位置查询与设置
// ----------------------------------------------------------------------------
// 循环i<count，位置按signed WORD扩成DWORD后与传入位置比较。
// 7FAB70匹配时返回标志BYTE，找不到返回1；缺席位置因此按已处理方向走。
// 7FAC40只把首次匹配的标志写1；找不到不追加、不报错、不扣款。
// 重复位置只命中第一项，另一个同位置项可能永远保持0；内容工具应检查唯一性。
// 4040接受handler并不检查7FAC40是否找到，随后仍执行扣款。
//
// 7FABE0 / 7FACB0：全完成与重置
// ----------------------------------------------------------------------------
// 7FABE0只要前count中存在0就返回0，否则返回1；count为0时直接返回1。
// 7FACB0清前count标志，不改位置和计数。计数没有在这些函数内重新校验0..9。
// 不要用“空集合返回完成”推导线上必有免费回报；须核实际地图初始化和入口可达性。
//
// kind67：落点与途中两条消费者
// ----------------------------------------------------------------------------
// 7C54B0的case67：先查当前角色是否全完成。全完成则插入6060和提示记录，再清标志。
// 未完成时，当前格未标记且signed现金严格大于investBase，则记中途标志0并返回0，
// 交给调用者后继流程；本分支本身不直接打开UI43。
// 7F5D90途中kind67也先查全完成；其额外门槛与002A请求见01。
// 两个大函数只分析投资分支，其他格类、移动与角色效果不在本清单完成范围内。
//
// 回报不是接受4040时立即发放
// ----------------------------------------------------------------------------
// 4040将当前格置1并扣本金，没有调用全完成判断和回报函数。
// 全完成检查发生在下一次进入上述kind67处理分支时，且在检查当前格是否已投资之前。
// 因而不能把“本次选是后已集齐”直接等同于“该4040同时发回报”。
// 回报字段是DWORD[L+1320]，取当前关卡值；确认投资后改配置可能造成显示/扣款/回报不一致。
//

// ----------------------------------------------------------------------------
