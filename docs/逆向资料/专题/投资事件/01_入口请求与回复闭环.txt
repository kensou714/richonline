// ============================================================================
// 投资通信与等待闭环
// ============================================================================
// G为游戏对象；slot=DWORD[G+0xE28]；P=DWORD[G+0xE00+4*slot]。
// L=DWORD[G+0xDF8]为当前关卡对象；P+1464为当前格。
// 消息号用十六进制，pending/UI编号用十进制。版本与复用原证见00。
//
// 4012 -> 7EF8F0 -> 65DAA0
// ----------------------------------------------------------------------------
// +0 WORD消息号；+2 WORD回复GmsvID；+4 signed WORD目标格；+6 BYTE中途标志。
// handler无独立长度参数。错位分支复制完整8字节，所以调用契约不能缩成7字节。
// 先64F710与WORD[G+83844]比较；失败弹错误并退出，不打开投资UI。
// 中途标志为0直接进入；标志非0要求目标格等于当前角色位置。
// 不匹配时复制原8字节，用63E5B0取得head，再64FA50插到该head之前。
// 本handler随即返回；不是网络重发，也不是在函数内忙等。持续错位可能挡住后续队列项。
//
// 进入时693B80把原中途字节保存到G+83833；它与银行G+83832、消费抑制位不同。
// 本地行动者打开UI43，持续参数8000，通知参数为0；UI自行取当前关卡金额。
// 所有客户端经7BB430设置pending27、duration8000和起始Tick。
// 这里没有余额检查；请求入口的前置检查不能代替服务端对回复的约束。
//
// 途中主动申请002A
// ----------------------------------------------------------------------------
// 7F5D90处理kind67的分支检查P+1488!=7、P+1499==0及7D5E10谓词为假。
// 若尚未全部投资、当前格标志为0，且signed现金严格大于investBase，才请求投资选择。
// 现金恰等本金不会进入此分支。7F5D10设置移动内部状态2并清DWORD[P+548]。
// 随后标记G+83833=1；693920构造首WORD002A，记录+2取G+0xC48低WORD，
// +4为当前格低WORD，按6字节提交。它申请投资窗口，不是直接支付本金的002B。
// 此处三项门槛仅按字段/谓词表达；尚未将角色状态7、P+1499、7D5E10全命名为产品概念。
//
// 7BC600 -> 002B选择请求
// ----------------------------------------------------------------------------
// 7D6170仅写首WORD002B；+2从G+0xC44子对象的+4 DWORD取低WORD，即G+0xC48。
// +4复制调用参数的低BYTE，不在发送函数内部归一化为0/1；+5保留栈初始化0xCC。
// 长度6，没有金额、地点或动作序号字段。+2不是接收校验的GmsvID字段。
// 仅63F760判定当前行动者为本地时调用6BF380并关闭UI43；非本地不发送、不关窗。
// 发送包装受主状态与连接谓词约束；关窗不代表服务器已经收到或处理。
//
// 4040 -> 7EFEB0 -> 662780
// ----------------------------------------------------------------------------
// 本handler直接消费+2 WORD GmsvID、+4 BYTE选择，读取跨度5字节；不能据此声称线包只需5。
// 校验GmsvID前即保存队列head。校验通过后关闭UI43；只在+4恰等1时执行投资。
// 接受：读取当前行动角色当前位置，7FAC40将匹配投资格标志写1；
// 再取DWORD[L+1316]本金，7F83F0(P,本金,1)扣现金，不足会继续扣存款并归零。
// 该资金函数返回值未作为拒绝条件；7FAC40没找到格时也不会阻止后续扣款。
// 两步各自重读当前行动槽；不是回复包指定角色，也不是入口固定角色快照。
// 本handler不检查pending27、原请求选择、余额、当前位置是否目标投资格或是否重复接受。
// 重复4040可能重复扣本金；这里只证明客户端静态信任边界，不证明服务端允许重放。
//
// 共同收尾
// ----------------------------------------------------------------------------
// 任意非1值均跳过标记/扣款，然后同接受分支一起6939E0清pending与duration。
// G+83833非0：7F5CC0(P,1)恢复移动字段，693FB0把P+1456字节加1，并选择运动音效。
// G+83833为0：构造6080，+2=2、+3=-1，按4字节插入入口保存的head之前。
// 4040本身不将G+83833清零；下一次入口或初始化负责后续值。
// 成功收到回复、完成本地扣款、清等待和继续移动是不同观察点。
//
// 取消、按键与自动选择不可混写
// ----------------------------------------------------------------------------
// 显式取消是选择0；发送0不会本地退还或扣除金额。
// pending27的7BB530自动动作是rand()%100>15，只有门控通过才执行，非固定默认取消。
// 7D5D20要求pending!=-1且无符号elapsed>=1000；没有拿duration8000作此判断。
// UI到期、玩家不操作、自动模式和服务端超时不是同一个入口；未证明全部统一发0。
