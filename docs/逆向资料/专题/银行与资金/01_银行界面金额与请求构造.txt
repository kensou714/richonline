 * 银行UI17：金额编辑、余额快照与12字节请求
 * 证据：bank_ui.json、bank_ui_helpers.json、bank_send_boundary.json。
 */

// 窗口对象W（工厂分配0x60字节）
// W+72 DWORD动作：0存款，1取款；713C00收到角色槽后默认设1。
// W+76 DWORD当前编辑金额，初始化0；显示/比较/除法多按signed32解释。
// W+80 DWORD通知传入的角色槽；W+84现金快照，W+88存款快照。
// W+92图像/样式相关保存值，此批不猜完整语义或初始化来源。
// 713C00通知时读取角色余额并显示；后续编辑使用快照，不每次查询最新余额。

// 键盘入口713D20
// 只有主状态62A0F0返回2才处理。
// Num0..Num9、Backspace、F9使用释放沿；分别转控件ID0..9、21、23的点击处理。
// Esc使用按下沿：7BBE60(2,0)后立即6939E0清本地pending。
// F9确认路径没有这个显式清pending，通常等待402A回复。
// 同帧F键/数字与Esc并非互斥的一整条链；Esc检查位于数字/F9链之后。
// 鼠标与键盘最后共用窗口虚表+120 -> 714080，消息第三参数在该函数未消费。

// 控件ID与编辑规则
// 0..9：若原金额<99999999，再做amount=10*amount+digit。
// 上限检查发生在乘十之前，不能写成“最终金额最多99999999”。
// 10：若原金额<9999999，再乘100；IDA将立即数98967F误展示为loc_98967D+2。
// 20：设为当前动作的全部来源余额。21：signed amount/10。22：设0。
// 30：动作改0；31：动作改1；只刷新选项外观，不自动重新夹紧已有金额。
// 32：提交动作2、金额0。
// 100..110：来源余额*(id-100)/10；先32位imul再cdq/idiv10，不是64位比例计算。
// id为101..110时，正来源金额大于INT_MAX/(id-100)会使中间乘积超出signed32；
// imul只保留低32位，随后cdq按其符号扩展，idiv10向零截断。id100乘0，金额为0。
// 这是指令行为边界，未证明现有服务器余额可达该范围，也未执行UI样例。

// 确认ID23
// 对动作0比较amount>现金快照，动作1比较amount>存款快照；超额则UI4显示文案173。
// 否则amount<=0时动作改2，amount>0用当前动作，传7BBE60(action,amount)。
// 改动作时没有把金额归零；若编辑值为负，仍以action2携带原负值。与ID32的(2,0)不同。
// 本分支没有目的账户容量限制；只按打开窗口时的来源余额判断。
// 714610把两个快照以%d写控件40/41；714540把编辑金额以%d写控件43。

// 7BBE60请求构造
// 先处理特例：action==1且amount==0时，读取当前行动角色全部存款；
// 若仍为0才把action改2。所以直接调用(1,0)语义是取全部，不等价于UI空输入确认。
// 构造7D5FC0仅写首WORD0x0027。
// +2 WORD取G+0xC44子对象的+4低WORD；不是此处从G+83844直接读取。
// +4 WORD动作，+8 DWORD金额，提交长度12。
// 栈记录入口以0xCC填充，+6/+7未在本构造链覆盖，不应将其猜成业务字段。
// 仅本地行动槽匹配时调用6BF380发送包装，然后关闭UI17；非本地不发送不关窗。

// 发送成功与调用成功分开
// 6BF380仅在主状态<12时进入发送链，取得共享锁后检查连接谓词，
// 成立才编码并向类别9交接，更新两个Tick；最后释放锁。
// 7BBE60没有等待网络发送确认就关UI；其返回值不能当成服务器已经处理请求。
// 发送包装完整传输契约见网络协议专题；此批不重复将下游所有函数算银行已分析。

// 内容扩展的直接价值
// 银行界面ID必须与代码绑定0..10、20..23、30..32、40/41/43、100..110保持一致。
// 改按钮文本不会改变存取动作；改ID可能落到另一路逻辑。
// 编辑器应按当前客户端signed32比例与快照规则预览，不用任意精度数学掩盖客户端行为。
// 真正余额约束仍以服务端规则为准；本轮没有更改服务器或界面资源。
