// ============================================================================
// 金额消费和等待：比较发生在扣款前
// ============================================================================
// 字段（R是角色对象；偏移十进制）
//   R+1504 DWORD现金；63F620读取，7FA050加款。
//   R+1508 DWORD存款；63F650读取，7FA0A0加款。
//   R+1512 DWORD点券；7F9D20加款，4078使用；不能并入现金或存款。
//   G+0xC5C子对象+36累计本组罚款金额；693CE0只做+=。
//   汇编665AE3的ECX=G+0xC5C，故累计项为G+0xC80，绝不是R+36。
//
// 6060（693320构造；67FA90消费；本组入队12字节）
//   +0 WORD=0x6060；+2 signed BYTE角色槽；+3 BYTE收入；+4 BYTE支出。
//   +5 BYTE现金；+6 BYTE存款；+8 DWORD金额；+7未显式初始化。
//   构造仅清+3..+6；不要把未写填充字节约定为零。
//   消费优先级：收入+3先于支出+4；现金+5先于存款+6。
//   slot直接用于G+0xE00+4*slot取R；这里没有范围检查。
//
// 现金扣款7F83F0(R,amount,1)
//   先提交负向浮动提示，再cash-=amount。
//   cash<0：deposit+=cash，cash=0；deposit<=0则deposit=0，返回1。
//   cash==0且deposit==0也返回1；其他返回0。
//   6060没有把返回1直接变成阶段2、破产包或网络确认。
//   存款扣款7F9F10只做deposit-=amount，再负值钳0；不消耗现金。
//
// 严格比较693220
//   以当前R为ECX，signed(cash+deposit)>amount；等额返回false。
//   4070/71/73/74/75/76/77/79/7A/7B/7C/7D/7E先排6060，随后才调用比较。
//   此时6060尚未消费，比较是原余额；成功才沿返回游标继续插入6080(stage2)。
//   多个扣款同时排队时不代表每次比较都看到了前一条的执行结果。
//   等额/不足分支没有本函数自己的继续记录；外部破产/回合推进未在本篇闭合。
//
// 6060之后的500毫秒等待
//   67FB64的ECX=G+0x65C，63EDF0检查四个模式谓词的OR。
//   模式通过且目标R的cash<=0，则64FB10(G,500)。不是cash+deposit<=0。
//   63EDF0不是角色破产字段；底层模式枚举复用地图资料，不能凭名字推断。
//   64FB10写G+12 duration和G+16 tick；基础队列到期继续，不是调用Sleep。
//
// 资金浮动提示7F36F0
//   金融函数以ECX=R+0x244调用；其内部16槽，每槽16字节。
//   +0 DWORD金额、+4 BYTE收入标志、+8 DWORD垂直偏移、+12 DWORD tick。
//   读写索引在容器+256/+260；旧项偏移+=16，新项偏移=0，尾=(尾+1)%16。
//   未见满队列保护；不能按一次浮动显示推断权威余额已同步。
//
// 动作阈值
//   scale=DWORD[G+83804]；693等构造不决定币值单位。
//   69B040：amount<1000*scale→15；amount>=5000*scale→13；其余14。
//   69B080：amount<1000*scale→18；amount>=5000*scale→16；其余17。
//   输入金额来自signed WORD；负数及32位乘加溢出没有本层拒绝逻辑。
//   本组无最终余额覆盖字段；重复消息会再次加减，不能当作可重放确认。
