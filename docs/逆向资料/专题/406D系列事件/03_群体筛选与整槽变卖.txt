// 406F / 6657D0：存款第一名可以有多人
//   7C0540按DWORD[G+0xE20]遍历角色，以BYTE[G+0xE30+i]!=0表示参与有效。
//   63E7D0的IDA名IsAutoHideMode误导；此处没有窗格自动隐藏语义。
//   先把8个DWORD临时余额清0；最大值initial=0，signed比较R[i]+1508。
//   第二遍把每个有效角色的存款==最大值写为BYTE mask[i]。
//   406F读取的是单字节mask，不是伪码局部变量名暗示的四DWORD数组。
//   所有有效角色存款0时均入选；全部负存款时可能无人等于初始0。
//   R[i]+112的字符串用于RichStr198 %s；ECX在665895取目标角色已核。
//   每人奖励完整包金额，未分摊；提示/资金/动作逐人串联，结束仅排一个stage2。
//   数量上限由外部初始化保证；本函数未验证G+0xE20<=8。
//
// 4072 / 665EF0：豪雨停走
//   有效角色且signed BYTE[R+1493/1494/1495/1497]全为-1才写R+1496。
//   四谓词依次63F4A0、63EF50、63EF80、63EFB0；694390只写单BYTE。
//   写入来源是DWORD[A8709C]低8位；本消息没有停留天数字段。
//   A8709C在当前IDA为FFFFFFFF，但无PE原始映射，不能称磁盘固定值或运行时值。
//   RichStr201写“一回”；这提供事件用途线索，不足以把变量固定成1。
//   不满足条件的角色完全跳过；没有覆盖已有住院/其他状态。
//   本组医院链证明R+1494为住院剩余值；其他三种状态名称不在此强命名。
//
// 4078 / 666B90：整槽出售给点券
//   循环i=0..7；6943C0检查i<8且signed WORD[R+1520+6*i]!=-1。
//   7F86A0(i,0)取ID；7F8710(i,0)取signed WORD数量。
//   627C20返回商品单例；6940B0以商品ID索引1128字节记录，读+60 DWORD价格。
//   7F9D20(R,price,1)给R+1512点券加一次完整价格，再7F8920(i,originalQuantity)。
//   没有quantity乘法，也没有商店4032使用的SAR1半价。
//   7F8920先减全部数量；signed WORD<=0时写quantity=0、ID=-1。
//   若角色属于本地玩家，随每次移除刷新UI12；不由本函数发4032/0031。
//   点券结算及库存修改在handler里即时执行，UI提示与动作之后才由队列显示。
//
// 六字节槽布局（本篇只消费group0）
//   group0基址R+1520；group1基址R+282；group2基址R+330。
//   每槽+0 signed WORD ID，+2 signed WORD数量，+4..5附加状态未由本组解释。
//   两个getter按group switch选基址，非法group返回-1；未检查slot范围。
