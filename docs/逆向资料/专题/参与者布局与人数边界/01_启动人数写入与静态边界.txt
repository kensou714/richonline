// 证据范围、版本归属见00；所有结论是静态事实或显式待验证假设。

// G+E20的已识别写入
// --------------------------------------------------------------------------
// 65B4D3：movsx eax,byte ptr [packet+11h]；65B4DA：写G+E20。
// 65B7C2：特殊模式进入普通循环前减1；65BB90：完成额外slot1构造后加1。
// 两处增减前提同为691A70→63EDD0检查M+24==2；不是把人数钳制到某个最大值。
// M+24==3分支先走另一循环，不执行该模式2修正；具体模式中文名不在这里强行绑定。
// G构造7BAE60未见直接初始化+E20；相邻+E24初始化为1，+E28=-1、+E2C=0。
// 7BAE60的成员构造未见覆盖E20的已核对范围；对象未完整memset清零。
// 不应假设malloc得到的初始人数必为0；正常生命周期依赖收到并完成4000初始化。

// G+E00表的写入与所有权
// --------------------------------------------------------------------------
// 7BAFD1：构造循环i=0..7将G+E00+4*i置0。
// 65B5E5、65B710：M+24==3分支按i保存新分配P（有资料对象/合成对象两条路径）。
// 65B99F：其他模式非-1对象ID路径按i保存新P。
// 65B887：特殊合成路径按G+E00+4*(n-1)保存，汇编位移DFC不能漏计。
// 65BAFF：模式2在循环后固定i=1创建P并保存；随后两个人数各加1。
// 7BB1DA：析构循环固定i=0..7，删除非空P后置空。
// 65B450覆盖旧指针前本地未调用旧P析构；重复4000是否会到达须追生命周期，不能断言必泄漏。

// 启动记录及局部读取范围
// --------------------------------------------------------------------------
// packet+17为signed参与槽数；packet+18也是signed字节，但写G+8，代表另一个选择字段。
// 每槽步长16：+20+16*i为signed对象ID；+22为signed位置WORD；+24为signed方向BYTE。
// 某些分支将+25+16*i起10字节拷到P+272；i=7时起点137、末字节146，至少147字节。
// 这是已证分支的直接读取下界，不宣称所有模式网络包一律147字节。
// ID==-1才进入合成分支；其他signed ID直接经693680索引*(G+1236)+4*ID。
// 693680没有本地ID范围判断；取得资料指针后初始化器会复制272字节。
// 不能将“人数合法”视为足够验证，ID、位置、方向、角色对象及所需资料记录仍需分别校验。

// 上游验证实际做了什么
// --------------------------------------------------------------------------
// 6BEE80调用7EF120解码后，把解码缓冲和长度交64F870。
// 7EF120检查输入指针非零、输入长度不大于1024及内嵌长度一致；没有按4000检查人数。
// 64F870将4000作为一般记录复制进本地队列，7BB290出队后按代码查表。
// 4000桥7EF6B0接收(G,packet)，改为ECX=G，参数packet交65B450；没有长度参数。
// 检查到的解码—包装—消费—桥接—初始化链均未见把packet+17拒绝/钳制到1..8。
// 外层网络接收、更早的房间合法性、服务端限制尚未全部证明；这是局部链结论。
// 队列每槽288字节是内部复制尺寸，不是人数安全检查，也不是原始网络长度证明。

// 负数、零与大于8的静态行为
// --------------------------------------------------------------------------
// 0x80..0xFF经movsx变为-128..-1；一般i<n循环会跳过，没有明确错误返回分支。
// 0人数同样跳过一般初始化循环，但后续线程启动和流程调用仍存在。
// 模式2还有固定slot1创建，因此不能把“循环跳过”等同于“没有任何P写入”。
// 未减员模式n>=9，或模式2减员后临时n仍>=9，才会让P创建循环的i<n允许i=8。
// 模式2初始n=9先临时减至8，普通P创建循环不达i=8；固定slot1创建后恢复人数9，
// 后续关系等循环又按9运行。不能把创建循环和恢复后的循环视为同一上界。
// 对于创建循环确实到达i=8的情形，若前序初始化均成功且该槽走P保存路径，
// G+E00+4*8恰等于G+E20，将P指针写到人数位置，随后循环读的上界也受到影响。
// 这是地址重叠的静态事实，不是已构造真实运行崩溃，也没有生成/发送异常数据。
// n>8还可让65B450的局部8字节关系表写越界，且G+E30/E38等8字节状态数组相邻。
// 650DC0在轮转排序路径使用模n且没有局部n==0检查；7CF170也有模n，但先受i<n循环限制。
// 因此零人数的除零可达性不能只看存在IDIV就下结论，需结合入口与有效槽条件。

// 修复设计可用约束（建议，不是当前代码）
// --------------------------------------------------------------------------
// 服务端序列化前和客户端受信边界分别验证1<=n<=8、模式修正后的有效槽、选择槽和资料索引。
// 在提交G状态前先确认足够长度及所有记录有效，失败时保留旧状态/明确退出初始化。
// 不要把n截成8继续消费不匹配的记录，更不能用硬编码8回合循环掩盖初始化失败。
// 当前任务只恢复约束，没有发布补丁；正常/缺槽/错误数量/重复初始化需在隔离环境独立验收。
