// ============================================================================
// 4096：两组17分支、ABI和字段宽度
// ============================================================================
// 原证：dispatch_tables.json、dispatch_branches.json、branch_helpers.json、data_ranges.json。
// 模式3：G+0x1477C表对象，695060按136字节记录寻址；分派表A67458，共17项。
// 模式4：G+0x14780表对象，695260按136字节记录寻址；分派表A67658，共17项。
// 两者用signed WORD[p+4]做记录索引，读记录DWORD+0作为类型t，间接call table[t]。
// 入口和寻址函数都没有在本组核对索引上下界或t<=16；有效输入依赖上游。
// 6931E0/694FD0以record+8作为格式文本；不得把p+4直接当类型编号。
//
// ABI
// ----------------------------------------------------------------------------
// 两个模式调度器保存ECX单例但核心操作取参数G；栈(G,p,cursor*)，retn0xC。
// 表中wrapper是cdecl(G,index,p,cursor*)：普通retn，调用方add esp,0x10。
// wrapper把G移入ECX，转入thiscall(index,p,cursor*)，后者retn0xC。
// 7CD440清醒卡保护helper的ECX也是G，内部才取当前P；不能错把ECX当P。
// 每个分支更新*cursor，再由4096决定是否插入E；wrapper不发送网络消息。
//
// 两模式实现地址；左为模式3，右为模式4
// ----------------------------------------------------------------------------
//  t   模式3       模式4       最远读取与局部操作
//  0   6592A0      6827E0      p+8 DWORD a；T30 -> C减a -> S扣款档，返回总资金>a。
//  1   659480      6829C0      p+8 DWORD百分数v；T30 -> C减q -> S扣款档，返回1。
//  2   659670      682BB0      p+8 DWORD a；T30 -> C加现金a -> S收益档，返回1。
//  3   659820      682D60      p+8 DWORD百分数v；T30 -> C加现金q -> S收益档，返回1。
//  4   659A10      682F50      p+8 signed32 n；p+12 DWORD[n]卡片编号；T30 -> T4列表 -> S20。
//  5   659D20      683260      p+8 DWORD卡片编号；T30 -> T4卡片结果 -> S21。
//  6   659F50      683490      p+8 signed32 n；p+12 DWORD[n]卡片槽；T30 -> T4列表 -> S10。
//  7   65A240      683780      本分支只消费提示索引；清状态组后P+1501=低BYTE(A870C8+1)。
//  8   65A460      6838A0      本分支只消费提示索引；清状态组后P+1502=低BYTE(A870C8+1)。
//  9   65A680      6839C0      本分支只消费提示索引；清状态组后P+1498=低BYTE(A870A0+1)。
// 10   65A8A0      683AE0      p+8 DWORD v；保护失败时排6069(+3=低BYTE(v+1))、6063状态6。
// 11   65AB70      683CA0      p+8 DWORD v；P+1500=低BYTE(v+1)，另调状态子接口5。
// 12   65AD90      683DC0      p+8 signed32 v；p+12低BYTE d；P+1652=(100+v)/100，P+1660=d。
// 13   65AEB0      683EE0      p+8 signed32 v；p+12低BYTE d；P+1652=(100-v)/100，P+1660=d。
// 14   65AFD0      684000      p+8 signed32 v；p+12低BYTE d；P+1656=(100-v)/100，P+1661=d。
// 15   65B0F0      684120      p+8 signed32 v；p+12低BYTE d；P+1656=(100+v)/100，P+1661=d。
// 16   65B210      684240      两次状态谓词及条件清理；本分支不读p+8，返回1。
// 所有分支先排T30，data首DWORD=2、第二DWORD=index、第三DWORD为当前表的文本指针。
// 数值类格式化先把p+8传sprintf；因此提示里的v与实际q/截断BYTE不必相同。
// 0..3/5/10/11最小跨度12；12..15读取p+12 DWORD后截低BYTE，最小跨度16。
// 4/6正n的跨度为12+4*n；n<=0跳过循环，但仍读取到p+11。
// 7..9/16最小跨度6；其余协议padding没有在这些函数被消费。
//
// 金额和卡片
// ----------------------------------------------------------------------------
// q的实际指令：imul32(v,P.cash)低32位 -> fild signed32 -> fstp float32 ->
// fdiv float32常量100 -> ftol2取EAX。不能替换成无限精度整数v*cash/100。
// C加现金：6060的+3=1,+5=1；C减现金：+4=1,+5=1；金额为DWORD+8。
// S收益档69B080：小于1000*scale为18、大于等于5000*scale为16、其余17。
// type0用扣款档69B040；type1使用q但无693220资金继续门控。
// type4用7F8780(P,卡片低WORD,1)逐张加入组0八槽；任一失败在列表末追加文本154。
// type5加入单张，同样保留成功/失败提示；返回1不等于卡片一定被收入。
// type6先7F86A0(P,包中槽,0)取原编号，再7F8920(P,槽,1)扣数量；槽没有局部范围检查。
// type4/6按n循环sprintf/strcat到共享缓冲；128是提示载荷标称长度，不是strcat保护。
//
// 两模式的差异与状态保护
// ----------------------------------------------------------------------------
// 模式3的type7..11先读BYTE[P+1696]；非0时排6001编号316、T4文本359，并跳过该状态效果。
// type7/8/9的免疫名称取Prop[1079/1084/1039]；type10/11取RichStr[22/71]。
// 模式4没有这项P+1696免疫分支；type10仍先调用7CD440(G,current,&cursor,scratch)。
// 7CD440检查卡片1071及适用性，成功排T4文本264、6001编号316、6063状态4和6061。
// 其内部卡片查找/适用性子树不在本专题重新全量审阅，复用回合继续专题。
// type7..9清组7F83B0会清P+1498/+1501/+1502/+1496，再设置本次目标字段。
// type12..15对v先32位加减100、再转float并除100，不钳制比例或持续时间BYTE。
// 资源type14名为“防御力上升”、type15名为“防御力下降”，实际P+1656公式相反。
// 这里只确认原文与公式；是否通过下游防御计算的分母解释，需继续追消费者，不能直接判BUG。
// type16：signed BYTE[P+1488]!=-1时排6050(slot)；signed BYTE[P+1491]!=-1时排6065(slot)，
// 后者另排T4“角色名\n定時炸彈拆除~”。两个条件独立，没有合并为互斥分支。
