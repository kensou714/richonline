// 二、金额继续条件与4093覆盖顺序
// 693220在693231读取P+0x5E0现金，69323A加P+0x5E4存款，
// 693242比较栈参数，693245执行setnle。结论是signed32总和严格大于金额，不能写成>=。
// 32位加法可能回绕；本地指令没有溢出保护，不能替换成无界整数算术。
// 4094/4095先排T30、6002、6060，再调用此谓词决定是否追加6080阶段2；
// 比较发生在资金记录被后续消费者应用之前，不是以扣款后余额决定本次排队。
// 模式3/4 type0分别在659402、682942调用同一谓词；百分比type1不以该谓词决定返回。
// 等于余额和不足余额不由这些入口追加E，但静态结果不证明最终流程永久停滞。
//
// 4093的直接调用顺序已核：
//   66A27B -> 7F9DE0，当前P正持仓按float市价与数量估值，ftol2后32位累计；
//   66A29C -> 7FA0A0(市值,0)，暂时追加P+1508存款；
//   66A2B4 -> 7F9950，正持仓先回写市场，随后各槽数量/成本归零；
//   66A2D3 -> 63F6B0，DWORD[p+8]直接覆盖P+1508存款。
// 因此最终存款取包+8；市值追加是此前的中间状态，不是最终权威值，也不是现金P+1504。
// 6063状态1与T30此前已排入本地队列，UI35/32刷新及E随后排入；立即写资金不等于6063已消费。

// 三、4096分派表与实际分支
// 模式3表0xA67458、模式4表0xA67658各17项，每项按当前PE小端DWORD重新读取。
// 表项先E9跳至wrapper：模式3为7B2E90+32*t，模式4为807D40+32*t，t=0..16。
// 独立核对34个wrapper的直接目标后，与正文两列34个实际实现地址完全一致。
// 两个调度器由signed WORD[p+4]查询当前136字节记录，取record+0 DWORD类型索引表。
// 它不是把包+4直接当类型；索引和类型的局部合法范围检查在这些入口中均未出现。
// 7B2E6D/807D1D按cdecl四栈参数(G,index,p,cursor*)调用，之后add esp,0x10；
// wrapper把G移入ECX并转thiscall(index,p,cursor*)，实际分支retn0Ch。
// 两个调度器自身栈参数为(G,p,cursor*)并retn0Ch；其最初ECX单例不应误认成实际游戏对象。
// 4096仅在模式3/4对应helper返回非零时追加阶段2。其他模式及返回零的情况不能补造网络ACK。

// 四、变长卡片列表与比例写入
// type4的659B70/6830B0及type6的65A0A9/6835E9，均用signed比较i与DWORD[p+8]，
// 随后的jge结束循环；i从0开始，所以n<=0不进入元素读取，但p+8仍已被读作DWORD。
// 正n元素从p+12按DWORD、步长4读取；未考虑指针回绕的正常输入最远端点为12+4*n。
// n<=0的最小直接读取跨度是12，不能把它缩成4096公共头的6字节。
// type4把卡片编号传加入方法，实际物品编号截低WORD；type6把数组项作为槽，先取旧编号后减数量。
// 128只是UI4提示记录携带的标称长度，sprintf/strcat没有据此得到写入容量保护。
// 原证并不证明负槽、超大n或异常卡片编号已由上游拒绝。
//
// type12..15在调用点读取DWORD[p+12]后由setter取低BYTE；直接跨度须为16，不能按BYTE读取计13。
// type14的65AFD0/684000调用7FA570：先32位100-v，再signed整数转float并除100，写P+1656。
// type15的65B0F0/684120调用7FA5D0：先32位v+100，再相同float除法，写P+1656。
// 两者均把持续参数低BYTE写P+1661。字节截断、32位回绕及float中间值都不能抹去。
// 资源type14写“防御力上升”，type15写“防御力下降”；原文与倍率增减方向确实相反。
// P+1656在下游是否用作分母等仍未闭环，不能仅凭方向差异断言客户端BUG。

// 五、等待字段与6002实际对象
// 67DA40在67DB1E把ECX恢复为G，67DB21调用64FB10；
// 64FB10写this+12等待时长、this+16 Tick，所以本处字段是G+0x0C和G+0x10。
// 队列对象Q=G+0x640的+12 head是另一个地址，不能与基础等待时长混用。
// 6003消费者不读记录+20，故data长度12不是本消费者自动深复制载荷的依据。
//
// 6002消费者67D880先按signed BYTE[record+4]定位P，再由7FB200/7F7670应用角色状态。
// 67D8DB再次从G+0xE00+4*slot取得P作为ECX，67D8E2调用694C20；
// 694C20只判断DWORD[this+40]!=-1，故门控是目标P+40，不是G内其他子对象字段。
// 门控成立才显示UI9、提交声音、按暂停标志设置基础等待；失败仍已做此前状态写入。
// 694BF0实际接收者同为P，声音编号为action+1000*(DWORD[P+40]+1)。
// 该调用链没有证明音频设备实际播放成功，1350等待也不是网络ACK。
