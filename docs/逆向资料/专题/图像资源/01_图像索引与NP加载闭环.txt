// 加载闭环
// ----------------------------------------------------------------------------
// 0x6D8130 复制 Tex 根路径，清零 this+630752，读取 Tex\\ToolConfig.kpd 的 pack。
// 节名来自 off_A23CD8，本专题未命名；值只接受 true 或 TRUE。
// dat 视觉映射的单记录占 12 字节：+0 npid、+4 运行时槽号、+8 变换标记。
// 记录地址写入 this+360652 指针表。npid 与运行时槽号是两种编号，不能混用。
// 0x6DA960 在 pack 非零时枚举 Tex\\*.*，回调上下文为 this+76。
// 回调 0x6DA900 检查目录属性 0x10 和文件名首字符 isdigit，再调 0x6DA7B0。
// 只检查首字符不等于全名为数字；内容工具应主动拒绝 01abc 等 atoi 歧义目录。
//
// 0x6DA7B0 接收 table=this+76。令 g=atoi(目录名)，r=table+4008*g：
//   r+0       读取 Item%s.tb 的 4000 字节索引。
//   r+4000    Pack%s.npp 的 FILE*。
//   r+4004    500*g，组的起始 npid。
// 路径为 Tex\\%s\\Item%s.tb 与 Tex\\%s\\Pack%s.npp。
// Item 打开失败仍继续打开 Pack；该函数未检查 fread 返回数。
// 初始化与析构交叉证明有 60 个组槽，工具应限制 0<=g<60。
//
// 0x6DBE30 从映射记录取 npid，g=npid/500，i=npid-组记录.base，item=r+8*i。
// pack=true：FILE* 非空且 item+4 的有符号 DWORD >0 时，
//            用 item+0 作为 SEEK_SET 绝对偏移，调 0x8123C0(NULL, FILE*, 0xFF00)。
// pack=false：格式化 根\\%02d\\%05d.np，调 0x8123C0(path, NULL, 0xFF00)。
// 由消费者证明每组 500 个 8 字节槽，+0 是包偏移。
// +4 仅作正值门槛，未传给解码器；“长度”只是待样本验证的候选名称。
// 此处未检查 fseek 返回值；包模式未见回落散文件。
// 0x6DB580 与多个绘制包装会按需加载；0x6DB920 则直接接收路径加载。
//
// 管理器字段与边界
// ----------------------------------------------------------------------------
// 0x6D7D00 清零和 0x6D7EF0 释放给出以下字节偏移：

// +360652   30000*4 字节：12 字节映射记录的指针。
// +480652   30000*4 字节：使用计数；绘制包装递增，图像释放清零。

// NP 外层压缩块
// ----------------------------------------------------------------------------
// 0x8123C0（跳板 0x60DB8C）可接收文件路径或已定位 FILE*。
// 路径进入 0x81B4C0；流进入 0x81B670。两者读取 1 字节移位量 k、两个 DWORD，
// 将 DWORD 的每个字节减 k，再读取载荷并逐字节减 k（模 256）。
// 解码器对象 +8 是预期解压长度，+12 是压缩输入长度，+4 为预处理输入缓冲。
// 0x81B7F0 分配输出，再调用：
//   KetLzoDecompress(对象+4的值, &输入长度局部副本, 对象+0的值, 对象+8的值)。
// 第四参数实际是 +8，不能依据名称改写为压缩长度。该参数用法需结合算法继续审计。
// KetLzoDecompress 是当前 IDA 符号；本专题未证明与标准 LZO 变种完全兼容。
//
// 解压后的 NP 头
// ----------------------------------------------------------------------------
// DWORD 由 x86 小端读取，紧邻无填充：
// +0 u8 mode；+1 u32 width；+5 u32 height。
// mode==1：+9 u32 frameCount；+13 u8 hasAlphaPlane；+14 开始帧数据。
// mode!=1：frameCount 设为 1；+9 开始数据；仅 mode==2 有直接像素填充分支。
// 未识别 mode 仍可能返回已创建对象，不能宣布其为受支持格式。
//
// mode==1 每次循环复制 768 字节 palette，再复制 width*height 字节像素索引。
// palette[index*3+0/1/2] 依次进入色值位 16/8/0，即 RGB 三元组。
// 有 alpha 平面时再复制 width*height 字节；无平面时非透明色像素 alpha=255。
// 第三个加载参数 65280=0x0000FF00 与 RGB 比较，已证是绿色透明色键，不是容量。
// 命中色键时 alpha=0，且仅第 0 帧设置透明掩码位。
// format==21 输出 32 位 ARGB 数值，小端内存为 B,G,R,A。
// format==26 取各通道高 4 位组合为 A4R4G4B4；不是原文件用 16 位像素。
// 显存行距从锁定返回的 pitch 取得，不一定等于文件宽度乘字节数。
//
// mode==2 固定一帧，源为 width*height*4 字节，按 B,G,R,A 消费。
// format==21 保持 32 位；format==26 转为每通道四位。
// alpha==0 设置透明掩码；任一 alpha!=255 清除完全不透明标志。
// mode==1 的不透明标志只在命中色键时清零，与 mode==2 的条件不同。
//
// 必须保留的异常记录
// ----------------------------------------------------------------------------
// mode==1 的 alpha memcpy 后没有推进源游标：
// 0x812656..0x81266E 只复制；此前索引复制在 0x81262B..0x812635 明确推进游标。
// 下一帧 palette 和循环后的时长表会从 alpha 起点继续。
// 不能把 palette+index+alpha 连续重复写成“已验证的通用多帧编码布局”。
// alpha 单帧没有后续读取时可能正常；alpha 多帧应拒绝自动重编码并要求人工审计。
// 是否实际资源依赖或绕开此分支，尚待样本统计，不在本轮声称已有运行时故障。
// 临时索引/alpha 缓冲在正常路径 delete[]；图形锁定失败早退没有经过两处释放。
// 此为静态失败路径清理缺口，尚未实测触发。
// 多处乘法和裸 memcpy 没有源容量核对，工具须在客户端之外校验损坏输入。

// 图像对象、动画与释放
// ----------------------------------------------------------------------------
// 0x811B30 清零 0xB0 字节对象并设置 +168=-1；0x811BA0 创建帧纹理和绘制缓冲。
// 字段由构建写入、属性查询、像素解码和绘制消费者交叉证明：
// +0/+4    绘制接口指针，确切 C++ 接口类型待恢复。
// +8       逐帧纹理接口指针数组。
// +12      输出像素格式值，此路径为 21 或 26。
// +16/+20  原始 width/height；0x6DC9E0、0x6DCA50 分别读取。
// +96      8 个纹理坐标 float 的副本；0x813C70 可按模式修改。
// +144     frameCount；+148 当前帧；+152 上次切帧 GetTickCount 值。
// +156     帧时长 DWORD 数组；+160 透明色；+164 首帧透明位图。
// +168     变换模式；+174 完全不透明标志。
// 这些均为字节偏移；伪代码 float* 不代表 DWORD 实际按浮点解释。
//
// frameCount>1 时，0x8123C0 从当前游标复制 4*frameCount 字节到 +156。
// 0x813E70 用 GetTickCount 差值与 duration[currentFrame] 比较，达到阈值后
// 当前帧加一，达到帧数后回绕 0，并更新 +152。
// 因此时长单位为毫秒；每次调用最多推进一帧，没有追赶全部逾期帧的循环。
// 然后从 +8 取当前帧纹理用于绘制。时长读取仍受前述 alpha 游标异常影响。
//
// 0x813110 对 +0、+4、+8 每帧接口调用虚表 +8，delete[] +8 指针数组、
// +156 时长表和 +164 透明位图，均置空；它不删除图像对象自身。
// 0x629C40 先调用析构 0x811B70，再按参数低位决定 operator delete(this)。
// 0x6DC310 在临界区释放单槽；0x6DC210 在临界区释放 30000 槽并清计数，
// 不关闭 Pack。0x6D7EF0 才额外关闭 60 个 FILE*，再销毁映射等成员。
