// 动作管理器：配置、调度与清理
// ============================================================================
// 定位
//   623CB0资源启动 → 627A90单例 → 7A5440加载Data/Anim.kpd。
//   单例指针A766D8；按需分配0x1820字节，628340构造128条40字节记录。
//   7A54A0读取配置 → 7A6030注册工厂/销毁 → 7AC6C0初始化128活动节点。
//
// 管理器布局（以下偏移均为字节）
//   +0x0000  AnimationRecord records[128]，每条40字节。
//   +0x1400  create[128]，函数指针；注册时先清512字节，再填0..46。
//   +0x1600  destroy[128]，函数指针；只见0..46写入，未见整体清零。
//   +0x1800  活动容器，32字节。
//
// AnimationRecord
//   +0x00  int id            配置indx。
//   +0x04  void* object      构造默认0；惰性创建并按编号复用。
//   +0x08  int surfCount     surf容器4个DWORD中的第1项。
//   +0x0C  int capacity      该槽配置初始化后为1，记录构造不设置此字段。
//   +0x10  int growth        该槽配置初始化后为1，记录构造不设置此字段。
//   +0x14  SurfRange* data   构造默认0；每条16字节。
//   +0x18  DWORD startedAt   每次start后记录GetTickCount。
//   +0x1C  int freePolicy    构造默认0。
//   +0x20  byte active       构造默认0；其余3字节未建立语义。
//   +0x24  DWORD timeLimitMs 配置time；0关闭管理器的超时结束。
//
// 配置的精确含义
//   7A54A0反复查找[ANIM]，读取indx/time；free缺省沿用构造值false。
//   A67444三个字符串按序为false、true、auto，7A58A0转为0、1、2。
//   不识别字符串返回-1；不是true也不是auto，因此正常结束不触发对象删除。
//   surf_0、surf_1等必须连续，遇第一个缺项立即停止，不再寻找后续编号。
//   7A5910仅接受other_A_B_C与npc_A_B_C：
//     other → type10；npc → type6；A=主编号，B=起始子索引，C=结束子索引。
//   B..C为闭区间，结束时通过6DC400逐项映射运行时槽，再6DC310释放图像。
//   surf不是需要循环播放的帧列表，而是结束时清理的资源范围。
//   7AC440/7AC4C0实现容量按1增长的四DWORD数组，扩容复制capacity*16字节。
//
// 启动：7A5C30
//   record.object为空则调用create[id]；未注册工厂则创建12字节通用基类。
//   调object.vtable[0](arg)，保存startedAt，然后active为0才追加活动链。
//   已在播放的同编号会再次start并重置时间，但不会生成第二实例或重复节点。
//   通用基类63E630的start/end均为空，tick永远返回0；只能靠非零time结束。
//
// 更新：7A5DA0 → 7ACA40 → 7A5EB0
//   每轮先调用object.vtable[2]()。它可以同时更新、绘制并返回是否完成。
//   只有其返回0且time!=0，才检查无符号GetTickCount-startedAt >= time。
//   完成后把id和活动节点索引分别写入A86974和A86B74，完成数量在A86970。
//   调object.vtable[1]()结束，再无条件遍历全部surf范围释放图像。
//   回调遍历完以后才摘除节点，避免在链遍历中修改当前next。
//   最后active=0，依据free策略选择销毁对象并清object指针。
//
// 两层释放不要混淆
//   surf释放发生在7A5EB0，与free取值无关。
//   free=false：保留动作对象；不表示保留surf。
//   free=true ：调用该id对应destroy。
//   free=auto ：625ED0判断可用虚拟空间；小于等于0x1000000时销毁。
//   当前阈值A67250为16MiB；API是GlobalMemoryStatus.dwAvailVirtual，
//   不是物理内存空闲量，也不是显存。未把阈值当作永不可变常量。
//
// 活动容器
//   +0  节点数组指针，每节点12字节：record*、nextIndex、prevIndex。
//   +4..+15 空闲索引栈；+16容量，+20活动数，+24头，+28尾。
//   空闲索引从127到0压栈；7AC7F0取一个槽并追加尾部。
//   7AC900更新前后指针后归还索引。6DFD10弹栈先减count，无下溢检查。
//   128个唯一编号且不重复入队时容量恰好足够；越界id会破坏这个前提。
//
// 当前样本
//   Anim.kpd有且仅有47记录，indx连续0..46，工厂也恰好注册0..46。
//   23记录显式free=true；其余24缺省false；没有auto样本。
//   时间800..6000ms，无time=0样本。所有记录名称见04，不猜运行时业务。
//
// 静态边界与协作约束
//   indx的atoi结果直接参与40*id寻址；未见0..127校验。start入口同样无。
//   构造未初始化每槽的id/time，也没有初始化未配置槽的surf容量/计数。
//   因而“有128槽”不代表可以安全启动47..127；必须同时配置、注册及验证。
//   工厂缺失时通用对象会被创建，但free=true/auto触发时销毁指针可能未设。
//   配置surf前缀错误会留下未建立的四字段输出，调用方仍追加；
//   缺下划线的循环也不检查字符串结尾；资源编辑器须先做严格格式校验。
//   本轮未执行畸形配置，不声称已有文件触发这些异常。
//   本轮只是文档和证据，不把修复建议伪装成已改客户端。
