// 角色精灵子对象：状态选槽、步态计时和装备叠加
// ============================================================================
// 范围与证据
//   角色对象记R，精灵子对象S=R+864(0x360)。
//   642480构造；642740更新外观；643A00为场景绘制；642B30为另一绘制入口。
//   补充原证：证据/角色精灵_IDA原始导出.json、角色精灵_依赖原证.json。
//   15函数、15chunk均与磁盘相同，见角色精灵_当前磁盘核验.json。
//   642B30/643A00体内众多装备类别仍以偏移命名；不宣称每种外观已命名。
//
// S布局（字节偏移）
//   +0    角色编号，构造-2。
//   +4    动作状态，构造-1；7F5D50同步R+384并写S+4。
//   +8    次状态/姿态编号，构造-1。
//   +12   方向0..3，构造-1；7F7940同步R+1460并经798350写S+12。
//   +16   附加类别A编号，正数时查映射；642B30绘制vehicle类型。
//   +20   附加类别B编号，决定身体用普通组还是替代组；不在这里强命名。
//   +24   构造清0，此批未见足够消费者确立用途。
//   +28   附加类别C；+32构造清0；+36附加类别D；+40附加类别E。
//   +44   外观/套装索引。
//   +48/+52/+56/+60/+64 五类装备编号。
//   +68   int imageSlot[4][26]，每方向26个“运行时图像槽”。
//   +484  固定fx_4图像槽。
//   +488/+492 两类附加外观查表结果。
//   +496/+500/+504 三类附加外观查表结果或记录指针。
//   +508/+512/+516/+520/+524 五类装备记录指针。
//   +528  步态游标，构造0。
//   +532/+536 计时器，构造先30ms，随即设置为80ms。
//   已证消费范围至少540字节；此处没有单独operator new来证明独立分配大小。
//
// 外观缓存：642740
//   输入+0角色编号或+36外观索引与当前不同时，重新建立4*26个图像槽。
//   输入+60 byte非0：把外观索引直接作为role主编号。
//   输入+60 byte为0：外观>0先检查角色是否可用该项；可用则取条目+16的
//   映射值；仅外观>0且可用性检查失败时退回0。外观<=0保留原值进入646650，
//   随后取角色资料的suit[映射值]；本路径未验证负索引边界。
//   646650读取：角色资料数组 + 3204*角色编号 + 24 + 4*映射值。
//   646610是附加条目+20指针所指byte数组按角色编号读取；无就地范围检查。
//   最终6DBA40(type5, resolvedRole, direction, slot)填入104项缓存。
//   注意通用role映射支持每方向100槽，精灵实际缓存这里只装0..25。
//   不能把100槽容量当作角色状态机已经会使用100个动作。
//
// 状态到图像槽：643A00
//   A=S+4动作状态；P=S+8次状态；D=S+12方向；B=S+20。
//   A=0：B<=0选P+6，B>0选P+16。
//   A=1或2：B>0选P+16；B<=0且P=6选12；其余选择步态游标0..5。
//   A=3：B<=0选13，B>0选23。
//   A=4：B<=0选14，B>0选24。
//   A=5：B<=0选15，B>0选25，同时改变附加外观绘制参数。
//   身体图像槽=imageSlot[D][选中槽]。
//   A=1/2普通步态每80ms最多推进一次游标，超过5回到0。
//   当前帧先使用旧游标选槽，再为下次绘制推进游标；不补发遗漏tick。
//   这层6槽步态与NP内部多帧是两层索引，不要把二者混合成一个frame字段。
//
// 方向依赖的装备叠放
//   643A00先绘制fx_4，再按方向决定部分附件放身体之前或之后。
//   五类装备中的S+60在方向0先画，S+48/+52/+56在方向2先画。
//   身体绘完后，尚未先画的类别才绘制，局部标志避免重复。
//   S+64这类在身体后绘制；另有附加外观/效果按动作和方向判断。
//   装备记录+192..255是4方向*4状态的图像槽：
//     每方向偏移16；S+48/+52/+56/+60一般动作取+0，A=3/4/5取+4/+8/+12。
//     S+64在644C3D..644C63始终取record+192+16*D，不随动作切换。
//   642B30另一入口按P=7/8/9选择相应状态，不能把两个入口判定混同。
//
// 装备位置锚点
//   身体图像槽经6DCB30取已加载NP对象+148的当前内部帧索引F。
//   装备记录+256保存锚点表指针；消费者读取的位置为：
//     2496*角色编号 + 624*方向 + 24*选中槽 + 8*F。
//   两个DWORD分别为dx和dy，最终绘制到x+dx、y+dy。
//   2496=4*26*3*8，624=26*3*8，24=3*8；布局与每槽三对坐标一致。
//   但本轮没有解出锚点表的分配/文件生产规则，三对坐标仍属布局推断。
//   若身体NP帧数>3或零基帧号F>=3，必须先审阅锚点表容量；F=3已进入下一槽，
//   不能靠改NP帧数扩动画。
//
// 已知边界
//   外观重建条件只比较角色编号和外观索引，未把输入+60模式位计入。
//   因而只切换该模式位不会重建缓存；是否存在这种调用序列尚未验证。
//   绘制按方向/状态直接索引，未见此函数先检查D和槽号范围。
//   默认未初始化动作-1若直接绘制，switch不会建立身体槽，后续仍消费；
//   正常角色初始化应在第一次绘制前写入有效状态，本轮未运行异常路径。
//   装备编号改为非正数时旧缓存指针不一定清空，但绘制受编号>0门控。
//   对未来资源工具：同时校验角色映射、4*26槽、状态选择、NP帧数和锚点。
//   单独验证“文件存在”不足以保证新外观在全部朝向/动作正确叠放。
