// 0号骰子动画：帧、运动、结束与队列等待
// ============================================================================
// 证据入口
//   当前Anim.kpd的indx=0注释为“投色子”，time=3000，free缺省false。
//   工厂7A6530分配0xE8(232)字节，7AA110安装虚表A2BFB0。
//   vtable+0 → 62F160启动；+4 → 63E6A0空结束；+8 → 62F620更新/绘制。
//   不依赖自动MFC符号来认定用途，配置和参数链共同支持骰子语义。
//
// 输入参数：62F160读取
//   +0   int count       参与动画的骰子数；对象内是三组并排数组。
//   +4   int result[3]   三个最终定格索引，分别读到对象+16/+20/+24。
//   +16  int screenX     mode=0时使用。
//   +20  int screenY     mode=0时使用。
//   +24  byte mode       非0使用当前角色/场景位置并走队列完成路径。
//   参数至少可读25字节；协议链使用28字节缓冲，+25..27用途尚未恢复。
//   启动函数没有限制count<=3；不要据此把任意数量当成支持。
//   协议4011、本地6000/6010的构造细节由移动协议专题记录。
//
// 232字节对象中的关键字段
//   +0       虚表。
//   +4/+8    计时器：间隔和上次更新时间。
//   +12      count。
//   +16..24  result[3]。
//   +28..36  最后横向滑动距离阈值，初始5/2/5。
//   +40..48  每轮弹跳路径阈值，初始192（1128267776的float位模式）。
//   +52..60  最后横向累计距离。
//   +64..72  当前弹跳累计量。
//   +76..84  横向速度，初始3/0.5/3。
//   +88..96  纵向速度，初始30。
//   +100..108 x[3]；+112..120 y[3]。
//   +124..132 方向代码1/1/3：1向左，3向右。
//   +136..144 阶段2=上升，0=下降，-1=最后滑动。
//   +148..150 是否进入定格等待。
//   +152..160 定格等待时长，800ms。
//   +164..172 定格开始时刻。
//   +176      骰子资源记录指针。
//   +180..188 当前图像索引。
//   +192..200 图像切换间隔，初始150ms，最后滑动时350ms。
//   +204..212 最近切图时刻。
//   +216..224 弹跳计数，初始1，最多进入第3轮。
//   +228..230 完成标志；+231 mode。
//   这些字段名为按消费行为给出的工作名，不写回IDB类型。
//
// 更新语义：62F620
//   先用81BD10判断16ms门控。未到门限仍绘制，但不推进运动状态。
//   门限到了，每个未完成骰子按阶段更新一次；不会按遗漏时间补跑多步。
//   切图另用150/350ms时钟；超时只将索引推进1并对资源帧数量取模。
//   上升每tick纵向速度减0.3；下降每tick加0.3。
//   落地后若计数<3则重启上升：计数+1、阈值除3、速度=35/计数。
//   第3轮以后进入最后滑动：横向速度1、纵向0、切图间隔350ms。
//   横向累计达到阈值则设定格标志，并将当前索引改为result[i]。
//   定格800ms后该骰子完成。所有骰子完成才进入自然完成通知。
//
// 自然完成与配置超时不同
//   mode!=0：62F620 → 64FB50，Game对象G+12基础队列暂停时长清零，返回1。
//   mode==0：62F620 → 63E130(1)，另一控制对象+1900标志置1，然后返回1。
//   管理器在tick返回1后调用空end并移除对象；free缺省false保留实例。
//   若tick仍未完成但管理器3000ms达到，同样移除，却只调用空end。
//   因此超时分支不会自动执行62F620内的上述自然完成通知。
//   本地6000等待为配置时间+100ms时，还存在外层计时推进；
//   不能把此静态差异直接称为“必定卡死”，需结合具体模式/队列实测。
//
// 计时器：81BCB0 / 81BD10
//   设置间隔时保存GetTickCount；检查为now>last且now-last>=interval。
//   通过后last更新为当前GetTickCount，不保存固定相位。
//   它使用显式now<=last拒绝分支，因此DWORD时钟回绕后可能长时间不前进；
//   与管理器仅做无符号差值的超时逻辑不同。未运行49.7天回绕复现。
//
// 静态风险和后续验证
//   count>3使多组数组和完成字节越界；资源帧数为0会参与取模。
//   result索引与实际帧数的上界尚待资源生产/访问链一起验证。
//   门控移动以tick次数驱动，低帧率只减少推进次数，配置截止时间仍按墙钟。
//   所以不应仅调整time来“修复动画”；先分清动作自然结束和等待截止。
//   以上是逆向边界，未修改动画参数或执行客户端。
