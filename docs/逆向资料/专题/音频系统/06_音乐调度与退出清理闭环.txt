// 第一批分类修正
// ----------------------------------------------------------------------------
// 0x821B80 并非暂停入口：它构造/复用无重复随机排列，选择下一列表项并开流。
// 0x822020 是暂停状态的后续完成器：转到下一目标、保存暂停位置或结束停止。
// 第一批 03/04 中“音乐状态转换/暂停函数”的未决描述应以本篇细分为准。
// 两函数已经从“仅导出”推进到有具体语义的审阅记录，见新 JSON 清单。

// 随机播放：0x821B80
// ----------------------------------------------------------------------------
// 当前随机顺序容器为空，或 M+16 的 bit 2 未置位时，重建排列。
// 循环 rand()%播放列表数量；与已放入项逐个比较，重复则重选，直到数量相等。
// 这不是 Fisher-Yates；也不能称密码学随机或保证严格均匀。
// M+544 保存随机顺序下标；重建后设 count-1，随后递增并按列表数量回绕。
// 参数 previous_index>=0 时把旧项移向末尾；随后跳过同索引，单元素列表例外。
// 选中随机顺序项后写 M+480；以其 MR 的文件/偏移/长度开 Miles 流。
// 自带淡入时长的项初始音量 0，否则 曲目音量*主音量；设置循环并启动。
// 未见空播放列表的显式前置拒绝：随机循环可不执行，后面仍取顺序容器项目。
// 外层调用者是否阻止空列表进入需继续核实，暂为边界候选。

// 正在播放 -> 暂停 -> 完成转换
// ----------------------------------------------------------------------------
// 第一批 0x820990：AIL_stream_status==4 -> 0x821130 更新音量；
//                      status==8 -> 0x822020 完成转换。
// 0x821130 对状态 1/2/3/4 按 M+520 开始时间和 M+516 时长淡出。
// 到时调用 AIL_pause_stream(...,1)，列表项同时记录 AIL_stream_position。
// 这些状态数值由实际调用和分支定义；没有把所有 Miles 状态值完全枚举。

// 0x822020 消费目标 M+524 与转换状态 M+508
// ----------------------------------------------------------------------------
// target=-4：选择临时记录。若 M+476 存在，回调/回收原记录后移到 M+472，
//   清 M+476；M+480 写 -4；转入统一开流分支。
// target>0：取该播放列表项，回调原项，M+480 更新；转入统一开流分支。
// target=-3 且 state=2：保存当前位置到 MP+0；列表项另保存到 M+512；
//   M+480=-3，关闭 stream，M+12=0，state=6，返回。
// target=-3 且 state=4：关闭 stream、清 M+12、完成回调、回收当前项，
//   M+480=-3，state=6，返回。
// 统一开流：target=-3，按 MR 绝对偏移定位；关闭旧 stream；新建 stream；
//   state=5 恢复 MP+0 位置，否则从 0 开始；设置循环/音量并启动，state=0。

// 候选缺陷：目标列表索引 0
// ----------------------------------------------------------------------------
// 0x820260 允许 a2=0；已有音乐时且非零渐变时长，将它写入 M+524。
// 0x82210D 比较 [M+0x20C],0；0x822114 jle 跳过“有效列表项”分支。
// 0x822020 局部选中项 v8 初值 0；target=0 既不是 -4，也不是 -3，
// 因而直接进入统一开流，随后读取 v8+16。静态上存在零指针路径。
// 验证条件明确：已有曲目 -> 带时长切换到播放列表第0项 -> 暂停完成器。
// 尚未动态执行；不能把所有“切歌卡住”都归因于此分支。

// 高层音乐注册及使用：资源ID转换为列表索引
// ----------------------------------------------------------------------------
// 0x69A940：H+20 先置 200，清空列表，注册后以返回的列表索引覆盖 H+20。
// 0x69A9B0：H+24 同样处理资源 201。
// 0x69AA20：从场景相关对象 +1416 取得资源 ID，再注册并存 H+28。
// 以上入口将播放模式设置为 10；第一批 0x820990 对该值走下一项处理。
// 0x69A6A0/0x69A6F0/0x69A740 播放上述三个存储的列表索引，渐变时间 0。
// 不把 200/201 武断命名为登录/大厅曲目；场景名称需调用者和资源内容证实。
// 0x69A7D0 使用资源 ID 启临时曲目，循环次数1、曲目音量1.0、渐变参数0。
// 0x69A830 向恢复入口传 -5；0x69A790 即时停止当前音乐。

// 高层退出清理：0x69A2F0 的实际顺序
// ----------------------------------------------------------------------------
// 条件 H+8!=0：
//   1. 0x6043D9 -> 0x822640(0)：停止音乐。
//   2. 0x6097BC -> 0x821980：音乐成员清理。
//   3. 0x609FEB -> 0x825F80(0)：结束全部音效，轮询回收活动播放记录。
//   4. 0x607ECB -> 0x825D60：音效资源/池/文件清理，再关 digital driver。
//   5. AIL_shutdown。
// 不论 H+8：调用 0x69ABE0 写 Voice.dat，再释放 H+44 和 H+56 两个数组。
// 这证明语音快捷配置在退出路径保存，不意味着硬崩溃或强退也会保存。

// 音乐池清理顺序：0x821980
// ----------------------------------------------------------------------------
// 0x60484D -> 0x821620：关闭当前流，播放列表项回池，资源注册索引置 -3。
// 0x6112FA -> 0x821800：清理列表及两临时记录。
// 0x605E00 -> 0x821720：资源记录回池，释放 ID 指针表。
// 0x610698 -> 0x8218E0：delete 空闲资源记录及播放记录。
// 0x60B08F -> 0x8219D0：CloseHandle 全部包文件。
// 第一批已核实 0x821800 的 M+476 检查后误删除 M+472；本批现在证明
// 它位于高层退出清理链。是否 M+476 实际非空仍需特定切换现场。
// 此高层链未单独调用音乐管理析构 0x81F890 关 driver；后面 AIL_shutdown
// 是否统一释放由 Miles 语义决定，不据此直接认定 driver 泄漏。

// 音效池清理顺序：0x825D60 -> 0x825DA0
// ----------------------------------------------------------------------------
// 0x601C01 -> 0x825A40：释放已载入数据，资源记录归还池，删除 ID 指针表。
// 0x60BE0E -> 0x825B80：结束活动 sample、归还 handle 和播放记录。
// 0x60F392 -> 0x825C10：销毁池中资源记录，释放 Miles sample handles，销毁播放记录。
// 0x608D44 -> 0x825D00：fclose 包文件；随后 AIL_close_digital_driver。
// 单看这一内层顺序是先释放资源后结束 sample；高层已经先调用 0x825F80(0)
// 停全部并轮询。因此补丁不可绕开上层停止步骤直接复用内层清理函数。
// 对其他直接调用者、并发线程、完成回调重入仍未做全面证明。
