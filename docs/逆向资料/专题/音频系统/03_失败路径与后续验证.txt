// A01：音乐文件打开失败哨兵判断不正确
// ----------------------------------------------------------------------------
// 0x81FCB1 调 CreateFileA；0x81FCC1 cmp [hFile],0；非零进入 ReadFile。
// Win32 CreateFileA 失败返回 INVALID_HANDLE_VALUE (-1)，不是空句柄。
// 后续没有检查 ReadFile 返回值或 NumberOfBytesRead 就消费头部 +8。
// 入口先 fopen 可过滤普通缺文件，但两次打开之间文件变化、权限/共享失败
// 仍可能触发错误分支；不能因扫描器预检查而认定此代码安全。
// 补丁候选：检查 -1、每次读取字节数、头/索引边界；保持成功返回 -1 的约定。

// A02：两类索引加载器缺少完整短读/溢出校验
// ----------------------------------------------------------------------------
// 0x824960 与 0x81FC50 未检查索引读取实际条数/字节数；条数直接乘 16 分配。
// 最大 ID 加一乘 4 也未显式检查溢出，资源 ID 直接寻址指针数组。
// 已检查函数正常返回前没有释放刚分配的临时索引缓冲区；这构成泄漏候选。
// 不把“未释放临时区”延伸成 EXE 所有资源读取器都泄漏。
// 先在离线工具拒绝畸形输入；动态内存分析需控制文件和开启调试堆单独验证。

// A03：音乐资源 ID 校验顺序
// ----------------------------------------------------------------------------
// 0x8200B0 / 0x820510 的静态分支先取 *(table + 4*id)，再检查 id<0 或 id>max。
// 若设备存在且传入非法 ID，边界判断发生在数组解引用之后。
// 不能假定外部可直接调用此入口；调用者是否约束 ID 尚需列全交叉引用。
// 补丁候选：先验证设备/表指针/范围再解引用，不改变有效 ID 的接口语义。

// A04：压缩音效长度参数不一致，当前无覆盖样本
// ----------------------------------------------------------------------------
// 0x825230 以 R+36 分配并读取压缩输入，再以 R+32 分配输出。
// 0x82540F 取 R+0x20，0x825412 push，0x825425 call 0x60C50C。
// 0x8278B0 把该第二参数用于 input_end=input+length，结尾返回剩余/超界状态。
// 因此调用者传入的是预期输出长度，而不是刚读取的压缩输入长度。
// 调用者同时忽略返回值和输出计数；汇编还能看到第五个常数 0 参数，
// Hex-Rays 显示四参而调用清栈 0x14，不能把伪代码签名当完整 ABI。
// 当前 1138 条音效全为非压缩；不能用现有正常播放否定这一候选。
// 下一步需可隔离的小型压缩样本、正确 LZO 变体、解码计数及真实调用 ABI。

// A05：音乐临时记录释放对象错位
// ----------------------------------------------------------------------------
// 0x82186F..0x821896：释放 M+472 并清零。
// 0x8218A3：检查 M+476 非零；0x8218AF 却读取 M+472；0x8218BC delete；
// 0x8218C7 又把 M+472 写零。M+476 在该分支没有释放/清零。
// 这是经指令核对的字段错位，不是仅依据反编译文本猜测。
// 仍需证明关闭路径实际调用此函数且 M+476 非空，才能评估用户可见泄漏。

// A06：淡出分支的音量乘数不对称
// ----------------------------------------------------------------------------
// 0x821130 淡入及转换淡出使用 曲目音量 * 主音量 * 比例；
// 自然结尾淡出分支只使用 曲目音量 * 比例，未乘 M+504。
// 0x822790 主音量输入仅接受 [0,1]，并不保证之后淡出仍保留此乘数。
// 验证场景：低主音量、非零结尾淡出时长，比较开始/结尾实际输出。
// 没有实机音量测量，暂不宣称已经修复“音乐突然变响”。

// A07：不要把函数返回值当全系统音频成功
// ----------------------------------------------------------------------------
// 0x69A3C0 即使音效或音乐初始化失败仍返回 1；实际可用状态写 this+8。
// 0x8245E0 sample handle 循环分配失败可提前 break，之后仍返回 1。
// 0x81F950 成功=-1，失败=-2；扫描函数不累加逐包失败结果。
