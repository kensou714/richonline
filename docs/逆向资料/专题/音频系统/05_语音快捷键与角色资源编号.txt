// 高层对象 H：60 字节，单例入口 0x6275E0，构造 0x69A270
// ----------------------------------------------------------------------------
// +0   4 指针     指向配置对象 +66 的音效开关字节；0x69B560 返回该地址。
// +4   4 指针     指向配置对象 +67 的音乐开关字节；0x69B580 返回该地址。
// +8   1 字节     总初始化状态；构造置 0；0x69A3C0 在两设备路径成功后置 1。
// +12  4 指针     音效管理对象地址 0xA803B0；0x69A540 以它作为 ECX 调播放器。
// +16  4 指针     音乐管理对象地址 0xA80630。
// +20  4 整数     音乐资源 200 注册后得到的播放列表索引。
// +24  4 整数     音乐资源 201 注册后得到的播放列表索引。
// +28  4 整数     当前场景曲目注册后得到的播放列表索引。
// +32  4 指针     可单独停止的音效播放记录；0x69A540 第三参数非零时写入。
// +36  4 整数     Voice.dat 的角色行数；来自角色管理器，非写死 8。
// +40  4 整数     每角色快捷键槽数；0x69AAA0 固定写 8。
// +44  4 指针     Voice.dat 展平 DWORD 数组。
// +48  4 整数     VoiceFace.kpd 的 [ALL] role。
// +52  4 整数     VoiceFace.kpd 的 [ALL] num。
// +56  4 指针     role*num 的表情映射 DWORD 数组。
// 配置开关使用指针是为了即时读取当前开关值，不是构造时复制一次。

// Voice.dat：快捷键槽 -> 扩展语句槽；不是音频文件
// ----------------------------------------------------------------------------
// 读取：0x69AAA0，以 rb 打开 Config/Voice.dat；分配 role_count*8*4 字节。
// 初始化：全部 DWORD 写 -1；打开成功后按预期总长度 fread 一次。
// 文件无头部；当前样本 288 字节=9 行*8 列*4 字节，小端有符号 DWORD。
// 0x69AF50 getter：voice[role*8 + hotkey_slot]；0x69AF90 setter 同一公式。
// 两函数不检查 role、hotkey_slot、数组指针或值范围；工具必须校验。
// -1 表示槽未设置；现有最后一行全 -1。不能据此断言第九角色在全部系统可用。
// 此行数与 VoiceFace 的 role=8 不同；增加角色前必须联合核对两张表。
// 写回：0x69ABE0，以 wb 重写 role_count*8*4 字节，没有文件头或版本号。
// 调用：高层清理 0x69A2F0 无条件经过 0x60C368 -> 0x69ABE0。
// 因此在游戏运行时外部编辑 Voice.dat，退出时可能被内存值覆盖。
// 读取短文件未检查实际读入长度；由于事先填 -1，未覆盖部分通常仍为 -1，
// 但这不是“自动兼容任何坏长度”的约定。写回也没有先判断 fopen 是否失败。

// 快捷键到选择流程
// ----------------------------------------------------------------------------
// 0x7094C0 检测左 Ctrl（VK=162）且 Shift（VK=16）未按下，
// 再检测 F1..F8（112..119），对应 hotkey_slot=0..7。
// 输入专题补证：606D55->64ED30读取输入对象+300+VK的释放沿；
// 81DCA0在WM_KEYUP写该槽。因此触发点是F键释放，左Ctrl仍保持且Shift未按，
// 不应写成“按下F键立即发送”。证据：../输入与快捷键/ida_input_raw.json。
// 当前角色取得后，0x60FB35 -> 0x69AF50 查快捷槽内容。
// 非 -1 且发送条件允许时，把语句槽写到 4 字节消息的 +2 字节并交发送入口。
// 本篇未恢复该消息 opcode/服务器回显全链，不把本地按键检测称为直接播音。
// 0x751E80 用相同槽内容生成 8 个快捷键标签。
// 0x752A00 case 205：取得列表选中项 -> 0x60224B -> 0x69AF90 写入；
// 再通过角色与选中语句槽算音效 ID 并试听。
// 0x7538E0 枚举 0..35 语句槽填列表；0x7098C0 分页显示语句文字。
// 修改槽数不是只扩大 Voice.dat：按键代码写死 8、列表写死 36，需一起修改。

// 编号层必须区分
// ----------------------------------------------------------------------------
// 0x69B130：普通角色音效 ID = 1000*(role+1) + event_slot。
// 0x69B170：扩展语句音效 ID = 1000*(role+1) + phrase_slot + 128。
// 0x69B150：扩展语句文字 ID = (role<<8) + phrase_slot + 1664。
// 例如 role=0,phrase_slot=3 -> 音效 1131，文字 1667；不是文件 snd1131.dat。
// 汇编证据：0x69B139/0x69B179 imul 0x3E8；0x69B156 shl 8。
// 文字编号与音效编号不共用空间；也不能拿 VoiceFace 返回的表情 ID 当音效 ID。
// 同一角色和语句槽在 0x7053D0 的事件位 0x08 分支同时走：
//   文案公式 -> 文本管理器；音效公式 -> 0x69A540；
//   VoiceFace getter -> 角色表情/界面显示状态。
// 这是“文字+声音+表情”联动的静态消费闭环。
// 0x73C0D0 在角色选择 UI 命令 1..6 中用普通音效公式 event_slot=65 试听。
// 尚未给该槽赋予角色台词的自然语言名称，需要实际音频/文本对应后再命名。

// VoiceFace.kpd：扩展语句槽 -> 表情值
// ----------------------------------------------------------------------------
// 0x69AC60 用公共 KPD 装载器读取 Data/VoiceFace.kpd；解析 [ALL] role 与 num。
// 字符串原址：0xA2344C="ALL"，0xA23458="num"；不是字符串指针变量。
// 对 role=0..role_count-1 查 [ROLE%d]，对 slot=0..num-1 查 face%d。
// 值经 atoi 展平写入；0x69AFD0 返回 face[role*num + phrase_slot]。
// 当前资源解码实测：[ALL] role=8、num=36；8 个角色各 36 个条目。
// 全部 face0..face35 均齐全；8*36 个公式生成的音效 ID 在第一批索引报告中
// 全部存在。证据 audio_highlevel_validation.json；存在不等于已实机播放。
// 解码证据：首字节偏移 50；原长度 3398、压缩长度 1275；lzokay 解压长度相符。
// 中文注释用 gb18030 解码无损往返；这不把全部客户端资源编码规定为 UTF-8。
// 调用方没有在这里验证查节/查键/取值成功；新增表必须补全连续角色/face键。
// getter 无边界检查；现有角色快捷表有第九行，不应盲目填值让 role=8 走此表。

// 高层播放、停止与音量参数
// ----------------------------------------------------------------------------
// 0x69A540 参数：(resource_id, loop_flag_byte, remember_byte)。
// 调低层 0x824D40 时循环次数=loop_flag_byte==0，左右音量均为 1.0。
// 显式汇编 0x69A583..0x69A58C：字节取值 -> 布尔取反 -> 压栈。
// 因而常见 (id,0,0) 向 Miles 传 loop_count=1；非零 loop_flag 传 0。
// Miles 对 0 的确切循环约定仍需 SDK 对照，本篇只固定原始传参。
// remember!=0 将播放记录保存 H+32；0x69A5D0 停止它并清 H+32。
// 0x69A620 停止全部；0x69A660 停止指定播放记录；底层 0x825F80
// 先将音量置零、AIL_end_sample，再调用状态轮询 0x825770 回收。
// 0x69A880/0x69A8E0 把整数百分比除以 100.0 传给音效/音乐主音量。
// 音效 0x69B5A0 和音乐 0x822790 都仅接受 [0,1]；超范围值被忽略而非夹取。
// 音效 setter 只改 S+636，未遍历正在播放的记录；音乐 setter 会应用当前流。
// 因此 App.ini 解析无夹取不代表底层会接受任意音量；两层边界应分别记录。

// 金额/数值分档 helpers：只记录算法，不捏造事件名称
// ----------------------------------------------------------------------------
// 0x69B000：x < 1000*y -> 9；x >= 5000*y -> 7；否则 8。
// 0x69B040：同阈值依次 -> 15 / 13 / 14。
// 0x69B080：同阈值依次 -> 18 / 16 / 17。
// 0x69B0C0：x < 50 -> 12，否则 11。
// 0x69B0E0：x >= 50 -> 19；x < 30 -> 21；否则 20。
// 0x69B110：x < 6 -> 12，否则 10。
// 示例 0x6592A0/0x659670/0x667B10 把 helper 返回值写入事件结构 +2 WORD，
// 同时写角色字节与 1350 时间值再排队。它们是事件槽候选，不是最终音频 ID。
// 仍要继续事件调度消费者以恢复具体台词、事件名称和正负金额含义。
