// 两条入口链
// ----------------------------------------------------------------------------
// 0x69A3C0：AIL_startup；初始化音效；成功后初始化音乐。
// 音效：0x6049D3 -> 0x8245E0 -> 0x60507C -> 0x8247D0。
// 音乐：0x6030E2 -> 0x81F950 -> 0x6003BA -> 0x81FAC0。
// 两扫描器从 i=0 拼 Sound/snd%04d.dat 或 Music/mus%04d.dat。
// 先 fopen rb 读取 12 字节头，再 fclose；第一个 fopen 失败就结束扫描。
// 第一文件的头 +4 保存为本批匹配值；后续只有头 +4 相等才注册。
// 不相等跳过当前文件但继续下一个号；不是“所有头不匹配就终止”。
// 两扫描器此处没有比较文件头 +0 魔数，没有检查 fread 实际返回条数。
// 音效扫描返回 1；音乐扫描返回 -1；不代表所有包都已成功注册。
// 单文件消费者：音效 0x609C12 -> 0x824960，音乐 0x60465E -> 0x81FC50。

// 文件头（文件起始 +0，固定 12 字节）
// ----------------------------------------------------------------------------
// 偏移  宽度      已证用途                          磁盘现值
// +0x00 4 字节    本群读取但未验证含义               snd% / mus%
// +0x04 uint32le  同一扫描批次的相等比较值           音效 130；音乐 13
// +0x08 uint32le  索引条数 N                         各包不同
// “snd%”原字节 73 6E 64 25，“mus%”原字节 6D 75 73 25。
// +4 可能是版本/类别标识，但本群只证明相等过滤，不能正式命名为版本号。
// N == 0 时消费者关闭文件并返回失败；非零时分配 N*16 字节索引临时区。
// 文件编号不是资源编号：mus0007.dat 有 2 项，mus0009.dat 有 4 项。

// 索引（文件 +0x0C 开始，步长 16 字节）
// ----------------------------------------------------------------------------
// 偏移  宽度      音效                               音乐
// +0x00 uint32le  资源 ID，作为稀疏指针表下标          同左
// +0x04 uint32le  文件绝对载荷偏移                    同左
// +0x08 uint32le  解码后的载荷字节数                  传给 Miles 的载荷长度
// +0x0C uint32le  非零表示压缩输入字节数；零=原样读    本消费者不保存、不使用
// 绝对偏移证据：0x825230 使用 fseek(..., offset, SEEK_SET=0)；
//   0x820260/0x820510 使用 SetFilePointer(..., offset, FILE_BEGIN=0)。
// +0x08 音效长度还供 AIL_file_type / AIL_set_named_sample_file 和缓存统计读取。
// 最大 ID 决定指针表分配：(max_id+1)*4 字节；不是按索引条数直接寻址。
// N*16、(max_id+1)*4 及 offset+size 都要由工具用宽整数校验溢出与文件边界。

// ID 冲突与加载覆盖（已核实，不应误当损坏）
// ----------------------------------------------------------------------------
// 0x824960/0x81FC50：只有 ID 槽为空才创建记录；随后无条件覆盖文件/偏移/长度。
// 因此按连续包扫描，后包同 ID 的描述覆盖前包；同包重复 ID 也是后项生效。
// 已有音效重复 ID：4、108、3157、2130、4143、6152、6160、28、29。
// 6160 出现 3 次，其余上述 ID 各 2 次；音乐 ID 1 出现 2 次。
// 例：snd0000 的 ID 4 为 offset=31436,size=6268；
//     snd0019 的 ID 4 为 offset=28,size=6298，后者最终覆盖前者。
// 例：mus0000 的 ID 1 被 mus0016 的 ID 1 覆盖。
// 不能把“去重”当无损整理；编辑器应显示覆盖链，保留顺序并让新增覆盖显式可见。
// 上述是静态扫描结果，不能推断游戏全部事件都实际触发这些资源。

// 音效载荷链
// ----------------------------------------------------------------------------
// 0x824D40 首次播放某 ID 时发现记录 +0 数据指针为空，调用 0x825230。
// +36==0：分配记录 +32 字节并原样 fread。
// +36!=0：先分配/读取 +36 字节，再分配 +32 字节解码缓冲区。
// 解码调用 0x60C50C -> 0x8278B0；库包装函数 0x827890 名为 KetLzoDecompress。
// 0x8278B0 的流尾令牌与向前/向后复制说明这是字节流解压实现。
// 本轮没有证明具体 LZO 算法变体与安全校验，不据此交付压缩打包器。
// 注意调用处第二参数传的是记录 +32，详见 03 中长度不一致候选。
// 载荷交 AIL_file_type：返回值 1、2、14 走“.wav”；13 走“.mp3”；
// 其余类型失败并释放数据。不能将所有 dat 看成裸 WAV 或将驱动采样率当输入限制。

// 音乐载荷链
// ----------------------------------------------------------------------------
// 注册时用 CreateFileA，保留 HANDLE；不整包载入内存。
// 播放先定位载荷绝对偏移，格式化两个反斜杠开头的“句柄,长度.mp3”特殊字符串，
// 然后 AIL_open_stream(driver, string, 播放记录+32)。
// 这是 Miles 接口字符串，不是磁盘上必须存在的“句柄,长度.mp3”文件。
// +32 原样传入 AIL_open_stream 第三参数；本群不擅自命名其单位或策略。
// 没有音效式解压分支；不能在 mus 的第 4 个 DWORD 写入长度就宣布支持压缩。

// 全部现有样本只读核对
// ----------------------------------------------------------------------------
// Sound：44 文件，1138 索引，ID 0..10163；每个载荷均以 RIFF 开始。
// Music：19 文件，23 索引，ID 1..201；无 RIFF 开头载荷。
// 全部索引第 4 DWORD 为 0；全部载荷边界在文件内；没有载荷落入索引区域。
// snd0000：N=38，首项 ID=0，offset=620，size=6192，压缩长度=0。
//   620 == 12+38*16；载荷开头 RIFF / WAVEfmt 空格。
// mus0000：N=1，ID=1，offset=28，size=2313302，末字段=0；载荷开头 ID3。
// RIFF/ID3 识别只说明容器特征，本轮未逐载荷验证所有音频帧可解码与时长。
// 这些数字来自当前文件集合；每份文件 SHA-256 和全部索引均保存在原始证据。

// 给内容工具的直接约束
// ----------------------------------------------------------------------------
// 保留现有头部、原始音频字节、ID 与覆盖顺序；新包号连续接在现有末尾。
// 对缺包、头 +4 不一致、短索引、过大 ID、载荷越界和新引入覆盖给出诊断。
// 重打包后重新计算绝对偏移；“包名后缀仍是 .dat”不代表内部结构没变。
// 可以先只读导出/替换未压缩载荷；压缩写入、改变音频类型、改变 ID 触发关系
// 都需单独实机验收，不能把静态格式读取成功当播放通过。
