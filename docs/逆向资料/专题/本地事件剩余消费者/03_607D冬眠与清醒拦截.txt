// 607D · 冬眠卡执行
// ============================================================================
// 40F4入口679530先动作66、道具506使用提示、声音329、扣发起卡，再排607D（2字节）。
// 若current本机，随后还排6006恢复请求。该恢复记录与607D内部的免疫/提示分开排队。
// 694A60仅写WORD607D；6812E0不读载荷，取当前队列游标并设scratch DWORD=0后调用7CF340。
// RTC明确EBP-12游标与EBP-24 scratch各4字节，伪码v3[6]不可当成一条24字节消息。
//
// 目标筛选
// ----------------------------------------------------------------------------
// 7CF340遍历i=0..参与者数量-1，只有以下条件全部成立才处理：
//   BYTE[G+3632+i]!=0；i!=current；
//   signed BYTE[P(i)+1494/1495/1493/1497]分别等于-1；signed BYTE[P(i)+1500]<=0。
// 这些字段分别由63EF50/63EF80/63F4A0/63EFB0/63F4D0检查，不能把伪码省略的ECX当G。
// 通过后直接互清P(current)+1472+i与P(i)+1472+current；清除发生在免疫检查之前。
//
// 第一层：狂暴免疫
//   6933F0检查BYTE[P(i)+1696]；非零时排声音316与UI4提示，使用RichStr359及Prop506。
//   RichStr359原文“%s處於狂暴狀態`n免疫 %s”；显示1350ms，6003等待字段未显式另写。
//   此分支不扣清醒卡，也不写冬眠计数；不能把免疫解释为607D整条消息失败。
//
// 第二层：清醒卡1071
//   7CD440先对P(i)查1071库存，随后800A50按当前地图校验卡片适用性。
//   任一步失败返回0；命中时排角色名+RichStr264“清醒卡生效”，显示1800/等待1350。
//   再声音316、6063角色i表情4、6061扣返回slot/group的一张清醒卡，返回1。
//   查卡返回槽可能来自group0或group1；不能强制解释为全部从背包group0取卡。
//   7F85C0先扫8个group0槽，再在模式允许时扫8个group1槽且要求其+4字节为0。
//   更完整的库存与适用性规则复用40C2和库存专题，不按伪码CWaitCursor名字推理。
//
// 第三层：写冬眠
//   仅当无狂暴且清醒卡未拦截时，7F8320把GValue[30]的低字节写P(i)+1500。
//   随后7F5D50把P+384动作状态设5并调用动画状态接口；本组未穷尽该接口图像副作用。
//   当前GValue.kpd indx30=2；Prop506文案为“使用後除自己以外的所有玩家冰凍1回合。”
//   这里是计数字段赋值；每日/每回合递减与文案天数不能未经复核直接等同。
//
// 完成边界
// ----------------------------------------------------------------------------
// 607D本身没有建立pending，也没有直接发TCP；循环可追加6001/6003/6063/6061表现记录。
// 正常受影响目标的冬眠字段在循环内同步写入；免疫目标只排表现记录。
// UI等待来自入队6003的消费者，不能把“函数返回”误写成“所有提示已播放完”。
// 生产者已经扣冬眠卡；所有目标免疫也未见回滚发起卡逻辑。
