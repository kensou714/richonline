// 6041 · 银行加发利息
// ============================================================================
// 7D6C80仅写WORD6041；7C0C50在7C1947构造并以Size=2入队。
// 该站点要求G+0xC44子对象+11==1、DWORD[G+3628]==current、63ECA0(M)成立。
// 63ECA0等价M+24模式为0，或模式为2且M+108为0；完整日历推进留回合专题。
// 67E8A0不读取载荷参数；循环0..G+E20-1，63E7D0要求BYTE[G+3632+i]非零。
// 每个有效P先读DWORD[P+1508]存款，以cdq/idiv10向零取商，再7FA0A0加入存款。
// 不是总存款先汇总再分，也没有商>0门；负值和32位溢出仍沿原指令执行。
// 最后显示UI4=G_MsgBox.ui，RichStr131“銀行加發10%儲金利息”，基础等待1800ms。
// 即便没有有效参与者，也会执行提示与等待。
//
// 金额结构与消费者
// ----------------------------------------------------------------------------
// 6067：7D6E60清+3/+4两标志；Size=12，+2 signed角色、+3增加、+4扣款、+8 DWORD金额。
//   67FFB0：+3非零先7FA050给P+1504现金加金额；否则+4非零7F83F0现金优先扣款。
//   两标志均为0不改金额；均非零只增加。无统一“结果值”或“设置余额”语义。
//   7C3220阶段0类型8站点：资源数值乘current现金，32位imul后idiv100；排+4=1扣款。
//   完整事件9替代分支及触发资格复用“回合继续与落点调度/阶段0_动态类型分支表”。
//
// 606E：7D6CB0仅写操作码；Size=8，+2 signed角色、+4 DWORD金额。
//   6803C0先7F83F0现金优先扣款；再63F620读现金，<=0调用63F680把现金直接写1。
//   此后存款可能为0；这是该消费者额外保底，不应混入所有扣款公共函数。
//   生产点：7C0C50中负数收益取负后传入，另PK条件路径传GValue[35]；7CEA20亦可生产。
//   本专题只审这些记录字段和消费者，不将7CEA20全部范围伤害机制宣布完成。
//
// 607C：7D6EA0仅写操作码；Size=8，+2 signed角色、+4 DWORD金额。
//   681290调用7F9F80存款优先扣款；不执行606E的现金保底1。
//   7C3220阶段0类型28取该资源记录+68金额，构造本记录；之后另排6009等待500ms。
//   500ms来自生产者后续记录，不是681290自己等待。
//
// 两种账户补差算法
// ----------------------------------------------------------------------------
// 7F83F0：cash-=amount；若cash<0，则deposit+=cash并cash=0；deposit<=0时deposit=0、返回1。
//   cash>=0时仅在cash==0且deposit==0返回1，其他返回0。
// 7F9F80：交换cash/deposit顺序；deposit<0才把差额转入cash，再把非正cash归0并返回1。
//   deposit>=0时仅在两个账户都为0返回1。
// 本组6067/606E/607C未把扣款返回值直接转换为破产、离场或网络请求。
// 三个消费者都传显示参数1；7F36F0把金额、增减方向和tick写入16槽表现队列。
// 表现队列不是再次扣款的账本；增加/扣款在调用时已改P+1504/P+1508。
// 例如cash=30、deposit=100、扣50：6067扣款后0/80；606E后1/80；607C后30/50。
// 上例假设正常非负金额，负金额与有符号溢出不能按商业规则自行“纠正”。
