// 4044入口：六字节业务记录与当前角色
// ----------------------------------------------------------------------------
// 662B20直接读取+2 WORD GmsvID、+4 signed WORD格位；不从记录读取参与槽。
// 64F710比较G+0x14784；不同先弹Error GmsvID，随后入口结束而不重插。
// 同步号相同后，用G+0xE28选择G+0xE00指针表中的R，比较R+0x5B8。
// 目标与当前格相等直接结束；不相等才构造临时记录并memcpy原六字节。
// 6942C0先写4044，随后复制覆盖六字节，不会生成新同步号或新目标格。
// 63E5B0以G+0x640取队列head；64FA50以该head调用6980F0，returnMode=1。
// 入口没有直接发包、修改当前位置、局部长度检查或重插次数上限。
// 这些结论仅限定入口与桥接，不排除上层网络校验，也不证明现场已发生停滞。
//
// RTC容量与按值ABI
// ----------------------------------------------------------------------------
// 独立解析662BD6/662BDE原始RTC描述：一个变量，偏移-0x14，容量6字节。
// 独立解析64FAE8/64FAF0描述：一个变量，偏移-0x12C，容量0x120=288字节。
// 64FA50的rep movsd传72个DWORD；6980F0从arg_0取整个按值槽，末尾retn0x128。
// 清栈296字节=288字节记录+position DWORD+returnMode DWORD；this在ECX。
// 失败反编译产生的v5[3]/v5[74]和众多参数不能替代RTC或ABI确定真实缓冲容量。
// 4044此调用Size=6；槽尾仍是调试初始化值，不是额外网络字段或288字节业务包。
// 64FA50本身未先限制Size<=288；本安全比较不能推广到全部调用者。
//
// 队首重插与先出队语义
// ----------------------------------------------------------------------------
// 6980F0比较两侧环形距离，搬移较短侧；前侧平局仍走前侧，保持既有相对顺序。
// position=head时前侧距离0，写prev(head)并更新head，新记录排在剩余队首之前。
// returnMode只选择返回新槽、next或prev；4044传1仍不会将记录插到队尾。
// 容量边界698640为head==next(tail)；失败返回-1，4044没有检查返回值。
// 7BB290在门控允许后经7D8010先推进head、count--，再复制288槽并按类型分派。
// 处理4044时原槽已出队；重插对象面对的是剩余队列，因此后继消息可能被延后。
// 服务器单次发送可对应本地多次处理同一记录，不能把重插误报为重复网络收包。
// 门控、容量和position合法性仍须按调用场景检查，不能称每帧必消费。
//
// 位置setter与独立运动更新
// ----------------------------------------------------------------------------
// 7F72A0写R+0x5B8后查询地图坐标，同时写R+0x21C=x*64+63、R+0x220=y*48+47。
// 因而替换单条格位写指令会遗漏显示坐标联动；地图查询输入边界仍未恢复。
// 694DB0仅从+0x5B8复制到+0x5BC，不是反向恢复当前位置。
// 6802A0的606C读取+2 signed BYTE角色槽、+4 signed WORD格位，与4044布局不同。
// 独立复读复用原证7F5D90/64FE70/64F780，共1215条指令、5041字节均匹配当前
// IDA与磁盘；相关四个跳板也匹配。此为字节复核，不提高大函数语义覆盖范围。
// 64F780先调用64FE70，再在后部调用7BB290；前者按活动槽遍历并调用7F5D90。
// 7F5D90受动作状态1、计时器、方向和跨格条件限制；到格后可写邻格或路线格。
// 因此运动可在后继队列仍受4044等待时推进并解除格位不匹配，但并非必然解除。
// 动作已停止、方向异常、路线不一致或槽变更等情况仍需运行快照判断。
// 不能由重插推出必然死循环，也不能由运动函数存在承诺所有停滞都会自行恢复。
