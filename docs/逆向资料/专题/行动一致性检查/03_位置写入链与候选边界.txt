// ============================================================================
// 参与者逻辑格位 | R+0x5B8 的写入与研究边界
// ============================================================================
// 4044 从 0x63E410 读取 R+0x5B8；该字段是 DWORD 逻辑格位，并非屏幕像素。
// 0x7F72A0 是直接设置格位的入口；0x60A086 是其 E9 跳板。
// 0x7F72C9 把传入 int 写到 R+0x5B8。
// 然后由 R+0x57C 取得地图相关对象，查询该格的坐标输出。
// R+0x21C = 第一坐标输出*64+63；R+0x220 = 第二坐标输出*48+47。
// 所以 setter 具有“逻辑格位 + 显示坐标”的联动副作用，不宜仅替换那条 DWORD 写指令。
// 地图查询辅助函数的边界检查没有在本专题重新展开；不能据 setter 宣称所有输入都安全。
//
// 位置快照与本地恢复记录
// ----------------------------------------------------------------------------
// 0x694DB0：读取 R+0x5B8，写入 R+0x5BC；这是快照拷贝，没有反向改写当前位置。
// 它的直接跳板 0x60ED07 只有一个已识别调用点 0x67FF56，所属函数 0x67FE70。
// 快照的完整消费用途本专题未闭合，暂不命名为“起点”“终点”或特定卡片状态。
// 0x6802A0 消费本地 0x606C 记录：+2 signed BYTE 为参与槽，+4 signed WORD 为格位。
// 它从 G+0xE00+4*槽取 R，调用 setter，再调用一个角色刷新入口。
// 这与 4044 布局不同：4044 的 +2 是 GmsvID，参与者由 G.currentSlot 选择。
// 606C 的生成、传送和恢复序列见“移动与动画协议/02_移动推进与完成回执.txt”。
//
// 运动 tick 的五处直接写入证据
// ----------------------------------------------------------------------------
// 0x7F5D90 的方向 0/2：累计 48 像素跨格；方向 1/3：累计 64 像素跨格。
// 0x7F5EE5、0x7F5F7B、0x7F5FF3、0x7F6089：写入地图邻接查询返回的格位。
// 四处写入前均把旧 R+0x5B8 保存到 R+0x218；跨格后重置 R+0x224 的累计位移。
// 若 R+0x228 非零，0x7F60D2 又按预计算路线格调用 setter，校正逻辑格与像素坐标。
// 此处“四条直接写 + 一条 setter 内直接写”为 5 个写指令地址，不是全部运行时来源。
// 0x7F5D90 为大函数，仅相关运动分支达到本专题语义审阅范围。
// 完整原证复用“移动与动画协议/证据/movement_protocol_core.json”的对应函数。
//
// setter 的已识别直接调用点
// ----------------------------------------------------------------------------
// 0x630D5E / 0x630CC0；0x631889 / 0x631800；0x631F69 / 0x631EE0。
// 0x65D834 / 0x65D770；0x661A0A / 0x661490；0x6802D6 / 0x6802A0。
// 0x7CF2D7 / 0x7CF170；0x7F411D / 0x7F3C70；0x7F60D2 / 0x7F5D90。
// 0x7F7EC8 / 0x7F7E80；0x7F8027 / 0x7F7FF0；0x7F8197 / 0x7F8160。
// 每对为“call 指令 / 所属函数入口”；这 12 个直接调用点已核对 IDA 与当前磁盘字节。
// 仅记录地址不等于完成调用者业务分析；函数名、角色槽来源及错误输入需逐场景审阅。
//
// 5B8h 字面候选：56 条已核验，不是全量位置写入索引
// ----------------------------------------------------------------------------
// position_displacement_scan.json 扫描已声明函数中含 5B8h 的汇编文本。
// position_displacement_verified.json 逐候选核对所属函数、指令长度、IDA 原字节与磁盘。
// 56 条分为：5 条直接写、44 条读、3 条 push 立即数、4 条 add 立即数。
// 0x69E43B、0x73F2A2、0x740A01 的 push 5B8h 是 Size 参数，不能当作格位字段。
// 0x69EBA0、0x6AA2FD、0x6AA783、0x6AA79B 是 add 地址偏移；对象归属另待证明。
// 即使指令访问 [reg+5B8h]，仍应查 reg 来源，不能跨对象复用 R 的字段解释。
// 文本扫描不会穷尽别名访问、间接调用、数组批量复制、未声明代码与动态生成代码。
// 因此不得把“只找到 5 条直接写”解读为“其他函数绝对无法改变位置”。
//
// 可操作的后续研究
// ----------------------------------------------------------------------------
// 把 setter 的 12 个调用点与各消息/初始化流程对应，分清强制定位、路线初始化与恢复。
// 追踪 R+0x5BC 的消费端，确认快照是否参与另一个一致性判断。
// 在运行时记录 4044 前后的 R.state/currentCell/currentSlot 和 Q.head/count，复核静态推论。
