// ============================================================================
// 游戏队列 | 插入位置、消费次序与停滞排查
// ============================================================================
// Q=G+0x640，记录槽步长固定 0x120=288 字节。
// Q+0x00：记录存储基址；Q+0x04：环形容量；Q+0x08：当前条数。
// Q+0x0C：head；Q+0x10：tail。名称由读写关系确定，不继承反编译的 MFC 函数名。
// 0x698680：next(i)=(i+1)%capacity；0x6986B0：prev(i)，0 时回绕到 capacity-1。
// 0x698640：head==next(tail) 的容量边界谓词，插入入口为真时返回 -1。
//
// 0x6980F0：在指定位置之前插入
// ----------------------------------------------------------------------------
// 实际形态为 Q(this), record[288] 按值, position, returnMode。
// 函数尾 retn 0x128，确认 288 字节记录与两个 4 字节参数的清栈大小。
// 算出 head 到 position 的环形距离，与另一侧距离比较，选择搬移较短的一侧。
// 插入前半段时向 prev 方向搬移，更新 head=prev(head)，使新记录位于 position 前。
// 插入后半段时向 next 方向搬移，更新 tail=next(tail)；相对记录顺序保持。
// 成功后 count++；返回游标依据 returnMode：0 为新记录，1 为 next(新记录)，2 为 prev。
// returnMode 仅改变返回值，不改变新记录的插入先后；4044 包装固定传 1。
// head 位置插入的前侧距离为 0，因此 4044 会成为新的队首，而非排到队尾。
// 容量边界触发时返回 -1；4044 入口没有检查此返回值，也没有本地重试计数器。
//
// 0x7BB290：先 pop，再调用类型处理器
// ----------------------------------------------------------------------------
// 消费受三个谓词门控；其完整来源本专题未重新展开，不能称每一帧必定消费。
// 门控允许后，0x7D8010 保存旧 head，更新 head=next(head)、count--，复制旧槽到临时区。
// 消费器再把 288 字节复制到全局 word_A87B88，读取 +0 signed WORD 类型。
// 类型在 0x4000..0x7FFF 且表槽非空时，间接调用表入口，并传 G 和该全局记录地址。
// 因此执行 4044 时，原记录已经出队；它拿到的是剩余队列的当前 head。
// 若格位尚未匹配，原 6 字节被插在剩余队列 head 之前，下一次消费可能仍取到 4044。
// 重插是本地操作；服务器日志出现一次 4044，也可能对应客户端多次处理同一条记录。
//
// 为什么不能直接写成“必然死循环”
// ----------------------------------------------------------------------------
// 移动更新链在消费游戏队列之前推进参与者；下一轮 tick 可能让格位达到目标。
// 若移动状态、计时器、方向和路线都有效，重复比较可以是正常等待动画到格的机制。
// 但格位持续不匹配、当前槽变更、动作已停止或方向异常时，后继消息可能被延迟。
// 若解除错误状态的记录恰好排在 4044 后面，则必须结合完整调度与现场观测判断影响。
// 本专题未运行现场复现，也未证明所有状态更新都依赖这条队列，所以只保留可能性。
//
// 最小观测记录：一次消费写一行
// ----------------------------------------------------------------------------
// 记录类型、record+2 GmsvID、G+0x14784 GmsvID、record+4 signed WORD 目标格。
// G+0xE28 当前槽、R 指针、R+0x5B8 当前格；同时保存参与槽切换发生的时间。
// R 的动作状态、总步数、步索引、方向值、路线格；具体偏移见“移动与动画协议”。
// Q 的 head/tail/count：进入消费者前、pop 后、4044 返回后各取一次。
// 标记 4044 是否重插、插入返回值、下一条类型；不要把本地重插算作新的网络收包。
// GmsvID 不匹配要单独标记，因为该分支弹窗后退出，不进入位置等待。
//
// 排查次序
// ----------------------------------------------------------------------------
// 先确认 4044 实际被消费，再确认 GmsvID 相等、当前槽和目标格是否合理。
// 格位不匹配时检查 4011 是否已消费，以及运动门控、方向数组和路线格是否继续变化。
// 若 R+0x5B8 始终不变，查动作状态与 tick；若不断变化却错过目标，查路线和槽对应。
// 若 GmsvID 不一致，查同步号更新链与消息顺序；不要试图用重发位置包掩盖它。
// 修复前保存原始包、客户端状态和队列快照；这比仅有服务端“已发”日志更能定因。
//
// 原证：check_queue.json、check_consumers.json；移动时序复用“移动与动画协议”专题。
