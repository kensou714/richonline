// 返回值与消费
// ----------------------------------------------------------------------------
// 五个惰性装载入口的反编译类型显示char*，但不是“返回帮助正文”。
// flag非零的早退路径保留this；实际装载或读取失败路径返回临时容器清理后的寄存器值。
// 不应把该返回值当作统一成功码或可供UI显示的字符串地址。
// 69D7E0/69D810/69D840/69D870/69D8A0的有限窗口显示：
//   先调相应装载入口，再读取+80/+8C/+98/+A4/+B0计数。
// 数量来自对象字段，不来自装载函数的返回值。
// 五个带index的短读取器补采了完整声明块，均先调用装载入口，再返回数组内部地址：
//   69D8D0：OP +84 + index*512；69D910：RULE +90 + index*512。
//   69D950：EVENT +9C + index*580；69D990：NPC +A8 + index*580。
//   69D9D0：prop +B4 + index*12。后面三者返回记录起点，不直接返回正文。
// 五者均ECX对象、一个栈上index、ret 4；不检查index、count或数组是否为空。
// 因而调用者必须先确认有效条目；getter没有提供通用“无条目返回空”分支。
//
// 文本存储差异
// ----------------------------------------------------------------------------
// OP/RULE文本在Help自有512字节槽内，EVENT/NPC名称与描述在580字节记录内。
// 这些字节由配置解析器复制；销毁临时KPD/文本对象不会直接释放Help数组。
// prop记录只保存名称/描述的外部表地址；销毁临时对象同样不能将其变成Help自有文本。
// 消费者不得释放借用的文本指针；Help数组或外部来源表失效后不得继续使用。
// 真实控件显示、所有消费者及动态资源热更新仍需单独验证。
//
// 已见销毁路径
// ----------------------------------------------------------------------------
// 629480以ECX接对象，先经612B55调用69C790，再按栈参数bit0决定是否delete对象。
// ret 4并返回原this；执行了delete的路径不能再解引用该地址。
// 69C790依次检查+84/+90/+9C/+A8，非零则传给91F7E0，随后把相应指针清零。
// 这些字段是前四类数组；不重置计数或flag，不遍历EVENT/NPC里的资源引用。
// 91F7E0完整17字节体把指针转交operator delete；未见逐元素析构循环。
// 分配侧91BD80完整17字节体把Size转交operator new，不能沿用IDA误识别的UI方法名。
// +B4不在清理体里：prop的12字节数组既不由该构造清零，也不由该析构释放。
// 这是本轮可以确认的代码遗漏范围；是否由其他路径接管，必须继续查写者/释放者。
// 不因常见C++容器习惯补出不存在的第五次释放。
//
// 重置与重新装载
// ----------------------------------------------------------------------------
// 69C880再次运行只重置count和flag，不先释放已有数组；不能认定它支持安全热重载。
// 69C790执行后若对象还被使用，flag仍可能为1；不能认定getter会自动重新装载。
// 单例创建未见同步机制；线程重入、分配失败及悬空借用均没有实机证据。
