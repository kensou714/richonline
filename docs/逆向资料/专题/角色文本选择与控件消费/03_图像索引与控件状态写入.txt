// ============================================================================
// 6DBA40 case10 / 图像数值寻址及控件落点
// ============================================================================
// 6DBA40为ECX=T加四个栈参数(kind,group,column,extra)，ret16，默认结果初始化为-1。
// 6DBA67先无符号检查kind<=11；6DBA74从6DBDB4+4*kind跳转。
// 旧完整主体止于6DBDB4，不能靠主体字节证明跳表；本批另采12项48字节。
// 证据/switch_table/bounded_raw.json#/data_windows/0：slot10=6DBABD、slot9=6DBA7B。
// 该表逐字节匹配当前PE与IDB，只新增数据证据，不增加函数覆盖数量。
//
// case10真实公式
// ----------------------------------------------------------------------------
// 6DBABD..6DBADB用JL/JGE检查：0<=group<signed DWORD[T+3ABFC]，0<=column<100。
// 通过后读取DWORD[DWORD[T+3AC00]+1200*group+12*column+4]。
// 1200为100条12字节记录，读取每条的+4 DWORD；不是返回记录首地址。
// 本题group=47、column=i+40，extra=-1未被此case读取。
// 正常非溢出角色序号0..59可进入列40..99；i=60首先命中会因列100而返回-1。
// i极大时i+40按32位回绕；有效读还必须满足回绕后signed列>=0且<100。
// 由于i由0开始、signed i<N且N最大INT_MAX，可达i不会回绕为0..99；故本链有效i仍为0..59。
// 同时要求signed DWORD[T+3ABFC]>47；查询本地没有T或表指针NULL保护。
// case9还经R的映射函数重映射group，不能把它的索引规则套给case10。
//
// 从返回值到控件存储
// ----------------------------------------------------------------------------
// 6FA7F0：ECX=C，把输入value、state=0、P=C+0xA4传给8E1C70，ret4。
// 8E1C70写DWORD[P+40*state+24]，因此本题是DWORD[C+0xBC]。
// 该槽是控件样式状态的图像数值标识，详见“控件图像状态记录/01_状态布局与调用约定.txt”。
// 在本链不存在字符串长度扫描、复制、引用计数或返回指针所有权操作。
//
// 8E1C70副作用与-1
// ----------------------------------------------------------------------------
// 新旧值不同且旧值!=-1时，读取全局ACC3C8的+2C回调；非NULL才以(C,state)调用。
// 回调发生在新值写入之前；本体不检查ACC3C8本身是否NULL。
// 随后总会写新DWORD，包括value=-1；旧值==-1只抑制上述回调，不拒绝新-1。
// 若C+181 BYTE为0不刷新；非0时，C+180非0/state0或C+180为0/state3才进入刷新。
// 本题固定state0，因此自动刷新还要求C+180与C+181都非0。
// 刷新走6033EE桥到8E2200，其完整契约复用既有控件专题，本批不再新增主体。
// AL可能来自状态BYTE或刷新结果，不可视作统一成功标志。
// -1进入图像槽不等于已证明隐藏、清图或显示缺省图片，最终绘制还取决于路径及资源状态。
