// 文本控制节点池与操作 / 文本消费与协作边界
// 复用依据：提示文本生命周期/证据/lifecycle.json；摘要见 reused_owner_audit.json。
// 8E1620 与 8EA2B0 的旧全部声明块已匹配当前 PE；语义仅复核本文所述路径。
//
// 文本子对象与消费循环：8E1620
//   子对象+00持 WCHAR 文本，+04持活动链，+08持逐字符 BYTE 宽度缓存，+0C持总宽。
//   控制开关+28h 非零时，经管理器+40h 取得链，写入子对象+04。
//   8E16CF 调 8EAA30 时传该活动链，因此此处求和后链继续由文本子对象持有。
//   宽度缓存分配 wcslen+1 字节，先清零；所有权不能与16B节点或文本副本合并。
//
// 8E16EA..8E1746 的完整循环
//   以 EBP 为字符索引、EBX 为普通段计数、EDI 为当前节点；界限是原文本 WCHAR 数。
//   节点非空且 BYTE+08 非零：取 BYTE+04 写当前位置缓存，读取 DWORD+00。
//   先把索引加 count-1，再在公共尾部加1；节点立即推进到 DWORD+0C。
//   普通路径调用管理器+20h 的逐字符回调，调用者清16B栈，取 AL写缓存。
//   字符只经 mov CX 装入再 push ECX，高16位未在本调用点归一化；勿擅定实参为零扩展 WCHAR。
//   普通段计数到节点 DWORD+00 时推进 next，并把普通段计数清零。
//   若当前节点为空，普通路径仍按字符测宽；不能说缺节点必定卡住。
//   控制段只写一个缓存位置，其余被跳过的位置沿用已清零内容。
//   求总宽使用节点 DWORD+04，缓存控制宽仅取其低BYTE，两者精度不同。
//   本循环不回收节点。链的重置/销毁需引用原文本所有权专题的回收路径。
//
// 有限外层窗口
//   8E43A0 的 8E447D：调用 8EAA30 时已有链实参为0；只据该调用确认临时求和入口。
//   8FF330 的 8FF4AC、8FF5C3、8FF83E：已有链实参为0，调用原地过滤 8EAAF0。
//   指针来自局部文本区；后续控件流程与全函数容量契约本批没有展开。
//   8EA2B0 的 8EA34E 窗口：调用 8E02F0，然后释放并清 ACC3C8 管理器。
//   每个 owner/start/end 见 bounded_audit.json；不能把调用窗口计作 owner 全函数复核。
//   这些窗口没有支持“异步队列”的结论，不与6003事件记录队列混用。
//
// 给后续协作者的限制
//   1. 只复现当前基线的字段和调用契约；新增目标需要独立记录版本及声明范围。
//   2. 普通段字体测宽依赖8171A0，本专题只确认调用和累加，未重建字体算法。
//   3. 注册路径已闭合，全部运行期回调改写者、池访问线程及重入行为仍未证明。
//   4. 8EAAF0 长文本容量、源缓冲可写范围、空回调路径和异常失败需要单独采证。
//   5. 未执行客户端，没有据静态资料宣称界面显示、控制图形或实机退出成功。
//
