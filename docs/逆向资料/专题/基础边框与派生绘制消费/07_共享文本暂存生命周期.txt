// 必要依赖补证：证据/supplement_raw.json#/functions/0，8EA8D0..8EA9CC。
// 一声明块252字节；不递归扩展、不改变四个固定新主体范围。原证保留伪码但不采纳char返回声明。
// 补证SHA256：d3741576bb9242cafef4b84269c62608719147b28d13dac9729ebf2f37613016。
// 五个DWORD栈槽依次为text、node_head、start、length、fill；只消费fill低BYTE。
// 两个出口均retn14h，callee清五词。入口ECX未作this使用，实际从ACC3C8重读全局表E。
// 90C070四处虽设置ECX=E，不能据此把此函数命名为依赖ECX对象的thiscall接口。
// 本体无CALL，无新桥；表重读与六条全局引用不证明运行时指针稳定。
//
// 清空早于参数门
// ----------------------------------------------------------------------------
// 8EA8DA令EDI=E+6C，8EA8E3令ECX=1400h，EAX=0，8EA8EC执行REP STOSD。
// 正常x86调用约定DF=0时，清空[E+6C,E+506C)共5000h字节；本体没有CLD。
// start在8EA8EA先TEST，REP不改该标志，8EA8EE再signed JL拒绝负数。
// 随后8EA8F8/FA以signed length<=0拒绝。因此参数无效也已执行共享区清空。
// 5000h是本次清零跨度，不是已恢复的分配容量；没有表NULL、长度上界或异常恢复门。
// 此函数不分配、不释放内存；E对象的创建、销毁、缓冲所有权仍未闭合。
//
// 节点前缀不是按start裁剪的普通子串
// ----------------------------------------------------------------------------
// 令p=0为输出单元数，t=0为源单元累计位置，N=node_head。
// N非NULL且signed t<=start时读取n=DWORD[N]、m=DWORD[N+4]；下一节点为DWORD[N+0C]。
// 只有n!=m且m==0才复制text+2*t开始的完整n个WORD到E+6C+2*p，再p+=n。
// 未匹配节点也t+=n并沿next前进；匹配节点不按start或length截短，t==start仍进入处理。
// 8EA91F的TEST接8EA92E的JBE只排除零；负n的位型仍进入递减到零复制循环。
// signed累计比较、32位加法及地址乘2均没有溢出门，节点无环检测，源端无NUL/容量门。
// 这里没有消费节点+08整块标志，不能把90C070的整块选择条件复制到此函数。
//
// 追加主体与终止WORD
// ----------------------------------------------------------------------------
// fill低BYTE为0：从text+2*start逐WORD复制length个单元到E+6C+2*p。
// fill低BYTE非0：8EA99B用MOVSX DX,AL，将signed BYTE扩展为WORD后写length次。
// 例如7Fh写007Fh、80h写FF80h、FFh写FFFFh；不是BOOL开关，也不是零扩展8位字符。
// 两条有效路径都在p+=length后显式写WORD[E+6C+2*p]=0，额外终止WORD占用空间。
// 本体不以输入NUL终止复制；有节点时输出是选中前缀加切片/填充，不是只返回length个单元。
// 若只按清零区间计算，输出和终止需满足0<=p且p<2800h；本体没有执行这一检查。
// 该算术界仅描述5000h区域内的写入位置，不证明相邻空间不可写或整个对象分配边界。
// 有效路径出口EAX为路径相关残值；无效参数路径EAX为0，不能归纳成稳定BOOL或char结果。
//
// 对90C070消费者的影响
// ----------------------------------------------------------------------------
// 四个调用均fill=0；调用先于颜色、行坐标和callback门，所以未绘制仍会清空/写入共享区。
// 后续十二词callback接收E+6C；文本不能安全保留到下一次调用之后而不另行确认生命周期。
// 本体未见锁、重入保存或线程局部区；不声明线程安全，也不直接把静态缺少锁定性为运行时BUG。
// 下一步仍需E对象分配/注销writer、运行时目标及嵌套callback证据，才可给出实际补丁方案。
