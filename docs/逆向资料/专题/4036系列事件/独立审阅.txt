// 二、4038与403B的RTC边界
// 4038：0x661454描述符count=1，变量表指针0x66145C；
// 首项offset=-20、size=8、name=0x661468，名称为xZy001。
// 0x661454原20字节：01 00 00 00 5C 14 66 00 EC FF FF FF 08 00 00 00 68 14 66 00。

// 不采用伪码v3[3]的12字节表观栈区作为有效消息大小。
// 4038先验包+2 WORD，再要求DWORD[G+3624]等于DWORD[G+8]；
// 包+4 signed DWORD大于0才调用650110减本机槽金豆并交动画41及UI1通知。
// 403B：0x661EA3描述符count=1，变量表指针0x661EAB；

// 三、UI40显示、隐藏与通知ABI
// 管理器6E3B40以ECX=manager，三个栈参数为UI槽、计时参数、初始化载荷，返回retn0Ch。
// 6E4020以ECX=manager，一个栈参数UI槽，返回retn4；隐藏只在槽对象存在且查询虚函数真时调用。
// 6E4640以ECX=manager，两个栈参数UI槽与payload，返回retn8；
// 它从manager+68所指132字节槽的+4取窗口，再以ECX=窗口调用vtable+16。
// 当前PE的UI40虚表0xA26280逐槽解析为：
//   +16  0x601AD0 -> 0x71E760，文本通知；
//   +60  0x6109A4 -> 0x6E2520，显示槽；
//   +64  0x60EA82 -> 0x71E730，隐藏槽；
//   +68  0x601C47 -> 0x6FA100，子窗口控制转发；
//   +80  0x61199E -> 0x6FA1E0，继续到6FA210读取子窗口+385 BYTE；
//   +152 0x60615C -> 0x6E26E0，按钮前置回调。
// +60和+64调用不传额外栈参数；6E2520和71E730也都以无栈参数retn返回。
// 显示对子窗口vtable+200/+196分别传1并写窗口+56=0；
// 隐藏先经64FB50清基础暂停，再对子窗口+200传0并写窗口+56=2。
// 403B begin调用顺序是请求创建/显示、请求隐藏、文本通知；end是文本通知后请求显示。
// 查询条件、对象创建失败等可影响实际显示，以上顺序不等于运行期每次必然可见。

// 四、403A本地命令与角色槽来源
// +14 BYTE非零路径在GmsvID验证之前分支，只排UI0的6008；
// 其24字节静态载荷首两DWORD写{320,signed BYTE[包+4]}，其余字节本入口没有写入。
// +14=0且ID通过、+4 signed BYTE不为-1路径依次排：
// 6008、该+4槽位置6005、文本338的6003、动画45的6000、行动槽位置6005，
// 最后只有行动槽等于本机槽才排6006模式1。
// +4=-1且+6=-1时，+12 signed WORD=0和7C0BB0为真才排常规事件；
// 先取P(DWORD[G+116])位置6005，再按配置文本决定6003，再排动画26，
// 最后694170验证行动槽后才补P(DWORD[G+3624])位置6005。
// +12=-1或1另走7C0A60/7C0AE0，不能与上述本地命令序列合并。
// +4=-1且+6不为-1的配置分支，先以包+8 WORD排6005，随后更新：
//   6619FD读取G+74h，7F72A0接收者为P(DWORD[G+116])；
//   661A1A读取G+74h，7F7940接收者同上；
//   661A68读取G+74h，7F4550同步配置的接收者仍同上。
// 文本与动画26之后，661BF0改取G+E28h，再排行动槽的位置6005。

// 五、UI40完成上行与风险边界
// 文本槽从窗口+72开始，四槽各128字节；+584/+588/+592为count/cursor/total，
// +596/+600为组开始和最近显示Tick。第五条的目的地址计算落到+584，
// 因此无界strcpy存在覆盖计数/时钟的静态风险；未声称本次运行已经触发。
// 每条文本增加10000 pending时长，end设置组Tick、显示首条并暂停基础队列。
// 自动完成71E8C0与按钮完成71EA30都构造8字节0036：
