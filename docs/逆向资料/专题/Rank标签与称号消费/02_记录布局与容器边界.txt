// 两层记录
// ----------------------------------------------------------------------------
// Category[i] = A859D0 + 84*i，i=0..4。
// +0..63   标签缓冲：7559E0写label，753ED0把地址传给控件。
// +64      32位index：基址A85A10；UI按84字节同索引读取。
// +68      称号容器起点：基址A85A14；读取器和UI均把该地址作为this。
// +72/+76/+80 对应容器this+4/+8/+12三指针；+68首DWORD本专题没有语义。
// 84字节步长与五项也由A1FF90的阵列析构实参印证，但该包装不证明完整析构效果。
// 容器内称号记录步长68：+0..63文本；+64 signed end；构造7986C0设-1并清文本。
// 所谓文本64不是64个中文字符；字节长度和终止NUL必须单独预检。
//
// 容器算术与无边界检索
// ----------------------------------------------------------------------------
// 79A590：begin非NULL时size=(end-begin)/68，否则0。
// 79A4B0：begin非NULL时capacity=(limit-begin)/68，否则0。
// 两者字段为this+4/+8/+12；除法按32位差值做有符号除68，未检查指针关系。
// 79A510取begin、79A550取end并写入输出迭代器；79C5A0经79C920写单DWORD。
// 79AE10经79C5E0执行迭代器指针 += 68*index，再把新指针写输出。
// 79ADE0经79C660返回迭代器首DWORD；79C610经79C950计算两迭代器差/68。
// 因此7997F0(this,index)返回begin+68*index，没有负索引或size上界检查。
// 空容器与越界调用不会在该链安全返回空字符串；本群没有替UI补充范围门。
// 返回的是容器内地址；若发生重分配，旧记录地址不能假定继续有效。
// 本群未证明多线程同步、迭代器调试容器绑定或协议响应所有权。
//
// 加入记录：确认的控制与未确认的构造
// ----------------------------------------------------------------------------
// 799860比较size>=capacity。容量不足时取end迭代器，经79A5F0进入79B080；
// 尚有空间时调用79A6B0(end,1,record)，将返回的end+68写回this+8。
// 79A5F0保存插入点相对begin的元素偏移，调用插入，再以新begin重建输出迭代器。
// 79A6B0调用79CD60并返回dest+68*count；79CD60转交79D790构造循环。
// 79D790以68步长逐项调79DDC0；异常路径调用79DE00。两叶子不在本批继续扩围，
// 故不能仅凭这些包装称已闭合对象构造、回滚及全部元素所有权。
// 79D730读AL辅助局部；本路径局部来自调试填充0xCC，不是业务常量返回。
//
// 79B080有限语义
// ----------------------------------------------------------------------------
// 入口把源记录17个DWORD复制到局部68字节快照，证明插入前保留值内容。
// count=0时不执行后续插入；容量够时按插入点到end的元素数分两种移动路线。
// 容量不足时先计算旧capacity+floor(capacity/2)，不满足可增长条件时置0，
// 再使候选至少为size+count。这里只恢复控制算式，不把未展开最大值助手写常量。
// 分配返回后依次调用前缀复制、插入构造、后缀复制，再释放旧储存并提交
// begin=new、end=new+68*(oldsize+count)、limit=new+68*newcapacity。
// 79B600把旧begin传operator delete；第二数量实参在这个包装中未使用。
// 79CF90是直接值填充：dest!=last时重复复制源68字节并令dest+=68。
// 当dest==last进入时无定义好的循环结果；不要把伪码result当可靠尾地址。
// 分配79B640仍委托79D030；范围复制79CF40委托79DAB0；反向移动79CFD0
// 委托79DB10；元素清理79B520委托79CEE0；最大值与异常助手也未闭合。
// 因而79B080按“插入与增长局部审阅”归档，不提升完整容器安全性或异常保证。
// 对任意插入位置、巨大count、别名输入、整数溢出、失败回滚不承诺支持。
//
// 退出边界与重载风险
// ----------------------------------------------------------------------------
// A1FF90传A859D0/步长84/数量5/回调60D178给阵列析构器920970。
// 60D178解析到7A1030，现场将this+68传6009B4 -> 7A10C0。
// 7A10C0未展开，所以这里只确认每分类容器析构入口，不宣称所有资源释放闭合。
// 7559E0没有在已有容器加入前清空；如果重载可达，会向各分类继续追加称号。
