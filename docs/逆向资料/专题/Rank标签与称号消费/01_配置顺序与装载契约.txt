// 实际循环与字段
// ----------------------------------------------------------------------------
// 外循环严格 i=0..4，格式化 RANK(i+1)；不读取分类总数，RANK6不会自动消费。
// label：字段0，逗号分隔，目标 A859D0+84*i，容量参数64。
// index：字段0读入32字节临时槽，atoi后写 A85A10+84*i。
// num：A2A9D8原字节6e756d00；755B92 push的是该直接字符地址。
// IDA自动名off_A2A9D8不表示DWORD解引用，不能把num解释成指针槽。
// num读入相同32字节临时槽，atoi得称号数；内循环 signed j<num，j从0开始。
// 每次格式化 TITLE(j)，选段，再构造68字节临时记录：前64字节清0，+64=-1。
// title以字段0/容量64写记录前部；end键找到才读32字节、atoi写记录+64。
// 每次把该临时记录加入本分类容器 A85A14+84*i。
// end是数值字段，既不是[END]节，也不是内循环停止标记；缺end保留-1。
// MORE/url与RULE/url分别写 A84418、A84310，容量参数均260，字段0/分隔符逗号。
//
// 同名 TITLE 的归属由物理顺序决定
// ----------------------------------------------------------------------------
// 608335 -> 819470 从文本对象+140向前扫描，命中后+140留在段正文起点。
// 609528 -> 819660 每次从该正文起点重置+144寻找键；找键不移动+140。
// 612C1D -> 819A20 使用+144的局部副本读取字段，不移动段扫描位置。
// 因而 RANK1后找TITLE0..2，之后找RANK2，会继续向前；下一组TITLE0..2
// 可以复用相同段名。这些段没有嵌套树关系、自动合并或按全局名称去重。
// 不能把资源改成所有RANK节在前、所有TITLE节在后，也不能用普通INI字典导出。
// 资源中的num=3使每组正好消费三个连续TITLE；这是代码和资源联读的结论。
