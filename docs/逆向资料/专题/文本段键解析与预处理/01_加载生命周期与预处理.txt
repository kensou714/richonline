// 加载、清理与CR预处理
// ============================================================================
// 入口桥             本体                职责
// ----------------------------------------------------------------------------
// 608F8D             8191D0              构造指针字段
// 60BA26             819220              调用清理的析构包装
// 60ACA7             819250              文件/内存文本加载
// 607C3C             8193F0              丢弃文本与游标
// 60D71D             819FB0              删除所有CR字节并替换缓冲
//
// 已见字段；按本群行为恢复，不当作原源码类型或精确sizeof
// ----------------------------------------------------------------------------
// +0x00 / +0        DWORD       文件流槽；读文件关闭后仍保留旧指针值。
// +0x04 / +4        pointer     自有缓冲基址；mode2复制，不借用调用者存储。
// +0x88 / +136      DWORD       当前有效长度；加载前为实参或ftell结果。
// +0x8C / +140      pointer     段扫描位置；命中后也是当前段内容基址。
// +0x90 / +144      pointer     键扫描位置；命中后指向值起始。
// +0x94 / +148      pointer     逐行游标；本篇不认领逐行取值本体。
// +0x98 / +152      DWORD       来源模式，已见1文件、2内存。
// +0x9C / +156      DWORD       加载尾部固定写1；后续行计数行为复用旧专题。
// 字段覆盖到+159只能证明最低跨度160字节；中间空隙不能推为未使用。
//
// 8191D0 / 819220 / 8193F0
// ----------------------------------------------------------------------------
// [事实] 构造仅清+0/+4/+140/+144/+148；不清长度、模式、行计数。
// [事实] 析构包装恢复ECX后调用607C3C；不应按伪码返回类型承诺成功值。
// [事实] 清理先清+0和三个游标，随后buffer非零才delete并将+4清零。
// 清理不调用fclose，也不清+136/+152/+156；这些字段不能代表清理后的有效文本。
// [推断] 活写流若直接进入清理，流槽会被丢弃；实际可达性须查写流调用者。
//
// 819250(mode, source, length, preprocess)
// ----------------------------------------------------------------------------
// preprocess只测试实参低BYTE；下文该参数的零/非零均指该BYTE，见819397 movzx。
// [事实] 先清理旧对象，再写+136=length、+152=mode；失败不回滚旧文本。
// mode1：fopen(source,"rt")失败直接return0，buffer和三游标已为NULL，
// 长度仍为本次实参、模式已为1，行计数仍为旧值；必须门控返回值。
// 打开成功：fseek(END)、ftell、精确new(length)、fseek(SET)、fread(size1)，
// 实际读取数覆写+136；fclose后不清+0。fseek/fclose返回未门控，
// ftell结果未检查为负；fread变短或为零仍可到达return1。
// [未知] CRT文本模式转换的全部细节、异常和分配失败由外部CRT决定，未在此闭合。
//
// mode2：精确new(length)、memcpy(buffer,source,length)，两者使用同一+136。
// 本体没有source非NULL、正长度或乘法上限检查，也没有额外NUL空间与NUL写入。
// 调用者可以独立释放原source，但传入原对象buffer再重载会先delete旧buffer；
// [推断] 这种别名输入具有读已释放内存条件风险，尚未证明存在该调用者。
//
// 无效mode：819356比较2失败后跳到819397；preprocess=0时完全没有加载，
// 仍写段/逐行游标=NULL、行计数=1并return1，+136仍为length、+152仍为mode。
// [事实] 因此return1只表示走完尾部，不保证mode合法、缓冲有效或文本非空。
// preprocess非零时仍会进入819FB0；无效mode且正长度时buffer为NULL却要读取，
// [推断] 这是不满足输入契约的路径；未构造样本或断言具体崩溃表现。
//
// 819FB0与游标顺序
// ----------------------------------------------------------------------------
// [事实] 先按旧+136分配新缓冲；signed循环i<length逐字节读取旧buffer，
// 仅跳过0x0D，其他字节保持原顺序；删除旧buffer后保存新buffer与新长度。
// 所有CR都会删除，包括独立CR和正文内CR；不是仅处理CRLF，也不是转码。
// 新容量仍为旧长度，未缩小分配；新有效长度等于保留字节数，不追加NUL。
// 本体不写+140/+144/+148，不保证游标指向新分配。
// 819250内部先调用预处理，再把+140/+148设成新buffer；+144仍为清理后的NULL。
// [推断] 若外部在定位后单独调用819FB0，旧游标会保留对已释放buffer的地址；
// 可达调用者和实际错误需另查，不能称资源编辑器可任意调用该预处理接口。
// 长度为负时signed循环不复制，但分配仍接收旧DWORD；不把它视为受支持输入。
