// 段查找与键定位：外层长度检查不等于逐字节有界解析
// ============================================================================
// 608335 -> 819470：从+140前进寻找段。
// 609528 -> 819660：每次从当前段+140重新寻找键，输出位置保存至+144。
// [事实] 二者均按字节和ASCII分隔符工作；strcmp精确比较，未见大小写折叠。
// [未知] isspace依赖CRT locale；本篇不从ASCII示例推定全部字符分类或文本代码页。
//
// 819470段扫描
// ----------------------------------------------------------------------------
// 外层计算(+140-buffer)并signed比较length，8194A5使用jge退出return0。
// 当前字节为'/'且后一字节也是'/'：消费至LF后再回外层；双斜线窥读+1
// 没有独立剩余长度检查。普通行也消费至LF，内循环没有长度或NUL判断。
// 当前字节恰好为'['：消费左括号，将段名及']'复制到共享ABAA60，
// 再把复制末尾']'改成NUL；右括号搜索与暂存写入均没有容量/长度门控。
// 之后isspace循环推进+140，包含可能被CRT分类为空白的LF，直到非空白。
// 比较成功时+144=+140、return1；比较失败继续从推进后的+140向前查找。
// 因而同名重复段可顺序遍历；不自动从buffer首重找，不合并重复段。
//
// [事实] 普通行前置空白不会由本体专门trim，而是走普通行跳过分支；
// 但上一段右括号后的isspace循环可能吞掉空白，使后续'['恰好成为当前字节。
// 所以不能把“任何带前置空白的段都不可见”写成无条件语法规则。
// [事实] 失败不清+144；先前成功定位的值游标可能残留，调用者必须检查返回。
// 失败已经消耗+140，不具备失败后恢复位置的事务行为。
//
// 819660键扫描
// ----------------------------------------------------------------------------
// 入口固定+144=+140；每次查键都会重置到本次当前段内容基址。
// 外层先signed比较差值与length，再检查当前BYTE为NUL；任一满足return0。
// 当前为//就消费至LF；当前为'['就return0，避免正常行结构下跨到下一段。
// 当前isspace非零则消费一个字节回外层；空白后的'['因此也能终止键查找。
// 键名复制到ABAB00，读到isspace或'='为止并写NUL；未见容量/长度门控。
// 不匹配键名时跳至LF继续外层；同段重复键是从段首找到的第一次匹配。
//
// 匹配键名若以空白结束，则继续找'='；此内循环没有LF/NUL/长度终止。
// [推断] 缺等号的匹配键行可让扫描越过后续行甚至正常段界，不能认为
// 外层遇'['的逻辑会保护已经进入等号搜索的路径。
// 找到等号后跳过isspace，但专门保留LF；因此空值可以成功并令+144指向LF。
// 成功只定位值首，不负责值长度、NUL追加、引号、反引号或字段分隔。
// return0时+144保存失败时的扫描位置，不清零；不能继续调用取值当作空字符串。
//
// 共享暂存与边界
// ----------------------------------------------------------------------------
// ABAA60为段名暂存，ABAB00为键名暂存，位于未初始化区；磁盘中不存在
// 可作为原初始化数据的对应字节。IDA数据项跨度不是已恢复源码数组容量。
// 本体既无容量比较，也无锁；两个对象也会共享暂存。
// [推断] 并发或重入需另有外部同步，不能仅凭不同this承诺线程安全。
// NUL并非段扫描或所有内循环的通用结束符；模式2没有追加NUL。
// 完整资源预检应逐字节验证LF、右括号、键等号、长度、目标容量与编码，
// 具体资源允许的段名/键名和重复项规则还需联合消费者提取。
