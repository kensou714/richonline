// 复用原证：859CC0、858FB0、6BEF20；本批补证861190和各buffer游标。
// 四个旧范围按原始单区间重核，不补造旧函数声明块或EH尾块。
//
// 一次pump / 859CC0
// ----------------------------------------------------------------------------
// 一次调用只处理ACB8F8当前队首。移除队首后退出，不在本体立即循环下一项。
// initiated=0时创建socket/event、注册0x33网络事件并调用connect，再置BYTE=1。
// 本体不检查socket、event、WSAEventSelect、connect返回值；网络event错误另处理。
// 后续Wait超时参数为0；本轮未证明调用频率和实际线程身份。
// WSAWaitForMultipleEvents与WSAEnumNetworkEvents调用返回值没有本地检查。
// FD_CONNECT、FD_WRITE、FD_READ、FD_CLOSE依据各自错误槽走分支。
// send非-1时推进发送readPtr；send=-1时立即走错误路径。
// 此处没有WSAEWOULDBLOCK特判，不能假定所有send=-1都可等待重试。
//
// 接收完成 / 858FB0
// ----------------------------------------------------------------------------
// 使用十字节头检查CRLF/type/length；响应类型0..3的体长为33、36、36、4。
// 接收体完成后调用既有回调路径，receivePhase重置1并释放动态bodyBuffer。
// 头/体的recv返回0，或-1且WSAGetLastError=10035时，只返回1继续等待事件；
// 不能把recv=0直接解释为已出队。其他recv=-1返回0，交由pump错误路径处理。
// 函数不主动出队。收完一个响应、回调、关闭socket与删除队首是不同条件。
// 无错误FD_CLOSE才进入正常销毁连接/出队路径；错误路径另回调后销毁/出队。
// 若服务端只发回包而保持连接，当前头可能继续占据队首；静态控制流支持
// 这一排查方向，但本专题没有证明某次实机卡住就是该原因。
// 下一连接需上层再次调用pump；实际调用者循环与服务器关闭行为待动态核对。
//
// 错误callback真实ABI / (type,3)
// ----------------------------------------------------------------------------
// 859CC0错误分支将sendBuffer.readPtr复位storage，再跳过2字节CRLF。
// 859F21先push 3；859F29调用60D4FC桥至861190；859F2E push eax，
// 859F2F间接调用[ACB8C0]。861190没有栈参数且普通retn，不消费先压的3。
// 所以读取到请求头DWORD type后，真正的回调栈参数是(type,3)。
// 6BEF20在[ebp+8]读取type、[ebp+0C]读取第二参数，并retn8。
// 旧伪码中的未定义v3不能解释为第三个协议字段或未初始化线上字段。
// 6BEF20只按type0..3转交四个管理器方法；管理器业务名称本轮未确证。
// type4触发错误时也读出4，但该回调本体没有对应0..3之外的业务分派。
//
// 服务端联调的可复查点
// ----------------------------------------------------------------------------
// 对照请求type、固定包长度和32字节字段，再核响应十字节头和固定体长。
// 将“发送响应”“客户端回调”“服务端关闭”“客户端出队”分别记时间点。
// 记录send=-1时的事件错误和WSA错误，验证是否属于可恢复拥塞而被本体放弃。
// type4的响应设计须继续采运行证据，不能只因请求编号4就返回响应编号4。
