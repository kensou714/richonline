//
// 公共头 / 85A470
// ----------------------------------------------------------------------------
// +00 BYTE  0D；+01 BYTE 0A。不是以C字符串形式传输的终止符。
// +02 DWORD type；+06 DWORD bodyLength；+0A开始body，无对齐填充。
// 公共构造先将type置FFFFFFFF、bodyLength置0；具体构造随后覆盖。
// DWORD由x86直接mov写入，线路表示为小端；不见htonl转换。
//
// 类型与长度 / body不含公共头
// ----------------------------------------------------------------------------
// 生产入口  包构造    type  body  总包  字段
// 85A1E0    85A3E0      0    64    74   两个32字节槽
// 85A4E0    85A710      1    96   106   三个32字节槽
// 85A7A0    85A9D0      2    96   106   三个32字节槽
// 85AA60    85AC60      3    64    74   两个32字节槽
// 85AD70    85B010      4    97   107   三槽及末尾1字节
// 五构造均按bodyLength对body执行memset0，然后生产入口写字段。
// +0A..+29取第一实参Source；+2A..+49取858DC0处理第二实参Str的返回值。
// type1、2、4的+4A..+69取第三实参；type4的+6A取第四实参低BYTE。
// 最后BYTE直接写入；本体没有归一化为0或1，不应擅自定义为bool。
// 各入口构造44字节连接和16字节buffer，buffer容量等于上述总包长度。
// 861270从栈上包起点memcpy整包；随后85B380将连接指针入ACB8F8。
// 入口返回容器/helper结果，不是服务器处理成功状态；ABI为调用方清栈。
//
// 字符槽 / strncpy32及共享变换区
// ----------------------------------------------------------------------------
// 每槽用strncpy(...,32)。短输入补零；长度达到32时不保证槽内有NUL。
// 服务端应按固定槽取值，不能越槽寻找终止符。编码与业务字段名称未证实。
// 858DC0先清零ACB8C4的32字节，再strlen(Str)，调用8613C0后返回ACB8C4。
// Str必须是有效NUL结尾输入；本地没有空指针检查。
// 8613C0创建临时对象，经861670处理Src/strlen，取得内部输出地址后memcpy。
// memcpy大小为min(a4,32)，858DC0传a4=32；本轮未展开861670等变换核心。
// 因此第二槽应称“变换输出”，不能直接命名为密码、密文或散列。
// ACB8C4为共享静态scratch；并发保护及线程归属未证实。
// 即使目标包先清零，随后strncpy32也可能覆盖整个槽，不能据此保证NUL。
//
// 请求五型 / 响应四型
// ----------------------------------------------------------------------------
// 复用858FB0只接受响应type0..3，预期体长依次33、36、36、4。
// A2F7D0响应长度表不能反推出请求长度；请求长度由上表构造真实写入确定。
// 已见type4请求不代表858FB0支持type4响应；其正确响应类型/是否只关闭未知。
// 6BEF20也仅按0..3分派；不存在本批已证实的type4成功回调处理。
// 业务名需后续由管理器实现、UI来源及服务端实录交叉确认。
