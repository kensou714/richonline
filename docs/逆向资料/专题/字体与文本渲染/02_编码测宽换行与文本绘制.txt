// 汉化与文本显示契约
// ============================================================================
// 版本/证据见00入口。本篇不讨论KPD解包，聚焦解包后字节如何进入显示。
//
// CPoint误名的实际职责
// ----------------------------------------------------------------------------
// IDA把0x60DBDC命名为CPoint(int,int)，但它跳到6DD600，实际接收
// 字号、窄字符串、x、y、颜色，选择字体对象并转UTF-16后调用816800。
// 6DD600汇编6DD648..6DD6A7明确选择12/14/16/24；旧伪代码省略了switch。
// 不得据伪代码签名把它写成MFC坐标构造，或丢弃字号参数。
// 6DD710为宽字符串绘制入口；6DD810转码后交矩形换行入口6DD880。
//
// 编码与共享缓冲
// ----------------------------------------------------------------------------
// 81BAB0调用MultiByteToWideChar(CodePage=0,flags=0,input,-1,buffer,1024)。
// 0是CP_ACP系统ANSI代码页，不是固定936/GBK，也不是UTF-8。
// 输出地址为共享对象+1040；对象由64F250懒分配0xC10字节并全局复用。
// 转换结果未检查、调用前没有清空该输出区；转换失败可能留下旧内容或未初始化数据。
// 内容工具应在发布前验证编码可往返且转换后含终止符不超过1024个WCHAR；
// 更换Windows语言环境或启用UTF-8系统ACP可能改变同一资源字节的显示。
// 同一全局宽字符串缓存与多个绘制临时全局变量说明调用不可假定线程安全。
//
// 8170C0是窄字符串测宽：先询问MultiByteToWideChar所需长度，分配临时宽数组，
// 再转换、调用816FD0、释放。它也使用CP_ACP，但没有固定1024输出数组。
// 所以“测宽成功”不能证明同一个长字符串通过绘制入口仍可安全显示。
// 816F90只是strlen字节长度，不是像素宽度。
//
// 测宽与字面覆盖不是一回事
// ----------------------------------------------------------------------------
// 816080固定WCHAR<128推进半字号，其它推进全字号，不读取GDI GetTextExtent。
// 816FD0按wcslen遍历并累加记录+4/+8；8171A0读取单码元推进量，816F20取左侧项。
// 文本以UTF-16码元遍历：代理对会成为两个独立缓存键/两次TextOutW，
// 无组合字符塑形、双向排版或emoji码点处理的证据。
// 未来汉化预览必须使用此固定推进规则；系统字体真实字面超宽仍可能被32像素表面裁掉。
//
// 816800 颜色与批量绘制
// ----------------------------------------------------------------------------
// 每WCHAR查驻留记录，不在则栅格化；每个字始终用size*size四点，随后x按推进量增加。
// 传入颜色同写四个顶点diffuse，UV来自当前缓存槽；每批12字，常数A67748=12。
// 绘制前关ALPHABLENDENABLE，选图集纹理，SetFVF0x144、28字节步长，
// DrawIndexedPrimitive(TRIANGLELIST,4*n顶点,2*n三角形)，完成再开混合。
// 本函数没有解析富文本颜色控制码，没有显式CR/LF换行，也不按单字颜色分段。
// 批量绘制选最后处理字所属图集；常规初始化只有1张图集，不能未经改动扩大图集数
// 并假设跨图集的一批12字还能正确显示。
//
// 6DD880 矩形换行
// ----------------------------------------------------------------------------
// 用rect.left/top起笔、right判断横向溢出；行高为字号+1，超过bottom停止。
// 溢出分支会把输入游标与行缓冲游标各回退一个WCHAR，然后截断并绘出已有行。
// 这是具体算法，不能简化成“放不下的当前字直接转下一行”。
// 首字就放不下时，6DD973..6DD9A7在游标尚未前进前判定left+advance>right：
// 6DD9B0和6DD9B9各回退2字节，6DD9C2必经写WORD[A833CE]=0，位于行缓冲起点前。
// 输入前读则有额外条件：画空行、复位行缓冲并推进y后，只有
// newY+字号<=bottom（6DDAAB..6DDAB1）时，6DDABB才读取WORD[input-2]。
// 若高度不足则跳6DDAE1，不执行这次输入前读；两种访问不能笼统称为同时必经。
// 普通溢出还存在记账差异候选：回退的是已收录的上一WCHAR，复制到下一行后，
// 6DDAD6仍累加本次溢出当前字的advance。ASCII与全角推进不同的混排可能出现
// 累计宽度与实际复制字符不一致；这是静态控制流结论，尚未构造实机触发。
// 行缓冲从全局A833D0起写，循环未见独立容量上限；不能从旁边符号距离推定安全容量。
// 汇编包含按空格/逗号/句点/感叹号回退断词代码，但var_41在6DD96B/6DD96F
// 先置0再无条件置1，6DD9C7..6DD9CD直接跳过断词块。
// 因而当前路径不应宣称支持英文按词自动换行；CR/LF也未被特别处理。
// 无效字号的switch默认分支没有建立合法字体指针；内容工具只接受12/14/16/24。
//
// 面向内容扩展的约束与未决
// ----------------------------------------------------------------------------
// 校验字节编码、宽字符数、字号、矩形至少容纳一个全角字；按真实规则预览自动换行。
// 更长文案应由上层分段，不能只扩大KPD字段长度就绕过1024转换缓冲和行缓冲限制。
// 新增字体需同时考虑ASCII掩码、系统字体可用性、固定推进、图集容量及回收。
// 待补证：首次未命中字形返回度量是否与缓存命中相同；字体配置缺失的默认初始化；
// 文本调用者的显式换行预处理；实际ACP与系统字体；失败路径泄漏；实机多语言显示。
