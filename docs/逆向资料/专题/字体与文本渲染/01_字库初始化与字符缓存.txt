// 两种字形来源：ASCII掩码与Windows系统字体
// ============================================================================
// 版本/原证见00入口。字体初始化6DD3D0创建4个0x160038字节对象：
// 字号12：512*512图集1张；14：512*512图集1张；16：256*256图集1张；
// 24：256*256图集1张。字体重量参数均0。
// 6DDCF0只映射12/14/16/24，其它字号返回0；绘制入口其它分支可能读未初始化局部。
// 因此目录有ascii32.dz不等于普通UI字号32已被支持。
//
// 字体名称与GDI
// ----------------------------------------------------------------------------
// 配置对象getter6DFBF0返回对象+104。7B74C0的Font.kpd消费者在[NAME]读
// GB2312/BIG5/EN；语言状态1/2/0分别选分支，EN键缺失回退SYSTEM。
// GB2312分支还经8190B0按一张内存映射表转换高位字节对；映射表的原始编码语义
// 未在本专题证明，因此不能仅凭键名称其为“Windows固定GBK绘制”。
// 当前Config/Font.kpd不在磁盘目录，但存在Config/Font.ini。
// 本专题未证明后者替代此加载链；不能把静态路径假装成已观察到的KPD文件。
//
// 815340使用CreateFontIndirectA：
// lfHeight=字号，lfWeight=传入重量，lfPitchAndFamily=1，lfCharSet=1(DEFAULT_CHARSET)。
// lfFaceName由strcpy写入，源配置读取上限64，LOGFONTA名称字段实际仅32字节；
// 当前函数未见复制截断。内容工具必须限制编码后名称<=31字节，不能沿用64字节。
// 创建兼容DC并选入HFONT；非ASCII实际取决于Windows已安装字体及字体映射。
//
// ASCII字库文件：不是压缩容器
// ----------------------------------------------------------------------------
// 文件路径Font\\ascii%d.dz，%d为字号。815340打开rb后直接fseek到4，
// 再按字符0..127、行0..size-1、列0..size-1逐字节读取。
// 5个现存文件的首DWORD恰好等于字号，大小严格等于4+128*size*size，
// 载荷字节集合只有0和1；消费者跳过头而不验证它。
// ascii12=18436，ascii14=25092，ascii16=32772，ascii24=73732，ascii32=131076字节。
// 完整逐文件SHA见ASCII字库样本JSON。
// 每字在内存保留32*32字节槽；实际文件每字只有size*size字节，读入时逐行嵌入。
// 本路径不能简单memcpy整份载荷成连续32*32槽；也不能把.dz当LZO文件。
// 只读编辑器应显示128格二值掩码，保留首DWORD，拒绝size>32或文件长度不符。
//
// 65536码元缓存与图集槽
// ----------------------------------------------------------------------------
// 815060构造65536个20字节记录；索引直接用16位WCHAR，不是Unicode码点。
// 字体对象主要字节偏移：
// +0      图集纹理指针数组；+4顶点缓冲；+8索引缓冲；+12像素格式26。
// +16     32*32临时图像对象；+20 HFONT；+24字号。
// +28     每张槽数=(图集边长/字号)^2，整数除法。
// +32     图集边长；+36图集数；+40当前槽；+44当前图集。
// +48     65536项*20字节的字符记录。
// +1310768 图集槽记录指针数组；+1310772起为128*1024字节ASCII掩码。
// +1441844 兼容DC句柄。对象总大小0x160038。
//
// 每字符记录（相对对象+48+20*WCHAR）：
// +0 i16图集槽；+2 i16图集号；初始化-1，表示未驻留。
// +4/+8/+12 3个整数度量槽；本路径计算为0、ASCII半字号/其它全字号、宽度-1。
// +16 度量已初始化byte；其它填充字节不推断语义。
// 每图集槽44字节：+0/+4像素x/y，+8..+39四角UV，+40反向字符记录指针。
// 替换槽前，816160将原字符记录的槽/图集号都置-1，然后写入新字并更新反向指针。
// 当前槽用完即前进图集，再回绕；是轮转替换，不是按最近使用排序的LRU。
//
// 816160 单字栅格化
// ----------------------------------------------------------------------------
// 先清32*32临时表面，GetDC后选HFONT，背景TRANSPARENT、文字白色，
// TextOutW(0,0,一个WCHAR)，释放DC再锁表面。
// WCHAR>=128：临时表面16位像素只要非零，就向图集写0xFFFF；否则保持0。
// WCHAR<128：从ASCII预置掩码取字节，只要非零也写0xFFFF。
// 图集格式A4R4G4B4，所以这条路径把覆盖度二值化，没有保留GDI抗锯齿灰度。
// 替换系统字体不会替换ASCII字形；修改ASCII文件也不会改变汉字系统字形。
// 暂存表面32*32和内部ASCII槽大小限定了现有算法可安全扩展的字号范围。
//
// 绘制缓存与释放
// ----------------------------------------------------------------------------
// 顶点缓冲1344字节=12字*4点*28；索引144字节=12字*6个u16。
// 顶点z=0.5f、rhw=1.0f，FVF0x144；图集/缓冲均MANAGED池。
// 8150E0释放图集、顶点/索引、临时图像和44字节槽数组，DeleteObject(HFONT)。
// 函数末对CreateCompatibleDC得到的句柄也调用DeleteObject，而非DeleteDC；
// 这是API配对可疑点，仅记录静态证据，未声称已测得GDI泄漏。
// 失败分支多处直接return0；完整部分初始化回收需继续沿上层析构入口审计。
