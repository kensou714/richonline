// ============================================================================
// 入口字段、游标与本地记录顺序
// ============================================================================
// 统一记号：G=游戏对象；P[i]=DWORD[G+0xE00+4*i]；N=DWORD[G+0xE20]；
// current=DWORD[G+0xE28]；enabled(i)=BYTE[G+0xE30+i] != 0。
// enabled读法由63E7D0核定，不是IDA误识别的自动隐藏窗口谓词。
// 每入口读packet+2 WORD，64F710与WORD[G+0x14784]比较，失败显示
// "Error GmsvID"后停止本handler业务。未见重发、强制纠正或网络回包。
//
// 游标：63E5B0返回G+0x640队列的head；每次64FA50插入后返回的新游标
// 用于下一条。因此正文列出的顺序就是插入顺序。三个入口均不检查-1。
// 队列拷贝记录本体，记录中的全局地址仍是指针，不是文本独立副本。
//
// 40A0 -> 66A970
// --------------------------------------------------------------------------
// packet+4+2*i：signed WORD卡片编号，-1为本槽无结果。循环i=0..N-1。
// 读取跨度下界为4+2*N；N和packet长度在本函数无交叉校验。
// enabled(i)且编号!= -1时：
//   1) 插6063 / 4B：BYTE+2=i，BYTE+3=4。
//   2) 立即调用7F8780(P[i], signed编号, 1)，返回值不检查。
//   3) 按P[i]+112名称、文本24、卡片表名称，sprintf成一行后strcat全局。
// 任一槽命中时插6003 / 24B：WORD+2=4；BYTE+4=1；BYTE+6=1；
// DWORD+8=1800；+12=1350；+16=&A7A970；+20=512。
// 最后无论是否命中，都插608A / 4B：BYTE+2=3。
// 所以库存满导致7F8780返回失败时，此handler仍生成“获得”提示。
//
// 40A1 -> 66AC20
// --------------------------------------------------------------------------
// packet+4+i：BYTE，零与非零区分结果。读取跨度下界4+N。
// 每enabled(i)依次插：
//   6005 / 4B：WORD+2=低16位DWORD[P[i]+1464]。
//   6063 / 4B：BYTE+2=i；BYTE+3=flag非零 ? 4 : 1。
//   6062 / 8B：BYTE+2=i；WORD+6=41；flag非零写BYTE+3=1，
//              flag为零写BYTE+4=1。构造器先清+3与+4。
//   6003 / 24B：UI槽4；显示标志1；等待标志1；1800/1350；
//               +16=&A7ABD8[128*i]；+20=128。
// 格式为角色名+文本24或28+十进制41+文本31，即获得/失去41点券。
// 循环结束后插当前角色位置6005，再插608A(+2=3)。
// 此处current没有本地合法范围或P空指针检查。
//
// 40A2 -> 66AF10
// --------------------------------------------------------------------------
// packet+4：signed WORD起始索引s；本handler读取跨度下界6B。
// 每个i均执行s=(s+1)%5（signed idiv），即使enabled(i)为零也轮转。
// enabled(i)时先排6005镜头，再读DWORD[A2D2C8+4*s]并switch。
// 第一轮访问发生在取模之前，没有本地0..4检查；负数取模仍可能负数。
// 在合法0..4起始值且表未变化前提下，只读{1,2,6,14,600}。
//    1：UI30新闻184(%d=600)，再6060(+3=1,+6=1,+8=600)。
//    2：UI30新闻185(%d=1600)，再6060(+3=1,+6=1,+8=1600)。
//    6：UI30新闻189(%d=1800)，再6060(+3=1,+6=1,+8=1800)。
//   14：UI30新闻197(%d=800)，再6060(+3=1,+6=1,+8=800)。
//  600：default，无本轮新闻和资金记录；仍保留前面的6005。
// UI30记录为6003 / 24B，WORD+2=30，BYTE+4=1，BYTE+6=1，
// DWORD+8=1800、+12=1350、+16=全局三DWORD地址、+20=12。
// 三DWORD={0, 分支编号, 文本地址}。资金记录为12B，BYTE+2=i。
// 循环后插当前角色位置6005，再插608A(+2=3)。
//
// RTC真实容量
// --------------------------------------------------------------------------
// 40A0的Source是128字节，伪码135不是可用长度。RTC还标示三个xPack
// 分别4/24/4B；40A1为4/4/8/24/4/4B；40A2为4B镜头、四组24B+12B、
// 保留48分支24B、结束4B+4B。构造器未赋值填充区不能叫零填充。
// 消费者不用的+3/+7等字节可能保留入口rep stosd的0xCC。
