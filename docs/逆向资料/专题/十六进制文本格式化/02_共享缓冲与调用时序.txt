// 共享缓冲与调用时序
// ============================================================================
// ACC3C8   保存调用方读取的管理器指针；本题只追它+60h处的间接回调槽。
// ACC3CC   ltoa临时字符区；函数显式清10字节，32位hex实际写入最多9字节含NUL。
// ACC3D8   返回结果起点；函数写入模板11字节，随后覆盖末尾L个数位。
// ACC3E2   结果末尾NUL位置，也是右对齐计算的终点。
// 这些地址是可回证的消费布局，不是恢复出的源代码struct或数组声明。
// IDA把ACC3D8标为10字节项，不足以证明对象只分配10字节，更不能据此声称模板写溢出。
// 临时区与结果区相差12字节；邻接与IDA next_head均不能单独证明容量。
//
// 生命周期
// ----------------------------------------------------------------------------
// 每次调用返回同一个ACC3D8；下一次调用先重新覆盖模板，然后生成新结果。
// 调用者如果只缓存指针，两次调用后的两个指针会观察到同一份最后结果。
// 需要跨调用保留值时应在下一次调用前复制11字节，或另写接受调用者缓冲的工具函数。
// 不可释放该指针；没有malloc/new配对，也不是调用者拥有的堆分配结果。
//
// 三次长度读取不是一个原子快照
// ----------------------------------------------------------------------------
// 8E03DB：第一次长度只判空。
// 8E03EF：第二次长度保存到EBX，后面决定复制字节数N。
// 8E03F9：第三次长度保留EAX，后面计算目标ACC3E2-M。
// 本函数没有锁、TLS或重入保护；临时区和结果区也不是每次调用独立分配。
// 若两次读取之间被其他调用覆盖，N和M可能不同；不能只检查最终字符串长度。
// 例如模型中N=8、M=1，则复制范围为ACC3E1..ACC3E8，越过原NUL位置；
// N=1、M=8则只改结果首数位，保留旧模板/其他调用写入的其余位置。
// 这是有限交错模型，不证明实际线程能够在这里并发，也不宣称已复现运行漏洞。
// 借用API lstrlenA本身并不构成线程同步；实际调度串行约束仍需另查。
//
// 保存调用方
// ----------------------------------------------------------------------------
// 45处均把格式化返回EAX作为第三个参数，键作为第二个参数，对象+8作为第一个参数。
// 间接目标为管理器指针ACC3C8所指对象的+60h槽；取槽地址通常早于格式化调用。
// 在格式化与该回调之间没有显式深拷贝，也没有另一次8E0380调用。
// 这证明就地交接，不证明回调同步消费完内容、成功落盘或不持有指针。
// 若未来替换回调为队列/异步保存，队列应持有内容副本，不能只保留ACC3D8。
