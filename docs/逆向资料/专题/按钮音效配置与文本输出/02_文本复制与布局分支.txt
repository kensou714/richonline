// 第二十三批 / 文本复制、尺寸与对齐：与音效配置独立的辅助链
// ============================================================================
// 字段偏移均十六进制：+58为UTF-16文本指针，+5C为分段链，+60为每单元BYTE宽度表；
// +64为文本度量字段；+68/+6C/+70/+74为布局矩形四字段；+78为行高度相关量。
// +160/+164为可用宽高；+240水平模式、+244垂直模式；+248多行BYTE、+249自动尺寸BYTE；
// +24C为间隔DWORD；+80为分段路径BYTE。语义依据本体访问与指定文本专题复用，不等于结构全定义。
//
// 90D890：复制文本配置并依次重布局，218字节，ECX=目标，栈参=源，RET4
// ----------------------------------------------------------------------------
// 先6091C7→8E2D80处理基础对象；未把其完整复制/回调表逻辑收入本批。
// 将目标+64置0，复制源+78、+68/+6C/+70/+74；四次循环复制+84..+90及+94..+A0。
// 再复制+7C DWORD和+80 BYTE，传(source[+58], target+58, 0)到601D1E→8E1800。
// 此处三个栈参由调用者ADD ESP,0C清理；源指针借用给helper，不能说直接共享到目标字段。
// 8E1800既有完整225字节契约：目标文本与源均非NULL且文本比较相等时直接返回，
// 不做宽表清理/重建。替换时仅目标文本非NULL分支释放旧文本并将+4节点链接回ACC3C4池；
// 目标文本为NULL而节点非NULL的异常组合不会在此回收该链。随后清旧宽表/度量，
// 非空源按UTF-16长度分配拷贝并重新建立文本数据。
// 只说明这个指定helper的拥有/替换语义；失败原子性、内存耗尽、非法源指针另属未决。
// 之后按顺序：源+244→90BAD0；源+240→90BA00；源+248低BYTE→90B9C0；
// 源+249低BYTE→90BFB0；最后才复制源+24C到目标。
// PUSH EAX/ECX前只写AL/CL，高24位不保证为0；被调BYTE参数仅使用低8位。
// 先布局后复制间隔的真实顺序必须保留，不可替换为“全部字段复制后统一布局”。
// 最后的+24C写入不产生返回值，EAX沿用90BFB0；不承诺返回目标指针或整体成功码。
//
// 90B9C0：多行标志，45字节，ECX=this，一栈参RET4
// ----------------------------------------------------------------------------
// 原栈参低BYTE直接写+248，不规范化为0/1；再用现有+240调用90BA00，+244调用90BAD0。
// 返回最后辅助的EAX；未知高位入参不影响本体BYTE写，但不能称全DWORD布尔参数。
//
// 90BA00：水平布局，147字节，ECX=this，一栈参RET4
// ----------------------------------------------------------------------------
// 先把模式写+240。若+58为NULL或首UTF-16 WORD为0，不改布局矩形，保留已写模式。
// +249非0就调用90BF60后返回；否则若+248非0，置+68=0、+70=宽度W(+160)。
// 单行时以有符号比较T(+64)与W：T>=W同样采用[0,W]。
// T<W时：模式0置[+68,+70]=[0,T]；模式1置[0,(T+W)/2]；模式2置[0,W]。
// 模式其他值不写矩形。加法为32位；CDQ/SUB/SAR实现有符号除2向0截断，未检查溢出。
// 此处不写左起点的居中偏移，勿擅自把逻辑改述为常规矩形居中算法。
//
// 90BF60：自动尺寸矩形，56字节，无栈参RET
// ----------------------------------------------------------------------------
// +58非NULL且首WORD非0时+164=+78，否则+164=0。
// 两种分支都把+68/+6C置0、+70=+160、+74=+164，返回EAX=+164。
// 不分配、不释放、不绘制、不调用音频设备；自动尺寸在此只更新高度与矩形字段。
//
// 新补90BFB0：44字节，一栈参低BYTE直接写+249，RET4。
// 低BYTE非0调用90BF60；为0则以ECX=this，压入this+0A8的DWORD和this+0A4地址，
// 经600ACC→8E1FB0调用后返回。后端完整尺寸恢复语义未在本批展开，不称简单恢复旧宽高。
// 本体不规范化BYTE、不检查后端成功，EAX沿用对应辅助返回。
//
// 90BAD0：垂直布局，919字节，ECX=this，一栈参RET4
// ----------------------------------------------------------------------------
// 先写模式+244；NULL/空文本立即退，布局字段保留。+249非0调用90BF60并重写矩形。
// 单行(+248=0)：设H=+164、L=+78、S=+24C；
//   模式3：top=0，bottom=L；模式1：top=(H-S-L)/2，bottom=(H+S+L)/2；
//   模式4：top=H-S-L，bottom=H；其他模式保留矩形。
// 除2及加减均遵循32位指令，不承诺溢出/负尺寸的源语言理想数学结果。
// 多行路径从行数N=1、当前宽度w=0开始，调用924FC0按UTF-16 WORD计长度，不按Unicode码点。
// +80=0逐UTF-16单元迭代；+80非0遍历+5C节点链：node+0为单元数、+4为块宽度、
// +8 BYTE非0的节点整体累加宽度，超W换行并以节点宽度重启；+8=0逐单元处理。
// 链下一项在+0C，字符索引增加node+0；本体未验证链无环、宽度表容量或文本长度一致。
// 逐单元检查LF(10)和两个字面单元反斜杠+n；并检查BYTE宽度+w是否有符号大于W。
// 遇此换行计数加1，重置下一次词边界检查；新w在宽度能容纳时0，否则为当前BYTE宽度。
// 没有把反斜杠+n两单元作为单一字符跳过的额外索引推进；不要擅加转义解码语义。
// 词边界检查标志开启时，90BC09/90BD07均PUSH四参：
//   (当前UTF-16指针，当前宽度表指针，W-w，w)，经6122D1→8E0A00；ADD ESP,10。
// 8E0A00既有123字节本体仅消费前三栈参；第四个w确实压栈，不能被伪码三参签名抹掉。
// 该辅助在[ACC3C8]+5128开关非0时扫描到分隔符或NUL；累计BYTE宽>=剩余空间返回AL0。
// 逗号/句号/空格/LF/CR/字面反斜杠+n可停扫描，只有当前宽度BYTE非0时检查分隔符。
// 返回AL0且当前w=0时暂禁词边界检查并强制本轮允许；w非0的AL0会换行后以当前字宽起行。
// 本体初始var_D未写即载入，但第一轮检查标志为1，会先调用辅助覆盖有效AL/var_D；
// 不仅凭反编译“未初始化变量”外观宣告实际未定义行为。
// 多行布局尾：模式3 top=0,bottom=H；模式1 top=(H-N*(L+S))/2,bottom=H；
// 模式4 top=H-N*(L+S),bottom=H；其他模式不更新。乘法低32位，无溢出检查。
// 返回寄存器随分支不同，不作为统一行数或成功码；本批未运行绘制/字体/超长文本实验。
