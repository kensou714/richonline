// code   外层跳板   cdecl桥接  内层跳板  thiscall handler  最大读取偏移
// 40C2   6043DE     7F09D0     6010B2    66FEE0            p+6
// 40C3   608187     7F09F0     610D50    670330            p+6
// 40C4   607359     7F0A10     60872C    6706B0            p+7
// 40C5   605856     7F0A30     605D7E    670BD0            p+6
// 桥接栈参数为(G,p)，把G送ECX、p压栈；桥接普通retn，handler retn4。
// 消费者伪码偶有stdcall遗漏G，已按保存ECX和retn4核对，不能照抄类型。
//
// p+2 WORD：与WORD[G+83844]核对的GmsvID；64F710不符弹错误并返回false。
// p+4 BYTE：发起卡的库存slot；p+5 BYTE：该slot所属group。
// p+6 BYTE：target参与者槽，作为数组下标时movsx作有符号扩展。
// 40C4 p+7 BYTE：目标group0中的卡slot，同样movsx。
// 其他字段/尾部填充没有在本组证明，服务端不得凭最小读取范围删减协议包。
// 40C2/3/4校验后取cursor；40C5先取cursor再校验，不因此发生业务入队。
// 此处没有target/slot范围检查；有效槽仍须由上层协议和服务端保证。

// RTC局部描述表补证
// ----------------------------------------------------------------------------
// 已保存16个本组函数的_RTC_CheckStackVars framedesc/vardesc原字节，共108个局部项。
// 这些表只说明编译器分配的局部对象边界，不是网络记录协议长度；记录长度仍以调用方传入Size为准。
// 7BC100的局部记录实际由RTC标为6字节；反编译伪码显示的v4[3]不是该记录的完整大小。
// 7B9AD0中String局部RTC标为128字节（伪码曾显示132），解析对象RTC标为160字节（伪码曾显示168），
// 容器局部RTC标为20字节（伪码曾显示24）。这些差异不得反推字段或擅自扩大服务端结构。
// 原始范围见证据/rtc_ranges.json；提取脚本只读IDA与当前磁盘PE，并要求逐字节一致。
//
// 四个handler的共同顺序
//   6007动作：50/51/52/53，对应Prop1051/1052/1053/1054。
//   6003文本：RichStr41 + target名字 + 两个换行 + RichStr40 + 道具名。
//   条件606B：若signed BYTE[P(current)+1472+target]>0，清除双方对应字段。
//   发起卡6061扣除：角色current、slot=p[4]、group=p[5]、数量1。
//   具体金钱、抢卡、防御与恢复顺序见后两篇，不能把共同项统一挪到函数末尾。
//
// 本组使用的本地记录（padding未列即未建立协议语义）
// ----------------------------------------------------------------------------
// 6007 /12B：+2 WORD动作；+4 BYTE角色；+5 BYTE等待；+8 DWORD时长。
//   6944A0只设6007、+5=0、+8=0。本组普通动作明确+5=0。
//   67DC90先经7FB200动作表改角色状态，再在P+40!=-1条件下显示UI23、播放声音。
//   动作50/51/52/53/56映射状态4，54/55映射状态0；不猜该状态的自然名称。
//   +5非零且通过上述条件才等待，+8=0时默认1800；非零用原值。
//
// 6003 /24B：+2 WORD界面；+4显示、+5隐藏、+6等待；
//   +8 DWORD显示时长、+12 DWORD等待时长、+16指针、+20长度。
//   通常UI4，显示1/隐藏0/等待1，显示1350、等待1000、长度128。
//   128是传入记录值，不是本专题已证明安全的字符串容量契约。
//   67DA40的等待使用+12，只有0才回退+8；G+12/G+16才是等待值/tick。
//
// 6060 /12B：+2角色；+3增加；+4减少；+5现金；+6存款；+8 DWORD金额。
//   693320清+3..+6。67FA90优先增加，其次减少；分账户调用金额消费者。
//   减现金后另有余额条件与500ms等待，不可把整链说成四次裸字段赋值。
//
// 606A /12B：+2角色；+3设现金；+4设存款；+8 DWORD新余额。
//   6948D0清+3/+4；6800F0现金分支先于存款。
//   本组+3=1 -> 63F680直接写P+1504，不是6060增减，也不改存款。
//
// 606B /6B：+2和+3为两方槽；+4建立、+5清除，+4优先。
//   本组+4=0、+5=1；6801E0 -> 63EFE0互相清P(a)+1472+b。
//   条件只检查发起方对应字节，写入则同时作用双方。
//
// 6061 /10B：+2 WORD卡ID；+4角色；+5 slot；+6数量；+7 group；+8添加；+9扣除。
//   63F6E0设+6=1、+7/+8/+9=0；未初始化+2..+5全部字节。
//   67FBE0优先+8添加，否则+9扣除；不使用的字段不能当零填充规范。
//   添加交7F8780，仅group0；扣除交7F8F90按group分发。
//
// 6006 /4B：+2为操作请求开关；+2=1仍受current角色三个状态字段资格门限制。
//   6006不清pending；6003/6000等待也不代表网络应答已完成。
