// ============================================================================
// 两个本地回调指针的绑定、清除与编号边界
// ============================================================================
// 指针       6BE090 注册                 E9 最终目标     6BE1C0 清除
// ACB864    6BE0E8 -> 60C5E3           6BE2E0         6BE210 -> 0
// ACB868    6BE0F2 -> 61029C           6BE8D0         6BE21A -> 0
// E9 字节在当前 PE 中分别为 E9 F8 1C 0B 00、E9 2F E6 0A 00；
// 离线按有符号 rel32 解出的目标精确为 6BE2E0、6BE8D0。
// ACB864/868 自身位于 .data 未落盘虚拟扩展区；不能给它们声称 PE 初始四字节。
// 6BE090/6BE1C0 的完整函数研究已见“启动线程与退出”专题；本专题只核上述赋值。
//
// 调用侧
//   ACB864：93 处间接 call；代表 8402EB 的 push 8 后直接调用。
//   ACB868：38 处间接 call；代表 82D93E 在类别 51 前还压入错误参数。
//   两者都使用栈上的 8 字节临时数据；示例见 01 与原证窗口。
//   6BE2E0/6BE8D0 消费逻辑复用“登录与大厅状态”专题，不把跳板视为新业务函数。
//   两个分发器均有 A76728 非零、管理器 +600 非零的门槛；门槛失败可使本地 UI 层无动作。
//   回调指针生命周期与分发器门槛是不同层，排障时要分别核对。
//
// 编号严格分层
//   event_index.json 的 category 是回调前一条 push 的本地十进制类别。
//   共观察到 73 个不同的类别数值；同一数值可由不同生产者重复使用。
//   它不等于大厅 TCP wire_type，也不自动等于 scheduler_key 或界面 ui_id。
//   比如 8402EB 的 8 和 82D892 的 20 是本地类别，不是线上 opcode 8/20 的证据。
//   登录与大厅状态专题已分清 wire_type、scheduler_key、callback_category、ui_id。
//   生产者只证明发起本地回调；不能据此推断服务端应回何种包或已经清除等待。
//
// 无 owner 的八处
//   ACB864：82D892 类别20；855BE5 类别0；855C2F 类别14。
//   ACB868：840BD1 类别207；8485FE 类别39；8486AE 类别40；
//            84946E 类别23；85494E 类别35。
//   这些站点各有 IDA 已识别指令及当前 PE 字节窗口，但没有声明函数 owner。
//   82D892 所在 82D820..82D8B9 范围另见“82BBE0高频数据入口”专题。
//   不能从局部代码反推正式函数入口、异常边界或运行时可达性。
//
// 排障次序
//   先核线上请求/响应与 scheduler_key，再核本地类别是否产生，
//   然后核 ACB864/868 是否已绑定及 A76728、管理器 +600 两层门槛。
//   仅看到服务器回包或回调站点都不足以证明等待 UI 已收尾。
