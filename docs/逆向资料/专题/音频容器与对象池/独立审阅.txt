// 结构布局及初始化
// ----------------------------------------------------------------------------
// C+0 为 DWORD 槽数组，+4 capacity，+8 grow_step，+12 count。
// 20 字节变体另有 C+16；构造和重置清零，其业务含义仍未恢复。
// M+456、M+528 是 16 字节头，邻接 M+472、M+544 为其他业务成员。
// 不能把所有相似操作都套成 20 字节头，再将邻接业务字段解释为 extra。
// 九个构造助手统一设 buffer=0、capacity=256、step=32、count=0。
// 构造不分配槽存储；七个 20 字节头写 +16，两种 16 字节头不写 +16。
//
// 音乐 M+416 为 MR 空闲池，M+436 为 MP 空闲池，M+456 为已登记 MP 列表。
// M+484 存 HANDLE，M+528 存排序播放列表下标；下标不是 MP 对象指针。
// 0x81F950 对 M+416 先重置为 64/32，再重置为 256/32；最终参数是 256/32。
// 两次调用均经 0x60A932 至 0x8235C0，第二次重置会释放第一次槽数组。
// 音效 S+528/S+548/S+588/S+608 分别是 sample/P/R/FILE* 池或栈。
// 参数依次为 64/10、64/10、20/10、5/5；64 是容量，不是必然分配成功数。
// 0x8245E0 用成功归池后 get_count 的结果写 S+8，实际 sample 数量由此形成。
// S+568 的活动 P 链、S+572 的 ID->R 表及 S+580/S+584 缓存链独立于容器头。
//
// 操作与生命周期
// ----------------------------------------------------------------------------
// 重置清计数并重建槽数组；追加按 capacity+step 扩容并复制旧 capacity*4。
// 弹出只减计数并取尾，擦除只移动槽；都不清旧尾槽，也不释放槽内元素。
// 插入仅接受 0<=index<count，尾部及空列表添加需走 append。
// 0x8244F0 和 0x827540 经 0x604CFD 至 0x91FC60，调用 scalar operator delete。
// 前者释放后清 buffer，后者不清；二者均保留其余头字段。
// 0x69BF90 等七个底层析构经 0x601CD3 至 0x91F7E0，调用 operator delete[]。
// 符号差异已准确区分；未恢复完整分配契约，不据此宣称 allocator 不匹配故障。
//
// 0x821620 将登记 MP 归池，0x821720 将资源表 MR 归池，再删除索引表。
// 0x8218E0 才逐个弹出并 delete MR/MP，0x8219D0 对 HANDLE 做 CloseHandle。
// 0x825940 摘活动 P 链，将 sample 和 P 归池，不释放 sample、不 delete P。
// 0x825A40 先删 R+0 资源数据，再归还 R、清 ID 槽，最后删 ID 表。
// 0x825C10 才 delete R，end/release sample，delete P；0x825D00 逐 FILE* fclose。
// 对象池、活动链与 ID 表必须按上层归还和销毁顺序维护，不能互换下标含义。
