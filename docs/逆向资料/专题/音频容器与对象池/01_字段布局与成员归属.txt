// 音频容器与对象池 / 字段布局与成员归属
// ============================================================================
// M 为音乐管理对象；S 为音效管理对象。偏移均为十进制字节。
// 工作名用于阅读；没有恢复原始 C++ 类名或完整模板声明。
//
// 容器头 C，字段层级 A
// ----------------------------------------------------------------------------
// C+0   4 字节  buffer      DWORD 槽数组指针；不是第一个元素本身。
// C+4   4 字节  capacity    容量字段；构造器先设 256，但 buffer 仍为空。
// C+8   4 字节  grow_step   线性增长步长；构造器默认 32。
// C+12  4 字节  count       有效元素数；检查使用有符号比较。
// C+16  4 字节  extra_zero  仅 20 字节栈形成员有此字段，构造/重置为零。
// extra_zero 的业务用途为 U，本题无后续消费者证据，不命名为 cursor。
//
// 16 字节列表与 20 字节栈形成员不能混同
// ----------------------------------------------------------------------------
// 0x69BD70、0x69BE80 仅初始化 C+0..12；对应 M+456、M+528。
// 0x823A20、0x823EF0 重置列表时也没有写 C+16。
// M+456 的 C+16 恰为 M+472 临时播放记录指针；M+528 的 C+16 为 M+544。
// 把通用 20 字节结构套在这两处会覆盖邻接业务字段。
// 其余七个本题构造助手确实写 C+16；成员间距也为 20 字节。
// default capacity=256 并不表示已经分配 1024 字节，必须先走重置分配流程。
// 证据：0x69BC50/0x69BCE0/0x69BD70/0x69BDF0/0x69BE80；S 对应构造助手。
//
// 音乐成员，元素工作类型层级 B
// ----------------------------------------------------------------------------
// 起点       头大小   元素                       重置入口 / 最终参数容量,步长
// M+416      20       空闲 MR 指针               0x8235C0 / 256,32
// M+436      20       空闲 MP 指针               0x8237F0 / 32,32
// M+456      16       已登记 MP 指针列表          0x823A20 / 8,8
// M+484      20       音乐包 Win32 HANDLE 栈      0x823C90 / 64,64
// M+528      16       播放列表下标组成的排序列表   0x823EF0 / 8,8
// M+544      4        随机/排序选择位置           不属于 M+528 的容器头
//
// 0x81F950 初始化 M+416 两次：先 64,32，再 256,32。第一次新数组随第二次
// 重置释放，不能只读到 0x81F9E0 就把最终容量记成 64。
// 0x81FA1B 设置 M+484；0x81FA30/42/54/66 设置其余最终参数。
//
// 类型回证
// 0x821720 把资源表 M+408 内的 MR 送入 M+416，再将资源槽清零。
// 0x81FC50 从 M+416 弹出复用 MR；0x8218E0 逐项弹出并 delete。
// 0x8200B0/0x820510 从 M+436 取得 MP；0x821620 从 M+456 移至 M+436。
// 0x8216BC 读取列表尾项，0x8216CB 放回 MP 池；0x821703 仅减少列表计数。
// 0x820260 以 M+456 的元素读取 MP 字段并启动 stream。
// 0x8219D0 从 M+484 弹出元素，0x821A11 交给 CloseHandle。
// 0x820DEB 把 0..播放列表 count-1 的整数放入 M+528；不是 MP 指针。
// 0x821B80 根据曲目条件重排 M+528，读取它的元素后再访问 M+456。
//
// 音效成员，元素工作类型层级 B
// ----------------------------------------------------------------------------
// 起点       头大小   元素                       重置入口 / 参数容量,步长
// S+528      20       空闲 Miles sample handle   0x826C50 / 64,10
// S+548      20       空闲 P 指针                0x826E80 / 64,10
// S+588      20       空闲 R 指针                0x8270B0 / 20,10
// S+608      20       音效包 FILE* 栈            0x827310 / 5,5
//
// 0x8246A8/BA/CC/DE 通过 ECX=S+各偏移调用以上重置函数。
// S+528 初始 capacity=64 是槽容量，实际 sample 数是 AIL_allocate_sample_handle
// 成功次数；0x824753 取 count，再保存至 S+8，不能把 64 当设备声道数。
// 0x824743 将新 sample 放入 S+528；0x824E46 弹出供一次播放使用。
// 0x824DF2 从 S+548 弹出 P；0x825940 把 P 和 sample 分别归还两池。
// 0x824BCB 从 S+588 弹出 R；资源表清理 0x825A40 把 R 放回此池。
// 0x824CE8 把已登记音效包的 FILE* 放入 S+608。
// 0x825C10 分别消费 R、sample、P 三个空闲池；0x825D00 消费 FILE* 栈。
//
// 与已有对象字段的衔接
// ----------------------------------------------------------------------------
// MR=20 字节、MP=36 字节、R=40 字节、P=32 字节，参阅“音频系统”。
// S+568 是活动 P 链表；S+572 是 ID 到 R 的表；S+580/+584 是缓存链头尾。
// 空闲容器、活动双链表和资源 ID 表是三种不同结构，不能互用序号。
// 容器头能保存任意 DWORD；具体所有权由以上调用方建立，不由助手类型名保证。
