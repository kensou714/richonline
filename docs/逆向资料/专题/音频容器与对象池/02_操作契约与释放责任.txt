// 音频容器与对象池 / 操作契约与释放责任
// ============================================================================
// 以下操作行为为 A；成员用途为 B。地址与完整指令见机器证据。
//
// 重置、追加、弹出
// ----------------------------------------------------------------------------
// 重置(cap,step)：参数分别有符号 >0 才覆盖旧 capacity/grow_step。
// 清 count；20 字节变体还清 C+16；释放原 buffer，再分配 4*capacity。
// 没有逐元素 delete、CloseHandle、fclose 或 AIL_release_sample_handle。
// 重置已装有活对象的池会丢掉元素入口；必须由调用方先完成业务清理。
//
// 追加(value)：当 signed capacity<=count，分配 4*(capacity+grow_step)，
// 复制旧 capacity*4 字节，释放旧 buffer，更新 capacity；然后写 buffer[count]
// 并将 count 加一。复制长度来自 capacity，而非 count。
// 不把反编译的 int/this 返回值当公共成功码；调用方主要消费副作用。
//
// 弹出：signed count<=0 时返回 0；否则 count--，返回 buffer[count] 的 DWORD。
// 不清除旧槽，也不释放被返回对象。count=0 与真实元素值为 0 共享返回值。
// 取计数：只读取 C+12；IDA 给出的 unknown_libname 或 MFC 名不能作为类名证据。
// 按下标取：signed index<0 或 index>=count 返回 0，否则返回指定 DWORD。
// 仅减尾计数：count>0 才 count--，不会取出元素或释放资源。
// 清计数：0x824470 无条件 count=0，buffer/capacity/旧槽均保留。
//
// 插入与删除，针对 M+528 的排序列表
// ----------------------------------------------------------------------------
// 0x8240B0 insert(index,value) 只接受 0<=index<count；index==count 被拒绝。
// 空列表不能靠 insert 增添首项，尾部添加须走 0x823FB0。
// 若扩容，分配新数组，将旧前段和后段分置插入位置两侧，再释放旧数组。
// 若不扩容，原数组后段右移一槽。size=4*(count-index)，然后写 value、count++。
// 0x824350 erase(index) 同样拒绝负数和 index>=count。
// 删除尾项只 count--；其他位置把后段左移一槽，再减少 count。
// 删除 index=0 的分支先 count--，复制新 count*4 字节。
// 未清尾槽、未析构元素；不能据伪代码的返回表达式建立成功/失败码。
//
// 重叠复制实现的回证
// ----------------------------------------------------------------------------
// 助手调用 j__memcpy：0x60E3E8 的 E9 跳板落至 0x9213A0。
// 0x9213B4..BA 以无符号地址比较判定 src<dest<src+size，成立时走 CopyDown。
// 0x92153C/40 把源/目标移至末端；大块路径 std; rep movsd; cld 倒序复制。
// 小块路径 0x921564 取负的 DWORD 数，再用 0x921638 为基址索引跳转表。
// 0x92161C..38 对应 7..0 项倒序复制展开；这不是伪代码中 abort() 的业务行为。
// 左移路径走 CopyUp，字节/WORD/DWORD 尾部也分别处理，返回最初目标地址。
// 此复制契约以入口 DF=0 为前提；入口没有 cld，前向 rep movsd 依赖调用约定。
// 后向大块路径在 std 后执行 cld；不能把它当作对所有入口 DF 状态的修复。
// 源区间必须可读、目标区间必须可写，覆盖请求的 size 字节；src+size 与
// dest+size 的 32 位地址加法须不回绕。地址合法性和此类前提没有本地验证。
// 六段跳转表总 120 字节已导出，并核实每项落至本函数实际指令。
// 本机器实现具重叠方向处理；“调用名为 memcpy”不足以证明此处覆盖错误。
// 源码重写仍应使用表达重叠语义的 memmove，不能依赖另一工具链同名实现。
//
// 数组释放与元素释放是两个层级
// ----------------------------------------------------------------------------
// 0x8244F0 用标量 operator delete 释放 buffer 后置 C+0=0，容量/步长/计数未复位。
// 0x827540 同用标量 operator delete 释放 buffer，不清指针。
// 两处调用 0x604CFD 的 E9 跳板，落至 0x91FC60，符号为 ??3@YAXPAX@Z。
// 析构后的旧 count 不能再用来调用 getter。
// 析构封装 0x823EC0/0x8272E0 用 ECX 传递原 C，再经 E9 落至这两个实现。
// 其他成员的构造/析构助手位于 0x69B770..0x69BFF0，详见逐函数清单。
// 其中列表释放 0x69BF90 也清 buffer，其余本题底层析构助手不清指针；这七个
// 实现经 0x601CD3 落至 0x91F7E0，对应 operator delete[] 符号 ??_V@YAXPAX@Z。
// 机器符号同时出现 operator delete 和 operator delete[]；这里精确记录目标，
// 未恢复编译器模板源码和分配契约，不据符号差异宣称已证实分配器不匹配故障。
//
// 上层真正释放元素
// ----------------------------------------------------------------------------
// 0x821620：MP 从已登记列表回到空闲池，MR+16 登记索引恢复 -3，非 delete。
// 0x821720：MR 从资源表回空闲池，删的是索引表数组，非逐项立即 delete。
// 0x8218E0：从 MR/MP 空闲池逐项弹出，再 operator delete 元素。
// 0x8219D0：弹出音乐包 HANDLE，逐项 CloseHandle。
// 0x825940：摘除活动 P，归还 P 与 sample；不是释放句柄或删除 P。
// 0x825A40：释放资源数据、将 R 归池、删除 ID 表。
// 0x825C10：先 delete 空闲 R；再 AIL_end_sample + AIL_release_sample_handle；
//           最后 delete 空闲 P。业务资源释放由这里完成，容器析构只删槽数组。
// 0x825D00：弹出音效包 FILE*，非空时 fclose。
// 完整退出顺序请复用“音频系统/06_音乐调度与退出清理闭环.txt”。
//
// 已知边界与待证问题
// ----------------------------------------------------------------------------
// capacity+grow_step、乘 4、count++ 无显式溢出检查；本题未证明实际可达恶意值。
// grow_step<=0、负 capacity、未重置先追加等状态没有本地修复分支。
// 构造器仅设头字段且 buffer=0，操作前置条件需要调用方建立。
// new 失败后的异常或返回规则属于 CRT 分配器语义，不能凭调用点猜为必然崩溃。
// 容器内部没有本题可见锁或引用计数；不据此断言整个音频线程模型不安全。
// 本题未改任何功能、不发布补丁、不做动态重排或并发压力实验。
