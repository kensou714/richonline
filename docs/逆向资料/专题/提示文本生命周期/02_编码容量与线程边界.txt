// 两层共享缓冲：实际容量来自已注册的转换回调
// ============================================================================
// 8E0650每次清零上下文ACC3C8所指对象+108开始的5000h字节，空输入直接返回此地址。
// 对非空输入，优先调上下文+52转换回调，传入output与10240；没有回调时才直接调用
// MultiByteToWideChar(CP_ACP,0,input,strlen+1,output,10240)。返回值未检查。
// CP_ACP是系统ANSI代码页，不是固定GBK、Big5或UTF-8。
//
// 正常客户端注册，不能忽略
// ----------------------------------------------------------------------------
// 6E2CD0 ->6E2E60；后者通过601E22 ->8E8660把6026F6 ->6E5F90写入上下文+52。
// 6E5F90没有使用容量参数：先64F250取得共享对象，再81BAB0转换到该对象+1040，
// 随后wcscpy到调用者指定目标，最后wcslen返回目标长度。
// 81BAB0固定CP_ACP、input长度-1、输出容量1024 WCHAR；不检查转换成功与否，也不预清空。
// 64F250首次仅分配C10h字节，无显式清零；因此失败后不能依赖输出是空串。
// 普通成功输入需包含NUL在内不超过1024 WCHAR；UI引擎的10240容量不是正常链的有效上限。
// 转换失败可能沿旧数据或未初始化数据继续wcscpy；这是静态风险，未做实机触发。
//
// 线程与重入边界
// ----------------------------------------------------------------------------
// 6E4640持有管理器临界区调用UI通知：6BFA00/6BFA40分别封装Enter/LeaveCriticalSection。
// 此局部锁只能证明同一管理器通知的串行区，不证明共享转码函数所有调用者都使用同一锁。
// 8E0650、6E5F90、81BAB0内部没有独立锁；ABABBC+1040和ACC3C8+108都全局共享。
// 8E1800完成自有复制后后续转换覆盖暂存区不影响该副本；但并发或重入发生在复制之前，
// 仍可能改变输入缓冲。未恢复全部线程调用图，不把它写成“已证线程安全”。
// 本专题不把8E0650缓冲地址暴露为可长期缓存的文本指针，也不把CP_ACP当发布格式定义。
