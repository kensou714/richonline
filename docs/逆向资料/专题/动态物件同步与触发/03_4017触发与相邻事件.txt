// 4017 -> 65DFF0：下界6字节，packet+4 signed WORD为目标格。
// 先取得本地队列插入游标，再核验GmsvID；地图读取this=M=G+0x65C。
// 要求目标动态记录存在且类型为12或27；其他类型不排以下两条记录。
// A787DC的位0仅保护693C40一次构造；载荷每次命中都会重写前四DWORD：
//   A787C4={0,type,116,position,第五DWORD}。
// 第五DWORD只由构造器设置-1，本处理器不把它重写成当前角色槽。
// 随后按游标依次插入：
//   6000 / 拷贝20字节：子事件WORD+2=13、BYTE+4=1，
//       DWORD+12指向A787C4，DWORD+16=20；构造器另外写+8/+12/+16为0。
//   6090 / 拷贝4字节：WORD+2=low16(position)。
// 65DFF0此时没有调用7E28B0清动态记录；“收到4017即直接清除”不成立。

// 6090 -> 682050
// 重新取队列游标，按消息+2 signed WORD再次确认动态类型12/27。
// 条件成立才以ECX=G调用7CBD50(position,&cursor,局部载荷,-1)。
// 这条入口没有自行构造6080继续事件；不能套用608F消费者的续行分支。
// 7CBD50及7CC490递归展开、格清理、资金和动画由../回合继续与落点调度/阶段外_范围效果.txt负责。
// 4017的全局载荷指针只随记录复制指针；重复下行改写全局区的生命周期需要运行时取证。
// 子事件13的动画完成契约未在本组闭环；已入队不代表动画已经结束。

// 4008 -> 65C1B0：下界6字节，与上述投放不是同一地图写入链。
// GmsvID通过后按游标依次排：
//   6005 / 4字节：WORD+2=packet+4；消费者67DB90转入镜头定位7B6F60。
//   606C / 6字节：BYTE+2=low8(G+3624)，WORD+4=packet+4；消费者见移动专题。
//   6000 / 20字节：子事件14、标志1、指针A78624、载荷大小16。
//     载荷写DWORD[G+3624]、signed WORD目标格，并写A78630单字节1；其余不整体清零。
//   608A / 4字节：BYTE+2=6。
// G+3624在载荷处以DWORD读，在角色记录处以BYTE读；应保留各处实际宽度。
// 子事件14和608A参数6的完整业务、本地移动后的网络响应仍未由本组证明。

// 6005镜头定位的局部结论
// 67DB90把this=G+1628的视图对象、地图M和signed WORD格号交给7B6F60。
// x=pos%width，y=pos/width；格中心像素是(64*x+32,48*y+24)。
// 根据视图尺寸的有符号WORD半值设置两组偏移，再调用7B6D50。
// 这不写角色P+1464；606C才是另一条指定角色位置设置记录。
// 视图后处理7B6D50未在本组审阅，不能承诺偏移已全部合法化。

// 4016 -> 65DF30：合法业务读取下界4字节。
// 身份通过后排608A参数8，并以64FB10设置G+12=500、G+16=GetTickCount。
// G+12/+16是本组确认的延时参数，不是通知队列G+24/+28的3000计时器。
// 401E -> 65E7A0：同样下界4字节；身份通过后取得游标，排608A参数5。
// 两者没有在本处理器修改动态地图；608A进入681C40，再交7C0C50。
// 681C40以signed BYTE读取+2并构造局部状态0；7C0C50完整选择业务本组未展开。
// 因此仅将这两个入口记录为相邻控制事件，不凭下行编号强行归属某种陷阱。

// 排障观察点
// 日志可区分401C立即动态写入、402F立即六格写入与4017排队后6090触发。
// 若4017没有产生本地事件，核对GmsvID、packet格号、M+60的现存类型。
// 若事件已入队而动态未清，核对子事件13完成、6090消费及消费时动态类型是否仍为12/27。
// 表满/重复登记、固定全局载荷复用、身份失败与队列满是不同边界，不能合并为“服务端没回复”。
