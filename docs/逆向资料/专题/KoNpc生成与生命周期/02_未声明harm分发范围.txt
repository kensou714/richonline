// [事实] ECX被保存为this，栈参数[ebp+8]作为游戏对象传给807440；
// 返回记录为0时直接返回初值0。非0时将四个flag复制到局部byte数组：
//   下标0 <- record+0x21E（542）：fire。
//   下标1 <- record+0x21C（540）：bomb。
//   下标2 <- record+0x21D（541）：missile。
//   下标3 <- record+0x21F（543）：frost。
// 字段token来自旧806A30加载证据；新窗口证明局部数组重排和分发顺序。

// [事实] 8075CB调用rand；8075D4执行有符号 idiv [record+0x224]。
// 0x224是十进制548，不是十进制224。它就是旧记录的num字段。
// 次数 = rand()%num + 1；若次数>num则将次数改为num。
// 循环i从0起，以有符号i<次数判断进入，每次累加分发助手返回值。
// [推断/前提] num>0且rand返回非负时次数在1..num之间；没有证明随机均匀。
// [事实] num=0且记录查询成功时执行除零，发生在任何harm有效性检查前。
// 负num没有本地拒绝；不能将负值视为文档支持的配置。
//
// [事实] 每次先取rand()%4作为下标（汇编含有符号余数修正），若flag=0：
// 允许最多20次重抽；次数用局部计数与0x14比较，首次抽样不计在20次内。
// 重抽后仍为0则从下标0到3扫描首个非0flag，用它覆盖选择下标。
// 四flag全0时顺序扫描没有覆盖下标，仍进入保留的选中下标分发分支，
// 不是“没有候选便跳过”。同一flag可在多次循环里重复命中，没有去重。
//
// [事实] 分发桥与已审阅返回0空桩精确对应：
//   fire    下标0：8076AB -> 60D3F8 -> 807830。
//   bomb    下标1：8076C5 -> 5FF843 -> 807860。
//   missile 下标2：8076DF -> 609FE1 -> 807890。
//   frost   下标3：8076F9 -> 6059AA -> 8078C0。
// 每个分支把同一游戏对象栈参数传入，ECX用保存this，并把返回值累加。
