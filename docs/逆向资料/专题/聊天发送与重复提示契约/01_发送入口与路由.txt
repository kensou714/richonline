// 发送入口与路由
// ============================================================================
// 0x64A520 为 thiscall；ECX 是历史/显示对象，栈参数依次为 mode、recipient、Source。
// 末尾 retn 0Ch；mode 是 32 位数，不是反编译声明中的 char*。
// Source 必须指向可读写、NUL 终止的文本；入口直接读首字节，没有 NULL 检查。
// recipient 只有 mode==2 才消费；Source 空串直接离开，不触发门控或历史保存。
// 不把 EAX 解释成统一成功码：不同退出分支返回来源不同，发送响应也未在此等待。
//
// 非空输入的执行顺序
// ----------------------------------------------------------------------------
// 0x64A56D：禁言标志非零时，先检查 A772A0 长门；失败显示提示 101 后返回。
// 0x64A5AC：mode==2 跳过重复门，其余模式检查 A772A8 短门及原始文本 strcmp。
// 0x64A625：接受候选后先 strcpy(A76E70, Source)，此时还未验证私聊收件人。
// 接着设置 28 字节栈参数；私聊 NULL、空名字、查找失败均可提前返回。
// 0x64A761/0x64A773：过滤 Source，再做发送用转义；Source 被原位修改。
// 0x64A786：复制到共享载荷；0x64A7B6：以消息号 13 调用 0x828F60。
// 0x64A7C5：分派返回后调用 0x64C140 恢复转义并保存历史。
// 这里没有检查分派的返回值再决定是否保存历史，也没有证明网络发送成功。
//
// 28 字节栈结构，基址为 ebp-24h
// ----------------------------------------------------------------------------
// +00 DWORD 来源字段       = 2。
// +04 DWORD route_kind     = 0/1/2，按 mode 路由填写。
// +08 DWORD sender_id      = 0x629E30 返回值；大厅对象 +1264 自身玩家 ID。
// +12 DWORD route_value    = 状态索引、当前索引或收件人槽。
// +16 DWORD dispatch_route = 0/1/4；0x828F60 case 13 实际以此选择发送分支。
// +20 DWORD payload_size   = strlen(A77090+2)+3，含两个标签和末尾 NUL。
// +24 DWORD payload_ptr    = A77090。
// 这是进程内调用参数，不是线上 28 字节报文头；指针不可直接发送到服务端。
//
// mode 与路由
// ----------------------------------------------------------------------------
// 0：route_kind=0；route_value=[0x64F200(大厅对象)+130h]；dispatch_route=0。
//    0x64F200 实际返回对象 +100 指针，不能因错误 MFC 名把它解释成窗口过程。
// 1：route_kind=1；route_value=0x64EFD0(大厅对象)；dispatch_route=1。
// 3：路由与 1 相同；但发送文本首标签仍由 mode=3 格式化，不能合并为同一模式。
// 2：名字非 NULL 且非空，0x6A2D90 返回首个匹配槽；失败 -1 立即离开。
//    成功则 route_kind=2、route_value=匹配槽、dispatch_route=4。
// 其他 32 位值：没有拒绝。预先清零的三个路由字段保持 0，继续格式化及分派。
// switch 的 cmp 3 / ja 包含负数按 unsigned 超界的情况，不可写成范围外返回。
// 64A807 的四项跳表为 64A663、64A688、64A6A7、64A688，原始字节另存 route_tables。
//
// 调用方证据边界
// ----------------------------------------------------------------------------
// 发现 8 条 incoming，其中 0x6042EE 是入口 E9 自身；真实业务 call 为 7 条。
// owner 为 0x737280、0x768930、0x772210；导航窗口只证明附近参数入栈。
// 本题没有全审这些 UI owner，不能据窗口推断所有输入都被长度配置约束。
