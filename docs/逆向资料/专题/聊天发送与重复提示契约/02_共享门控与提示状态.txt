// 共享门控与提示状态
// ============================================================================
// A76E68 BYTE   重复触发后的长门标志。
// A76E70 字符缓冲：最近接受候选的原始文本；容量未声明，不是存储 char* 的指针变量。
// 缓存内容不是最后成功发送或过滤后的文本。
// A772A0 +0/+4 长门 interval / last；A772A8 +0/+4 短门 interval / last。
// 0x64A520、0x64A820 共用上述状态；跨入口的相同原始文本也参与重复比较。
// A76E6C 虽有 DWORD 项定义，但本导出没有引用，不给它臆造业务含义。
//
// 条件初始化：0x64A430
// ----------------------------------------------------------------------------
// 每次写 this+2A800h、+2A804h、+2A808h 为 0；历史写游标 +2BD4Ch=0，读游标 +2BD50h=-1。
// 只有 A67341 非零才清 A76E70 首字节并初始化两个全局门：短门 100 ms，长门 300000 ms。
// 0x60BAB7 -> 0x81BCB0 写 interval 并用 GetTickCount 写 last；随后 0x81BCF0 又把 last 写 0。
// 最后 A76E68=0、A67341=0；不是每次进入 0x64A430 都重置共享禁言状态。
// 函数后半还读取另一对象的提示 ID，若非 -1 则显示；不在本题推断该来源对象业务。
//
// 有副作用的计时门：0x6107F1 -> 0x81BD10
// ----------------------------------------------------------------------------
// 第一次 n=GetTickCount；unsigned n<=last 或 n-last<interval 时返回 AL=0。
// 通过时第二次 GetTickCount 写 last，然后返回 AL=1。
// now==last 即使 interval==0 仍失败；差值恰好等于 interval 可以通过。
// 这不是仅查询剩余时间的函数；调用成功会延后下一次可通过时间。
// 它先做 unsigned now>last，回绕后不采用模 2^32 差值判定；恢复行为需另查。
// 两次时钟读可以不同，模型不可用第一次 n 代替最终存入 last 的值。
//
// 重复拦截：0x64A520 / 0x64A820
// ----------------------------------------------------------------------------
// 长门 flag=0 时跳过；flag!=0 且长门失败显示文本表 ID 101、颜色 FFAF3333。
// 长门通过仍继续，不在这两个发送入口清 flag，且通过已经刷新长门 last。
// 0x64A520 的 mode==2 仅跳过短门和 strcmp，仍受外层长门限制。
// 其余情况：短门通过便继续；短门失败时 Source 与 A76E70 不同也继续。
// 短门失败且原始文本相同：显示 ID 100，用新 GetTickCount 写长门 last，flag=1 后退出。
// 非私聊的不同文本走接受路径不会刷新失败的短门；短门成功时已刷新，但这些路径不校验收件人。
// 私聊 mode==2 不调用短门；flag!=0 时长门成功已刷新 last，随后仍可能因收件人无效退出。
// 私聊收件人无效仍先改缓存，所以缓存不能称为“最近一次发出的聊天”。
//
// 到期提示：0x64C400
// ----------------------------------------------------------------------------
// flag=0 什么也不清理；flag!=0 才调用长门。
// 长门通过时显示 ID 102、颜色 FFAF3333，再 flag=0；失败保持 flag。
// 先发送调用使长门通过、刷新 last，但 flag 仍为 1，随后清理调用可能立即失败。
// 这项调用顺序敏感性由指令直接支持；本题未证明实际调度顺序或可见故障。
// 提示内容取自 0x629D90 文本表，100/101/102 是 ID，不根据中文措辞臆造服务器错误码。
