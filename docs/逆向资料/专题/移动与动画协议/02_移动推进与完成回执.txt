// ============================================================================
// 移动推进与完成回执
// ============================================================================
// 主链：64F780每轮调用64FE70，对活动角色调用7F5D90，再在后部消费游戏消息队列。
// 64FE70依据参与槽活动谓词遍历，不只更新当前槽；活动谓词完整业务来源未在本批展开。
//
// 运动门控与物理跨格
// ----------------------------------------------------------------------------
// 7F5D90只有R+384==1且R+848计时器81BD10允许tick才继续。
// 81BD10要求now>previous且now-previous>=interval，成功把previous重新记为当前tick。
// 7F3840构造角色时，7F38AE以R+848调用81BC80(30)，经81BCB0写间隔30ms并记tick。
// 这是默认最小间隔，不保证固定FPS：每轮至多推进一次，没有累计遗漏tick的追赶循环。
// 后续改速调用未全查；TickCount回绕前置比较也应保留原语义。
// 每次按directions[stepIndex-1]设置R+1460，并同步精灵方向。
// 0/2方向每次y±8，累计48完成一格；1/3方向每次x±8，累计64完成一格。
// 无效方向没有任何推进分支：若已消费方向不是0..3，位置和步索引可能停住。
// 跨格后R+536保存旧格，R+1464更新邻格，R+548清0。
// R+552非零时随后用routeCells[stepIndex-1]重设当前格及像素，服从预计算路线。
// 因此画面先按方向移动，再按路线格校正；两份数组必须共同一致。
//
// 正常结束回执
// ----------------------------------------------------------------------------
// 到格效果处理完成后，stepIndex++；若有符号stepIndex>有符号总步数：
//   7F5C90把动作状态置0；R+552非零才构造6字节上行消息并停止循环移动音效。
//   +0 WORD=0x0011（693890），+2 WORD=G+3144低16位，+4 WORD=当前格低16位。
//   6BF380负责后续编码和连接门控；本函数不直接证明send成功。
// R+552==0的移动可以停止但不发0011，所以不能把“动画停了”作为发包证明。
// 反之部分途中效果也发0011；服务端不能仅按消息名假定一定走完初始所有方向。
//
// 途中分支：保持动态层与静态层分开
// ----------------------------------------------------------------------------
// 动态类型11（7FDA70）会停止移动、移除效果；R+552非零发送0011，随后排效果动画。
// 动态类型30（7ECA20）移除效果并将总步数加一，排动画42，随后继续步数逻辑。
// 动态特殊状态分支可停止并发送0012；触发依赖6022FA/607098/608E25等谓词，
// 本轮保留完整原证但未完成各状态正式名称，不能仅据编号命名为某张卡片。
// 静态事件9：还有剩余步、两个禁止状态均无、605BEE为假且非特殊模式时，
//   状态置2，停止移动音效，保存G+83832=1，发6字节0028：同步字段+当前格。
// 静态事件67：若相应状态条件及资格满足，状态置2，保存G+83833=1，发002A。
//   资格/金额判断细节调用未全部命名；4012后续打开投资窗口，见03。
// 这些暂停不是永久卡死证明：应等待对应服务端响应，再恢复或进入选择流程。
//
// 静态61传送的本地恢复链
// ----------------------------------------------------------------------------
// 仅还有剩余步且R+1488!=7、R+1499==0时进入。
// 置状态2并停音效 -> 查成对出口 -> 插动画26离开 -> 6005移动镜头 ->
// 606C设置指定角色到出口并附加刷新 -> 动画26出现 -> 6091恢复。
// 6091=682150：7F5CC0(1)令状态1/位移0/标志1，再693FB0使步索引加1，重启音效。
// 6091不是“所有地图到格后的固定网络回包”，它在这里由客户端队列生成。
// 606C=6802A0读取消息+2角色槽、+4位置WORD；反编译省略this，汇编确认索引角色指针。
//
// 4013到格时序与本地重排
// ----------------------------------------------------------------------------
// 4013=65DBE0校验GmsvID后比较包+4 WORD与当前角色当前格。
// 相等：插本地6080阶段0；不相等：把原6字节4013重新插入游戏队列。
// 4012与4018也有类似机制：包+6非0且指定位置尚未到达时，把原8字节包重新插队。
// 每轮最多消费一条，重排允许运动tick先推进；不能误报成网络重复发包。
// 若路线位置永远对不上、角色状态被停住或方向数组有坏值，重排条件可能持续成立。
// 客户端本函数没有重排次数上限；日志需同时记录队列消费与位置比较，才能定位卡点。
//
// 定位缺失0011的最小观测字段
// ----------------------------------------------------------------------------
// G.currentSlot、GmsvID、G+3144同步字段；R.state、stepIndex、totalSteps、currentCell；
// R+552、R+548、timer.interval/previous；directions[index-1]与routeCells[index-1]。
// 同时记录4011已消费、6000等待是否解除、6010是否消费、是否转入0028/002A/0012。
// 最后检查6BF380状态/连接门控；仅查服务器“已发4011”不足以证明客户端进入移动。
