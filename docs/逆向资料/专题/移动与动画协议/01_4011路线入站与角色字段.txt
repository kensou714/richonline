// ============================================================================
// 4011路线入站与角色字段
// ============================================================================
// 入口：4011 -> 610F6C -> 7EF8D0 -> 601BA7 -> 65D770。
// 先经64F710比较packet+2 WORD与G+83844；不符弹Error GmsvID，不推进本链。
// 字段来自消费端实际读取；最小被读范围不等于完整wire固定包长定义。
//
// 入站字段
// ----------------------------------------------------------------------------
// +0 WORD      消息号4011。
// +2 WORD      GmsvID，和游戏对象字段比较。
// +4 int16     起始格，写当前角色R+1464，并重算R+540/+544像素位置。
// +6 int8      骰子个数；循环累加packet[8+i]的有符号BYTE值。
// +7 int8      路线方向数量；用于2bit解码与预计算路线格。
// +8/+9/+10   三个骰子值；三个位置始终复制到骰子动画参数，循环上限另取+6。
// +11起       打包方向；每字节四个方向，从低两位开始：bits0..1、2..3、4..5、6..7。
// +24 int32    仅当前角色等于本地槽时，值>0才传给后续UI辅助函数，具体业务名未定。
// 本地当前槽分支的固定字段读取达到+27；公共路径读至+10，再按计数读骰子和路线。
// 这是分支最小可读范围，不是28字节wire包长断言；非法计数可导致更远读取，本函数不检查。
// 7D8210输出每方向一个BYTE，算术右移后&3，因此方向输出为0..3。
//
// 两种长度不能混用
// ----------------------------------------------------------------------------
// dice_sum = sum(packet[8+i], i<signed packet[6])；低8位保存G+83828和R+1419。
// route_count = signed packet[7]；只决定解码多少方向、生成多少预计算格。
// 7F7770固定复制36字节到R+1420，无论route_count多少，并把R+1456置1。
// 步进终止比较使用R+1419的骰子和，不直接使用route_count。
// 动态30途中可增加R+1419，因此路线数量可能要包含额外步；不能假设两值永远相等。
// R+1420..1455共36字节，R+392起的对应格数组也有36个DWORD至R+532。
// 本函数未验证route_count<=36、骰子个数<=3、有效方向数量覆盖最后实际消费步。
// 解码不足的尾部栈内容随后被固定复制；若消费超过有效数量，可读到非方向值。
// 此处是输入合同缺失的静态观察，未证明服务端会发送非法数据。
// 7F5D90先读方向并尝试跨格，到格后才检查总步数；因此总步数0并非此链的安全空操作。
// 若route_count为0，方向缓存可能保留0xCC等栈填充，随后没有合法方向分支推进。
// 合法服务端实现应拒绝这类不一致输入，不能用“空路线+启动6010”表达原地完成。
//
// 角色字段：相对R，单位字节
// ----------------------------------------------------------------------------
// +384 DWORD   动作状态：0停止、1移动、2途中暂停；不是网络消息号。
// +392 DWORD[] 预计算到达格；7F71D0按方向、邻接及允许传送生成。
// +536 DWORD   前一格；每次物理跨入新格前保存旧R+1464。
// +540 DWORD   地图像素x；起始格x*64+63。
// +544 DWORD   地图像素y；起始格y*48+47。
// +548 DWORD   当前格累计位移像素；6010启动与整格结束时清0。
// +552 BYTE    使用权威路线格并发完成通知的标志；本地6010/6091设1。
// +848         计时器子对象：+0间隔DWORD、+4上次TickCount。
// +864         精灵动作子对象；状态和方向setter同步给其成员，详见角色动画资源专题。
// +1404 DWORD  所属游戏对象G指针；实际发包/本地插队时使用它。
// +1408 DWORD  角色参与槽；不是GmsvID或资源角色ID。
// +1419 int8   要消费的步数，最初来自骰子和，动态30可增加。
// +1420 BYTE[36] 方向序列。
// +1456 int8   从1开始的当前步索引；方向下标=此值-1，预计算格下标相同。
// +1460 DWORD  当前方向；0/1/2/3为+y/-x/-y/+x。
// +1464 DWORD  当前格号。
// +1488 BYTE   等于7时禁止路线传送；状态正式名称未由本批确认。
// +1499 BYTE   非零时也禁止路线传送；状态正式名称未由本批确认。
//
// 预计算格：7F71D0
// ----------------------------------------------------------------------------
// 从起始格沿解码方向逐项调用7E1580邻接，写R+392+4*i。
// i!=0且当前静态事件61、传送开关非零时，先取7E6910成对出口，再走下一方向。
// 4011根据R+1488==7或R+1499!=0关闭传送；其他情况开启。
// 本函数没有地图边界校验；资源与服务端必须保证方向、出口和坐标有效。
//
// 动画与移动排队
// ----------------------------------------------------------------------------
// 65D770将骰子个数、三值存全局A787A0..A787AC，A787B8置1，构成28字节参数。
// 经64FA50插入本地6000：动画ID0、等待标志1、显式等待时长0、参数指针及长度28。
// 若G+83829非零，再插6011；该处理器67E130比较猜测值与骰子和，处理20/40金额分支。
// 最后插6010，其67E0C0对当前角色调用7F5CC0(1)启动移动并请求循环移动音效。
// 67D750消费6000时调用动画启动；等待值0则取动画时长，写队列等待=时长+100。
// 这些记录按前次插入返回位置串接，故骰子动画等待影响6010何时真正被消费。
// 骰子完成清队列等待的资源侧实现由角色动画专题追踪；本专题不以画面播放推定已发回执。
// 4011末尾6939E0清G+83790/G+83792交互等待；这不等于清G+12动画队列等待。
//
// 同步字段补证
// ----------------------------------------------------------------------------
// 4004 -> 65BEF0先校验GmsvID，再将packet+4 DWORD经693710写G+3144。
// 63E440从子对象+4返回DWORD，本批上行调用只写其低WORD。
// 7D87B0初始化该字段为0；不能拿4011.packet+2原样当作所有上行+2字段。
