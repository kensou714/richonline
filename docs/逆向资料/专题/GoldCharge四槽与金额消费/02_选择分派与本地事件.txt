// 选择分派与本地事件
// ============================================================================
// 70ABA0 从首参数控件取得编号，按1..26跳转；第二栈参数不参与业务分支，retn8。
// 跳表的5..9、11..20及范围外编号直接返回AL=1；返回1不是服务端确认。
//
// 编号1、2、3
// ----------------------------------------------------------------------------
// 先调用727BD0，将编号低BYTE写当前对象+5B1；再更新当前控件与另两个控件图像。
// 最后分别在70AC94、70AD08、70AD7C调用70B050，参数仍是编号1/2/3。
// 本分支没有再次调用727850；不能把初始化/刷新时的资格门当成不可绕过扣款门。
// 70B050 构造6字节本地记录：+0 WORD=20(0x14)，+2 WORD=标识低16位，+4 BYTE=选择。
// 标识来源是R+0C44内嵌对象的DWORD+4，经63E590/63E440后只保留AX。
// 70B050@70B088写+2，70B08F写+4，70B092/70B098以长度6调用6BF380。
// 第+5字节保持入口调试栈初始化的0xCC；727CC0仅写首WORD，不清整个结构。
// 这里没有任何G0..G3金额字段，也没有本地余额减法。
// 6BF380以下队列/网络消费不在本批闭合，不能直接把这6字节称为服务器线上的包。
//
// 编号4的资格与禁止状态
// ----------------------------------------------------------------------------
// F(P)真：跳过金额门；F假且P150假：要求Q(R,G3)；F假且P150真：要求Q(R,G3 sar1)。
// 两段短路门见70AD89..70ADF5；P150可能被调用两次，文档逻辑以稳定对象状态为前提。
// 金额不足进入虚+A0路径，调用提示ID588，再向触发控件虚+C4传0。
// 金额足够后仍有三项阻挡：BYTE[P+5DA]!=0、signed BYTE[P+5DD]>0、
// signed BYTE[P+5DE]>0。后三者由727C00/727C30/727C60确定。
// 阻挡时提示ID329；未阻挡时调用this虚+98，再取控件20的+181状态并翻转低BYTE，
// 将翻转值送虚+C8。该分支不直接生成编号20或22的本地提交。
// 不把+5DA/+5DD/+5DE直接命名为具体游戏异常状态；写入来源尚未在本批闭合。
//
// 编号21..26与编号10
// ----------------------------------------------------------------------------
// 21..26先调用this虚+98，再以727C90写本地记录首WORD=22(0x16)。
// +2 WORD同样来自R+0C44内嵌对象DWORD+4的低16位；+4 BYTE=控件编号-20，范围1..6。
// +5同样保持0xCC；70AF7C/70AF82以长度6送6BF380，金额和资格不在此分支复核。
// 提交后向触发控件和控件20虚+C8传0，再调用712610(0)；后者业务未扩展证明。
// 编号10调用this虚+98与7BB870(0)，本批不把该接口强称联网或回合完成。
//
// 协作开发约束
