// GoldCharge 四槽缓存与资格门
// ============================================================================
// 本文地址均属于当前 RnClient.exe；二进制 SHA256 与保存范围见阅读入口。
// 初始五种子、七个短依赖已逐指令审阅，深层谓词和实机显示不由静态分支替代。
//
// 记号与对象
// ----------------------------------------------------------------------------
// G0..G3 分别为 DWORD[A87480]、[A87484]、[A87488]、[A8748C]。
// R 为 629C90 返回根对象，P 为 63F840 返回的当前对象；后者本批只复用调用接口。
// F(P) = signed DWORD[P+A0] > 0；63E080@63E093/63E09A。
// P150(P) 与 P0E0(P) 分别表示 7FB150、7FB0E0 的 AL 布尔结果。
// 两者先检查 7D7850，再取 7D7A30 的结果送另一表谓词；深层元数据未在本批闭合。
// 当前资源注释提供步行/机车用途，但不能仅据资源注释给 P150 强取车辆业务名。
// Q(R,c) = signed DWORD[R+600+4*DWORD[R+8]] >= signed c。
// 727850@727861/727867/727870/727873 实现 Q，返回 AL、retn4；无写入和扣款。
// 控件状态读取 6FA210 返回 BYTE[control+181]，本篇不把非零强称已选择。
// 虚表 +C8 调用只记录传入低 BYTE 状态，具体虚实现未在本批采全。
//
// 709E50 的初始化与四槽赋值
// ----------------------------------------------------------------------------
// 先清 this+5D 起128字节，再清 this+4C、+50、+54、+58 四个 DWORD。
// this+5C 最终写0。调用参数 a2 未参与费用分支，函数以 retn4 收栈。
// 首个特殊分支要求 64F200 返回地址首 DWORD 等2，且 727B10 返回非零。
// 该分支使控件4虚+C4收到0，控件1..3虚+C8收到1；四个费用缓存仍为0。
// 普通分支按 P150 -> P0E0 -> 其余的顺序，互斥选择下面规则。
// P150真：若F假，将 G3/2 写 this+58；this+4C/+50/+54 保持0。
// P0E0真：将G2写this+54；Q(R,G2)假则控件3虚+C8收到0；F假时G3写this+58。
// 其余：G0写this+50，G1写this+54；两次Q失败分别使控件2或3虚+C8收到0。
// 其余且F假时G3写this+58；F真保持this+58为清零值。
// 本函数只填费用缓存、图像接口和控件状态；补充回调链仍未证明实际费用显示。
// 关键位置：70A227/70A234、70A295/70A29F/70A2DF、70A348/70A352/70A393。
// this+50/+54/+58 的赋值位置为70A3D3/70A3DE/70A3F8。
//
// 70A7E0 的状态刷新
// ----------------------------------------------------------------------------
// 特殊分支同上时直接结束；其余按参数指针首 DWORD 分派0、1、2，其他值不处理。
// 0：把控件1..3的+181 BYTE存入this+49/+4A/+4B，再逐个调用虚+C8(1)。
// 1：把上面三个 BYTE 逐个送回虚+C8；push寄存器高位并不等于已规范化BOOL。
// 2：P150真或727B40/727B70真时跳过费用刷新。
// 727B40/B70分别检查 BYTE[P+5D0] 等4或6，不将该枚举硬编码为新业务语义。
// P0E0真时，仅当Q(R,G2)假且控件3的+181非零，才调用this虚+78(control2,0)，
// 随后控件3虚+C8(0)。金额不足本身不保证发生该控件切换。
// P0E0假时，G0不足且控件2状态非零，才切向控件1并使控件2/3虚+C8收到0。
// G0足够，或者虽不足但控件2状态为0，都会继续检查G1。
// G1不足且控件3状态非零时，才切向控件2并使控件3虚+C8收到0。
// 关键跳转：70A9F3、70AA14 ->70AA9B；不能概括为G0不足就不查G1。
//
// 有符号边界与编辑含义
// ----------------------------------------------------------------------------
// Q接受任意32位参数；c=0时仍要求余额>=0；负费用不是自动拒绝。
// 709E50 半价缓存使用 cdq;sub eax,edx;sar1，对signed G3执行向零截断除2。
// 70ABA0 半价资格使用纯 sar1，对负奇数向负无穷取整；例如-3分别得到-1与-2。
// 当前包G3=300，两处均为150；以上差异是静态边界，不声称已在运行中触发。
// 资格通过不证明扣款成功，缓存不代表服务端计费权威；更改客户端费用不应替代服务端校验。
//
// 回调桥与剩余显示边界
// ----------------------------------------------------------------------------
// 709E50为控件1..4注册5/6/20，代码指针604FB9/601F7B/5FFD89分别经E9到
// 6EEBD0/6EEC20/6EEC70。三个cdecl包装均先push1并调用6279C0，再将其返回值
// 作为ECX调用64F060；常量1的实际归参未在本批闭合，不照抄伪码归到后一个调用。
// 最后将原调用参数转发给所得对象虚+64/+6C/+90；这些包装不读四个费用缓存。
// 运行时虚表接线、缓存如何格式化显示仍未知，不把补桥称为实际费用显示闭环。
