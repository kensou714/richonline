//   +1920 / 0x780 : 条目数组指针                6A9430、6A8E00
//   +1924 / 0x784 : 普通邮件指针视图起点        6A8E00、7987A0
//   +2324 / 0x914 : 礼物邮件指针视图起点        6A8E00、7987C0
//   +2724 / 0xAA4 : 扫描槽数                   6A9430、6A8E00
//   +2728 / 0xAA8 : 普通组计数                 6A8E00、798740
//   +2732 / 0xAAC : 礼物组计数                 6A8E00、798770

//   这支持固定 100 槽布局，但不证明修改总槽数后所有写入均有保护。
//
// entry 已核偏移；每槽步长 332 / 0x14C 字节
//   +0   : 非零时界面改用文字号 87/88 格式化；确切业务枚举未恢复。
//   +4   : 有效标识，-1 表示空槽；与 +8 一起交给本地操作分派号 50。
//   +8   : 第二标识；失效操作返回后置 -1。
//   +12  : 分组类别，只收类别 0、1；界面据其零/非零选择颜色。
//   +16  : 普通邮件发件人显示来源；礼物页第二标签来源。
//   +48  : 更新路径复制字符串；本专题未闭合其消费语义。
//   +80  : 普通邮件主题显示来源。
//   +101 : 普通/礼物页第三标签文本来源；不因资源位置推断日期编码。
//   +113 : 更新路径复制字符串；确切业务语义待查。
//   +123 : 过滤函数复制头 8 字节；更新路径采用字符串复制。
//   +324 : signed DWORD > 0 判为礼物组；显示名使用低 12 位。
//   +328 : 更新时复制与 +324 相同来源；后续独立用途未闭合。
//   字段间距只是内存布局证据，不自动等于原始数组容量和 C++ 声明。
//
// 创建 / 6A9430
//   删除旧条目数组并清指针；总槽数写 100，两组计数清 0。
//   分配 0x81B0 = 332 * 100 字节；对 100 槽调用 6B8170。
//   6B8170 仅写 entry+4=-1，没有把整个槽清零。
//   因此不能把未写字段或 +8 宣称为初始化为零。
//   分配为空时仍写总槽数 100；异常策略和随后真实执行结果未验证。
//
// 宿主构造 / 69DF50
//   本专题只核 owner+1920=0、两组计数=0；本函数未设置总槽数字段。
//   不能把这些局部字段的核查提升成宿主全部成员初始化证明。
//
// 宿主销毁 / 69E600
//   本专题只核删除 owner+1920 并清 0；没有同步清视图和两组计数。
