// ============================================================================
// 邻接方向与路线生成
// ============================================================================
// 证据与版本边界见00；完整指令见证据/map_runtime_core.json。
// 本文讨论客户端本地算法，不把随机路线推定为服务端权威路线协议。
//
// 方向与邻接
// ----------------------------------------------------------------------------
// 728730：opposite(dir)=(dir+2)&3。
// 7E1580：0=格号+宽，1=格号-1，2=格号-宽，3=格号+1；其他方向返回-1。
//   对应63E340/63E370/63E390/63E3C0；其自身没有边界检查。
// 7E1600：x=index%width，y=index/width；0/1/2/3依次为+y/-x/-y/+x。
// 63E880：直接检查 terrain[index].kind!=-1，无index范围判断。
// 因此四方向候选算法依赖地图边缘布局与调用前置条件。负索引、左右跨行、宽为0
// 都不能凭“目标地形可走”判定安全；未来地图编辑器必须主动拒绝不合法拓扑。
// 7E14A0独立调用坐标边界谓词；7F7990有使用这一类方向检查的上层路径，
// 但7E1A40/7E1B10/7E1C60并不因此自动得到全局边界保证。
//
// 三个拓扑查询
// ----------------------------------------------------------------------------
// 7E1A40(index,dir)：排除dir反方向后，四邻中恰好一个可走则返回其方向，否则-1。
// 7E1B10(index)：不排除方向；四邻中恰好一个可走则返回其方向，否则-1。
// 7E1BD0(index)：可走邻居超过两个则返回真，可用作分岔候选判据。
// 7E1F60(index,&dir)：当前方向可走则直接返回邻格；否则从方向0..3寻找首个可走且
// 非反方向的邻格，更新dir并返回。找不到返回-1，不是随机选路。
//
// 7E1C60 路线字节序列生成
// ----------------------------------------------------------------------------
// 参数：起点格、初始方向、目标步数、输出方向字节数组、可选传送标志指针、传送开关。
// 返回值：额外步数数量。不是最终格号，也不是已写数组长度。
// 初始邻格可走且动态类型不是29时，写第一个方向并前进一步。
// 动态类型29：不写步数，反转行进方向；7ECA00严格只判断等于29。
// 动态类型30：目标步数加一；7ECA20严格只判断等于30。
// 后续每步：先7E1A40唯一非反向出口，再7E1B10唯一出口，最后rand()&3抽方向。
// 随机抽取排除上一步反向，并重复抽取直到地形可走；不存在循环次数上限。
// 地图无合适出口或动态29循环时可能不推进输出计数，这是静态可达风险，
// 未经运行时复现不能认定当前地图已出现此故障。
//
// 额外步数去重
// ----------------------------------------------------------------------------
// A8D390是已触发的动态30格号DWORD缓存；A8D3E8为数量，每次生成清零。
// 首步触发也加入缓存；后续只对未访问过的格追加一次，额外步数最多18。
// 同格往返不反复加步；不同动态30格可把请求N步扩展至N+18步。
// 本函数没有输出容量参数，调用者必须为扩展后方向数准备缓冲区。
// 本批未证明所有调用者的容量均足够，不能给N+18贴上“已保证安全”的结论。
//
// 传送
// ----------------------------------------------------------------------------
// 已行走至少一步、当前静态事件为61且传送开关非零时，调用7E6910换到成对出口。
// 可选标志指针非空才写1；入口没有把它清零，调用者应先初始化。
// 7E6910还支持静态28，分别读取地图 +76/+78、+80/+82，并返回不等于当前格的一项。
// 没找到返回0，不能当成-1哨兵处理；成对出口缺失必须在资源验证阶段发现。
//
// 已确认调用者与边界
// ----------------------------------------------------------------------------
// 7F77C0是7E1C60唯一直接跳板调用者（606274）；传入目标步数1、输出this+1420、
// 标志指针0、传送开关0，读首方向更新this+1460，再提交其反方向。
// 该对象this+1464为当前格，不能与地图对象的相同偏移混为一谈。
// 函数还检查前后邻格的另一谓词，具体玩法身份本批未定。
// 7F7C10沿四方向各探测至多两格，遇不可走即停，检查动态效果谓词。
// 不能把以上本地对象直接命名为“玩家掷骰移动处理器”；4011网络入口尚未在本批闭合。
//
// 渲染坐标
// ----------------------------------------------------------------------------
// 7E16C0：屏幕x=x*64-视口x，y=y*48-视口y；开关有效且地产种类12时再减64/48。
// 7E17C0：同样基准再加64/48；可用于编辑器对齐原客户端投影锚点。
// 视口偏移取有符号WORD。上述是函数计算结果，不擅自推定图片实际宽高或碰撞箱。
//
// 推荐验证顺序
// ----------------------------------------------------------------------------
// 先验证方向与索引，再验证地形/动态层分别可读，然后验证28/61出口及30加步去重。
// 地图工具应输出孤立格、所有出口被阻挡的环、跨行邻接及路线容量预算。
// 服务端必须使用自身确定的路线权威与边界校验，不复制客户端无边界随机循环。
