// 用构造器事实解决跨专题误名
// ============================================================================
// 6001 / 6002 / 6007：都出现12字节对象，但不能互相替代
//   6001：60715B -> 693420；默认BYTE+4=0、BYTE+5=0、DWORD+8=0。
//   6002：6079B7 -> 693260；默认BYTE+5=0、BYTE+6=1、DWORD+8=0。
//   6007：605211 -> 6944A0；默认BYTE+5=0、DWORD+8=0。
//   三者+2 WORD均须由调用者填写；6007的+6并没有构造默认值1。
//   6001的+4初始化不能套到6002/6007，后两者的角色字段由实际调用点赋值。
//
// 免罪卡7CD1C0提供同一函数内的明确对照
//   7CD297 -> 60715B -> 693420：首WORD6001，+2=315，+6由调用点写0；
//   对象EBP-76，RTC描述size12。这一项曾在4080专题被误称6005。
//   7CD2D5 -> 6079B7 -> 693260：目标等于当前槽的动作56，首WORD6002。
//   对象EBP-96，RTC描述size12；+4写目标、+6写1、+8写1350。
//   7CD30F -> 605211 -> 6944A0：非当前槽动作56，首WORD6007。
//   对象EBP-116，RTC描述size12；+4写目标、+5写1、+8写1350。
//   这两条动作在调用点写入的布尔字段位置不同，不能只换操作码保留同一套字段布局。
//   RTC表头7CD3B5有7条描述；正文以精确EBP偏移匹配，不按伪码数组名猜对象。
//
// 真正的6005
//   6025C0 -> 6937D0只写首WORD6005，当前63个调用点RTC容量都是4字节。
//   代表站点65C1FB：EBP-20，RTC头65C2EE、条目65C2F6，入队65C218/Size4。
//   对照说明：看到某个编号315并不能据编号内容判定消息种类；必须还原构造器。
//
// 6061：伪码局部数组20不等于真实对象20
//   6079BC -> 63F6E0；构造只写首WORD、+6=1、+7/+8/+9=0。
//   本批94个直接调用点RTC都给出size10；入队候选也为10。
//   7CD34A对象EBP-136，RTC表项size10；伪码可能把其保护空隙并入20字节数组。
//   不能按伪码数组容量拓展通信长度，不能把未写+2..+5理解为默认全零。
//
// 607B：对象总容量260，数据区不是伪码中的264
//   677614 -> 611FC5 -> 694A00只写首WORD607B。
//   RTC头6776C2，条目6776EE，EBP-356对象size260；67765C入队Size=0x104。
//   此调用点+2 WORD记录数量，+4开始复制4*数量字节。
//   因而已知对象内+4之后还有256字节；伪码把该片段显示为264字节不能采信。
//   这里确认容量，不据此宣称调用者做过数量范围检查或输入一定安全。
//
// 6080与纯操作码对象
//   608876 -> 693BE0还写BYTE+3=255，即signed解释-1；+2仍由调用者赋值。
//   当前84个调用点RTC容量4。stage2后的角色/辅助字节不应凭相似消息重填。
//   6083等纯操作码临时对象常无RTC条目，Size2先压栈，再构造，push EAX返回this入队。
//   字典将其记为“RTC未登记、已见前缀2”；不能补造“RTC证明对象2字节”。
//   6021的7CF64D则有真实RTC size2，但后续走另一包装入口，保守提取器没有将其
//   强行归为64FA50站点；没有入队候选不等于该消息未被使用。
