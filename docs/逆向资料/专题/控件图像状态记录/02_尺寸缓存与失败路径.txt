// ============================================================================
// 600ACC -> 8E1FB0：状态保存不是图像成功标志
// ============================================================================
// 输入ECX=C，栈P和new_type。无论正常分支或错误分支，最后P+4=new_type，EAX=new_type。
// 只有P.type==5且new_type==1才进入尺寸逻辑；其它值不清尺寸，不发回调。
// i=P+12，无边界检查；若S+8图像标识>=0，优先ID分支，即使同时存在路径。
// 标识<0时需S+20指针非null且首字节非0；不满足则仅保存P+4，活动尺寸保持原值。
// 两个缓存尺寸都为0才调用获取尺寸回调；任一非0均沿已有缓存分支。
// 因此(0,高)、(宽,0)、(-1,-1)均被视为已有缓存，不自动重试。
//
// U+16：ID尺寸回调，cdecl九参数
//   (id,第二参数,float0,float1,float2,float3,&width,&height,C)
// U+20：路径尺寸回调，cdecl八参数
//   (path,float0,float1,float2,float3,&width,&height,C)
// 汇编分别add esp,0x24/0x20；实际默认实现只读取其中部分参数，不改变调用方约定。
// U全局本身未判null；槽内函数指针判null。缺回调输出诊断并保留活动尺寸。
// 回调只判AL；AL==0清当前槽宽高为0，输出诊断，然后仍保存P+4=1并返回1。
// 失败分支不清C+352/+356，因此旧活动尺寸可以保留；这不是成功加载证明。
// AL!=0且P==C+164时镜像宽高；已有缓存分支也可镜像，不校验正数范围。
//
// 默认回调与诊断原证
// ----------------------------------------------------------------------------
// 6E4D00按ID向图像管理器查询宽/高；6E4D40先把路径映射到ID再查询。
// 两者完成调用后无条件mov al,1；不会把管理器宽高返回-1转成AL==0。
// 因此(-1,-1)可能进入活动尺寸且后续不重试；实机是否可达需资源错误场景验证。
// A67AA0按GBK可读为“获得图片大小失败”；A67AB8为“没有指定获得图片大小的函数”。
// 原字节与NUL边界已导出；这是诊断字符串的解码，不证明全客户端文本编码统一。
// 回调可修改P+12：函数返回后重新读取索引进行清零/镜像，本批未证明回调不重入。
// 离线模型明确固定索引、不重入，不能拿模型替代外部回调线程与内存安全结论。
