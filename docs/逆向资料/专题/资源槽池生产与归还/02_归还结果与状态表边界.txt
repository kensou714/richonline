// ============================================================================
// push、pop与资源归还 / 分清三层语义
// ============================================================================
// 满池谓词6DFD50
// ----------------------------------------------------------------------------
// 读N=P+8、K=P+4，以signed比较N>=K；XOR EAX后SETNL AL，完整EAX严格为0或1。
// 它只判断计数与容量，不检查B、slot值或重复项。
// 在正常0<=N<=K前提下可防止push超过容量；负N不是此谓词保障的合法状态。
//
// 旧push 6DFCA0与旧pop 6DFD10
// ----------------------------------------------------------------------------
// push：谓词AL非零则EAX=0并退出；否则B[N]=slot，N++，EAX=1，ret4。
// 没有去重、slot>=0、slot<30000或B非NULL检查；重复归还可把同一slot多次压入。
// count负数时signed门可能放行，写负索引；count>=capacity时拒绝写槽数组。
// pop：先做32位N-1并写回，再读取B[N]；无空池或合法计数门。
// N=0时形成-1索引读取路径；这不是已复现的实机越界报告。
// 6D7690使用ECX原pool转发一个栈DWORD给push，正常RTC路径保留EAX，ret4。
// 因此6D7690伪码的stdcall遗漏ECX语义；不应据此实现错误调用包装。
//
// 根对象归还6DBDF0
// ----------------------------------------------------------------------------
// 输入ECX=C、一个栈DWORD slot。6DBE05令ECX=C+40，6DBE08调用6D7690。
// 无论push成功1或失败0，6DBE13都清BYTE[C+92A4C+slot]，随后保留push返回值。
// 此BYTE表与C+580CC的DWORD反向记录指针表不是同一张表。
// 本体不清C+580CC+slot*4，不改原12字节记录的+4，也不验证slot是否可索引BYTE表。
// 所以“归还函数会注销所有引用”是不成立的；满池失败也会改变这个BYTE。
// C+92A4C的完整业务意义、其余写者及指针表何时失效仍需后续分析。
//
// 两个业务caller窗口
// ----------------------------------------------------------------------------
// 7DE5C0@7DEA78从地图对象+584取slot，经627760取配置根，再于7DEA86调用6DBDF0。
// 紧邻返回后继续检查地图对象+5A0，没有测试归还EAX；只认这个局部窗口。
// 75C580@75C5DC先调用旧6DC310，@75C601再调用6DBDF0；两次均取某列表元素+80字段。
// 两次之间重新查列表元素，不能只凭同偏移证明运行中两次返回对象必然相同。
// 归还后直接跳循环，窗口没有处理EAX失败；6DC310完整清理效果不在本批扩大认领。
// 动态取槽798810@798821令ECX=其this+40再调6D7660，证明相同布局的子对象消费。
// 未追798810所有caller，不能把其所有实例自动等同全局配置根C。
//
// 维护约束
// ----------------------------------------------------------------------------
// 修改归还逻辑前，先关闭slot唯一持有者、BYTE标志与反向指针表之间的同步关系。
// 满池返回0不能被视为全无副作用；原生6DBDF0仍清BYTE。
// 静态局部缺门不证明上层完全无约束；动态错误、并发与实际可达性尚未验证。
