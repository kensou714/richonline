// 对象布局与操作契约
// ============================================================================
// S+0       DWORD：本专题未证明具体调试代理/分配器身份。
// S+4..19   16B：短字符串字节缓冲，或首DWORD保存堆缓冲地址。
// S+20      DWORD：长度，不包括尾部NUL。
// S+24      DWORD：容量，不包括尾部NUL。
//
// 62BB80与62BF70均比较[S+24]与16，返回S+4或[S+4]。
// 62BA40仅读[S+20]；62BE10写[S+20]后在真实data+length写一个零字节。
// 写终止符函数本身不检查容量，调用者须先满足缓冲前提。
// 62BE70是单字节char_traits::assign，不是复制整个文本。
//
// 构造和释放
//   62B830：保存ECX=S，准备栈上的分配器参数，初始化容量15/长度0；
//            然后62BA60先strlen输入，再62BC50显式长度赋值。
//   62B7B0：同样先初始化，再62B910复制源字符串从0到剩余全部。
//   88EE20：同样初始化，再62B910复制源对象的指定pos/count。
//   62B8A0：用release=1、new_length=0调用62BAD0；不负责释放S对象本身。
//   62BAD0：release非零且容量>=16时，先按指定长度复制堆内容到S+4，
//            再62BFC0释放旧堆地址；最后容量设15，62BE10写长度和NUL。
//            它自身不检查new_length<=15，缩回短缓冲的调用者负责限制。
//   62BFC0：第二参数容量+1未被使用，实际调用operator delete。
//
// 子串复制与自赋值：62B910
//   ECX为目标S；第一个栈参数为源T，第二pos，第三count。
//   用T+20检查pos，pos>source_length会走91BE10抛out_of_range。
//   size=min(count, source_length-pos)，均为无符号比较。
//   S==T时先删除pos+size之后，再删除开头pos个字节。
//   S!=T时先62BE90确保容量，再从data(T)+pos复制size并补NUL。
//   反编译伪码遗漏源对象ECX，不能把检查误解成检查目标长度。
//
// 裸字节赋值与内部别名：62BC50
//   62CA90检查Src是否处于[data(S), data(S)+length)半开区间。
//   内部Src改走62B910(S,S,Src-data,size)，避免释放源缓冲后继续使用。
//   Src==data+length不算内部指针；调用者仍须提供合法size。
//   外部Src按显式size复制，不检查Src是否NUL结束，也不检查外部可读大小。
//   size=0时62BE90清长度，复制步骤跳过，空字符串仍写NUL。
//   本组不转GBK/CP950/UTF8；长度以字节计，不保证字符边界。
//
// 删除：62BD10
//   pos>length抛异常，count裁到length-pos；count=0直接返回S。
//   非零时移动尾部length-pos-count字节，再缩长度并写NUL。
//   62BDE0调用CRT memcpy_0；重叠复制能力须按真实CRT实现另审，
//   不能仅凭伪码j__memcpy_0把它断言为标准memcpy无重叠契约。
//
// 复用价值
//   做资源文本替换或EXE补丁时，先分清S对象与data裸指针。
//   不能直接改[S+4]为借用地址：容量>=16后析构会释放它。
//   参数是明确长度时可含内嵌NUL；经62BA60的路径只认首个NUL。
//   未证明所有文本容器采用此布局；公共TextCursor、Config树另有专题。
