// 核心结论
// ----------------------------------------------------------------------------
// 64FF10用ECX=G及六栈参数，固定遍历八槽；每槽先清out[i]再检查可用位。
// 可用槽从G+3584+4*i取P；四个状态谓词读取P的signedBYTE，不存在P空指针检查。
// 所有主筛选谓词只消费AL；getter与部分谓词的高24位不能当成布尔返回值。
// a5/a6只读低BYTE，非零即豁免对应筛选；冗余a6第二读在稳定参数前提下可折叠。
// 命中后写out[i]=1、count++和DWORD[*last]=i；最终last为最高命中槽。
// 零命中不会写last；该值不能脱离count读取，也不能由调试填充值推断默认槽号。
//
// 7F7400由DWORD[P+1404]取得G，再由63E0E0取得G+3092地址。
// 63E000返回子对象+4的地址；两次movsx WORD读G+3096/G+3098，非DWORD偏移。
// P+540/P+544为32位坐标；与上述signedWORD镜头偏移相减得到right/bottom。
// 四条signed jle/jge均排除边界；普通整数域严格矩形共63*95=5985个点。
// 两次镜头读取无快照保证；sub32回绕不由普通数学公式覆盖。
//
// 四个调用者分别使用(a5,a6)=(1,1)/(0,1)/(1,0)/(0,0)。
// 六push顺序及ECX恢复正确；单命中使用last低BYTE，多命中进入编号25候选界面。
// 零命中的本次调用路径不读取last；已有编号25选择状态另读旧选择DWORD。
// 654780前置扫描未形成完整新契约；四者返回码与8字节发送不等同于网络ACK。
// 其余14个调用者只核窗口参数，尤其658510全局last的全部后续消费仍未恢复。
// RTC错误路径保存EAX/EDX/EBX/ESI/EDI并恢复EBP，不外推保存所有寄存器。
