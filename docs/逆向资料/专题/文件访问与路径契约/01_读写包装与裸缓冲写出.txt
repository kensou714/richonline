// 实际调用链
//   5FF1EA -> 923F60 -> 606580 -> 924000：先锁FILE，再fread，解锁后保留读取结果。
//   60FEAF -> 9243E0 -> 6056D5 -> 924480：先锁FILE，再fwrite，解锁后保留写入结果。
//   5FFCDA -> 9243C0 -> 924240：fopen转_fsopen，第三参数64。
//   60FE5A -> 923D90：fclose。不要只根据反编译符号把游戏调用归到裸CRT实现。
//
// 元素数量，而非字节数量
//   924000/924480以ElementSize*ElementCount计算总字节数；乘积为0立即返回0。
//   成功返回ElementCount，失败返回已完成字节数除以ElementSize。
//   把整个缓冲当一个元素写入时，只能得到0或1；0可能伴随部分内容已写出。
//   乘积是32位运算，未见乘法溢出检查。此结论不等于任意巨大输入可安全使用。
//   fread的EOF与读错误都可能返回0；底层分别设置FILE标记10h或20h。
//   fwrite短写与底层-1返回会设置20h；游戏调用者是否读取此标记需分别判断。
//
// 923D90 / 空FILE并非受保护的失败返回
//   Stream为空先进行CRT调试报告；用户选Ignore可以继续执行。
//   随后仍访问Stream->_flag，因此断言不能当作可靠的空指针校验。
//   flag含40h时只清flag，返回初始-1；通常路径锁FILE，调用923E80后解锁。
//   923E80的底层刷新/句柄关闭细节未在本专题展开，不对所有关闭失败作推断。
//
// 81B8B0..81B973 / 裸缓冲写出区间
//   IDA未声明函数。依据入口指令、retn 8及相邻字符串确定本次人工审阅区间。
//   81B973..81B980为pFout字符串及对齐字节，独立留证，不冒充代码或声明尾块。
//   ECX保存对象；参数1是文件名；参数2完整比较8000h或4000h。
//   8000h选择wb；4000h选择wt；不是可任意组合的位标志。
//   其余模式不赋值FILE局部槽；触发_RTC_UninitUse后仍可能继续走写入和关闭。
//   写入顺序：fopen -> fwrite(object+00指针, object+08长度, 1, FILE) -> fclose。
//   未见fopen空结果检查、fwrite元素数量检查或fclose结果分支。
//   object+00/+08仅表示此区间所消费的原始指针与长度，不能命名成Windows CFile。
//   wt按CRT文本模式处理；复制资源二进制应保留wb语义，不能只改文件扩展名。
//   不把本区间的偶然EAX值当稳定成功协议；调用约束需由真实引用者另证。
//
// 819C20 / 简单文本FILE槽
//   布尔参数非0选择at，否则wt；将fopen结果直接写入对象+00。
//   返回FILE是否非空，未先关闭旧槽；重复打开的所有权需要调用者自行约束。
//   819C90直接fclose(object+00)，不检查空值，也不把槽归零。
//   自动识别的MFC标签仅为IDA名称，不作为源码类名、析构语义或安全保证。
