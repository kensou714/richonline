// 对象恢复：TextCursor，已见字段覆盖到 +0x9F
// ----------------------------------------------------------------------------
// +0x00  4  FILE*       写出流；读文件时临时保存流，读完 fclose 后未清空。
// +0x04  4  byte*       自有文本缓冲；加载时分配，释放时 delete 并置零。
// +0x08 128 char[]      写出暂存区；范围由下一已知字段 +0x88 推断。
// +0x88  4  int         缓冲有效字节数；文本 fread 返回实际读取数。
// +0x8C  4  byte*       节扫描位置；找到节后留在节头后的首个非空白字节。
// +0x90  4  byte*       键扫描位置；命中后指向值的开头。
// +0x94  4  byte*       独立逐行读取位置；不随取值函数的局部指针推进。
// +0x98  4  int         来源模式：1 文件，2 内存；其他值没有有效加载分支。
// +0x9C  4  int         逐行计数；加载后 1，每次逐行读取加 1。
// 依据：8191D0、819250、8193F0、819CC0、819D10、81A090、81A2E0。
// 调用者栈槽显示 168 字节，含调试布局；不能据此把 sizeof 定死为 168。
//
// 生命周期与所有权
// ----------------------------------------------------------------------------
// 8191D0 只清零 +00/+04/+8C/+90/+94；其余字段不能在加载前直接使用。
// 819250 先调用 8193F0，再写长度/模式。文件失败返回 0，旧内容已经被释放。
// 模式 1：fopen(rt)，按 ftell 分配，实际长度取 fread 返回值，随后 fclose。
// 模式 2：按指定长度复制；不是借用调用者的指针，因此双方可独立释放。
// 两分支均未额外分配或写入末尾 NUL；所有读取者必须按真实格式结束。
// a5 非零会经 819FB0 重建缓冲并删掉所有 CR(0x0D)，不仅仅删 CRLF 的 CR。
// 加载末尾设置 +8C/+94 = 缓冲首地址；+90 由后续找节/找键确定。
// 8193F0 不 fclose；其职责是释放读缓冲并清游标。写流由 819C90 显式关闭。
// 若把同一对象的写入打开和读取加载混用，不能假定析构替调用者关闭写流。
//
// 三个游标并非同一个位置
// ----------------------------------------------------------------------------
// 819470 从 +8C 向前找 [section]，匹配大小写敏感，成功写 +90 = +8C。
// 它不把 +8C 回到缓冲首，也不主动越过当前节全部内容。
// 再次找同名节会从当前节内容继续前行，可用来遍历重复节。
// 819660 每次调用先令 +90 = +8C，再查指定键；因此同节各键可乱序查询。
// 遇下一个 '[' 即失败；同节重复键通常由从节首向前的首次命中决定。
// 找键不推进 +8C，所以普通字典的覆盖/合并语义与客户端不一致。
// 8198E0 和 819A20 用局部指针读值，不修改 +90；同一值可重复取。
// 81A2E0 使用 +94 逐行读并消耗 LF；它不调用节键扫描器，也不解转义。
// 6C5510 的 EOF 仅比较 (+94 - 缓冲首) >= 长度；不保证下一行存在 LF。
// 6C1260 是逐行消费样本：解包 -> 模式2复制 -> EOF -> 逐行读取 -> sscanf。
//
// 81A090 定位规则；不能直接当作 fseek
// ----------------------------------------------------------------------------
// mode 0：+94 = 缓冲首 + offset；同步 +90/+8C。
// mode 1：只有 +94 += offset；不会同步节键游标。
// mode 2：+94 = 缓冲首 + 长度 + offset - 1；同步 +90/+8C。
// 所以 mode 2, offset 0 指向最后一字节，而不是标准 SEEK_END 的尾后一字节。
// 没有范围检查，也没有重算行号。其他 mode 没有定义有效返回语义。
//
// 文本语法与编辑器应当保持的行为
// ----------------------------------------------------------------------------
// 节扫描器仅在当前字节恰好为 '[' 时认节；前置空格可能使整行被略过。
// 找节遇 // 会跳到 LF；其他非节内容也整行跳到 LF。它不是通用 INI 解析器。
// 键名读到 isspace 或 '='；中间空白后继续找 '='；值首空白跳过但保留 LF。
// 值读取保留尾部空格、引号、分号、// 等普通字节，不具备行尾注释语法。
// 8198E0 到 LF 停止，写 NUL；返回的是 LF 值 10，不是字符串长度。
// 高位字节 >= 0x80 固定按两字节处理，未验证第二字节是否合法。
// 仅将反引号+n 转为 LF；反斜杠+n不解转义。不能推导为 UTF-8 解析器。
// 819A20 读取第 index 个分隔字段，index 从 0 开始，分隔符是调用参数。
// 跳过分隔符后使用 isspace，包含 LF；空字段或末尾分隔符可能跨行。
// 搜不到所需分隔符而先遇 LF：输出首字节置 NUL，返回 0。
// 值末尾没有自动 trim；包含分隔符的引用字符串没有 CSV 引号保护。
//
// 边界与共享状态：静态风险，未制作畸形输入运行复现
// ----------------------------------------------------------------------------
// 819470 节名暂存位于全局 0xABAA60；IDA 数据项跨度 160 字节。
// 819660 键名暂存位于全局 0xABAB00；IDA 数据项跨度 156 字节。
// 这两个跨度不是已恢复的源码数组声明；复制循环均没有容量检查。
// 两个解析对象仍共享上述暂存；本群未见锁，不能承诺多线程可重入。
// 外层长度检查保护不了内层找 LF、']'、'=' 和字节对复制循环。
// 8198E0/819A20 的容量断言在复制及写 NUL 之后；它们不是安全截断函数。
// 81A2E0 没有容量参数；调用端的目标数组大小必须另外提取。
// 缺 LF、缺右括号、缺等号、孤立高位字节均不能送入客户端试探兼容性。
// 编辑器应保留原始编码与顺序，独立按字节校验，并按每个消费者的容量限长。
//
// 写出器：结构化参数表与局限

// 819D10 接收 count 与每项 8 字节的描述表：+0 数据指针，+4 类型编号。
// type 3：解引用32位整数 -> %d；4：32位整数 -> 0x%x；5：float -> %f。
// type 6：指针直接作为字符串；7：指向布尔字节 -> true/false。
// 项间加逗号，行前拼 key = ，末尾拼 LF；未知类型无输出分支。
// sprintf/strcat 均无界；+08 暂存区不能用于任意长度的编辑器导出。
