// ============================================================================
// KPD 公共容器：双缓冲、九字节头、压缩调用及错误传播
// ============================================================================
// 当前 Richonline/RnClient.exe，2026-10-09 静态分析；版本指纹见 00 专题。
// 所有地址为 VA。没有执行解码器、运行游戏、修改资源或修补 EXE。
// 原证：证据/parser_kpd_functions.json、parser_kpd_callers.json、parser_lzo_core.json。
//
// 容器对象：仅列已证字段
// ----------------------------------------------------------------------------
// +0x00 4 byte*  原始/解压数据，自有；读取原始文件或解包生成。
// +0x04 4 byte*  压缩数据，自有；读取容器后已减去偏移字节。
// +0x08 4 int    原始长度；原始装载设置，解包用于目标分配，+08访问器返回它。
// +0x0C 4 int    压缩长度；压缩器回写，容器头第二个长度，读取载荷使用它。
// +0x10 1 byte   逐字节偏移量；保存时 rand()%127+1，读取时来自文件头。
// 对象至少覆盖17字节；调用者24字节栈槽包含调试布局，不能作为精确 sizeof。
// 81AD10 清零前16字节；IDA错误命名为 CRect 构造，不能按 CRect 语义理解。
// 81AD80 释放 +00/+04 并置零；81AD50 是其析构包装。
// 627140 返回 +00；627120 返回 +08，后者被识别为日期状态访问器并不可靠。
//
// 外层格式：不是节键文本本身
// ----------------------------------------------------------------------------
// 文件偏移 0      1 字节：key。
// 文件偏移 1      4 字节：原始长度的4个小端字节，各自加 key 后写出。
// 文件偏移 5      4 字节：压缩长度的4个小端字节，各自加 key 后写出。
// 文件偏移 9      压缩长度字节：压缩流每字节加 key 后写出。
// 加减运算按字节模256；不是对整个DWORD加减 key，也不是异或。
// 81B4C0 以 rb 打开/读取/关闭；81B670 从当前 FILE* 位置读，不关闭外部流。
// 81B670 返回循环结束计数，通常等于压缩长度，不能按 BOOL 成功标志解释。
// 两者都先释放旧双缓冲；仅文件版检查 fopen，fread 的短读未验证。
// 压缩缓冲分配 raw + (raw >> 1) + 16，却读取 packed 字节；未见 packed<=容量判断。
// 文件头没有魔数或版本号；扩展名和成功 fopen 不能证明格式正确。
// 8123C0 同样消费此层，解出的是图像结构；外层并不专属于文本 KPD。
//
// 原始装载与保存
// ----------------------------------------------------------------------------
// 81AE00：参数0x8000为 rb，0x4000为 rt；其他参数没有有效文件打开分支。
// 文本模式先读取以确定CRLF转换后的长度，再重新分配及读取。
// 81B050：先清理再复制指定原始内存，设置 +08。
// 81B0C0：按 raw+(raw>>1)+16 分配 +04，再压缩到 +04，回写 +0C。
// 81B150：随机选 key，头长度在栈上加 key，但载荷是在 +04 上原地加 key。
// 写出完成后不减回来，因此同一对象不重新压缩而再次保存会累计变换载荷。
// 本函数未检查 fopen 与 fwrite；返回 fclose 的结果，不能代表所有字节写全。
// 81B310 是接收 FILE* 的对应写出函数；IDA命名为 ATL::CImage::Load 是误识别。
// 72B910 提供真实调用闭环：复制128字节 -> 压缩 -> 保存 -> 析构。
// 该流程每次重新生成压缩缓冲，没有证明可以复用已保存后的缓冲再次保存。
//
// 解包链与容易被忽略的长度参数
// ----------------------------------------------------------------------------
// 81B7F0：local_len = +0C；分配 +00 = new[raw + raw%4]。
// raw+raw%4 并不是通常的向上4字节对齐；例如raw=1分配2，而不是4。
// 随后 KetLzoDecompress(+04, &local_len, +00, +08)。
// 827890 将这四参改序交给 8278B0(src, 第4参, dst, 第2参)。
// 8278B0 立即令 *out_len=0，输入端点为 src+第2参；遇终止标记后写实际输出长度。
// 因此本客户端把 raw 作为底层输入端点长度，而 packed 只初始化随后被清零的local。
// 不能把包装的第4参误记为“输出容量”；底层没有逐次写入的目标容量检查。
// 指令证据：81B84F读+08、81B852入栈，81B859取local地址；827890改序调用。
// 底层末尾返回：输入指针==端点为0，小于端点为-8，大于端点为-4。
// 返回发生在终止标记之后；并非安全的逐步输入边界检查。
// 827890 的声明是 void；81B7F0随后 LeaveCriticalSection，未检查底层状态或local_len。
// +08仍保留声明长度，调用者使用它复制数据；不能称该链验证了解压长度一致性。
// 这些是当前二进制的确定行为；本轮不把修正建议写成已验证的客户端补丁。
//
// 压缩流与并发
// ----------------------------------------------------------------------------
// 827860 -> 8282C0 使用 0xABB338 作为共享工作区；长度>13进入827F70匹配压缩核心。
// 8282C0追加17,0,0终止标记，并回写输出长度。
// 8278B0包含字面量复制与向后匹配复制，行为符合LZO类流；核心全部原证已保留。
// 827F70的哈希桶/字典更新见03专题；未独立证明具体LZO发行版兼容性。
// 压缩和解包都在0xABAB9C临界区内，Enter/Leave实现在6BFA00/6BFA40。
// 此锁不涵盖前述文本节键暂存区；不能推导整个资源解析层线程安全。
//
// 离线工具必须采用更严格的契约
// ----------------------------------------------------------------------------
// 先验证至少9字节、正长度与合理上限、9+packed不越界，再分配。
// 明确使用真实packed长度和目标raw容量，核对实际输出长度等于raw。
// 不复刻客户端忽略短读和解压状态的行为；这不会改变合法数据的内容。
// 写出应在副本上加key，或每次由原始数据重新压缩，避免保存两次产生不同层数。
// 容器成功解包后仍须按消费者验证文本、图片或其他内部结构，不能只看后缀。
// 本轮结论可用于离线校验器规格；尚无实机回归或完整压缩往返工具交付。
