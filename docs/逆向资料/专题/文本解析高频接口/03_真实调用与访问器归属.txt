// 界面配置生命周期
// ----------------------------------------------------------------------------
// 8E4AD0以管理器this+104保存Config*；空时new 0x30并调用90F7D0。
// 参数a3低BYTE非0时取管理器+20760的NUL字符串为循环key，lstrlenA作key长度，
// 调9105D0；否则调9100A0。偏移key的来源与分发本专题未继续展开。
// 之后用90FEC0查询Head节的Head键，再按得到的节名查询Height/Width/Left/Type
// 及IDA符号off_A67B1C所引用的另一位置键；该符号的原始文本本专题未单独核验。
// 8E4DC0遍历Section，按Parent值与目标父节点名称比较，读取尺寸/位置/类型建子节点。
// 这证明高频查找是已加载配置树的接口，而不是每次重新扫描文件。
// 成功末尾调用90F820销毁Config并delete，管理器+104清0；所有借出配置字符串失效。
// 失败路径并非一律销毁：装载返回0、Head缺失等路径可留住+104对象；下一次调用
// 可能继续使用旧树。该事实与装载器不主动清树的行为共同影响重试，未运行重试场景。
// 界面控件是否复制每一种属性字符串由相应构造/setter决定，本专题不冒称已全追完。
// UI4提示->label链由其它专题独立追踪；此处不修改或重复计入其覆盖。
//
// 防止空指针的组合接口
// ----------------------------------------------------------------------------
// 90FEC0(this=Config,section,key)：先校验两名字非NULL非空，再找节、找键，
// 每步检查0，最后返回Entry+4借用值。名字无效、节/键缺失或空值都可能返回NULL。
// 90FFB0同样逐级检查，最后90ECC0转整数；缺失与数值0无法从返回值区分。
// 90FF40先取或创建节，再调用90F1D0更新字符串；返回值不是可靠的写入成功状态。
// 8E4DC0部分字段直接连用90F150->90EC10/90ECC0，没有逐字段NULL检查；因此资源
// 编辑器必须保留消费者要求的键，不能只依据组合接口的安全行为猜测全部调用者。
//
// 高频访问器：各自字段与真实ECX链
// ----------------------------------------------------------------------------
// 82AB80仅读DWORD[this+32]；82A900仅读DWORD[this+80]；均没有NULL检查或所有权转移。
// 代表调用点828F60 case34：829204取8976E0单例，82920B调用82AB80，
// 将返回值作ECX交829212的82A900，再将其结果作ECX交82AA00读取+24。
// 表示 Manager(+32)->ObjectA(+80)->ObjectB(+24)，不是同一对象三个字段的连续地址。
// 8976E0懒初始化ACBB30，897440将单例+32清0；运行时填充来源尚未闭环。
// 附带访问器82A940读+4、82A980读+12、82AA00读+24、82AB40读+44；不同调用者
// 可能以不同对象作为this，不凭这些相同偏移赋予全局一致业务名。
// 828F60是大型分派函数：本轮只审阅该局部ECX链；其余分支只有全块原证导出。
