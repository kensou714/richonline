// 本批基线为00所列SHA256；VA均为当前RnClient.exe静态地址。
// G：游戏对象；M=G+65C；V=G+C14。这些等式是调用点和旧读取器的局部契约。
// 63E0E0返回this+C14；63E000返回this+4，不读取所指对象中的DWORD。
// 第二套矩形实际显示用途未闭，不能凭数量命名主画面、小地图或缩放比例。
//
// 已证明的视图字段（偏移十六进制；以下字段均为WORD）
// ----------------------------------------------------------------------------
// +00/+02  第一矩形宽、高；初始化为参数a1/a2低16位。
// +04/+06  第一矩形左、上；初始化为0。
// +08/+0A  第一矩形右、下；初始化分别复制a1/a2低16位。
// +14/+16  初始化清零；本专题未给出进一步消费语义。
// +18/+1A  两矩形共享的地图横、纵像素界；初始化取a3/a4低16位。
// +1C/+1E  第二矩形宽、高；初始化为610、536。
// +20/+22  第二矩形左、上；初始化为0。
// +24/+26  第二矩形右、下；初始化复制第二宽、高。
// 7B6C90没有写+0C..+13；上述字段不是完整C++结构定义或对象分配大小。
//
// 7B6C90 / 185字节声明块，50指令
// ----------------------------------------------------------------------------
// ECX=this，四个栈参数占四DWORD槽；实际mov读取各参数低WORD，ret10h。
// 写字段的先后见formal_functions.json#/functions/0，normalized_assembly保留原指令。
// 最后EAX从this取出后没有再次改写，因此返回this；不检查指针、尺寸或边界。
// 本体不调用7B6D50；初始化右下未根据地图界夹取。
//
// 64F2A0的实参顺序 / 仅局部契约
// ----------------------------------------------------------------------------
// 64F50A：ECX=M，60BF9E五字节jmp→691A20；返回DWORD[M+20] * 48。
// 64F50F先push纵界。64F519：ECX=M，60B044五字节jmp→6919F0；
// 返回DWORD[M+1C] << 6，64F51E再push横界。
// 64F51F push569；64F524 push621；64F52C设置ECX=V；
// 64F532经611A48→7B6C90，因此a1=621、a2=569、a3=横界、a4=纵界。
// 两尺寸读取器各27字节、11指令，无内部调用；运算是32位，不检查负数或回绕。
// +1C是M内十六进制偏移1C，即十进制28字节；不是偏移28h。
// 将其命名列数依据7E1600按它除余，像素尺度依据两尺寸读取器与中心算法相互印证。
// 行数对应M+20；生产路径、地图实际运行值与尺寸有效范围未在本批闭合。
//
// 初始化之后的居中
// ----------------------------------------------------------------------------
// 64F53A..64F54C：先push M，再push0，ECX=V，60729B→7B6F60。
// 即按格编号0在同一地图M居中；该调用随后夹取，所以不能把构造本体说成已夹取。
// 完整旧64F2A0原证用于验证参数栈；只认此局部，未重新认领250指令全业务。
// 四显式窗口保留原始边界，短窗口不足的前文由完整旧函数来源补齐。
