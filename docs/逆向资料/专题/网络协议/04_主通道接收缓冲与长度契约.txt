// 主通道与文本通道不能共用结构体
//
// 首批文本缓冲16字节，依赖填满容量；本批主通道使用带虚表、
// 读写位置、limit、capacity 的缓冲对象，支持抛出范围异常。
// 主通道缓冲字段均为相对于缓冲 this 的字节偏移。
//
// +00 DWORD   虚表。
// +04 DWORD   读位置；0x87B1A0返回，0x87B140用基址加它取读地址。
// +08 DWORD   标记字段，重置为-1；完整mark语义未逐一追踪。
// +0C DWORD   写位置；0x867880返回，0x867820用基址加它取写地址。
// +10 DWORD   另一标记字段，重置为-1；不直接命名读/写mark。
// +14 DWORD   limit；0x867520返回 limit-writePos。
// +18 DWORD   capacity；0x8680E0重置limit=capacity。
// +1C DWORD   数据基址；视图对象从外部传入，不一定拥有内存。
// +20 DWORD   动态拥有缓冲的存储字段，0x867E60分配后接线。
//
// 0x87B0F0 返回 writePos-readPos。不要误当 capacity。
// 0x868160 设置limit：要求 writePos<=newLimit<=capacity，否则抛PosOutOfRange。
// 0x867570 推进写位置：空间不足抛BufferOverflow，但负数并无独立拒绝。
// 0x8680E0 重置两个位置为0、两个标记为-1、limit=capacity。
// 0x867F50 是非拥有数据视图；缓冲“析构”不等于所有版本都释放外部数据。

// 大厅收帧器：0x88FF40、0x88D9A0、0x890090
//
// 收帧器 +04：底层reader；+08：内嵌缓冲；+2C：收帧阶段。
// 构造0x88FF40为内嵌缓冲分配1MiB，将limit设为8，阶段设0。
// 0x890090只要目标缓冲仍有空间，就调用reader虚表+4读入；
// reader返回<=0立即返回，否则持续读到本阶段填满。
//
// 阶段0：收满8字节头；0x88DB90取头+4的总帧长L。
// 若L<=0或L>1MiB，重置收头状态并设置errno=34，返回-1。
// 否则将内嵌buffer.limit设置为L，再进入阶段1。
// 注意：此时writePos已经是8，因此L=1..7不是正常通过，
// 会在0x868160触发PosOutOfRange异常。它不是静默容忍的短包。
//
// 阶段1：继续收至L字节；0x88DBD0再次检查总帧长<=1MiB。
// 完整帧从内嵌读地址复制到调用方写地址，再推进调用方写位置。
// 最后重置内嵌缓冲、limit=8、阶段=0。
// 8字节头的类型值并未在本函数里决定业务分派。

// 复制先于调用方空间检查
//
// 0x88D9A0先调用0x87CF10→0x87D3F0执行memcpy，
// 然后调用0x867570推进目标写位置；因此后者的容量异常不保护前面的复制。
// 对“输入长度上限1MiB”与“调用方buffer实际容量”的契约需要单独核对。
// 0x87EE40使用1024构造底层读写组件，但不能凭这个参数就宣称目标溢出：
// +120调用方缓冲的创建与扩容路径还需关联完整所有权链。
// 本条仅确定检查次序，不声称已经证明远端可稳定触发内存破坏。
//
// 第三批后继补证：0x87D9D0明确把管理器+120业务buffer构造为1MiB，
// 与收帧buffer同额；正常默认链并非1024目标。旧原证仍保留。
// 参见../登录与大厅状态/02_登录初始化与UI收尾.txt及其
// 证据/state_gates.json中的完整构造器；替换buffer路径仍需单独核验。

// 主泵与错误返回
//
// 0x87FA30先处理游戏接收对象，再处理大厅收帧和0x87FD30分派。
// 大厅管理对象+112为接收对象，+116为底层传输，+120为业务缓冲。
// 循环读帧直到返回<=0；WSAGetLastError()==10035视为本轮暂时读完。
// 非10035返回失败；不能只看errno判断完整断连路径。
// 0x88DEE0 select包装：超时写errno=11；select非0继续底层读取，
// 当前实现并未在该包装里单独区分select返回-1。
// 0x87C270与0x87B1E0分别调用recv/send，socket位于其this+8，flags来自+4。
// 这些偏移属于socket reader/writer，不能套用到管理对象。

// 游戏接收泵与业务交接
//
// 0x87BB40：游戏对象+4 reader、+8 transport、+12业务buffer。
// 先调用transport虚表+12；循环调用reader虚表+4，成功时0x87BC60分派。
// 0x87BC60读外层类型：type1走虚表+4，type299走虚表+8；其它返回消费值。
// 此处不是内部0x4000等业务操作码分派，不能把299和4000混为同一层。
//
// 0x8577E0从299载荷取label WORD、W WORD、flag BYTE，
// 调用全局0xACB870(label, payload+5, W, flag, 0, 0)。
// 0x6BE090注册回调跳板0x612CCC→0x6BEE80。
// 0x6BEE80在状态门槛通过后调用0x7EF120，将输出放到0xA82610，
// 将输出长度放0xA82ADC，再经0x604640交给0x64F870。
// 0x64F870之后的本地游戏消息队列由基础队列专题继续分析。
