// 本轮已闭环：双槽文本通道
//
// 0x8CD310 地址初始化；0x8CD400 事件泵；0x8CCC20 接收器。
// 详见01和02；对象、收发帧、缓存、回调及销毁均有本轮原始证据。

// 高价值候选A：带 CRLF 的四类型请求队列
//
// 0x859CC0 处理全局队列 0xACB8F8 的头部连接；0x858FB0 接收。
// 接收头检查 CRLF，随后读取类型和长度；类型范围0..3，
// 长度要求严格等于 0xA2F7D0[type]。完成后回调 0xACB8C0。
// 存在32字节字符串和单字节状态消费，但真实业务名未闭环。
// recv==0 与 WSAEWOULDBLOCK 返回1；外层监听 FD_CLOSE。
// 下一步：导出长度表、请求构造器、回调和UI入口，确认队列所有权。

// 高价值候选B：两类定长记录列表
//
// 0x862E40 是阻塞等待事件的请求入口；0x8628C0 为接收器。
// 全局阶段 0xA677F8 从1收头、2收体到3完成；类型 0xA677FC 为0或1。
// 类型0按20字节步长消费列表，类型1按76字节步长消费。
// 当前头部只见类型<2检查，载荷长/列表数量的约束需要再追踪。
// 不据两个步长命名成服务器列表、排行榜或其它业务。

// 高价值候选C：三类型结果及固定容量数组
//
// 0x8BB2E0 为单全局连接泵；0x8BA950 为接收器。
// 类型0..2，载荷长度由0xA3023C最小表与0xA30248最大表限制。
// 类型0出现36字节单记录与36字节数组，计数位于目标对象+3600。
// 类型1出现44字节数组，计数位于目标对象+4400。
// 类型2返回一个标量；完成调用 0xACBD60。
// 容量迹象均为100条，但还没有把表限制、数量和目标分配一起闭环；
// 暂不把100写成已验证协议上限。
// 注意：FD_CLOSE 分支伪代码读取 iErrorCode[0]，与常见[5]不同。
// 下一步必须核对对应汇编并识别调用者，不能机械修正原程序行为。

// 主大厅传输复核入口
//
// 0x88D9A0：阶段字段+44；收头后长度要求>0且<=0x100000，
//           失败设置 errno=34；完整帧检查失败设 errno=22；恢复头长8。
// 0x88DEE0：select 等待包装；超时设 errno=11。
// 0x87C270 / 0x87B1E0：recv/send 薄包装。
// 0x87BB40：相关错误转换入口，待结合既有传输证据继续展开。
// 不把函数局部1MiB检查自动写成所有连接统一上限。
