// P1 · 正文含单字节 0x80 时，排版循环没有推进
//
// 位置：0x6BEFB0；证据：dual_text_callback.json 的完整汇编。
// 条件：名称比较通过，正文扫描到非零字节 0x80。
// ASCII 分支要求字节 <0x80；双字节分支要求字节 >0x80。
// 精确等于 0x80 时两个分支均不消费源指针，循环又跳回 loc_6BF0BF。
// 汇编中的 cmp eax,80h / jge 与 cmp eax,80h / jle 可相互核对。
// 这是确定的局部不前进路径；主线程泵到此回调时可能表现为客户端卡死。
// 尚未运行客户端复现；不把其它游戏卡住现象自动归因于本路径。
//
// 建议补丁方向：显式消费或替换非法单字节；依据确定码页校验双字节对。
// 验收数据：空串、ASCII、正常双字节、0x80、行末第29/30字节边界。
// 服务端兼容策略可先拒绝/替换非法编码；这不能代替客户端边界修复。

// P1 · 响应载荷长度缺失下界
//
// 位置：0x8CCC20。头部只要求 type=0、L<=432。
// L=0：分配零容量，进入阶段2后剩余接收量为0，内部循环无退出推进。
// L=1..31：收完后固定读取32字节名称，已超出本次分配容量；
//          读游标继续前移，余量 L-32 为负，后续 Count+1 分配不可靠。
// L=32：正文为空；名称槽恰好完整，是实际解析逻辑的最小完整载荷。
// 建议恢复边界为 32<=L<=432，并在每个读游标推进前检查剩余量。
// 不通过向运行客户端发畸形包验证；当前仅保留静态条件和回归设计。

// P1 · 正文末尾残缺双字节未检查第二字节
//
// 位置：0x6BEFB0。首字节>0x80 时无条件读第二字节，再前进两字节。
// 接收器只追加一个 NUL；若最后有效字节是双字节首字节，
// 排版器会把补充 NUL 当第二字节消费，下一轮再从终止符之后读取。
// 具体运行结果依赖堆布局；不把静态越界路径写成稳定崩溃复现。
// 建议回调接收明确正文长度；若保留旧 ABI，至少检查第二字节是否为NUL。

// P2 · 缓存没有随请求名称建立键
//
// 位置：0x8CD9E0、0x8CDF60。
// 缓存命中后把当前名称和全局旧正文一起送给 UI，比对名称也会通过。
// 因而正确性依赖所有名称切换先失效缓存；本轮只证明存在失效调用，
// 尚未证明所有上层流程都正确失效。先追踪 UI 生命周期，不能直接宣布误显。

// P2 · 非阻塞发送的部分完成
//
// 位置：0x8CD400。FD_WRITE 只调用一次 send；短正数推进游标。
// 代码未在同一次事件里循环发送剩余字节，-1 也没有区分 WSAEWOULDBLOCK。
// 尚未证明42字节请求在当前环境会短发；不可凭这点宣称请求必丢。
// 后续补丁应保留待发状态，在可写时继续直至发送完或明确阻塞/错误。

// P3 · 错误处理与对象初始化
//
// socket、WSACreateEvent、WSAEventSelect、connect 的直接返回值未逐项检查；
// +08 标志仍置1，错误发现依赖后续网络事件。
// 若要改造通道，先为事件创建失败、连接拒绝、远端正常关闭设计状态迁移。
// recv==0 不能与有效收包等同；当前外层另处理 FD_CLOSE。
