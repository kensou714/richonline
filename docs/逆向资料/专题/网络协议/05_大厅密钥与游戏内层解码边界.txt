// 大厅C2S：12字节头之后才进入变换
//
// 0x88D820从包视图生成 {payload,length,flag} 三字段临时描述：
// 0x88FDA0取读地址+12，0x88FDF0取有效长度-12。
// 变换对象在发送上下文+124，密钥对象在+128；这些是内存偏移。
// 通过变换虚表+4到0x8DC8E0；length!=0才调用0x8DF990。
// 0x8DC8E0返回原地址/长度，低字节flag=1；不另分配新载荷。
//
// 大厅S2C：8字节头之后才进入解密
//
// 0x87F650使用0x88D900取读地址+8，0x88D950取有效长度-8。
// 0x8DC9D0执行反向变换包装；length!=0才调用0x8DFAC0。
// 头长度差异必须保留，不能给两方向统一减12或减8。

// 底层变换的前置条件
//
// 0x8DF990无条件先异或首字节，再循环其余length-1字节；
// 所以直接调用时length=0并不安全，正确零长度行为来自包装层跳过。
// 0x8DFAC0同样无条件异或首字节。移植时不要只照抄底层函数。
// key按有符号int计算余数；发送端key%2!=0反转，接收端key%2==1反转。
// 负奇数分支不对称；与“任意整数key的自逆算法”不是同一命题。
// 负length也不是包装层拒绝条件；合法帧长与头长契约在更外层保证。

// 密钥对象：0x8DFD80及0x8DFFF0
//
// 密钥算术对象为0x80字节分配；前24 DWORD来自表0xA67938。
// +100 DWORD 基数g；+104随机索引rand()%24；+108所选指数。
// +116 DWORD 模数p；+120 DWORD本方公开值pow32(g,e,p)。
// +96、+112、+124不能仅凭空洞擅自命名，本批未恢复所有访问。
// 0x8DD020从首帧载荷前两DWORD构造该对象；从第三DWORD取得对方公开值，
// 经密钥虚表+12到0x8DD200，计算并保存共享值到密钥包装对象+4。
// 包装对象+16指向回发公开值的4字节数据；+20为长度4；+28为算术对象。
//
// pow32执行乘积低32位，再有符号idiv取余，并逐位处理指数。
// p=0会除零；有符号除法的INT_MIN/-1也有异常边界。
// 本批没有证明首帧路径拒绝全部非法参数，服务端应使用已验证正参数。
// 不能以标准大整数DH实现替换而声称所有溢出和符号行为完全一致。

// 游戏内层：0x7EF120，没有使用上述key
//
// 参数为 encodedPtr、encodedLength、outPtr、outLengthPtr。
// 入口只检查encodedPtr非空及encodedLength<=1024，比较为有符号。
// 将下标1、3、5...的字节抽入全局0xA8DCE0，反转后逐字节减107。
// 前2字节解出正文长度N，要求N==抽取数-2，然后复制正文到outPtr。
// 最大encodedLength=1024，抽取512字节，故解码正文最大510字节。
// 函数没有outCapacity参数，不可单独用它证明任意调用方容量安全。
//
// 重要差异：奇数encodedLength不会被拒绝，最后偶数下标字节不被抽取。
// 因此严格“编码字节数必须偶数”的服务端校验，是更严格实现约束；
// 不能写成这个客户端解码器本身已有的条件。
// 负长度或不足4字节最终因N与负剩余长度不等而失败，但仍会读取全局
// 暂存区前2字节；正确成功下界和空正文策略应由封装层明确处理。

// 与游戏队列的契约缺口
//
// 0x6BEE80把解码长度原样交给0x64F870，不在此处夹到288。
// 0x64F870与后续队列存在288字节值传递记录，不能将解码上限510
// 自动视为队列也可容纳510。仍需逐分支确认同步处理与入队范围。
// 本批记录的是跨层容量不一致待核验，不是已实测远程攻击结论。
// 服务端当前编码器上限509属于服务端实现，不能替代客户端容量证明。

// 复核与后续补丁建议
//
// 用独立离线模型验证空载荷包装跳过、正负奇偶key、32位乘积溢出。
// 对内层校验偶数长度、嵌入长度、具体消息最小长度与目标记录容量。
// 若修改客户端，必须同时修改调用接口或显式传递目标容量，避免只扩大全局数组。
// 本轮未对EXE打补丁，未向客户端发送畸形帧。
