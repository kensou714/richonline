// 四类型队列连接：0x859980→0x859CC0→0x858FB0→0x6BEF20
//
// 0x859980来自配置+3376地址、+3392端口，注册0x6BEF20回调。
// 地址保存0xACB8B8、网络序端口0xACB8BC、回调0xACB8C0。
// 0x859CC0只泵全局队列0xACB8F8头部对象，connect初始化和后续事件分开。
// 0x858FB0头部先检查CRLF，再读type和length；type只能0..3。
// 本批读取0xA2F7D0长度表：type0=33，type1=36，type2=36，type3=4。
// 这是响应体固定长度；不是请求体长度，也不包含CRLF头。
//
// type0消费name32+状态BYTE；name非空则增对象，否则清理并回调(0,0)。
// type1先读结果DWORD，结果0时消费name32并更新列表，然后回调(1,result)。
// type2同样结果DWORD+name32，成功时执行查找/删除链，再回调(2,result)。
// type3读取结果DWORD，回调(3,result)。
// 收完体重置阶段为1并释放动态体buffer，能够继续收下一响应。
//
// 0x6BEF20按四个type分别调用同一管理器上的四个不同方法。
// 本批仍没有用类定义/UI资源确认列表业务身份；“好友”只可作为后续假设。
// 路径价值：中等；需要追加四个管理器方法及请求构造，再给业务命名。

// 两类列表连接：0x863440→0x862E40→0x8628C0
//
// 配置+3430地址、+3446端口；保存0xACB91C和0xACB920。
// 0x862E40在当前线程等待WSA事件，超时值INFINITE。
// 注册READ/WRITE/CONNECT/CLOSE；完成与错误都关闭事件与socket。
// 没有依据将此入口称作游戏主线程；调用线程归属需要单独查调用者。
//
// 0x8628C0头部两DWORD：type、L；本函数只检查type<2，然后分配L。
// 收完后type0消费数量及20字节记录，type1消费数量及76字节记录。
// 阶段1→2→3，和四类型通道循环返回阶段1不同。
// L=0时可能停在阶段2；数量与L的相容性未在当前函数局部校验。
// 仍需读取相应缓冲方法与目标容器，不能只看步长宣称固定数组越界。
// 路径价值：中等；优先完成请求内容、记录字段与目标容器生命周期。

// 三类型结果连接：0x8BB090→0x8BB2E0→0x8BA950→0x755DE0
//
// 配置+3412地址、+3428端口；单连接指针0xACBD64。
// 长度表0xA3023C/0xA30248：
//   type0：44..3644字节。
//   type1：4..4404字节。
//   type2：4字节。
// type0 = DWORD标量 + 36字节记录 + DWORD数量 + 36字节记录数组。
// type1 = DWORD数量 + 44字节记录数组。
// type2 = DWORD标量，存入0xACBD68。
// 数组计数分别存目标+3600和+4400，容量迹象为100条。
// 长度上限并没有自动限制计数字段，当前循环直接使用载荷计数；
// 必须补“计数<=100且固定前缀+计数*步长<=L”的调用链约束取证。
//
// 0x755DE0：type0/1成功刷新UI105；type2读取标量，1..10000使用文本1054，
// -1使用文本1053；失败显示文本1055。尚未定位这些文本的真实中文含义。
// 不因显示列表和名次数值迹象，就把它命名成已证实的排行榜协议。
//
// 已用汇编确认：0x8BB2E0的FD_CLOSE分支读取iErrorCode[0]，
// 不是常规FD_CLOSE对应的iErrorCode[5]。这是原程序行为，不是反编译猜测。
// 可作为清理错误分支补丁候选；不能把它扩散到其它事件泵。

// 首批11个初读候选如何处理
//
// 主通道5个：0x88D9A0、0x88DEE0、0x87C270、0x87B1E0、0x87BB40，
// 已结合reader、缓冲、上层泵作结构和ABI复核，见04。
// 辅助通道6个：0x858FB0、0x859CC0、0x8628C0、0x862E40、
// 0x8BA950、0x8BB2E0，已复核类型、长度表、事件错误和回调连接。
// 仍未完成全部业务身份与记录字段，不把第二轮复核写成协议全面恢复。

// 优先级评选
//
// 最高：主通道跨层容量、type299输出与288字节本地记录契约。
//       与卡住、崩溃及服务端合法发包直接相关，证据可闭合。
// 高：三类型结果列表的数量/长度关系，已有具体容量与计数消费点。

// 低：尚无可达调用者的listen/accept/UDP库包装；保留台账而不先猜协议。
