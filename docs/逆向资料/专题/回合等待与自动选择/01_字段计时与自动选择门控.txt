// Game字段：位置与含义均来自实际读写，不宣称恢复了原始类名或完整sizeof。
// +83780 / DWORD / 常用选择持续值；地产6092/6093把同一值传给UI和pending。
// +83784 / DWORD / 暂存剩余值；694870写duration-(tick-start)，无饱和保护。
// +83790 / WORD  / pending类型；-1表示没有本项等待。
// +83792 / DWORD / pending持续值；绘制和暂停补偿读取，不是每帧递减计数。
// +83796 / DWORD / pending起始tick；7BB430取GetTickCount写入。
// +83830 / BYTE  / 自动选择替代门控；7D5E10仅判!=0xFF，未恢复产品名称。
// +83831 / BYTE  / 6021消费抑制位；这是另一字段。
// +3620  / DWORD / 7D5DB0比较的阈值字段；>=2或>=3，不冒称“托管次数”。
// +3624  / DWORD / 当前行动槽；+8为本地槽，63F760判二者相等。
// +52    / 指针  / 指向配置单例+68；7BB530检查其首字节非零。
//
// 建立与清除
// ----------------------------------------------------------------------------
// 60C3F4 -> 7BB430(G,type,duration,unused)；末尾retn 0xC。
// 写type、duration、当前tick；第三个栈实参不被读取，不能命名为重试次数。
// 60AC43 -> 6939E0：type=-1、duration=0；保留start、暂存剩余值和其他字段。
// 构造7BAE60设置type=-1，但没有在这段显式初始化duration/start；不得补成0。
// 本地0x6004 -> 67DB40直接读记录+2 WORD和+4 DWORD，再设置pending。
// 该handler不验证类型范围、不校验持续值，也不读取本地记录+8行动者字节。
// 不能把网络包0x6004直接等同这个受信本地事件的合法来源。
//
// 自动选择：64F780 -> 60B210 -> 7BB530
// ----------------------------------------------------------------------------
// 每帧入口先执行基础队列消费者7BB290，之后调用7BB530；二者各自检查条件。
// 自动选择必须同时满足：
//   G+83831为0；
//   7D5DB0为真，或7D5E10为真；
//   BYTE[DWORD[G+52]]非零；
//   7D5D20为真：signed WORD[G+83790]!=-1且无符号tick-start>=1000。
// 7D5DB0的分支：7C0BB0返回非零时比较G+3620>=3，否则比较>=2。
// 7C0BB0又依赖玩法谓词及G+3640+DWORD[G+116]，完整玩法名称尚未恢复。
// 7D5E10只判G+83830!=-1；7CF6A0将其设2，7CF730正数时减一并判是否到0。
// 因而0也通过!= -1的门，不要将它解读为“剩余次数必须大于0”。
// G+52来自7BAE60调用配置单例627450，再经727A10返回单例+68。
// 这里只证明地址关系，不将配置字节直接叫成玩家托管开关。
//
// 一秒是最早允许动作的时间，不是每个pending自己的超时。
// 7D5D20完全不读duration；duration=500、8000或10000时仍比较同一1000。
// 通过门控后每次调用rand()%100，记r；switch分派详见02。
// 分派后再次检查配置字节，并且63F760确认本地为当前行动者，才调用6939E0。
// 不论该switch分支是空函数、default，还是请求提交被其他入口拒绝，
// 尾部都不检查动作返回值；因此清pending不是“请求成功”的证明。
// 非本地行动者通常不能通过动作包装中的63F760，且尾部不清pending；
// 但状态20的7BC100没有该包装门，不能把全部动作一概说成本地才提交。
// 若pending未清，后续帧仍可能重新进switch、重新抽rand；没有本函数内置重试间隔。
//
// 基础队列的等待是G+12/G+16，不是上面的pending
// ----------------------------------------------------------------------------
// 64FB10(G,duration)写G+12和G+16=当前tick；64FB50只清G+12。
// 64FB70在G+12非零且elapsed>=G+12时清零，返回是否仍暂停。
// 7BB290门控：G+83831为0、G+0x640队列非空、64FB70不暂停，才取一条记录。
// 它不直接检查G+83790/-1，也不读G+83792。
// 等待玩家选择本身不会阻止基础队列继续消费，服务端回复仍能被分派处理。
// 反之，清pending也不会解除G+12的动画/界面暂停。
//
// 画倒计时：650240
// ----------------------------------------------------------------------------
// 条件为type!=-1且duration!=0；秒数=(signed32)(duration-(tick-start))/1000。
// 非负才绘制，用sprintf("%02d")，但只取输出前两个字符做数字图片索引。
// 因整数除法向0截断，过期不足一秒的负毫秒值可能仍显示00。
// duration大到超过两位秒数时，显示不能代表完整数值；没有业务提交副作用。
// 本函数未在剩余为0时清等待、生成取消或驱动下一回合。
