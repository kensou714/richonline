// ============================================================================
// 计数、两列表与名义四槽 / 6A4E70后半段
// ============================================================================
// 6A4FEE：kind11返回a、kind10返回b，两者DWORD相加写R+60。
// kind11/10局部复用82B090：对应列表对象首DWORD；对象缺失时返回0。
// 6A5018的jle为signed R+60<=R+3C；超过则reset并AL0。
// 只有signed上限，没有a/b非负门、加法溢出门、R+3C<=4门。
// 所以这一步不能证明后续实际写入项数<=4，也不能证明R+60是非负有效计数。
//
// 两轮拼接
// ----------------------------------------------------------------------------
// t从0起；signed a>0时kind13返回Q，以signed k<DWORD[Q]遍历。
// 每项取DWORD[DWORD[Q+4]+4*k]，写DWORD[R+64+4*t]后t++。
// signed b>0时kind12返回S，同样按DWORD[S]实际长度遍历。
// 第二列表每项另外写BYTE[R+74+t]=1，再t++；第一列表对应BYTE沿用reset的0。
// a/b只是是否进入列表遍历的门；不核a==Q.count、b==S.count。
// 不核Q/S本身或其data指针，不核实际signed count和buffer容量。
// 82B090内部缺对象返回0不构成本入口对返回Q/S的NULL保护。
//
// 四槽布局与写入边界
// ----------------------------------------------------------------------------
// +64..73：四个名义DWORD值；+74..77：四个名义BYTE分类；+78..7B：DWORD状态。
// 名义四槽由reset固定4次及6A6E00固定4次读共同证明，不是生产循环的容量门。
// t=4时DWORD写落到+74..77，会覆盖分类；t=5时DWORD写落到+78..7B。
// t=6时DWORD写落到下一条R(i+1)+00；本地没有截断、拒绝或扩容分支。
// 第二列表t=4的BYTE写+78也进入状态；更大值可继续落到后续记录。
// 这是本函数缺少局部边界检查的事实；是否可达及数据是否可信需要运行证据。
//
// R+78 / 来源bit11归一为整DWORD状态
// ----------------------------------------------------------------------------
// 6A5151最终写DWORD[R+78]；来源DWORD[P+20]&0x800经过neg/sbb/neg得到0或1。
// 整DWORD替换，不保留R+78旧位，也不是将0x800位直接存入R+78。
// 与前批6B7DF0对R+78严格等1的consumer可对接；深业务名称仍保持未知。
// 尾部的DWORD覆盖可能改写越界填列表造成的该字段，但不修复其他已覆盖区域。
// AL1只表示走完本地路径，不保证四槽未溢出、列表一致或所有副作用可回滚。
