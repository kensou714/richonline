// 以下偏移相对于缓冲对象this；来自867FD0/867F50/867E60/8680E0及访问器。
// 名称是研究别名，不能把CRT/MFC自动函数签名当作原始C++类名。
//
// +00  DWORD  虚表指针，各派生构造器重写。
// +04  int32  读位置r；87B1A0返回；87D0D0相对推进。
// +08  int32  标记槽，构造/重置为-1；完整mark/reset语义本轮未闭合。
// +0C  int32  写位置w；867880返回；867570相对推进。
// +10  int32  另一标记槽，构造/重置为-1；不凭相邻布局命名读写mark。
// +14  int32  写limit；867520返回limit-w，868160受约束设置。
// +18  int32  capacity；867DB0返回，868390直接写入。
// +1C  byte*  数据基址；867820返回base+w，87B140返回base+r。
// +20  byte*  自有版本保存的分配指针；8679D0对它调用delete[]。
//
// 两个剩余量
//   可写量：limit-w；可读量：w-r。读接口不直接拿limit或capacity当可读长度。
//   868160要求w<=新limit<=capacity，否则构造PosOutOfRangeException并抛出。
//   868390直接改capacity，没有同样约束；不是保证所有调用时对象都合法的证明。
//   8680E0将r/w清零、两标记置-1、limit恢复为capacity；不会清空底层数据。
//
// 借用视图
//   867F50(base,capacity,w,r)先通过867FD0设置(limit=capacity,capacity,w,r)，
//   再写+1C=base。未分配、未复制，不因此取得外部存储所有权。
//   867A50 -> 867AB0只改虚表并返回；此基类析构不释放+1C。
//   867AF0/867B60的低位删除标志控制是否释放对象this，与是否释放数据不同。
//
// 自有版本
//   867E60(Size)构造基类后调用91BD80分配Size字节，保存到+20，
//   再以868060把同一地址接到+1C。91BD80实际转operator new，自动MFC名称错误。
//   8679D0先delete[](+20)，再调用基类析构；本轮按实际入口记录分配/释放，
//   不据此虚构原源码new表达式。867BD0另按标志释放对象this。
//   构造器早期读取+20作为基类实参，随后分配并重新接线；早期值不证明可用缓冲。
//   成功构造后+1C与+20相等。若以后重新绑定+1C，不可假设析构会释放新地址，
//   因为析构明确释放+20；本轮未证明任意重新绑定方案拥有正确生命周期。
//
// 868060重新接线的顺序
//   先8680E0按旧capacity重置，再868390写新capacity，868160设新limit，最后写base。
//   不分配、不复制、不清零、不更新+20。不能把它写成“自动扩容”。
//   867DF0及867930/867980/867C40属于薄包装；派生层的析构最终到8679D0。
//
// 容量及有效内容不同
//   分配Size不是已经写入Size。有效可读区间由r..w决定。
//   8673B0先创建带12字节头的自有缓冲，再复制Src的Size字节，不能当裸内存拷贝构造。
//   87BE40对应带8字节游戏头的构造后复制；两者总分配Size分别加12、加8。
//   868060/8680E0及这些分配链均未见初始化整个数据区的memset。
//   这与另一个简单缓冲族867130的显式memset有差异，不能把后者清零结论套入本族。
//
// 未决项
//   原始类名、两标记完整操作族、所有重新绑定调用者、跨线程同步未完整恢复。
//   只从本字段布局不能证明任意外部指针的真实分配长度等于capacity。
