// 6B8980(this=L, capacity, growth)，callee ret8；原证bounded_raw.json#/functions/2。
// 先写count=0、capacity=arg0、growth=arg4，再以low32(capacity<<2)申请字节并写base。
// 两parser均压16再压32，因x86压栈顺序，capacity=32个DWORD，growth=16个DWORD。
// 初始每列表申请128字节，四列表各自申请；不能把32/16误称字节数或16个频道类别。
// 函数不释放旧base，不清数组内容，不验证负值/零值/溢出；只适用于已清理或未持有内存的L。
// EAX在正常路径保持分配结果，caller并不检查；分配器抛异常/返回NULL的全局策略另列未知。
// 不从没有caller检查推断当前实机一定分配失败。
//
// 6B8A60(this=L, value) / 复用旧入口，当前完整块核验
// ----------------------------------------------------------------------------
// formal_functions.json中该项保留旧source_record_json，当前Capstone解码来自216字节块。
// 6B8A82比较signed count与capacity，JL跳过扩容；否则申请low32((capacity+growth)*4)。
// 新指针先写base，再复制旧capacity*4字节；复制按容量，不是count。
// 旧base非0才delete[]，最后capacity加growth。它不回退新指针、也不在本体保护运算溢出。
// 6B8B10写base[count]=value，随后count加1，返回count-1；callee ret4。
// 成功正常域：第33次追加前容量32，扩成48；第49次扩成64，原顺序不改变。
// 上述序列以前32/48次追加成功及内存有效为前提，不是任意坏状态下的保证。
// count负值、growth<=0、释放后继续用L等输入无本地修正门；不能称通用安全容器。
//
// 6B8A00(this=L) / bounded_raw.json#/functions/3
// ----------------------------------------------------------------------------
// 若base非0，delete[]后写base=0；若已经0，直接返回。
// count/capacity/growth不写，故重复调用本清理入口不会重复释放同一base。
// 清理结果是“base空、元数据仍旧”，不是可直接调用append的正常空列表。
// 它确实清掉base，不能写成遗留悬空base；外部借用旧数组地址是否仍存活未知。
// return的业务意义未建立，不把无显式结果写入的入口当bool成功函数。
//
// 6A0B50(this=M) / bounded_raw.json#/functions/1
