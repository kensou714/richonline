// 对象与适用域
// G游戏；M=G+0x65C地图对象；P=G+0xE00中由G+0xE28选出的当前角色。
// 当前道路格r=P+1464；地产索引p= signed WORD[M的+48指针+8*r+2]。
// 地产记录D=DWORD[M+56]+68*p：+0类型，+1类别，+2等级，+3所有者，+6 WORD组号。
// 此函数没有在使用p前另查是否-1；调用前提必须由上游保证，不能补写成有范围保护。
// 模式门：M+24==0，或(M+24==2且M+108==0)，或M+24==4；否则返回1。
// mode4在本函数内会排除状态3/4/6效果；状态5分支没有相同的mode4排除。
// 状态字段是P+1488 BYTE，727B40/701530/7D7400/727B70分别比较4/3/5/6。
// 本文只用已证数值命名状态；具体神明/道具名须由资源及状态写入链另证。

// 调用约定与顺序
// thiscall(G, &cursor, &scratch, start, oneStage)，末参在本函数按BYTE使用。
// start=4从状态4条件开始；3、5、6直接跳到各自对应阶段。
// 其他start值也从状态4开始，并非直接忽略。
// 在某阶段条件不成立时，oneStage非0立即返回1；为0则按4→3→5→6继续筛选。
// 一旦阶段效果成立，生成其任务后直接返回，不在本次继续其他状态。
// &scratch在本函数未读写；仅保持跨阶段接口形状，不能命名成已消费的错误输出。
// 7C6640的地产收尾与本地6084都会进入本函数；各自start/flag要按调用点区分。

// 状态4阶段
// 需P+1488==4、7E3D30可升级、D+1!=1且非mode4。
// 可升级谓词排除类别8/9/10，模式0要求signed等级<5，其他模式要求<7。
// 成立先排6003/UI4文本139（1800、1350）；若当前角色是所有者，再排6002动作19。
// D+0==11或D+1在2..6：排6070，p/当前槽/delta1，共6字节，返回1。
// 其他类别若自有：排两字节6085，置G+83808=1，返回0。
// 其他类别且非自有：排6073，p/类别3/标志1，共6字节，返回1。
// 这里的升级是角色状态附加效果，不等同玩家普通落点的建造选择。

// 状态3阶段
// 需P+1488==3、自有、7E3D30可升级、D+1!=1、非mode4。
// 先排6003/UI4文本151、6002动作rand()%2+19。
// D+0==11或类别2..6：排6070(p,当前槽,1)，返回1。
// 其他类别：排6085并置G+83808=1，返回0；选择窗口接手后续流程。

// 状态5阶段
// 需P+1488==5且当前角色不是地产所有者；本分支不要求原地产已有所有者。
// 排6003/UI4文本141；原所有者不为-1时先排6063(原所有者,2)。
// 然后排6071(p,当前槽)，构造器把+5标志置1，记录长6；再排6002动作19，返回1。
// 6071消费端有撤除旧归属、赋予新归属、模式专属同步及音效/显示链。
// 本轮只确认上述调用与字段，完整归属集合与组加成维护仍由地图专题深入。

// 状态6阶段
// 需P+1488==6、非mode4，以及7E3DF0：类别不为8/9/10且signed等级>0。
// 排6003/UI4文本143，再排6072：+2 WORD p、+4 BYTE1、+5 BYTE1、+8 DWORD123，长12。
// 消费端7E4020执行等级扣减；显示使用动画4与参数123，完成控制见下文。

// 6070 -> 680490：增级与显示交接，最小读取6字节
// +2 signed WORD p，+4 signed BYTE角色槽，+5 signed BYTE delta。
// 调用7E3F30(p,delta)，按条件排6002动作6/5，更新地产显示7E73F0。
// 动画管理器7A5C30(id4,{p,11,...})启动后，取694BC0(id4)并交64FB10暂停基础队列。
// 不能把“handler返回”当成已解除等待；动画4的结束回调是独立闭环，未在本篇展开。

// 6071 -> 6806D0：归属转移，最小读取6字节
// +2 signed WORD p、+4 signed BYTE新所有者、+5 BYTE是否启用部分音效和显示。
// 若原所有者存在则先处理模式4附加清理，调用7E3E60移除旧归属。
// 新所有者!=-1才调用7E3C00赋予；后续可能重算地产类型8/9/10对应功能及组提示。
// 本函数分支较多，当前只标局部分析，未把内部全部集合维护函数算完成。

// 6072 -> 680A90：减级，最小读取12字节
// +2 signed WORD p；+4 signed BYTE减少量；+5 BYTE是否暂停队列；+8 DWORD动画参数。
// 7E4020先取signed BYTE等级，在DWORD中减实参，写回低BYTE后再signed检查<=0。
// 检查成立才归0；不是无限精度饱和减法。类型11可能清类别并重置原归属；其他分支另证。
// mode4额外调用三项更新，随后刷新显示、启动动画4；仅+5非0才调用64FB10。
// 7E4020的伪码char形参会遮掩DWORD减法；这里只按汇编描述，不扩展合法输入域。

// 6073 -> 680BC0：写类别后增级，至少直接读到+4
// +2 signed WORD p，+4 BYTE新类别，经63F2D0写D+1；随后7E3F30(p,1)。
// 刷新地产显示及适用模式的类型功能，启动动画4参数11，并调用64FB10。
// 本构造端写+5=1但此handler不读取它，不能自动命名为被消费的布尔字段。
// 反编译标注fastcall；原注册6073的桥接实际以ECX传G、栈传记录，按thiscall调用。

// 6085 -> 681980：选择等待
// 只在当前行动槽等于本地槽时开UI13，持续参数取DWORD[G+83780]。
// 所有客户端均写pending9，duration同G+83780，setter末参数1；handler不读输入字段。
// 6085本身只有消息WORD；地产位置从当前状态取得，不在这两字节中传递。
// 这里是明确转入等待的一个返回0路径；不能推广成所有7CB3F0返回0都由网络造成。
