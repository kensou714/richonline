// ============================================================================
// 阶段 2：建筑选择、升级上限及本地交互事件
// ============================================================================
// 适用指纹与全部证据见 阶段2_01_入口与分支树.txt；以下均为静态结论。
// mode3/mode4 的选建造流程以 0x7C6B34 为入口；重入 a4=8 可直接抵达这里。
//
// 特殊建筑：新建与升级不共用同一个条件
// ----------------------------------------------------------------------------
// L 为 68 字节地产记录；L+1 为建筑种类，L+2 为当前等级，L+3 为所有者。
// 0x63F290 判 L+2 == 0：无抑制状态时构造本地 0x6092 并返回 false。
// 生成点 0x7C6BBC -> 构造函数 0x7D7560；消息只含两字节本地操作码。
// level==0 且三项参与者抑制条件任一命中时，0x7C6BD6 -> 0x7C7E08 -> 0x7C89E5返回 true。
// 该提前返回不经过0x7C6E05建筑效果；不能合并为“未弹选择窗口就继续建筑效果”。
// 等级非零：mode4 用 0x8054C0，mode3 用 0x7ACBC0 检查关卡上限。
//   mode4：level >= DWORD[关卡对象 + 216 + 4*kind]。
//   mode3：level >= DWORD[关卡对象 + 1232 + 4*kind]。
// 参数来自 G[895] 或 G[894]；这些偏移属于各自对象，不能合并成同一结构。
// 达关卡上限时跳过升级询问，不生成“技能不足”文本341。
// 未达关卡上限时，再比较 0x7F74B0(kind-11) 返回的当前能力是否严格大于 level。
//   能力>level -> 0x7C6DEB 构造本地0x6093，返回 false。
//   能力<=level -> 排文本341，然后继续类型效果。
// 0x7F74B0 有普通能力字节表与另一模式 DWORD 表两个来源；本轮未完整命名另一模式。
// 不应把物理可容纳等级、关卡上限、参与者能力三个概念合并。
//
// 选择窗口消费者：等待状态不是网络 opcode
// ----------------------------------------------------------------------------
// 本地码  构造实现  handler     本机槽显示内容  登记等待状态
// 0x6092  0x7D7560  0x6821D0   UI编号41        23
// 0x6093  0x7D7590  0x682230   UI编号5         24
// 0x6094  0x7D75C0  0x682340   UI编号42        25
// 0x6081  0x7D7470  0x681540   UI编号3          4
// 0x6082  0x7D74A0  0x681690   UI编号5          5
//
// 所有这些 handler 都经 0x63F760 比较 G+0xE28 当前槽与 G+8 本机槽。
// 只有本机槽才调用显示 UI 的入口，但登记等待状态在这个条件之外。
// 因而观战/其他参与者不会弹同样窗口，却仍可能等待后续消息推进。
// 等待写入器 0x7BB430：WORD[G+83790]=状态，DWORD[G+83792]=时长参数，
// DWORD[G+83796]=GetTickCount()；第四实参在本轮所见实现里没有被消费。
// 等待状态23/24/25不能直接当作服务器消息号；选择结果和超时应另追消费者。
// 本节不证明 BOSS 自动升级已经由该函数实现；当前可见的是本地交互分流。
//
// 普通自有地产升级
// ----------------------------------------------------------------------------
// 普通模式判定 0x63ECA0：模式0，或模式2且次级模式0。
// 0x7E3D30 排除类型8/9/10；模式0 要求 level<5，其余允许该路径的模式要求 level<7。
// 类型1（0x63F500）不走普通升级询问。
// 升级费用 0x7E3CE0：L+0 类别11返回500，类别12返回1500，其余返回-1。
// 调整器 0x7CF5E0 的 ECX 为 G，第一个栈参数为槽号，第二个为原费用。
// 0x7CF5F4 取 DWORD[G+0xE00+4*槽号]；0x63F3C0 判断该参与者 P+152 > 0。
// 命中才算术右移费用一位；普通升级调用点0x7C92EF传当前槽，不是全局半价。
// 0x7C9327 读取 P+1504；0x7C932F 的 jle 把“余额相等”归入不足提示129。
// 只有严格大于费用才构造 0x6082；生成点0x7C933F，清 BYTE[G+83808]=0。
// 如果将服务端条件写成 >=，必须明确这是兼容策略变化，不是上述客户端原条件。
//
// 升级检查之后仍可能执行建筑效果
// ----------------------------------------------------------------------------
// a4=7 和非零等级的升级检查未暂停路径会到 0x7C6E05；level==0受抑制则直接返回。
// 此处再次判断是否本人所有，或当前参与者 BYTE[P+1480+所有者] 标志非零。
// mode4 且两条件都不成立时，转入他有类型效果；mode3 的控制流不同，不可合并。
// kind=11：sub_5FF2EE -> 0x63F390 读取 BYTE[G+3672+当前槽]，值为0且无抑制时
//   排0x6094并返回 false；这里不是本机槽比较，标志的写入来源仍待确认。
//   真正的本机槽比较在0x6094 handler 0x682340内，经0x63F760决定是否显示UI42。
// kind=16：结合 P+1488 当前状态，取 mode3/mode4 各自资源对象中的等级效果。
//   可生成文本342、343、354、355；也可能生成本地0x6050/0x6051及0x6083后暂停。
//   0x6051 的部分效果资源对可见 (132,101)、(148,108)、(138,104)；
//   他有分支另见 (135,102)、(145,107)、(142,106)。这些数字的资源域尚未逐项命名。
// kind=15：取等级收益，再经 0x60B288 调整，生成文本342/357、0x6060和0x6000。
//   另有 0x7FA140 对 P+1504 与外部上限比较；限值来源尚未完整恢复。
// 其它 kind 或未触发效果时返回 true，交给 stage6 继续。
// “建筑满级”只跳过升级询问；不能据此删除类型11/15/16落点效果。
//
// 事件族和结构长度：只描述本地构造
// ----------------------------------------------------------------------------
// 0x6000 构造0x63F080，常以20字节排队；含效果号、时序和内存指针。
// 0x6002 构造0x693260，常以12字节排队；含动作/表情编号、参与者及1350等参数。
// 0x6003 构造0x6932B0，常以24字节排队；含文本指针、长度及1800/1350等参数。
// 0x6050 构造0x693570，阶段2以4字节排队。
// 0x6051 构造0x694810，阶段2以12字节排队，资源对不能当作网络字段定义。
// 0x6060 构造0x693320，阶段2以12字节排队，用于参与者数值变化展示路径。
// 长度来自本函数调用 sub_609D34 时的 Size；不是对应网络包的完整长度。
// 0x6003 的文本编号通过 0x629D90 做“固定行宽*编号+基址”寻址。
// 当前未转储 RichStr 对应行内容，不把编号129/341自动替换成自拟提示句。
//
