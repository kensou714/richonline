// 他有地产的免收/暂停分支
// ----------------------------------------------------------------------------
// 主函数行1338开始缓存所有者、地产组、kind==0、kind==1。
// 普通模式下若参与者状态字段、地产L+4，或当前参与者按所有者索引的
// P+1472/P+1480字段命中，会生成说明后跳过收租。
// kind2/kind6在其中有显示例外；不是所有免收分支都会显示同一条说明。
// 相关文字编号：263、268、21/23/22、71、30、32、34、37、251。
// 这些组合由本函数拼接，尚未确认所有名字，不用现实规则反填未命名状态。
// 免收分支最终调用 0x7CB3F0(4,0)，并非直接“当前玩家回合已结束”。
//
// kind0：同组地产合并租金
// ----------------------------------------------------------------------------
// 0x7C9A67 调 0x7E4140，先取当前地产的所有者 owner=L+3、组 group=WORD[L+6]。
// 遍历地图地产索引列表，逐一取得有符号 WORD 地产编号 q。
// 仅当 q 的类别Lq+0==11、kind Lq+1==0、owner相同、group相同时纳入。
// 每块租金 = DWORD[Lq+8] * DWORD[M+100] * 系数[level] / 1000。
// 若有符号 BYTE[Lq+5] > 0，该块结果再乘2；最后累加各块。
// 系数表 VA 0xA2D920 的前6个DWORD：500、1000、2500、5000、8000、12500。
// 本轮核对了这24字节的IDB/磁盘一致性；文件偏移4389152，见stage2锚点JSON。
// 不把紧邻的-1、1062等DWORD自动认作更高级别系数；表边界还须结合初始化复核。
// 0x7E424D、0x7E425D用32位imul保留乘积低32位，0x7E4264的cdq再作符号扩展，
// 0x7E426A以idiv 1000作有符号整除，余数舍弃、商向零截断；不是64位中间乘积。
// 正常非负且未溢出时等同上述公式；模拟原行为须保留32位乘法溢出和整除次序。
// 可见代码未在这里夹取 level 或检查乘积溢出；内容工具必须限制不受支持的等级。
//
// kind1：按同所有者数量计费
// ----------------------------------------------------------------------------
// 0x7C9A8D 调 0x7E42B0：费用 = DWORD[M+100] * 4000 * count(owner)。
// count 的实现0x7E6B40遍历同一索引列表，只计类别11、kind1、所有者匹配的地产。
// 与kind0不同：这里没有group相同的筛选，不按当前地产等级做系数索引。
// 本轮未把kind1强行命名为某一种现实建筑，名称需由Data/Build等资源确认。
//
// kind5：等级乘比例
// ----------------------------------------------------------------------------
// 0x7E42F0：费用 = 有符号BYTE[L+2] * 150 * 调用传入的比例值。
// 如果0x7ECB10判断 L+5>0，再乘2；比例取得入口 j_unknown_libname_632 尚未定名。
// 此分支使用文本160和10拼接金额说明，之后进入同类支付拦截链。
// kind5与kind0/1的费用来源不同，不应共享同一个“当前地块租金”公式。
//
// 支付链：状态、道具、余额不足均可能拦截
// ----------------------------------------------------------------------------
// P+1488==0：生成文本136和动作事件；本路径跳过常规转账展示。
// P+1488==1：生成文本137和动作10，费用乘2，后续双方还产生一个效果记录。
// 0x7CCE60：普通模式且金额>=5000，检查道具1050及可用条件。
//   成功则生成文本256、资源312、动作49及道具事件，返回1；调用者跳过常规支付链。
//   本轮未完整追该道具使用后的网络确认，不能把返回1说成服务器已扣款。
// 0x7CD090：本阶段传入分支0；金额>=10000且道具1056可用时进入等待。
//   写G+83812/83813/83814为分支/付款槽/收款槽，G+83816为金额。
//   构造另一个两字节本地事件，返回0；主函数随即返回false。
//   该两字节事件的消费者与道具确认时序尚未在本批审阅。
//
// 常规支付展示前，0x7FA0F0把金额夹到 P+1504 与 P+1508 两个DWORD之和。
// 随后分别为所有者和当前参与者构造0x6060，带相同金额及不同标志位。
// 这里只证明消息构造和输入数值；实际账本修改由消费者与服务器协议共同确认。
// 若状态1加倍分支触发，还生成0x6000效果号37，数据中双方标志置1、数值置200。
// 最后0x693220检查 P+1504+P+1508 > 实际金额；相等会返回false。
// 因而资金耗尽路径会阻止stage6自动追加；应追破产/结算流程，不能补一条换人包了事。
//
// 类型3/4与本人类型2的等待边界
// ----------------------------------------------------------------------------
// kind3 -> 0x7CA1D1构造0x6087；handler0x681A50打开UI15，等待状态11、时长1000。
// kind4 -> 0x7CA212构造0x6088；handler0x681AF0打开UI16，等待状态12、时长1000。
// 两个主分支均立即false，暂不猜UI的具体业务名称。
// 本人kind2 -> 构造0x6086；handler0x6819E0本机槽开UI14，登记状态10。
// 主函数还以 *a3+G[20945] 登记同状态10；应保留累计时序，不把两次登记简单删除。
//
