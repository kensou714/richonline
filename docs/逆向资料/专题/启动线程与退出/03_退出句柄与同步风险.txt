// 全局临界区 C=0xA767D0（32位RTL_CRITICAL_SECTION，24字节）
// ----------------------------------------------------------------------------
// 0x6BFAB0 返回C；0x6BFA00 EnterCriticalSection(this)；0x6BFA40 Leave(this)。
// CRT初始化片段 A1DCC3 把C放ECX，经60409B->62F0D0调用InitializeCriticalSection；
// 同时atexit注册A1FEB0，经611C73->62F120调用DeleteCriticalSection。
// WinMain在基础线程尾标志A86720成立后，每轮消息泵前进入C。
// WndProc总在入口进入C、各正常返回前退出C，因此主线程Dispatch时可递归持锁。
// 临界区允许同线程递归，不应把这个正常嵌套直接报告成死锁。
// 退出资源总清理前，WinMain先离开帧持锁，再单独重新进入C保护0x624080，随后退出。

// 具体候选：logo门控与锁释放条件不对称
// ----------------------------------------------------------------------------
// 0x7A3EEE..7A3F00：只要A86720!=0就Enter C。
// 0x7A3F89..7A3F9D：必须A86720!=0且A86800!=0才走正式帧/Leave路径。
// 窗口一：A86720已置1但2500ms门控尚未打开，会Enter C后走logo；WinMain直接
// 控制流未见与帧首匹配的Leave。若间接调用不补偿，下轮可继续递归Enter，
// 可能累积计数而阻塞其他取C的线程；不能只凭直接CFG就声称已实测锁泄留。
// 窗口二：7A3EEE首次读A86720=0而跳过Enter；基础线程在消息泵期间写1，
// 若A86800已为1或本轮打开，7A3F89第二次读到1，便进入正式帧并执行
// 7A4000（正常帧）或7A3FAE/7A3FD9（退出）的Leave，当前轮没有配对Enter。
// 两次读取是跨线程普通字节读，既有上一轮递归计数会改变窗口二的实际效果。
// WndProc自身Enter/Leave正常配对，不能直接抵销帧首Enter。
// 下游也有Leave包装调用：UI路径和解压路径使用各自锁，不可看到同名包装
// 就算作全局C的补偿；完整虚调用/间接调用链尚未穷尽，动态计数仍未实测。
// 复现应逐轮记录两次标志读取、门控值、线程ID、C的Owner/RecursionCount及
// 各Leave接收的ECX，而不是只用“基础加载<2500ms”一个时间条件判断。
// 尚未实机观察，不能把所有加载/界面卡住都归因于这里。

// 总退出次序：WinMain 0x7A4104 起
// ----------------------------------------------------------------------------
// Enter C -> 0x624080业务资源清理 -> Leave C -> 0x7A3160销毁辅助对话框 ->
// 0x7A3620注销MAIN_WND_CLASS/ReleaseMutex -> 0x7A3670 ExitProcess。
// 0x7A3670调用GetCurrentProcess/GetExitCodeProcess，把取得值直接传ExitProcess；
// 未将WM_QUIT.wParam作为实际退出码；该函数声明noreturn，后面的WinMain返回通常不可达。
// 0x7A3620只有ReleaseMutex，没有CloseHandle该互斥体；进程退出最终回收句柄。
// 不把“进程退出前尚未CloseHandle”直接等同长期运行的资源增长。

// 0x624080资源总清理的可定位顺序
// ----------------------------------------------------------------------------
// 首先在特定配置条件下ShellExecute配置里的退出地址；本轮只读未触发它。
// 然后逐个全局单例清理/置零，先A76744、A7671C、A76740、A7673C等，
// 中途0x60100D -> 0x6BE1C0终止辅助线程并清回调指针。
// 游戏/数据对象依次释放后，处理角色对象A766D0、文字对象A766CC，
// UI管理器A766C8，再音频高层A766C4，再其他资源与配置A766B4，最后收底层。
// 音频高层：6032C7->629840->603574->69A2F0，停止音频、保存Voice.dat并释放数组。
// 因而退出音频前已释放角色管理器，但Voice写回只用H中缓存行数/数组，不再次取角色表。
// 全量的每个全局地址/具体删除入口均保留原证；尚未确认类名的对象不瞎命名。

// 启动/辅助线程句柄及关闭者
// ----------------------------------------------------------------------------
// 创建点        入口实现   保存位置                  已查关闭/状态读取
// 7A403E        7A2970     全局A86724                 未见本群Close/Join；只判零创建。
// 6253D8        623EE0     全局A766A0                 625310查退出码0/1后Close并清0。
// 6BE152        6BF2C0     管理对象+8                 6BE1C0 Terminate/Close/清0。
// 65BD13        682660     游戏对象+20                6826A0码0后Close并通知。
// 728F06        729D90     UI对象+108                 729500码0后Close；728B30强停清理。
// 72A4C9        72BAB0     UI对象+488                 729F80强停关闭；72A870也轮询。
// 72A541        72B9E0     UI对象+484                 72A870轮询关闭后可建72BAB0。
// 72ACD0        72BAB0     同UI对象+488               第二阶段替换线程。
// 731881        731A90     UI对象+96                  730A30强停关闭。
// 7318C1        732490     同UI对象+100               730A30强停关闭。
// 81F095        81F1A0     父函数局部hThread          81EFB0强停关闭。
// 81F0BB        81F360     父函数局部hObject          81EFB0强停关闭。
// 这是本客户端业务区CreateThread直接引用列表；不声称覆盖Miles/CRT/MFC内部线程。
// 创建均为flags=0的立即可运行线程，没有CREATE_SUSPENDED后的统一挂接阶段。

// 不应记录成活跃周期任务的死代码：0x6BF2C0
// ----------------------------------------------------------------------------
// 6BF2DC xor eax,eax；6BF2DE jz 6BF343；6BF343 xor eax,eax 后返回。
// 因此中间事件101轮询与Sleep(20)整个循环在当前基线永远不可达。
// 这个函数仍被CreateThread创建，句柄仍存+8；“创建过”不等于持续后台运行。
// 现有磁盘与本函数指令相等，所以本结论不依赖旧数据库对新代码的猜测。

// 其他线程只恢复生命周期相关边界
// ----------------------------------------------------------------------------
// 72B9E0/72BAB0：每轮Sleep1，每>=1800ms分别查询一个连接条件，最多4次失败。
// 成功返回1；累计第四次失败返回0。不能把7.2秒近似等待称严格网络超时协议。
// 729D90：复制36字节记录数组到私有缓存，构造探测对象，完成后持局部锁拷回。
// 81EFB0：WSAStartup/RAW socket后建发送和接收线程，按参数Sleep后Terminate两者；
// 发送入口81F1A0每轮Sleep10；接收入口81F360有时间窗口与recvfrom。
// 这些是连通性探测链，不是游戏主TCP收包线程，不能混算协议吞吐或心跳频率。
// 731A90：读取公告URL与<title>RnNews文本，最终从该后台线程调用控件虚函数。
// 732490：按参数里的两个CRITICAL_SECTION指针依序进入、调用UI73、逆序离开；
// 731850传入的指针分别是UI对象+104和+128，不能当作全局C。
// 从反编译省略的this参数恢复锁归属时必须看ECX；7324B0/7324BD已核对。

// 同步与退出的后续复现点
// ----------------------------------------------------------------------------
// 1. 主状态5线程CreateThread失败：已设置started字节，没有自动重试，可能常驻加载UI。
// 2. GameInit失败仍置完成标志：后面可能继续读取未初始化单例，需特定缺资源样本。
// 3. TerminateThread不等于协作退出：若线程正持局部锁/分配资源，所有权可能被截断。
//    当前只能列出实际强停地点，未证明每个地点都会死锁或泄漏。
// 4. 公告线程后台控件调用与UI析构竞争：需要记录线程ID/控件生命周期再决定修补。
// 5. 字节完成标志用普通读写，未见该入口通过事件/等待API移交；本专题未证明
//    整个程序所有资源依赖都被全局C保护，不能把C当万能线程安全证明。
