// 入口链与启动条件
// ----------------------------------------------------------------------------
// PE 入口 0x606918 为 CRT start 跳板；业务 WinMain 是 0x7A3D90。
// 本篇未逆向 CRT 初始化全部模板，避免把运行库导出计成游戏语义成果。
// WinMain 先检查命令行非空，空则返回0；再读取 Tex/ToolConfig.kpd 的 pack。
// 0x7A3BB0 对 pack 接受 true/TRUE；当该标志成立且命令行不以 run_ 开头，
// ShellExecute RichTool.exe 后返回；以 run_ 开头则将后缀交 0x622E20。
// pack 不成立则把完整命令行交同解析器；本篇不猜测解析字段或联网凭据格式。
// 0x7A3270 注册 MAIN_WND_CLASS，WndProc 为 0x603BC3 -> 0x7A29E0。
// 原始目标客户区 814×637；生成 RichOnline 主窗口，随后 0x7A3120 建资源128对话框。
// 当 Config/Rn_Multi_Client.exe 不存在，以命名互斥体 RnClient 判断重复实例；
// 本篇只说明已有代码行为，不创建该文件或变更多开策略。

// 初始化阶段一：主线程同步，0x623B60
// ----------------------------------------------------------------------------
// 保存 HWND 到 0xA76500、HINSTANCE 到 0xA76588；调用 0x623AD0 建输入/字符基础。
// 读取 Config/ 配置，创建设备，读取 Role.kpd、LogFixStr.kpd、初始化音频并设音量。
// 设备调用链：0x60E11D -> 0x698D10 -> 图像专题的设备创建入口。
// 因此设备创建归属 WinMain 当前线程，而不是后面的基础资源线程。
// 设备失败弹 D3DDevice Init Failed，角色表失败返回0；WinMain 不进入主循环。
// 音频高层失败仍可能返回1，详见音频专题，不能用本阶段返回值替代各设备状态。

// 初始化阶段二：基础资源线程，0x7A2970
// ----------------------------------------------------------------------------
// 主循环末端若全局 HANDLE 0xA86724==0，CreateThread(0x603F79, NULL)。
// 入口跳板 -> 0x7A2970：先 Sleep(100)，再 0x623CB0(HWND)。
// 加载链包括 Anim、RichStr、Prop、VehPet、ASTable、Avatar、BossWar、KoBuild、
// Interface，以及 TeachBoard、Rank、StockName/StockRace 等。
// 其中UI/贴图管理器从此后台入口初始化；不要因为WinMain建了窗口就断言后续
// 所有资源创建也发生在主线程。具体D3D内部调用见图像专题。
// 加载返回0时弹 GameInit Failed!，随后仍把 BYTE 0xA86720=1，并返回1。
// 因此 A86720 表示线程到达尾部，不是全部基础资源加载成功证明。
// A86724 当前引用仅主循环判零/写句柄；本群未见查询完成码或 CloseHandle。
// 线程创建失败保留0，下一帧会再次尝试；已经退出的非空句柄不触发重试。

// Logo 与正式帧的两条件门控
// ----------------------------------------------------------------------------
// BYTE A86720：基础线程尾部写1；BYTE A86800：主循环累计时间超过2500ms写1。
// 三处A86720/A86800/A86724在.data零填充区，映像加载器初值分别0/0/0。
// .data RVA=0x666000，原始数据长0x11000，虚拟长0x6C3F8；相对节偏移分别
// 0x20720/0x20800/0x20724，均超过原始数据范围且位于虚拟范围。
// 原证IDA globals中的FF/FFFFFFFF并非可用初值，不能推导为标志初始开启。
// 完整节头、地址映射见startup_globals_pe_zero_fill.json；加载器初值与CRT
// 执行后的实际值需区分，本群仅列出已发现的写者，未实测全启动过程。
// 计时由第一次走logo分支的 timeGetTime 起算；严格 >2500，指令7A3F7B/7A3F80。
// 同时满足两标志才调用正式帧 0x624CA0，否则调用logo绘制 0x624C00。
// 初始化快也会继续logo；初始化慢则超过2500后仍等待尾部标志。
// 消息泵一直在工作，但正式帧里的退出检测与状态调度受两条件限制。
// 初始化线程异常未写标志时，即使计时已满也无法只靠计时进入正式帧。

// 初始化阶段三：主状态5的数据线程，0x625310
// ----------------------------------------------------------------------------
// 全局主状态 A6723C 磁盘初值5；正式帧表第5项进入 0x625310。
// 第一次进入保存 A769BC=GetTickCount；A769C0 bit0防止重复初始化时间。
// 当 BYTE A769B8==0 且经过时间严格>1000ms：先A769B8=1，再CreateThread。
// HANDLE保存 A766A0，入口0x6030BF(StartAddress) -> 0x623EE0。
// 此线程读 Npc、Feast、Build、Level、Stock、Pawn、MapView、PlusPrize、
// TeachMode、Filter/FilterN、FaceCtrl；任何已检查加载失败返回0，成功返回1。
// 主帧同时执行UI更新，随后GetExitCodeThread轮询。
// 汇编625434..62543E：仅 exit_code==1 或 ==0 才收尾；其他值继续等待。
// 不沿用Hex-Rays的“<=1”去解释有符号负值；API返回DWORD，精确比较为准。
// 收尾先CloseHandle/置0；0弹 InitData Failed! 并返回0触发总退出；
// 1将主状态设0，关闭加载窗口，再进入账号/连接相关界面路径。
// 创建失败后 A769B8 已置1、HANDLE为空，没有当前入口自动重试；可留在加载UI。
// GetExitCodeThread 本身的BOOL成功值未检查，失败也可能一直等待。

// 消息泵：PeekMessage，不是GetMessage阻塞循环
// ----------------------------------------------------------------------------
// 每轮PeekMessageA(NULL,0,0,PM_REMOVE=1)直到无消息。
// 消息0x12(WM_QUIT)只将本轮局部quit=1并停止取消息；其他消息Translate/Dispatch。
// 两初始化标志都成立后，quit=1、退出标志A76691!=0、或0x624CA0返回0，
// 任一条件都会离开主循环，执行退出资源链。
// Logo阶段收到WM_QUIT只保存在本轮局部变量；下一轮重新清0，未观察到持久退出位。
// 这是启动中退出处理需要复现的候选，不是说正常完成后WM_QUIT无效。
// WndProc的WM_DESTROY发PostQuitMessage；WM_CLOSE在主状态0或6才允许确认框，
// 状态5仅MessageBeep，其余状态显示文案114；确认后0x796BE0写A76691=1。

// 主循环节流：阶梯预算，不是固定60FPS
// ----------------------------------------------------------------------------
// 每轮用GetTickCount测经过时间 e；在创建基础线程之后计算Sleep。
// e < 15：max(15-e,2)；15<=e<20：max(20-e,2)；
// 20<=e<25：max(25-e,2)；25<=e<30：max(30-e,2)；e>=30：2。
// 理想低负载周期15ms附近；边界14/19/24/29ms还会加至少2ms。
// Sleep调度粒度、消息数量、绘制耗时会改变实际帧率，静态公式不证明固定FPS。
// 不把另一个死分支中的Sleep(20)误当运行中游戏循环，见03。

// 正式帧职责边界，0x624CA0
// ----------------------------------------------------------------------------
// 先做本地通知/输入坐标/绘制准备，按主状态函数表调用当前状态更新。
// 状态返回0立即把失败传给WinMain；否则继续绘制、音频轮询、截图检查和其他更新。
// 音频轮询在此处：0x609B95取得高层对象 -> 0x608C2C -> 0x69A4E0。
// 截图检查0x626050读取PrintScreen；详细输入/图像行为归相应专题。
