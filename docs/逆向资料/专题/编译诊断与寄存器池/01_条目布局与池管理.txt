// 寄存器条目 / 96字节记录与索引池

// 9CAD79入口ECX是池对象；分配0x60字节，9CB6FC仅返回this，9CB700填写字段。
// Hex-Rays显示stdcall并遗漏ECX池参数；须以9CAD7D保存ECX、9CADC9恢复ECX为准。
// 初始化失败负值路径删除条目并返回-1；当前9CB700实际无失败分支，恒返回0。
// 成功调用9CAA68登记条目，返回池索引；分配/登记失败用-1作哨兵。
// 9CA930为条目删除包装：先空析构跳板，标志bit0为1时operator delete(this)。
// 9CA953是另一个对象的删除包装，未强行合并为本条目的析构。
//
// 条目已观察布局 / 名称为工作解释，非恢复的原源码类型
// ----------------------------------------------------------------------------
// +00 DWORD 类型/描述表索引（9CAA68用它索引池+10指针表）。
// +04 DWORD 初值-1；9CAA68要求它为-1才做常数属性分类。
// +08 DWORD 初始化参数2；+0C DWORD初始化参数3；真实业务名尚未恢复。
// +10 double初始化数值；+18 DWORD属性位初值0。
// +1C..+3C：9个DWORD全部初值-1；995011使用+1C关联参数索引、+20来源条目、+2C操作记录。
// +40 DWORD引用/使用计数初值0；995011对输入条目执行inc [entry+40]。
// +44/+48 DWORD关联上下文初值0；995011继承旧结果条目这两个字段。
// +4C DWORD初值0；+50 DWORD初值-1；+54 DWORD初值0；+58 DWORD初值-1。
// +5C..+5F未被9CB700写入；不能把96字节整个记录称为完全初始化或全零。
// +08/+0C及其余哨兵字段的精确枚举和后续写入仍需按读写交叉引用追踪。
//
// 池对象局部布局 / 不等于整个对象
// ----------------------------------------------------------------------------
// +08 uint32已登记数量；+10 ptr类型/描述指针表；+14 ptr条目指针数组；+20 uint32容量。
// 9CAA68仅在count==capacity时扩容：容量0变1024，否则机器DWORD容量翻倍。
// 分配4*新容量字节，复制4*count字节，剩余指针槽清零，删除旧数组后更新+14/+20。
// 分配失败先删除传入非空条目，再返回-1，调用者不能重用该条目指针。
// 最后array[count]=entry、count++，返回旧count；传入空条目也允许登记为一空槽。
// 9CAF88使用无符号JNB判断index>=count返回0；合法索引取array[index]。
// -1作为uint32索引被拒绝；范围内空槽同样返回0，不能区分两种原因。
// 未见局部容量翻倍/乘4溢出检查；此处不证明真实编译输入可令池达到异常尺寸。
//
// 属性分类 / 仅有限、可转int32样例作直观解释
// ----------------------------------------------------------------------------
// 条目非空、类型描述+4的bit7置位、条目+4==-1时，先给属性+18加0x20。
// bit01：数值等于0或1；bit02：与转int32值差的绝对值小于磁盘double 1e-6。
// bit04：非负；bit08：非正；bit10：绝对值<=1；各标志按OR累积。
// 指令通过x87状态字测试，并调用原CRT __ftol；NaN/无穷/越界转换不套用Python语义。
// 磁盘常量A3FF08=1e-6、A2B480=0、A226E0=1已另存原字节。
//
// 993EC8哨兵填充 / 不是带长度验证的memset包装
// ----------------------------------------------------------------------------
// 汇编从参数2载ECX，test后JBE只在零值跳过；非零时EAX=FFFFFFFF、rep stosd。
// 它逐DWORD写-1，次数是原uint32计数；返回0、retn8。
// 伪码memset(...,4*a2)只是效果表达；真实指令没有先计算4*a2后传给memset。
// 空指针、缓冲容量和负数误传均未在入口校验；0次填充不访问指针。
