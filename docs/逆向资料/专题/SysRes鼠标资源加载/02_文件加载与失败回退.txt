// 6BAB70完整声明块403字节、121指令；以下流程以调用按ABI正常返回为条件。
// 先完成数量查询，再写BYTE[M+0]=1、BYTE[M+1]=0；失败分支也不会撤销这两次写入。
//
// 文件路径与格式化
// ----------------------------------------------------------------------------
// @6BABD8压A23BCC原字符串SysRes\04_%02d.ms；@6BABDD目标是EBP-94h。
// @6BABE4经60361E调用9206D0旧sprintf入口，caller清三个DWORD，未检查其返回值。
// 该入口没有传容量参数；RTC帧描述符6BAD03记1变量，变量记录6BAD0B给offset=-148、size=128。
// 变量名6BAD17严格NUL串为szTmp，因此EBP-94h缓冲区的RTC声明容量是128字节。
// 到下一DWORD局部EBP-10h相距132字节不等于数组容量；不能沿用伪码name[132]。
// 在已证i=0..99范围，结果SysRes\04_00.ms至SysRes\04_99.ms长度15字节，加NUL为16。
// %02d是最小宽度，不是截断宽度；修改数量算法或文件模式时应重新核长度和表上界。
// 路径为相对路径，基于进程当前工作目录；本体没有拼接EXE目录或做路径存在预检。
//
// 每槽加载链 / 调用参数按源机器码记录
// ----------------------------------------------------------------------------
// @6BABFF：LoadImageA(hInst=0, name=路径, type=2, cx=0, cy=0, fuLoad=10h)。
// Windows常量2为IMAGE_CURSOR，10h为LR_LOADFROMFILE；flags中没有LR_SHARED或LR_DEFAULTSIZE。
// 结果直接存M+0C+4*i；非零进入下一槽，NULL才执行下一步。
// @6BAC2C：LoadCursorA(hInstance=0, lpCursorName=7F00h)，即系统IDC_ARROW资源编号。
// 该返回覆盖同槽；非零继续下一槽，NULL再进入失败提示。没有第二个文件名回退。
// @6BAC5B经60C179→629ED0读DWORD[A76500]作为HWND，不创建窗口或验证该句柄。
// @6BAC61：MessageBoxA(HWND, A23BE0的Init Cursor Failed!, caption=0, uType=0)。
// 提示返回值未参与决策，@6BAC6E置EAX=0并走公共尾部；不再加载后续槽。
// 文件缺失不必然使整个初始化失败：系统箭头非零时流程继续，表中可能多个槽别名同一箭头。
// 两次API都NULL才到本体显式失败返回；API异常、错误诊断或无效指针不属于统一0返回契约。
//
// 成功与失败的状态边界
// ----------------------------------------------------------------------------
// 任一槽失败时，前面已加载的槽保持原写入，失败槽为0，后面的槽保持进入前表值。
// 本体没有局部回滚、已加载句柄清理或恢复输入BYTE；启动失败后的全局清理不能由本体推定。
// 结束循环后缓存及SetCursor见03；不核SetCursor返回成功，随后直接置EAX=1。
// 因而n=0也会产生本体成功值；它不是“已加载至少一只有效光标”的断言。
// 启动窗@623CF2测试结果；零时@623CF6置零并跳623ECE，非零继续后续资源初始化。
// 有限窗口只证局部失败传播，不代表整个623CB0或所有启动退出清理路径已审。
// 再次调用没有先释放原表；覆盖、遗留旧槽和中途失败的实际可达性仍须上层生命周期证明。
//
// 导入与运行库证据等级
// ----------------------------------------------------------------------------
// 当前PE导入表确认AD3F38/3F3C/3F88/3F8C分别对应四USER32接口，详resource_audit.json。
// IAT磁盘DWORD是PE导入名字导航，不是运行时函数地址；本批不采IDB解析后的IAT值作相等证据。
// 91F6D0在前置CMP相等时直接RET并保留EAX；异常诊断被调用时的用户交互不在本批闭合。
// RTC栈变量检查前压EAX、后弹EAX；cookie相等时91FBB0的CMP/JNZ/RET不改变EAX。
// cookie不等、保护诊断失败或栈损坏不承诺仍按0/1正常返回，也不扩为运行库全语义分析。
