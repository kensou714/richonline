// 鼠标对象M的已知分配大小1ACh；构造仅清+0C起190h，恰好100个DWORD句柄槽。
// 初始化6BAB70与选择6BAD80写字段不同，不能把两段伪码折叠成同一操作。
//
// 完成加载后的四个DWORD
// ----------------------------------------------------------------------------
// @6BAC7D读槽0即[M+0C]；@6BAC80写[M+19C]，@6BAC92复制该值至[M+1A4]。
// @6BAC9E读槽1即[M+10]；@6BACA1写[M+1A0]，@6BACB3复制该值至[M+1A8]。
// 随后@6BACC5调用SetCursor([M+19C])，即槽0；返回的旧句柄未保存，后面直接EAX=1。
// 两份槽0/槽1快照为已证字段消费，不在本批给+1A4/+1A8命名恢复光标或默认外观。
// n不足2时仍读槽1；在首次构造未被其他写者改变的条件下，n=0两槽均0，n=1槽1为0。
// SetCursor(NULL)的Windows接口含义是移除当前光标；本批未实机观察该分支是否可达。
//
// 旧6BAD80的后续选择契约
// ----------------------------------------------------------------------------
// 接收一个栈索引，读取M+0C+4*index，本体没有索引或NULL有效性检查。
// 若表值等于[M+19C]，直接保留并返回该旧缓存，不调用SetCursor，不更新+1A0。
// 不相等时把选中表值同时写+19C和+1A0，再调用SetCursor；这次没有写+1A4/+1A8。
// 系统调用分支返回API旧光标句柄，不是刚选的新句柄；相等分支返回缓存，两者需区分。
// 初始化成功后+1A0可仍是槽1，而+19C是槽0；第一次“选择槽0”相等路径不会统一它们。
// 此差异按字节记录，不把它命名为BUG，也不推所有消费者要求两个字段始终相同。
//
// 旧释放路径与句柄来源配对
// ----------------------------------------------------------------------------
// 6BAB00固定遍历i=0..99；对非零[M+0C+4*i]调用GDI32!DeleteObject，忽略返回BOOL。
// 本体未调用DestroyCursor，未清表，也不对同一非零句柄去重。
// +19C/+1A0/+1A4/+1A8均未独立释放；它们只保留表项值，不能视作四份额外拥有的资源。
// 629890先调用6BAB00，再按flags bit0决定operator delete，返回旧this地址，ret4。
// 已冻结退出局部624A14压1，624A1C经60DEF7调用包装，624A33清A766C0；本批不扩全退出。
// Windows接口契约下，文件LoadImageA未设LR_SHARED所获光标应按非共享cursor所有权处理；
// 系统LoadCursorA返回共享光标，不由应用销毁；两者可能混存在同一表中。
// 现有退出一律用DeleteObject，和cursor专用释放规则不一致，应列为后续修补审计点。
// 本批未运行DeleteObject、未测句柄表或泄漏，不宣称已复现泄漏、重复销毁或系统资源破坏。
// 将来修补应先记录每槽来源/共享性、重载和别名关系，再决定释放；不能批量替换成DestroyCursor。
//
