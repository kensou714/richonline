// SysRes鼠标资源加载 / 当前资源样本与二次开发约束
// ============================================================================
// audit_resources.py只读SysRes/04_*.ms并逐文件保存SHA、编号、目录和DIB字段。
// 当前39个文件：04_00.ms至04_38.ms连续；这是本工作区静态快照，不代表运行配置必为39。
// 审计未调用Windows LoadImage，不生成或覆盖任何光标，也未检验外观与实际系统接受度。
//
// 实际文件结构 / 全39文件一致的部分
// ----------------------------------------------------------------------------
// 文件头reserved=0、type=2、count=1：均为单图CUR目录结构，尽管文件扩展名为.ms。
// 每文件2238字节；6字节目录头和16字节目录项，图像数据从offset22起，占2216字节。
// 目录宽高32×32、热点x=1/y=1，保留BYTE=0；热点位于图像范围内。
// 图像为40字节BITMAPINFOHEADER，宽32、高64、planes=1、bitCount=8、compression=0。
// DIB高64包含32行XOR图像和32行AND掩码，不是64像素高的最终光标。
// 数据分解：40字节DIB头 + 256项×4字节调色板 + 1024字节XOR + 128字节AND = 2216。
// 审计逐项验证目录范围、图像长度和末尾边界，没有尾随未解析字节；不据此保证每个像素正确。
// resource_audit.json按文件保存热点、位深、大小、SHA及22字节头；内容变化可重跑精确对照。
//
// 添加或替换时应保留的接口约束
// ----------------------------------------------------------------------------
// 最小替换可先保持既有CUR结构、32×32/8位/热点规则和文件编号，再通过客户端实机验收外观。
// 格式已由文件头与加载type共同支持；不要仅改扩展名就把普通BMP/PNG当可接受光标。
// 相对目录必须随进程工作目录可见；当前加载无绝对路径解析或按资源包查找的本体逻辑。
// 添加04_39.ms不自动增加n；n来自配置根100项的非FFFFFFFF统计，须先闭其记录生产者。
// 稀疏有效项只影响数量，loader始终取00到n-1；不能只把文件名改成原配置记录槽号。
// 100是当前表和计数上界；只改循环上界会触碰+19C缓存等邻接字段，需一并修改布局与消费者。
// 文件坏或缺失时可能静默回退系统箭头；仅见游戏启动成功不能证明自定义资源已生效。
// 将来工具可把每槽“文件成功/系统回退/失败”独立呈现，避免只显示总返回1。
//
// 未闭项目
// ----------------------------------------------------------------------------
// 配置文件到C+3AC00记录的生产、记录12字节全布局、39文件与游戏功能名称尚未闭合。
// 没有把编号0/1/3/18/38自动命名为箭头、攻击或建造；名称需与实际调用点和美术外观对应。
// 未实验其他位深、尺寸、多图CUR、ANI或PNG内嵌能否被本程序/当前Windows接受。
// 未执行失败加载、二次加载、主题切换、退出句柄回收；静态资源结构不是实机兼容认证。
