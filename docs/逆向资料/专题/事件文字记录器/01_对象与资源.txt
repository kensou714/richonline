// 格式器：627380 从 A766AC 取得单例；首次分配 0x114（276）字节，
//   调 7DCBE0。构造仅明确清 +260 表指针和 +272 loaded，不清整对象。
//   +0       sprintf 的目标起点；至首个已知成员 +260 之间有 260 字节。
//   +260     DWORD，固定文本表指针。
//   +264     DWORD，单槽字节步长；当前资源写 64。
//   +268     DWORD，分配槽数；当前资源写 256。
//   +272     DWORD，装载完成标志；7DCFE0 在此为 0 时立即返回。
//   尚无源码声明证明前缀数组的精确 C 类型；不要把首成员间距当作已证明
//   的安全容量。7DE2D0 只返回 table+index*stride，不检查 index 或 loaded。
//
// 输出器：6271B0 从 ABABC4 取得单例，首次分配 0x2C（44）字节。
//   +0/+4    Game/Sys 的 FILE*。
//   +8       DWORD，提交门限；本版启动传 1024。
//   +12      Game 缓冲对象（16 字节）。
//   +28      Sys 缓冲对象（16 字节）。
//   每个缓冲对象 +0已用字节、+4容量、+8增长块、+12数据指针；初始化
//   81D760 分配门限大小、增长块 512。81D710 构造只清数据指针。
//
// 临时事件记录：RTC 的 xLog/xLogMsg 真实长度为 12 字节。
//   +0 DWORD 事件号；+4/+8 是事件专用 DWORD，按事件分别作指针或整数。
//   64F1A0 只写 +0，不清剩余字段；64F1D0 和 6B8420 等写入器只写 +4。
//   0/1 事件无需后两个字段；128 用 +4 字符串；28 用 +4 字符串、+8整数。
//   不按伪码中的 v5[20]、v1[4] 判断长度，编译器调试填充不属于结构体。
//
// 资源装载顺序
//   81B4C0 读取首字节 key 和两个 DWORD；其余字节逐字节减 key，再交
//   81B7F0 的 LZO 解压调用。本文件 key=118、压缩长度1774、原长度4908。
//   819250 的 mode=2 把解压内存复制给文本解析器；不依赖资源句柄持续存活。
//   819470 找 [ALL]；819660 找 size/count；8198E0 取行值后 atoi。
//   7DCCC0 分配 stride*count，然后逐节找 [STRING]、indx、win32，写指定槽。
//   全部结束后写 loaded=1，构造事件0并送入格式器，产生“系統 啟動”日志。
//
// 资源语法不能简化成普通INI后任意修剪
//   搜索键会跳过等号后前导空白；复制器保留行尾空格，遇 LF 才终止。
//   高位字节按双字节原样复制；反引号+n（60 6E）会转为一个 LF。
//   资源当前用 LF 行尾；不擅自改 CRLF 或删除尾随空格，许多组合词靠空格分隔。
//   STRING 只有72条而非256条，new未整体清零；未定义槽内容不能作为空字符串使用。
