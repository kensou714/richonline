// 事件文字记录器
//
// 当前客户端这套代码生成本地文本日志。7DCFE0 格式化事件，6271B0 取得
//   输出器，81C190 选择缓冲，9243E0 最终调用 fwrite。该终点是文件输出；
//   649A30/64B880 界面文字函数也会把原文作为事件 128 送入这条日志链。
//
// 资源入口：623B60 -> 627380 -> 7DCCC0，文件 Data/LogFixStr.kpd。
//   当前文件解包 4908 字节，CP950 严格解码并原样回编码成功；声明 256 个
//   64 字节槽，实际提供 72 条 STRING，最长 win32 值连 NUL 为 24 字节。
//   linux 字段保留在资料中，但本 Windows 装载器只读 win32。
//
// 格式器支持 65 个有输出的事件：0..63 写 Sys，128 写 Game。64..127、
//   129..255 和范围外事件均不生成文字。事件号是本地 DWORD 字段，不能
//   因资源内存在 first_x4010 等文字就认作网络消息号。
//
// 输出器 81BEA0 以追加文本模式 at 打开：
//   Log/Game/YYYY-MM-DD/game.txt
//   Log/Sys/YYYY-MM-DD/sys.txt
//   启动调用 623AD0 传门限 1024。一次追加使缓存累计达到门限，或调用者
//   force 字节非 0 时提交 fwrite。否则常驻内存，关闭时由析构补写。
//   “提交 fwrite”不等于调用 fflush，也不证明数据已经同步到磁盘介质。
//
// 阅读次序：01 对象与资源；02 全事件参数字典；03 输出与边界；
//   04 来源与维护；05 逐函数审阅。证据目录保留完整函数块、伪码、汇编、
//   PE对应字节、RTC变量表、格式常量及资源原字节，支持逐项回查。
