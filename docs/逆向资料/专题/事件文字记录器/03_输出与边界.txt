// 格式化和文件写入的真实边界
//
// 7DCFE0 先检查 loaded，再把对象首BYTE清0。0..127先选Sys通道1，switch
//   实际只有0..63；128..255选Game通道0，但只有128生成文字。最终首BYTE
//   非0才调用输出器，因此未支持事件不会把上一次文字重复输出。
//   格式串原证末尾是 0A 00，代表LF和NUL；不是反斜杠+n的两个字节。
//   字符串参数用 %s，整数参数用 %d，资源内容不会再次被当作格式串解释。
//
// 81C190：channel0使用对象+12、FILE*+0；channel1使用对象+28、FILE*+4。
//   strlen结果决定追加字节数，不把NUL追加到缓存。达到门限或force非0时，
//   FILE*非空才执行 fwrite(buffer,used,1,file)，然后无条件把used清0。
//   文件打开失败时仍会丢弃达门限的缓冲；写入返回值不参与重试或状态恢复。
//   当前导出的29处格式器直接调用都传force=0，包括构造/析构事件。
//   日期由81BC30的time/localtime取得；629FC0年+1900、629FF0月+1、62A020日
//   三getter交给%d-%02d-%02d。仅初始化81BEA0建目录，未发现输出时跨日重开。
//
// 81D810 的扩容：不足字节 need=used+incoming-capacity；need>0 时按
//   growth*(need/growth+1)增加容量，复制旧capacity字节，释放旧块，再追加。
//   是容量拷贝而非只拷贝used；growth当前为512，无额外字符串终止字节。
//   81D6E0只清used，不释放内存。81D7C0只释放data并清指针。
//
// 析构与关闭
//   624080释放A766AC -> 629A20 -> 7DCC10，先生成事件1，再释放固定文本表。
//   624080末尾602DF9 -> 623B40 -> 61280D -> 81D9B0，后者释放输出器。
//   81DB00 -> 81BE00：先81C2B0提交两路剩余字节，再fclose，最后释放两缓存。
//   81C2B0自身不清used；已见直接调用只有析构，不能把它当作可反复调用的
//   “写后清空”接口，否则同一缓存可能重复提交。
//
// RTC与复制断言
//   7DCCC0：xLzo20、szTmp128、xStream160、xLog12。
//   81BEA0：szRoot4、szGame5、szSys4、szGameFile9、szSysFile8、szDate16、szName64。
//   这些是RTC表中的真实尺寸；伪码会把保护间隙并入局部数组，不能照抄。
//   7DCFE0 的缓冲位于堆对象内，不受上述局部RTC数组保护；仅有iLogType
//   未初始化使用检查。不能据此宣称格式化有长度限制或越界防护。
//
// 8198E0先复制完整行、写NUL，再判断count+1>bufferSize并调用断言；
//   断言文字“iCount <= iBufSize”，源码路径kwCommon.cpp，行453。
//   此检查发生在写入后，不是提前截断。7DCCC0也未验证索引上下界、整数乘法
//   溢出、重复indx、size/count转换结果。当前资源72项均在界内，不能推及任意资源。
//   7DCFE0用sprintf，不传容量；固定事件在当前资源下最长27字节（不含NUL），
//   动态事件的字符串长度由调用者决定，没有在此函数限制。
//
// 上述是静态行为证据，未构造溢出输入、未调用游戏、未修改资源；运行时文件
//   权限、磁盘写入失败、跨日目录切换和异常退出时落盘行为仍需单独实测。
