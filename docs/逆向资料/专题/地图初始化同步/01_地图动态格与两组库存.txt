// 地图动态格与两组库存 / 四个接收入口
// ============================================================================
// 共用游戏ID检查：607A2F -> 64F710。
// 比较WORD p+2与WORD G+0x14784；不相等时弹出Error GmsvID并跳过本次写入。
// 这不是包长检查。四个入口均先读取p+2，未携带或检验包长。
// 原证：证据/map_sync_entries.json、map_sync_helpers.json、map_sync_flags.json。
//
// 4001 / 批量动态格列表
// ----------------------------------------------------------------------------
// 5FFEFB -> 7EF6D0 -> 60C4FD -> 65BDB0 -> 6076DD -> 7E0F30。
// 65BDB0把ECX改为M=G+0x65C，将p+4传给7E0F30。
// N=DWORD M+0x124。对i=0..N-1读取src+4*i的signed WORD位置。
// 位置等于-1：跳过该条；否则取signed BYTE src+4*i+2调用7E2320。
// src+4*i+3未在这段循环读取；不能填成地产等级、方向或玩家编号。
//
// 数据布局（记录步长4字节）
//   p+0    WORD    内层命令4001（由分派层识别）。
//   p+2    WORD    游戏ID。
//   p+4+4i WORD    signed位置；-1表示跳过。
//   p+6+4i BYTE    signed动态类型；只在位置不是-1时消费。
//   p+7+4i BYTE    此消费者未读，含义未知。
// 建议发送完整4+4*N字节记录块；这来自记录步长，不能说入口验证了该长度。
// N>0时所有位置WORD的读取至少需4*N+2字节；若最后一条有效则至少4*N+3。
// N<=0时循环不读取记录，但共用ID检查仍需要p+2的WORD。
//
// 4002 / 单格替换
// ----------------------------------------------------------------------------
// 605FD6 -> 7EF6F0 -> 600F86 -> 65BE10 -> 7E2320。
// p+4的signed WORD是位置，p+6的signed BYTE是类型；实际消费前缀7字节。
// 7E2320在DWORD M+0x3C指向的数组中定位cell=base+4*位置：
//   cell+0 = 类型参数；cell+1 = -1；cell+2 = -1；cell+3 = 1。
// 最后一个字节经63E8C0(position,1)写入；不擅自将其命名为刷新完成。
// 此入口没有位置/类型范围检查，也没有地产所有权、建筑等级或现金写入。
// 重发会重新清cell+1/2，不是只修改类型的无副作用增量更新。
//
// 4003 / 库存组1全量替换
// ----------------------------------------------------------------------------
// 608B64 -> 7EF710 -> 612600 -> 65BE80 -> 7F7710(src=p+6,null)。
// p+4的signed WORD为参与者槽；P=DWORD[G+0xE00+4*槽]。
// memcpy(P+0x11A,p+6,0x30)。接收入口实际消费前缀54字节。
//
// 4007 / 库存组2全量替换
// ----------------------------------------------------------------------------
// 60431B -> 7EF790 -> 608574 -> 65C140 -> 7F7710(null,src=p+6)。
// 槽读取方式相同；memcpy(P+0x14A,p+6,0x30)，前缀同为54字节。
// 这两个入口没有本地槽号/缓冲区长度防护，没有在复制后追加刷新或确认包。
//
// 库存记录与其他组的区别
// ----------------------------------------------------------------------------
// 组0位于P+0x5F0；组1位于P+0x11A；组2位于P+0x14A。
// 每组8槽，每槽6字节：WORD物品ID、WORD数量、BYTE状态、BYTE未知。
// 7F86A0读ID、7F8710读数量；7F89D0仅对组1/2读signed BYTE状态。
// ID=-1为空槽；不能把全零数据等同空库存，也不能用4003/4007修改组0。
// 状态和未知字节必须一起保留；替换是完整48字节复制，不是逐槽追加。
// 组的业务名称见 ../道具与卡片操作/01_卡片栏与三组库存.txt 的证据边界。
// 原证：证据/map_sync_load_inventory.json；物品操作的完整语义由该专题负责。
