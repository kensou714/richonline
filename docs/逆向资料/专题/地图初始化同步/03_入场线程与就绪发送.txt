// 入场线程与就绪发送 / 区分0001初始化通知与0000资源完成通知
// ============================================================================
// 原证：map_sync_start_thread、start_ready、ready_poll、ready_send、tick、
// send_gate、send_object.json；均位于证据目录且含完整汇编、伪码与字节核验。
// 4000处理65B450复用 ../参与者布局与人数边界/证据/participant_startup.json。
// 本页没有运行复现；“可能卡住”表示静态控制流可达的风险。
//
// 初始化通知和线程创建
// ----------------------------------------------------------------------------
// 65B450先创建参与者和初始状态，再CreateThread(入口60B89B,参数G,flags=0)。
// 创建返回HANDLE存G+0x14；未在此处看到失败重试。
// 之后调用UI动作77；该初始化通知与下述内层WORD 0不是同一条发送路径。
// 65B450另调用81BCB0(20000)设置计时对象的期限与GetTickCount。
// 81BCB0是写期限/起始tick，不是Sleep(20000)，也不是保证20秒内发地图就绪。
// 64F2A0中的同函数参数3000同理，不应写成“加载时强制睡眠3秒”。
//
// 辅助线程预热可见资源
// ----------------------------------------------------------------------------
// 60B89B -> 682660，参数G经63E210转M=G+0x65C，再调用7E83D0。
// 7E83D0按当前视口计算范围，访问背景块、8字节图层及68字节格记录资源。
// 多处60554A获取资源管理器，60C057提交对应资源句柄。
// 三阶段之间/末尾各调用Sleep(500)；这只构成至少约1500ms的主动睡眠，
// 资源调用与调度时间额外叠加，不能当作精确1.5秒加载时长。
// 682660正常结束固定返回0，不在该线程体里构造或发送地图就绪消息。
// 其他被调资源函数的内部等待及异步状态不在本页证明范围内。
//
// 主循环中的完成轮询
// ----------------------------------------------------------------------------
// 624E80 -> 60368C -> 6826A0，ECX=游戏对象G。
// 若G+0x14非0，GetExitCodeThread取退出码；只在退出码等于0时继续：
//   1. CloseHandle；G+0x14=0。
//   2. 在局部缓冲区上调用6035DD -> 694EE0，写入WORD 0。
//   3. 610977 -> 6BF380(buffer,2)，尝试发送这2字节内层消息。
// STILL_ACTIVE=259或其他非0退出码不会进入完成路径。
// 未检查GetExitCodeThread的BOOL返回值；调用失败时不应假定退出码已有效更新。
// 没有线程句柄时直接退出轮询，不会独立检查“地图就绪是否已发出”。
//
// 发送门槛与一次性丢失窗口
// ----------------------------------------------------------------------------
// 6BF380先检查62A0F0返回的全局状态A6723C，必须signed值<12。
// 然后取6281B0返回的单例A76724，经629C20读取其首字节，必须非0。
// 条件成立才以7EEF70混淆内层消息，再828F60(action=9,发送参数)提交。
// 6281B0仅保证按需构建12字节对象，首字节的业务含义不能仅凭此函数命名。
// 6BF380未检查7EEF70返回值；对本次2字节输入，编码容量路径本身足够。
// 进入动作9不等于网络端已成功收到；下游连接/队列语义由通信专题负责。
//
// 关键风险：句柄先清，发送门后查。若状态>=12或首字节为0，6BF380跳过提交，
// 而下一次6826A0已看不到句柄，因此该轮询入口没有自动重试这个WORD 0。
// CreateThread失败返回NULL时也没有进入完成通知路径。
// 这两点支持排查“服务器等0000而客户端停在加载阶段”的假设，但未证明当前
// 用户实测卡住就是这条路径；需同一时段的线程状态、门字节及通信日志验证。
//
// 日志与回归观察点
// ----------------------------------------------------------------------------
// 分别记录收到4000、辅助线程创建结果、退出码、句柄清零、状态门与首字节门。
// 服务器应把初始化通知0001与地图就绪0000分别记录，不用0001替代0000证据。
// 若客户端WORD0未出现，先定位本地完成/发送链；不要任意补发服务器开局消息。
// 同版地图的4001列表N及4003/4007库存快照应有独立记录，不能用“已入场”概括。
