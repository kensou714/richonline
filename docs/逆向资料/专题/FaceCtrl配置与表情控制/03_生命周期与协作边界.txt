// 一、分配与释放
// ----------------------------------------------------------------------------
// 628FB0 首次访问申请 8 字节并构造，失败时全局可保持零；后续访问复用 A7673C。
// 64CE70 的 64CE9B 经 601CD3 到 91F7E0 释放记录数组，64CEA6 清对象 +0。
// 析构没有清对象 +4，不能把已析构对象当作可再次调用的有效空对象。
// 629160 的 629171 调 64CE70；629179 检查 flags 低位，置位时释放对象本体。
// 退出 624080 的局部链：6241CF 检查 A7673C，6241F2 经 604050 调 629160。
// 该调用压入 flags=1，624209 随后把全局清零。退出函数其余系统不在本专题审阅。
//
// 二、复用范围与未知
// ----------------------------------------------------------------------------
// 证据/reused_evidence.json 保存 15 个依赖的原记录与来源 SHA256。
// TeachMode 来源使用 chunks 保存主块和异常尾块，不套用现代 byte_ranges 字段名。
// 6E8F50 老档案只保存主范围，未保存异常尾块；不得据此宣布工厂完整覆盖。
// 64A9F0 只复核两处 FaceCtrl 消费现场，不宣布整个聊天系统完成。
// 623EE0、624080 只复核加载与退出局部，其他启动、线程、界面行为保持未知。
// 6279C0、6E4640、6E6080、6E3B40 只解释 4F 创建和分发合同；其他槽位另行分析。
// 81B4C0、81B7F0、819250、819470、819660、8198E0 的共享语义复用旧专题。
// 本批复核它们在 FaceCtrl 链内的参数和使用限制；不重复计算新增函数覆盖。
// KPD 自身原包、解包及字段偏移已独立复算；未进行游戏画面或音效的实机测试。
//
// 三、二次开发的分层
// ----------------------------------------------------------------------------
// 配置层负责别名字节与 face 编号；文本过滤层负责最终进入匹配器的消息字节。
// FaceCtrl 只做匹配并提交 4F 参数，不删改输入文本、不处理房间网络协议。
// 4F 界面实例负责接受选中 face；后续动画资源的编号合同不能从别名文件单独推出。
// 新增别名应先保持已有 face 编号与资源合同；新增表情需要继续核对实际下游。
// 将解析校验放进独立工具比默默依赖客户端的事后断言更适合协作维护。
// 修改客户端时应另立补丁记录，保存基线哈希、原字节、改后字节和回退方案。
// 本批不添加补丁，不改资源、不改 IDB，仅输出证据与可追踪的静态分析资料。
//
// 四、证据入口

// lifecycle_raw.json：629160 与 64CE70；consumer_constructor_raw.json：6FC000。
