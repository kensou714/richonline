// FaceCtrl 对象布局与配置加载
// ============================================================================
// 基线：当前 Richonline/RnClient.exe，SHA256：
// a23410e79637e312c932f861176d8d81cd1fd5d222a286f279feccdece6263c2
// 本文结论来自保存的指令、声明块原字节和当前资源；没有运行游戏验证画面。
//
// 一、对象与记录
// ----------------------------------------------------------------------------
// 628FB0 使用全局 A7673C 保存单例，628FE9 申请 8 字节，629006 调用构造。
// 64CE50 只在 64CE61 把对象 +0 清零；没有对对象 +4 的明确初始化。
// 对象 +0：动态记录区指针。对象 +4：有符号记录数量，加载时才明确写零。
// 64CEC0 的 64CFC2 按 count * 108h 申请记录区，64CFE0 保存指针。
// 每条记录 108h / 264 字节：+0 是 face 整数，+4 是已读控制词数量。
// +8 起每个控制词占 8 字节。由记录步长可容纳 32 个槽，这是布局容量推断。
// 注意：加载循环没有 i < 32 判断，不能把布局容量当成程序实际限制。
//
// 二、加载顺序
// ----------------------------------------------------------------------------
// 启动 623EE0：62403E 压入 Data\\FaceCtrl.kpd，62404A 经 60D655 调 64CEC0。
// 62404F 检查返回值；加载返回零进入启动失败分支。仅这一局部现场已复核。
// 64CF14 经 60FD9C 调 81B4C0：读取二进制 KPD；返回零则加载返回零。
// 这条失败路径没有重置对象 +0 / +4，不能把失败理解成有效的空集合。
// 64CF44 调 81B7F0 解压；64CF7B 调 819250 以 mode=2、flag=0 准备解析器。
// 两者返回值都没有被本加载器检查，文件打开成功不等于内容有效。
// 64CF83 清零 count；64CF95 用 819470 逐个寻找精确大小写的 ITEM 节并计数。
// 有符号 count > 0 时才分配；64CFEC 重置解析位置后第二遍枚举 ITEM。
// 每个 ITEM 先查 face，再以容量 128 复制到临时串，atoi 后写记录 +0。
// 查 face 的返回值没有检查：缺失键不能被解释成明确的默认 face=0。
// ctrl 从零开始：sprintf("ctrl%d", i)，查键失败立即结束该 ITEM 的控制词循环。
// 64D092 传容量 8，64D0A7 计算记录 +8+i*8，64D0B2 调 8198E0 复制值。
// 64D0CA 写记录 +4=i。ctrl0、ctrl1 连续存在才会读取 ctrl2，键缺口截断后续。
// 没有 ITEM 的已打开文件也能返回 1；重载正数量会覆盖旧指针而没有先释放。
// 本次只定位到启动调用，重载泄漏属于再次调用时的条件风险，不是已发生事件。
//
// 三、容量不是复制保护
// ----------------------------------------------------------------------------
// 8198E0 从解析器 +90h 指向的值开始复制，遇原始 LF 结束，再追加 NUL。
// 高位字节 >=80h 按两字节搬运；反引号后跟 n 会写入 LF，继续扫描源串。
// 81997C 增加包含终止符的计数，819988 已写 NUL；8199F4 才比较 count 与容量。
// 8199F7 jle 通过；超长走 819A08 的断言。因此容量 8 是事后检查，不是截断。
// 常规单字节控制词最多 7 字节再加 NUL；高位字节须符合复制器双字节约定。
// ctrl32 会写进下一条记录开头，末条则越过分配区；超长别名也可先越界后断言。
// 畸形无换行值、截断的高位字节、缺失 face、数量乘法溢出均无本地完整防护。
// 81B4C0 未逐项检查 fread 返回长度；64CEC0 也没有分配失败与乘法溢出保护。
// 这些是静态合同缺口，当前原包并没有触发该问题的证据。
//
// 四、原包事实
// ----------------------------------------------------------------------------
// Data/FaceCtrl.kpd：392 字节，首字节密钥 78；余下 391 字节逐字节减密钥。
// 解码后的前 8 字节为小端解压长度 714 和压缩长度 383，其后为 LZO 数据。
// 原包 SHA256：a5b19d206d68aad9681e08c10036e7c60fc435ab8b335da0b511e1241ee02bd4
// 明文 SHA256：3761f6a37568d7fd48f24556a3b54d123e0b4edaa5d0da104438984a4f874cd3
// 明文有 9 个 ITEM、54 个键值；face=1..9，每节 ctrl0..ctrl4 连续存在。
// ITEM 行偏移：21、98、174、253、332、410、487、563、639；偏移均相对明文。
// 当前 45 个控制词的字节长度为 2..5，常规 NUL 需求后仍落在 8 字节槽内。
// 各节 ctrl4：sad、cry、angry、smile、laugh、sleep、faint、shock、hit。
// 例如 face1 的 ctrl1 为 :(，ctrl3 为 ng；face4 的 ctrl1 为 :)，ctrl3 为 wx。
// 高位控制词已保存原字节与 CP950 / GB18030 候选往返，不宣布客户端运行编码。
// 能按某编码往返只证明可表示，不能证明原作者意图、字体编码或服务器文本编码。
