// ============================================================================
// 本专题只做静态审阅和局部字节核验；下列场景尚未在游戏窗口中执行。
// 测试应在副本和调试环境完成，并记录版本、输入、调用路径与实际结果。
//
// 已知边界：索引与容量
//   8F4050 取文本只判 index<capacity，不按 count 检查，也不判非负。
//       汇编 8F405A cmp、8F405C jge；之后按 index*160 访问 R+8。
//   8F42D0、8F39D0、8F4690、8F4C20 同样缺少负索引防护。
//       删除虽检查 count 上界，仍会接受负索引。
//   8F3FD0 是不同情况：8F4014 jge 后还有 8F4016 test、8F4018 jl，
//       明确排除负数，不能把所有列表接口概括成相同边界。
//   count==capacity 时在中间插入可能向 table[count] 写入一槽。
//       index==capacity 的追加走滚动路径；两种路径不能合并叙述。
//   MaxRow<=0 与 160*MaxRow 的 32 位溢出没有入口保护。
//       没有证明现有配置实际使用这些输入。
//
// 已知边界：布局与文本
//   可见行数的除数 Height+Space 可能为 0；非零 Height 不是充分条件。
//   可用宽/高可为负；水平偏移只做一次减法，纵向不足一页也不清正偏移。
//   截断与折行栈缓冲各 10240 个宽字符，没有显式限定终止符空间。
//   加权计量与按宽字符截断的单位不同，不能只检查 MaxCount 的数值。
//   拆行入口会临时改写输入，客户端补丁必须保证输入内存可写。
//   记录含多个拥有指针，外部插件不得 memcpy 后把两份当成独立对象。
//
// 资源编辑器建议的前置约束
//   MaxRow 使用正整数并给出工具自身的合理上限；先用宽整数计算 160*N。
//   保持 0<=count<=capacity；取/改/删有效行时要求 0<=index<count。
//   插入要求 0<=index<=count，并明确决定满容量时是拒绝、扩容还是滚动。
//   要求 Height>0、Height+Space>0，宽高扣除滚动条后仍为正。
//   长文本同时校验宽字符数、加权计数和每段缓冲可容纳的终止符。
//   这些是新工具的约束建议，不代表当前客户端已经具有相同保护。
//
// 建议回归场景
//   常规：256 容量插入、删除、清空、再次使用；主文字与提示均非空。
//   容量：缩小后保留前几行，放大后旧样式/文字仍在；确认无双重释放。
//   满容量：末尾追加与中间插入分别记录，勿用前者结果替代后者验证。
//   样式：对已有行修改字体、前景/背景色；确认提示文字是否应独立更新。
//   零高度：传 0 后分别观察模板与已存在行，验证实际渲染结果。
//   布局：正/零/负 Space，水平条与垂直条分别可见、隐藏和不存在。
//   滚动：空列表、不足一页、起始行大于 count、超大水平偏移。
//   文本：ASCII、汉字、控制文本，LF 与字面反斜杠+n，开启/关闭自动折行。
//   配额：MaxCount=-1、0、边界值；旧行含汉字时替换为 ASCII 及反向替换。
//   长度：10239/10240 宽字符及折行头尾各靠近边界；调试器监测写越界。
//   配色：只设 FontBColor、只设 FontColor、两者不同、两者均缺；逐态对照。
//   选择：单选 -1/0/count；多选超过 31 行时记录返回值和可见状态差异。
//
// 离线核验
