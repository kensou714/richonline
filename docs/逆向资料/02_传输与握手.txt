// 大厅C2S帧：客户端发往服务端
//
// 已核实：多字节整数按小端复制，头长12字节。
// 帧偏移    宽度      内容
// 0         4         魔数0x10A1D85F，线上5F D8 A1 10。
// 4         4         大厅消息类型。
// 8         4         总帧长减4，也就是载荷长度加8。
// 12        可变      普通消息的变换后载荷。
// 证据：登录基类0x88D260、构造0x88D2B7、载荷变换0x88D820。

// 大厅S2C帧：服务端发往客户端
//
// 已核实：头长8字节，与C2S不对称。
// 帧偏移0是4字节类型，偏移4是4字节总帧长，偏移8是载荷。
// 接收器0x88D9A0先收满8字节，再按总帧长收完整帧。
// 不能把C2S的“长度再加4”用于S2C。

// 密钥建立
//
// 已核实：大厅连接成功后先等待服务端首帧。
// 首帧载荷前三个DWORD为g、p、serverPublic。
// 完整提供参数至少需20字节总帧；这不是历史首帧唯一长度证明。
// 待验证：正式服务器首帧type与实际参数范围未由新版抓包确认。
// 客户端从24个小素数指数中随机选e，计算公开值和共享key。
// 0x8DFFF0保留乘积低32位，再执行有符号除法取余。
// 不得无条件替换为任意精度标准模幂，否则溢出行为不同。
// 回应type759携带4字节clientPublic，总帧长16，头内长度12。
// 此握手回应绕过普通载荷变换；后续登录才走加密入口。

// 普通大厅载荷变换
//
// C2S：每字节异或key低8位；若有符号key%2不为0则反转载荷。
// S2C解密：若有符号key%2等于1则先反转，再逐字节异或。
// 负奇数的两种判断并不等价，移植时必须保留这个区别。
// 头部不参与该变换；已追踪大厅发送链没有压缩步骤。
// 证据：0x8DF990、0x8DFAC0；不扩展为所有连接均无压缩。

// 游戏入场type0
//
// 已核实：游戏连接采用独立接收器，不执行大厅的上述密钥握手。
// 游戏帧头为[type:4,totalLength:4]。
// NEW入场载荷24字节，总帧32字节。
// 已弃用ORIGINAL遗留分支入场载荷32字节，总帧40字节。
// “24与32差异”指载荷，不是两种总帧长。
// NEW载荷依次为3个DWORD、8字节令牌、最后1个DWORD。
// 旧分支额外两个DWORD；新版禁止携带旧字段。
// 实现：decode_game_admission、encode_game_admission。

// 游戏type299封装
//
// 以下偏移相对于299载荷：
// 0         2         内层标签，按有符号16位保存。
// 2         2         编码字节数W，当前实现要求不大于32767。
// 4         1         模式/标志字节。
// 5         W         内层编码内容。
// NEW尾部为0字节；已弃用ORIGINAL遗留分支尾部为4字节。
// 实现严格检查载荷长度等于5+W+版本尾部。
// NEW活动回调未用标签和标志选择0x4000，也不据此确定棋盘模式。
// 不要把封装标志、房间模式和EMP地图模式当成同一个字段。

// 内层编码
//
// 明文前加2字节小端长度，各字节加107取低8位，反转顺序。
// 再将填充字节与变换字节交错写出；有效数据在奇数下标。
// 解码从末尾奇数下标逆序取字节并减107，校验嵌入长度。
// 当前编码器明文范围2至509字节；解码输入上限1024字节。
// 长度错误在进入业务处理前拒绝，不能靠补零掩盖截断。
