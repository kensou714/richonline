// 候选评选方法

// 每维 1 至 5 分；分数只用于安排调查先后，不等于实现完成率。

// 风险可控：5 表示无需改代码且能回滚；1 表示影响内存布局或通信状态。
// 总分为五维相加；优先级还要考虑前置依赖和未知项。
//
// 专题                     内容 复用 证据 验证 可控 合计  推荐
// 公共文本解析及长度校验       5    5    5    5    4   24   先做离线校验器

//
// 公共文本解析器：最值得先建立的编辑器约束
// ----------------------------------------------------------------------------
// 跳板 0x60FD9C -> 0x81B4C0：以 rb 打开文件，读取 1 字节偏移量及两个 DWORD。
// 该函数逐字节减去偏移量并读取载荷；单独调用它不等于完成解压和语义解析。
// 跳板 0x60ACA7 -> 0x819250：模式 1 以 rt 读取文件；模式 2 复制给定内存。
// 因而“同样按节/键读取”不能推出明文 INI 和 KPD 可以直接互换。
//
// 跳板 0x608335 -> 0x819470：查找 [节名]，strcmp 精确比较；跳过 // 注释行。
// 跳板 0x609528 -> 0x819660：当前节内查找键名，遇下一个 [ 返回未找到。
// 键与值用 = 分隔；键名同样 strcmp 精确比较，不应擅自改变大小写。
// 跳板 0x60FDE2 -> 0x8198E0：读取到 LF；高位字节 >= 0x80 时成对复制。
// 反引号加 n 会转成 LF；它不是 C 风格反斜杠加 n。
// 该函数在复制与写 NUL 之后才检查 iCount + 1 是否超过传入容量并 assert。
// 因而参数中的容量不是提前截断保护，编辑器必须自己限制编码后的字节长度。
// 还应保证每个值有换行、双字节文字完整，并用无损往返检查保留原编码。
// 未证明全资源可使用 UTF-8；不要因文档是 UTF-8 就把资源统一转为 UTF-8。
//
// 实用产物：离线校验器应报告文件、节、键、原始行号、字节长度及允许上限。
// 对未知键保留原值；对重复节保留顺序，不能用普通字典合并掉重复 [INTF]。
// 未决：截断文件、缺右括号、尾部无 LF 的全部分支尚未逐指令审计。
// 当前结论足以要求编辑器拒绝这些输入，不足以声称客户端安全处理了它们。
//
// 启动表：按失败分支制作资源诊断清单
// ----------------------------------------------------------------------------
// 0x623B60 经 0x601562 -> 0x7B74C0 使用 Config/；再读 Data/Role.kpd。
// Role 读取失败会返回 0；Data/LogFixStr.kpd 的调用在此处未检查返回值。
// 同函数通过 0x60B972 -> 0x69A3C0 进入音频初始化。
//
// 0x623CB0 按调用顺序装载 Anim、RichStr、Prop、VehPet、ASTable 等 KPD。
// RichStr 字符串 VA 0xA221B8；消费者跳板 0x606EA9；失败时本函数返回 0。
// BossWar/BwbValue/BwNews/BossWar_v 共同交给 0x606BED。
// Interface/ 字符串 VA 0xA222C4，使用点 0x623E35。
// 它经 0x61223B -> 0x6E2CD0 初始化 UI，再经 0x60C804 -> 0x6E2F70 读 Intf.kpd。
//
// 0x623EE0 读取 Npc、Feast、Build、Level、Stock、Pawn、MapView、PlusPrize、
// TeachMode、Filter、FilterN、FaceCtrl；这些分支中多处失败会直接返回 0。
// Build 字符串 VA 0xA2234C，使用点 0x623F1B；消费者跳板 0x5FFBA4。
// 入口跳板 0x6030BF 被 IDA 标作 StartAddress；不能据此假定全部表在主线程加载。
//
// 实用产物：列出实际读取路径、必需/可选判断、解析器、依赖资源和启动失败表现。
// 只记录本轮看到的返回值检查；没有检查不意味着资源真正可删。
// 不能用“忽略所有失败返回”作为缺资源补丁，后续对象可能从未初始化。
//
// 音频：目录和初始化已证，容器替换仍需后续研究
// ----------------------------------------------------------------------------
// 0x69A3C0 调用 AIL_set_redist_directory("Sound\\") 与 AIL_startup。
// 0x6049D3 -> 0x8245E0 接收 Sound/、snd%04d.dat、20、1000000。
// 0x6030E2 -> 0x81F950 接收 Music/、mus%04d.dat。
// 两个实现都调用 AIL_open_digital_driver(44100, 16, 2, 0)。
// 这是输出设备初始化参数，不是所有输入音频必须同采样率/编码的证明。
// 0x8245E0 的 20 用于分配 sample handle 的循环；不是 snd 文件数量上限。
// 0x81F950 成功返回 -1，失败返回 -2；不要把所有非零返回都解释为失败。
//
// 0x7B74C0 读取 App.ini 的 Sound/Music、SndVol/MusVol。
// 开关与 "true" 精确比较；音量用 atoi，读取处本轮未见范围夹取。
// 0x69AAA0 读取 Config/Voice.dat：按角色数乘 8 分配 DWORD 表，并先填 -1。
// 0x69AC60 读取 VoiceFace.kpd 的 role 和 face%d 对照；各编号语义仍待场景核实。
// 音频容器索引、事件到编号、循环行为、缺失编号回退没有在本专题证明。
//
// MapList：目录数据有连续键和运行时筛选
// ----------------------------------------------------------------------------
// 字符串 VA 0xA23978 -> 使用点 0x6A957E -> 实现 0x6A9530。
// 实现经 0x60FD9C 读 Data/MapList.kpd，再把解码后的内存交给公共文本解析器。
// 按 XIN_MAP、CHU_MAP、ZHONG_MAP、GAO_MAP 四节处理。
// 每节从 item0 开始递增查找，第一个不存在的 itemN 就结束本节。
// 因而新增条目不能留编号空洞，不能假定最大 item 编号之前都会被扫描。
// 每个值通过 0x60FDE2 读取，传入容量为 128 字节。
// 值还传入 0x611CC8 -> 0x7E6F10；随后通过运行时判断才加入列表。
// XIN_MAP 使用 0x6054B4；其余节涉及 0x5FFBE0、0x608628、0x604703。
// 本轮没有还原这些筛选条件全部语义，因此不能保证加了 itemN 就一定显示。
// 0x608C4F -> 0x7DED90 仅把名称格式化为 Map\\%s；这一步不是地图解码。
//
// 实用产物：地图编辑器同时检查连续 item 键、对应 EMP 文件、地图配置和服务端支持。
// 列表新增、EMP 成功读取、对局事件全可用，是三个不同的验收点。
//
// Intf.kpd：固定容量、字段写入和依赖序列
// ----------------------------------------------------------------------------
// 0x6E2F70 把当前 Interface/ 根与 Intf.kpd 拼接，读取失败返回 0。
// 分配 160 项，每项 132 字节；后续 sub_605C3E 也接收常数 160。
// 每个 [INTF] 的 indx 经 atoi 直接参与 132 * indx 索引。
// 本轮所见函数未在该写入前进行 indx 范围校验；编辑器应强制 0 <= indx < 160。
// 重复编号也应报冲突，不能靠最后一次覆盖来处理合作内容。
//
// 字段     单项偏移  静态已证读取行为
// indx     +0        DWORD 编号。
// file     +8        公共读取函数传入容量 64；不能超过 63 个编码字节。
// draw     +72       与 "true" 比较得到布尔值。
// dynPop   +73       与 "true" 比较得到布尔值。
// center   +74       与 "true" 比较得到布尔值。
// nadjust  +75       与 "true" 比较得到布尔值。
// free     +76       经 0x60FAEA 解析；枚举语义本轮没有确认。
// offsetX  +80       atoi 得到 DWORD。
// offsetY  +84       atoi 得到 DWORD。
//
// prev_0、prev_1… 与 dvs_0、dvs_1… 分别循环读取；首个缺号结束。
// 各值转整数后交给 0x5FFF41；本轮未证明两组依赖的显示/销毁顺序含义。
// 字段名字可提示用途，但字段消费证明仍需沿窗口创建、显示、关闭路径继续追踪。
// 扩大 160 不能只改分配常数；还需要枚举遍历、回调注册、释放路径和 ID 依赖。
//
// Tex：配置映射和包文件必须作为一个变更单元
// ----------------------------------------------------------------------------
// 0x6D8130 读取 Tex/ToolConfig.kpd，并检查 pack 值是否为 true 或 TRUE。
// 标志写入对象 +630752；此函数还按顺序处理 road、thing、event、build、vehicle、
// role、npc、fx、mood、card、other、extend 的 .dat 映射。
// 本轮只确认这里设置标志，没有证明关掉 pack 后所有资源都会走散文件路径。
//
// 0x60D376 -> 0x6DA7B0 使用数字目录字符串，通过 atoi 得到组号。
// 拼接 Tex\\%s\\Item%s.tb；读取 0xFA0 = 4000 字节到组记录。
// 再拼接 Tex\\%s\\Pack%s.npp；保存打开的 FILE* 到组记录 +4000。
// 组记录步长 4008；+4004 写入 500 * 组号。
// 这里的 4000 字节不能单凭除法就宣布是 500 条“已完全还原”的索引。
// 记录字段、偏移基准、压缩方式、图片尺寸与透明度都要由后续读取端核实。
//
// 映射消费者可见固定循环：build 有 10 个等级槽与 10 帧槽；role 有 4 个方向槽、
// 每方向最多 100 个帧槽；vehicle 有 4 个方向槽、每方向 10 个帧槽。
// 它们描述此处视觉映射容量，不等于玩法建筑等级或所有动画实际帧数。
// 遇到条目缺失会提前结束对应内层循环；内容工具应保留编号与连续性。
