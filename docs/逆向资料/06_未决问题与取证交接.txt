// 能进入棋盘不等于所有角色、地图、事件或整局结算已通过实测。

// 尚待补证的协议问题
//
// 首握手type：初始化链读取参数，却没有证明正式服务端固定类型。
// 握手参数：负key及32位溢出范围缺少新版真实抓包确认。
// 网络包长：4010/4011的handler消费范围不证明原服务器完整长度。
// 未读字段：4011+20..23及若干房间扩展字节仍需保留未知标记。
// 自动决策：客户端可自动选择不等于原服务器BOSS采用确定性策略。
// 全部消息：注册表包含本地事件，不能将注册数量直接称协议总数。

// 一次卡局最小证据
//
// 记录当前客户端版本、服务端构建、所用配置和日志文件名。
// 写清操作：人物、地图、回合、起点、预期落点、界面停在哪里。
// 截取卡住前后连续日志，保留两条连接各自的ID和时间信息。
// 记录外层type、内层opcode、明文长度、calendar及GmsvID。
// 保存服务端异常、连接关闭与后续轮询记录，不能只截最后一个包。
// 账号口令、令牌及个人资料不得原样进入公共证据文档。
// 如需脱敏令牌，保留同一会话内可关联性，不伪造实际字段含义。

// 诊断顺序
//
// 先确认服务端是否收到对应请求，再确认是否成功解码和授权。
// 若收包后断线，沿异常和GameSession关闭路径查原因。
// 若连接仍在，核对当前pending类型、截止时间和poll执行条件。
// 若已经发包，核对客户端GmsvID、对象状态及本地队列执行门槛。
// 最后核对回包是否真正结束事件，并允许下一回合推进。
// 单纯补发下一回合包可能掩盖未完成事件，不能替代状态修复。

// 新调查交接模板
//
// 对象版本    输入文件相对路径、SHA-256、IDA基址。
// 问题范围    一个具体请求、落点或状态迁移，不泛称完整协议。
// 请求结构    方向、命名空间、字段偏移、宽度、符号与长度。
// 响应结构    handler地址、实际消费边界、后续本地事件。
// 状态前提    当前角色、地图、pending、所有权和资源条件。
// 副作用      金额、库存、建筑、日历和界面关闭行为。
// 证据分级    哪些已核实，哪些是兼容策略，哪些仍待验证。
// 验证记录    静态核对、自动测试、真实TCP、用户客户端实测分开写。
// 剩余问题    明确可继续调查的地址、资源或缺少的现场输入。
