// MapView：地图记录、图像键与频道
// ============================================================================
// 生产与根指针
//   0x628C60 取单例；0x628CD7 写 0xA76704；0x7E8E40 仅清对象首 DWORD。
//   对象 +0x00 为记录数组指针，+0x04 为 count；构造不保证 count 已初始化。
//   启动 0x623FA2 压入 Data\MapView.kpd，0x623FAE 调 0x7E8EB0，局部检查返回。
//   加载取得解析源后清 count；第一遍数 ITEM，复位后分配，第二遍逐项写字段。
//   0x7E8FD5 的 imul 0x114 证实数组分配步长；0x622D50 迭代调用记录构造。
//   0x7ECD20 仅清记录 +0x00 / +0x80 两个 BYTE，不保证其他字段或填充全零。
//
// 每条记录 R = DWORD[对象+0x00] + index*0x114
//   +0x000..0x07F   map 字符串槽；加载传容量128给 0x8198E0。
//   +0x080..0x0FF   摘要字符串槽；外层地图文件探测成功后取摘要并 strcpy。
//   +0x100 DWORD    pic_enb 图像键结果；0x7E90DD 写，0x7E9571 读。
//   +0x104 DWORD    pic_dis 图像键结果；0x7E912C 写，0x7E95F1 读。
//   +0x108 DWORD    channel 索引；0x7E9177 写，0x7E9671 读。
//   +0x10C DWORD    winCond 图像键结果；0x7E91FB 默认 -1，0x7E9252 改写，
//                  0x7E94F1 读；不是 channel 字段，也不据名称定义胜利规则结构。
//   +0x110 BYTE     new 标志；0x7E918C 默认0，0x7E91E6 写，0x7E96F1 读。
//   +0x111..0x113   本专题没有业务写入证据；不命名字段，不推定零填充。
//
// 查询与实际消费
//   五个 getter 均按 map 精确 strcmp 顺序扫描，重复 map 只返回首个匹配。
//   0x7E9490 / 0x7E9510 / 0x7E9590 / 0x7E9610 依次查 winCond、两图像、频道；
//   未命中 DWORD 查询返回 -1。0x7E9690 查 new，未命中 AL=0。
//   0x7E93A0 查 0xA67568 四项表：CHU=0、ZHONG=1、GAO=2、XIN=3，未知返回 -1。
//   0x71E1B0 的 winCond 路径存接收对象 +0x50，再交控件 ID1；并有后续状态动作。
//   0x73F420 局部列表路径按可用性选 pic_enb/pic_dis，new 交 ID+3 的虚槽。
//   0x73FE50 用频道选择图像参数36/37/38/33；不读取 winCond。
//   图像赋值并不证明图像存在、最终绘制成功或拥有图像对象。
//
// 所有权与边界
//   关闭局部 0x6244B0..0x624500 调 0x6293E0(flags=1)，随后清全局槽。
//   0x7E8E60 只 delete[] 当前首指针并清零，不按记录释放图像，不清 count。
//   正条目重载覆盖旧数组指针，零条目重载只清 count；现有析构不能追回旧数组。
//   map/pic_enb/pic_dis/channel 查键结果未逐项设门；new/winCond 有默认值。
//   解析器容量是复制后的断言；摘要读取100字节未补 NUL，外层 strcpy 无容量。
//   0x7E72A0 在累计偏移23320处读100字节；Map+0x520 属临时 Map，非 MapView 字段。
//   分配失败、乘法溢出、重复加载、摘要异常是静态合同缺口；没有本专题实机复现。
//   未知：图像管理器所有权、控件最终效果、完整模式容器与外部可用性合同。

// Pawn：四档范围与押金表
// ============================================================================
// 生产与根指针
//   0x628C10 在 0xA76700 为零时申请 0xD0，未见对象构造或字段清零。
//   0xA76700 在 raw-backed .data，当前磁盘值零；它不是 BSS。
//   启动局部 0x623F8B 取对象，0x623F92 调 0x7F1D70 加载 Data\Pawn.kpd。
//   加载四个 LMT 段的 min/max 和四个 PAWN 段的 num/item%d；不是典当交易证据。
//
// 内嵌四档布局；档位0..3分别对应 CHU/ZHONG/GAO/XIN
//   档位   min(double)   max(double)   count(int32)   items(int32)首地址
//     0      +0x00          +0x08          +0x40          +0x44
//     1      +0x10          +0x18          +0x64          +0x68
//     2      +0x20          +0x28          +0x88          +0x8C
//     3      +0x30          +0x38          +0xAC          +0xB0
//   各 count/items 区块步长0x24；count后有8个物理 DWORD 槽，末槽到 +0xCC。
//   0x7F1E81/0x7F1EBC、0x7F1F08/0x7F1F44、0x7F1F90/0x7F1FCC、
//   0x7F2018/0x7F2054 的 fstp qword 写对应八个 double，不是32位整数赋值。
//   count/items 通过32位转换写入；循环按 signed count，没有 count<=8 钳制。
//
// 查询与实际消费
//   0x7F2630 返回 count，0x7F26E0 返回内嵌 items 地址，调用者不获得分配所有权。
//   访问器 unsigned 检查只接受档位0..3；非法分支诊断后若返回仍取 0xCCCCCCCC。
//   0x75CE30 的 0x75D03C..0x75D138 局部读另一配置对象 +0x40 作为档位，
//   按 count 遍历 items，使用文本库索引80构造控件12选项；文本格式仍未知。
//   0x75E6F0 的 0x75EC9B..0x75ED35 局部直接按选择索引读 items，无二次容量门。
//   0x7F2790(mode=2/3)直接 AL=1；其他模式扫描表精确成员匹配，不读 min/max。
//   0x7BA0B0 的输入记录：+0x30模式、+0x34/+0x38/+0x3C前置选择、
//   +0x40押金、+0x44四档索引。这个记录不是 Pawn 对象本身。
//   组合门依次检查前置选择和模式，最后调用押金成员门，任一 AL=0即退出。
//
// 所有权、限制与未知
//   items 是对象内部地址，不得 delete[]；此专题没有闭合单例最终释放路径。
//   8槽是物理容量，不是客户端已经实施的配置上限。超量会覆盖后组或越过对象。
//   重载不清少写的尾槽；所有键读取未逐项检查，返回1不代表各字段有效。
//   Pawn +0x40 是档位0的count；显示消费的配置 +0x40 是另一个对象的档位来源。
//   八个 LMT double 的真实消费者未闭合，不能据本次未找到读取判定范围限制无效。
//   未知：三前置表生产、选择索引完整保证、资金扣除与服务端确认、RTC返回合同。
//
// Pawn 证据入口
//   Pawn四档配置与业务消费/01_加载与对象布局.txt：分配、字段、样本及容量。
//   02_消费者与校验契约.txt：两个访问器、两处UI局部、成员门和组合记录。
//   证据/functions_raw.json：加载、组合门、items访问器及UI本体。

// Feast：二进制月日对与模式标志
// ============================================================================
// 生产与根指针
//   0x6288B0 在 0xA766D4 为零时申请 0x340；无可见目标构造或清零。
//   启动 0x623EFF 压 Data\Feast.kpd，0x623F0B 调 0x7D8BE0。
//   0x7D8C6B memcpy(this,data,length)，长度取自资源容器；没有固定806字节门。
//   随后写两组标志；读取失败不写目标，成功短数据只覆盖前缀，旧值可能保留。
//
// 表对象布局；当前资源不是文本
//   +0x000..0x325   31条年记录，每条26字节、13对 signed BYTE 月/日。
//   +0x326..0x332   模式组A，13 BYTE；成功加载时全写1。
//   +0x333..0x33F   模式组B，13 BYTE；槽7与10写0，其余写1。
//   0x7D8C76 是 +0x326 写1锚点，0x7D8CF8 是 +0x333 写1锚点。
//   两组标志来自代码，不属于当前806字节解包体；单改包不能改变默认标志。
//   没有已证 vptr、数组指针或内嵌count，不套用 MapView/FaceCtrl 管理对象布局。
//
// 日期状态 C 与表对象分开
//   C=G+0xC44，0x63E590 返回此子对象；C不是 Feast 单例，也不是其数组记录。
//   C+0x08 signed WORD 年；C+0x0A signed BYTE 月；C+0x0B signed BYTE 日。
//   4052 -> 0x662DC0 -> 0x694320 窄写上述字段，不写 C+0x10。
//   C+0x10 DWORD 是 0x7D89D0 写入的查值槽，0x7D8A0E 为写入锚点。
//   +0x0A 与 +0x10 分别是月字节和查值槽；不能沿用十进制“+10”造成混淆。
//
// 查值、模式门与消费
//   0x7D8DE0：offset=(year-2004)*26+slot*2，slot扫描0..12。
//   两字节 movsx 后分别比月日，首命中返回slot，无匹配 -1；没有年份范围门。
//   当前样本标签2004..2034；2035起点落 +0x326 标志区，不是下一年资源记录。
//   成功默认状态下2035/1/1静态命中槽0；不认定支持2035或已被服务端触发。
//   0x7D8EB0：先判P0，真取A；否则判P1，真取B；否则0。P0/P1业务名称未知。
//   0x7D89D0 先存槽再过模式门，通过后用 0x7D8B75 的52字节表分派13个业务。
//   重复日期只返回首槽；首槽被门拒绝不会改查后槽。13个业务本体未展开。
//   0x7D8E60 仅判断槽!=-1，不查模式标志；0x7080D0据此取日期图集基号5或65。
//   因此UI特殊日期图像与日期业务门的接受域不同，不能相互代替。
//
// 所有权、限制与未知
//   单例无本专题已证内嵌堆指针；0x624864..0x624887 局部直接delete对象并清槽。
//   memcpy长度无目标容量比较；真实可达性仍需通用容器长度及解压合同补证。
//   小于2004的年份向对象前读；大于2035超过当前分配区，上游保证仍未知。
//   未知：其他日期写者、年份策略、深层模式含义、业务输出后继、完整刷新绘制。
//   0x7C19AD..0x7C19E9 的调用局部消费非零继续、零跳转；不据此称通信失败。

// FaceCtrl：控制词记录与4F表情更新
// ============================================================================
// 生产与根指针
//   0x628FB0 取全局单例；0x628FE9 申请8字节，0x629006 调 0x64CE50。
//   0x64CE61 仅清对象 +0x00 指针；+0x04 count 到加载时才明确写零。
//   启动 0x62403E 压 Data\FaceCtrl.kpd，0x62404A 调 0x64CEC0，随后检查返回。
//   加载先枚举 ITEM计数，再按 count*0x108 分配，复位后第二遍解析记录。
//   0x64CFC2 为分配步长锚点，0x64CFE0 写对象首指针，0x64CF83 清 count。
//
// 每条记录 R = DWORD[对象+0x00] + index*0x108
//   +0x00 int32    face，源为face键转换结果；缺键没有明确默认值门。
//   +0x04 int32    已读控制词数量；0x64D0CA 写当前成功解析的连续项数。
//   +0x08         控制词槽首地址，每槽8字节，槽j地址为 R+0x08+j*8。
//   0x64D092 传复制容量8，0x64D0A7 算目标地址，0x64D0B2 调 0x8198E0。
//   布局容纳32槽，不是运行钳制；ctrl从0逐键读取，遇缺口停止，没有 j<32 门。
//   0x8198E0 先复制含NUL内容、后检查容量并断言，不能按8字节参数当截断保护。
//   当前原包9 ITEM、face1..9，每条ctrl0..4；45控制词长2..5字节。
//
// 匹配结果与提交参数
//   0x64D180 在 0x64D1A6 先 strlen，0x64D1B1 才判断指针，非NULL安全接口。
//   0x64D22C 调 strstr；0x64D246 的 jge 保留较早规则的同偏移命中。
//   最早字节位置获胜，同位置按 ITEM/ctrl先后；不是词边界或最长词匹配。
//   face=-1 仍竞争最佳位置，末尾抑制分发；不是扫描阶段直接忽略该规则。
//   聊天局部 0x64B569 / 0x64B766 使用消息标识与文本；不认领整聊天函数。
//   参数 P+0x00 DWORD 更新位0x10，P+0x04 DWORD 调用方标识，P+0x08 DWORD face。
//   写入锚点为 0x64D272 / 0x64D27C / 0x64D282；0x64D292 交 0x6E4640(slot=0x4F)。
//   0x73B694 and edx,0x10 证实表情更新位；0x10不是消息长度。
//   P+0x0C 无业务赋值，本分支不读；不能以调试填充构造四DWORD网络包。
//
// 4F对象身份与实际接收
//   UI管理器全局 0xA766C8，0x6279C0申请0x6C0；这里只复用4F局部合同。
//   0x6E6080 注册创建表：manager+0x184 对应0x4F，桥0x601B6B -> 0x6E8F50。
//   实例槽地址为 DWORD[manager+0x44]+0x4F*0x84+0x04；0x6E3B40可写创建实例。
//   0x6E4640仅对既有实例调用虚槽+0x10，实例不存在则跳过，不负责就地创建。
//   工厂申请0x93C，经0x6FC000构造；0x6FC035 写首DWORD虚表0xA27120。
//   虚表+0x10保存0x60A72F，E9直达0x73A590；构造写入和桥均有独立原证。
//   4F对象+0x68起构造4个子对象，步长0x21C，不属于FaceCtrl配置记录数组。
//   表情分支遍历控件100/200/300/400；通过状态门且索引0关联数据首DWORD
//   与P+0x04相同后，将P+0x08交对应子对象的0x797800，再记录GetTickCount。
//   0x73B72F 子对象算式：this+0x68+0x21C*(控件编号/100-1)。

//   0x64CE9B delete[]当前配置数组，0x64CEA6清首指针；不清count。
//   0x629160先调上述析构，flags低位控制本体删除；退出局部传1后清0xA7673C。
