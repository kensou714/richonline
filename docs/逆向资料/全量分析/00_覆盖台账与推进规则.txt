// inventory.json：版本、识别规模与分类数量。
// functions.json：逐函数地址、跨度、IDA名称/标记、分类；初始语义状态均为未分析。

// ida_types.json：299个现有类型，其中93个含成员；包括SDK类型，不能算作游戏结构恢复量。

// merge_evidence.py：生成上述专题证据覆盖索引，不修改任何人工审阅结论。
// 首批人工审阅迁移.json：保留首批中文清单的原级、原行、证据和状态定义。
// review_coverage.json、merge_reviews.py：合并显式人工记录，保留每个来源与局部覆盖范围。
// followup_queue.json、build_followup_queue.py：保留全量入口并提供后继选点，不生成语义完成率。
// archive_validation.json、validate_archive.py：UTF-8、中文注释排版、JSON/Python语法时点检查。

// 归一化仅沿已证E9跳板追踪，不会猜测未解析函数指针。

// 覆盖等级
// 已识别：有函数边界、地址或符号；没有业务语义承诺。
// 仅导出：已保存伪代码/汇编，还没有逐分支解释与交叉检查。
// 已分析：职责、输入输出、关键状态、失败分支均有中文说明和原始证据。
// 待验证：函数已有分析，但具体字段或行为仍缺调用者、资源样本或运行证据。
// 已实测：有独立真实运行记录；静态分析和离线解析不能自动升级到此状态。
// 专题函数清单保存人工结论，不能因重新导出全量索引而抹掉人工进度。
// 新清单统一使用va/status/conclusion/unknown/evidence；va写十六进制入口地址。
// 状态必须说明局部范围；state留给游戏或异常状态机，不用作人工审阅分级键。
// 历史review_status/中文状态兼容读取，但新文件沿用统一键，避免汇总静默遗漏。
// 同一入口的不同专题记录保持独立，不采用最高等级自动合并为完整语义。

// 每组交付要求

// 全局：地址、读写入口、生命周期、用途证据；名称只作检索标签。
// 格式：文件偏移、长度来源、字节序、索引基准、校验和真实样本。
// 价值：对协议修复、内容编辑、功能补丁或故障定位的具体帮助。
// 不把一个未知局部变量命名后就算作恢复，也不以全部反编译导出代表全部分析。
