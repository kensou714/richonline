// 证据优先顺序
// 当前目标指纹 -> PE映射/原始字节 -> 指令与ABI -> 数据流/调用者 -> 伪代码摘要。
// 库签名、自动类型名、邻接地址和英文函数名只作线索，不能直接充当业务事实。
// 原始证据保持原貌，修正解释写在文档和审阅清单；不要把错误伪代码“修好”后当原文。

// 范例一：大结构按值传递被拆成几十个伪参数
// 地址：64FA50 -> 6980F0；另698050为尾插。
// 伪代码现象：64个int形参、STACK[0x144]、local variable allocation failed。
// 指令事实：调用者sub esp,120h，ECX=48h，rep movsd；被调用者retn128h。
// 结论：记录288字节按值传递，后接物理下标和返回位置模式，各4字节。
// 调用者设置this=G+640h；不能把隐藏ECX或尾部参数从伪签名中删去。
// 来源：../专题/基础对象与分派/01_游戏记录队列与消费门控.txt。

// 范例二：char类型污染导致600被显示成88
// 地址：87E640的调度注册与错误路径；868E50、87E170的键类型。
// 初读伪代码会产生600与88不一致的印象。
// 汇编各关键调用均push258h，即600；834BC0读DWORD比较，86BB60复制DWORD键。
// 结论：该链没有已证明的600/88键错配。另一常量58属于UI回调类别，
// 不能跨层拿它与scheduler键比较后宣布丢失回复。
// 来源：../专题/登录与大厅状态/及其独立审阅反馈归档。

// 范例三：MFC/CRT名字覆盖了游戏职责
// 7EE330自动名_cfltcvt_init，实际包含310个游戏分派表写入。
// 64F870自动名CMFCOutlookBarTabCtrl::RecalcLayout，实际按消息号同步处理或入队。
// 7D8110自动名COleDispParams析构，局部事实是释放记录存储数组并置空。
// 文本绘制CPoint误名、UI工厂和其他库标记也需按this/参数/资源交叉核对。
// functions.json保留原name和库候选分类，不能批量把库标记从待办中删除。

// 范例四：IDA未加载区的FF不等于运行初始值
// 地址：A86720、A86800、A86724等启动全局。
// 其VA落在.data虚拟范围内，但超出该节文件原始数据范围。
// PE加载时对应零填充；IDA取回的FF属于数据库表示，不能写成变量初值-1。
// 初值判断必须保留节RVA、SizeOfRawData、VirtualSize和变量偏移证明。
// 同理，.idata导入槽的FF可能来自XTRN表示，不能误报为整段文件被修改。
// 来源：版本核验_第二批.json；../专题/启动线程与退出/。

// 范例五：文件指纹变化不能用当前路径掩盖
// 当前磁盘A234...，本轮IDA输入基线CB35...。
// 两文件差异仅811100中三个push立即数：20/40/80 -> 24/44/84。
// 对整份磁盘字节仅在内存逆转三处后SHA256精确匹配历史输入，证明差异范围。
// 三项增加D3DCREATE_MULTITHREADED，但Reset线程约束仍需另查API合同。
// 其他函数局部一致可延用证据；811100必须写出两版行为，不能混用常数。

// 范例六：跳板和桥接层不能算成业务分析完成
// 14191个直接E9跳板只是已识别；310个24字节桥接只是ABI已核对。
// cdecl(Game*,packet*) -> thiscall(handler)的模板不读取业务字段。
// 实际长度、消息方向、地产选择、等待清理都必须在真实handler和构造者确认。
// followup_queue.json保留全部入口；review_coverage.json保存每个来源的原状态。

// 范例七：伪数组容量会把RTC保护间隔算进去
// 67F680伪码Buffer[132]，实际RTC表67F89C的szTmp为EBP-144、128字节。
// 同类误差见4009、403B、401D；不能用两个局部变量地址相减代替真实数组大小。
// 校验方法：导出RTC头的count/table，再读每项offset/size/name并比对磁盘。
// 40C1的5个xPack容量分别为12/24/4/10/4字节，与各本地记录复制跨度一致。
// 来源：../专题/40C1状态事件/证据/data_layout.json。
//
// 范例八：相似构造器必须核首WORD
// 605211 -> 6944A0写6007；6079B7 -> 693260写6002；693420写6001。
// 6050清附身后的条件动作由67F7AB调用6079B7，实际补6002，不是6007。
// 两者均可能传type、角色号与等待时间，形状相似并不能互换消息编号。
// 核查入队前构造call目标与首WORD store，再核消费者读取的flag偏移。
// 来源：../专题/40C1状态事件/证据/conditional_6002.json。
//
// 范例九：API名称的“所有指令”不保证包含异常尾块
// 当前IDA Domain版本get_instructions对627C20等函数只返回主范围。
// get_chunks另返回异常处理尾块；仅重验已存指令字节无法发现遗漏。
// export_function_group.py已改为显式get_chunks，再逐块get_between去重。
// 40C1的61函数实际有68块；补齐7个21字节尾块后，指令字节为8859。
// 覆盖检查应核声明块是否全部有原证，再独立核指令地址和当前磁盘字节。
// 旧专题主干结论不自动失效，但“完整原证”的范围需通过尾块完整性审计纠正。
// 来源：../专题/40C1状态事件/独立审阅.txt；尾块完整性审计/。
//
// 范例十：立即数搜索结果不是未声明函数
// 录像532字节扫描产生33个指令地址，单项assembly仅为一条指令字符串。
// merge_evidence把它们另列instruction_observations，不计原证函数或未声明范围。
// 指令所在函数已知，也不表示该函数的整段控制流已经导出或分析。
//
// 范例十一：完整指令枚举仍可能漏块内原始填充
// 91FBB0块内有db 12h dup(0CCh)，枚举对象的size只覆盖首字节。
// 旧unwind_runtime.json因此漏91FBBF..91FBCF的17字节，另份主范围原证才覆盖。
// 已补明确标注的非指令原始字节；独审重核组内缺口为0。
// 共享导出器新增chunk_byte_ranges，逐声明块保存完整原始字节；
// byte_ranges仍保留原来的指令枚举区间，两种统计不可直接相加。
// 新字段只对后续导出生效，不偷偷覆盖历史原证或提升旧文件完整性结论。
// 来源：异常尾块与清理契约/独立审阅.txt；
//       尾块完整性审计/后续导出器块内填充核验.json。
//
// 每条拟写结论的最小核对
// 记录函数VA和证据文件，说明适用版本；字段写明偏移单位和宽度。
// 形参有疑点时同时检查调用者push/ECX及callee retn，不只看伪代码。
// 错误路径必须跟到清理和状态写入；只读到中间return不能断言永久等待。
// 静态异常写清输入前提、未展开依赖和是否实机验证；不能以候选名称代替事实。
