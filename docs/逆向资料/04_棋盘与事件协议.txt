// 初始化与标识
//
// 已核实：0x4000初始化参与者，0x4004发布初始快照。
// 当前服务端授权后发外层type1和0x4000。
// 收到内层0x0000地图就绪后，发0x4004及开局消息。
// 内层0x0001是初始化通知；当前实现不把它当作地图就绪。
// 客户端发送通知仍有状态门槛，不能假定构造通知就一定发出。
// C2S业务包+2通常是calendar低16位；S2C+2是GmsvID。
// 二者来自不同字段，不能因为都是WORD就互换。
// 当前实现以快照及非动画回合包维护action_counter。

// 回合与移动
//
// 0x4010：+4行动槽，+5回合锚点，+6是否先执行动画。
// handler至少消费7字节；内部对象8字节不等于历史网络包必为8。
// 0x4011：+4起点WORD，+6点数组件数，+7方向数。
// +8..10为三个点数组件；+11开始每方向占2位，低位先读。
// 方向0加地图宽，1减1，2减地图宽，3加1。
// 方向数组容量36；路径必须覆盖点数消耗及额外步数效果。
// 本地行动者还读取+24的DWORD，其完整业务名称仍待确认。
// 不能把未读的+20..23直接命名为填充或其他金额。

// 移动结束不是一个万能确认
//
// 0x0011携带当前实际位置，普通结束或部分提前停止会发送它。
// 0x0012是特定倒计时效果分支；0x0028、0x002A是途中事件。
// 所有这些请求都应按触发条件处理，不可统一当成落点结束。
// 常见落点响应0x4013确认位置后，客户端才执行相应落点逻辑。
// 移动完成、落点完成和整个回合完成是三个独立阶段。

// 自有空地：建造
//
// 静态已核实：0x7C6640自有地产分支触发本地0x6092。
// UI41为本地玩家打开选择，所有参与者进入pending23等待。
// C2S0x0037为6字节：opcode、calendar、选择字节、未写入的末字节。
// 选择11..20表示建筑种类，10表示不建造；按键路径可发送-1。
// S2C0x403D消费5字节：opcode、GmsvID、已解析选择。
// 返回11..20才建造；返回10或-1都只关闭等待并继续phase6。
// 兼容策略：当前服务端把请求-1解析为关卡默认建筑。
// 不能直接回显-1并声称客户端会建造默认建筑。

// 已建自有地产：升级
//
// 静态已核实：当前等级同时低于关卡上限和行动者技能才可升级。
// 本地0x6093打开UI5，并进入pending24。
// C2S0x0038为6字节，+4仅允许0取消或1确认。
// S2C0x403E消费5字节，+4为1才使当前地产等级增加1。
// 客户端通过本地0x6070修改等级，保留所有者和建筑种类。
// 确认和取消都会清除等待并继续phase7。
// 达到上限时跳过升级等待，不能凭空等待一个不存在的选择。

// 玩家与BOSS的当前策略
//
// 玩家：先确认落点，再等0x0037或0x0038；取消与超时也必须收尾。
// BOSS：自有空地自动建默认建筑；可升级时自动确认；满级继续。
// BOSS确定性自动处理是项目规则，不是原服务器行为的抓包证明。
// 当前超时策略：建造回复10；升级回复0；随后推进回合。
// 请求不带地产ID，服务端必须绑定当前行动者、地产和待决类型。
// 403D/403E在客户端不具备幂等性，重复接受会重复升级。
// 服务端要一次性结算，不能因重复请求再发第二次接受回包。

// 数值与范围
//
// 403D默认建筑免许可证；非默认合法建筑消耗对应许可证1张。
// Build.kpd的licence是物品ID，不是建造价格。
// 403E升级路径不重复扣许可证，也未见现金或存款扣除。
// BS_1_1常见建筑上限5，不等于物理写入函数的硬上限7。
// 地形231和232引用同一个地产216，只修改该地产一次。
// 当前construction资源校验明确绑定BS_1_1，不代表全图通用。

// 尚未覆盖
//
// 当前地产入口仍拒绝重叠角色及对手拥有的地产，不能标记全面完成。
// 不支持落点会抛错；GameSession异常路径会关闭游戏会话。
// 记录卡住现象时必须同时检查异常与连接关闭，不能只找缺少回包。
