//
// 找到正在运行的实例
// ----------------------------------------------------------------------------
// 先读 RichOnline.Admin.launch.json 和界面中的服务路径、数据目录、PID。
// 命令行可以覆盖旁置配置，不能仅凭文件内容断言实际运行路径。
// 从对应数据目录的 logs 读取当前进程日志，再核对 ready 和启动时间。
// 管理器界面只保留最近有限行数，屏幕上看不到不代表原始日志没有记录。
//
// 关联最小证据链
// ----------------------------------------------------------------------------
// 客户端操作时间 → 连接标识 → 收到 C2S → 业务分支 → 发出 S2C → 后续回报。
// 记录房间、当前行动者、计数域、落点、地产归属和等待阶段。
// 大厅与游戏可能是不同连接；大厅还在线不能证明游戏连接正常。
// 服务进程仍在也不能证明某个房间、连接或待决选择仍有效。
//
// 常见分歧点
// ----------------------------------------------------------------------------
// 未见 C2S：先核对是否观察了正确连接，再查客户端输入门槛或动画未完成。
// 收到 C2S 后断开：定位明确的拒绝或不支持事件，检查当前状态是否有处理分支。
// 收到 C2S 却没有后续动作：区分合法等待、超时未驱动和处理函数提前返回。
// 已发 S2C 但界面不动：复核加密封装、长度、字段域、对象初始化和阶段顺序。
// 界面关闭后才卡住：检查是否等待了错误 ACK，或遗漏取消与超时的回合推进。
// 这些是排查入口，不是看到现象就可直接写入报告的根因。
//
// 一条历史案例
// ----------------------------------------------------------------------------
// ../local-server/runtime/native-boss-live-20261009/logs/native-63848.jsonl
// 既有修复记录引用该文件第 409–412 行：BOSS 的 C2S 0x0011 到达落点 231，
// 关联地产 216，随后出现 richonline_boss_landing_unsupported 并关闭游戏连接。
// 根因记录为旧地产解析只接受未归属地产；修复增加自有地产处理分支。
// 这条案例不能推导所有卡回合都由地产导致，也不能证明最新部署已带该修复。
//
// 崩溃与转储
// ----------------------------------------------------------------------------
// CoreDump/ 下保留若干历史 dmp；只有发生时间、进程和二进制匹配才可关联。
// 区分访问违规、CRT 主动终止、普通断线、手工结束进程和服务端主动关闭。
// 已退出进程抓不到本次栈时，应明确写“缺少本次堆栈”。
// 不得把旧访问违规转储当成随后 CRT termination 的现场证据。
//
// 需要新现场时，先保存客户端散列、异常码、模块、偏移、调用栈和相关日志。
// IDA 地址需注明映像基址，运行地址受装载位置影响时给出换算依据。
// 仅凭反编译器函数名、char 截断或猜测类型不能确定线上字段宽度。
// 关键读取回到汇编核实，有疑点的业务名保留未知，不用补零伪装成已知默认。
//
// 修复落地检查
// ----------------------------------------------------------------------------
// 先将最小失败条件变成已有测试体系内的可重复场景，再做必要的状态修复。
// 自动加密 TCP 验证负责包序与状态，真人客户端负责窗口、动画和可操作性。
// 将两个结果分别记录，并列出地图、角色、超时和取消等实际覆盖范围。
// 新 exe 存在不代表已经切换：最终核对启动路径、散列和本轮 ready 公告。
// 无需排查就不能重启当前实例，以免丢失待决状态和其他协作者现场。
//
